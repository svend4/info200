# daten11 — «Информационная ОС для файлов»: 4-уровневая система метаданных с CLI-инструментами и веб-интерфейсом

## Обзор

daten11 — прототип «информационной операционной системы для файлов»: методология и набор инструментов для многоуровневой организации метаданных файлов и папок. Рядом с каждой папкой хранится `.folder-meta.json` (+ `.folder-readme.md`), рядом с каждым файлом — `имя.meta.json`, `имя.summary.md`, `имя.toc.md`. Поверх этого работают три CLI-утилиты на Python (менеджер метаданных, краулер, поиск), bash-скрипт автогенерации и Flask-веб-интерфейс с деплоем на Render.com.

Репозиторий целиком на русском языке (код, доки, README). Создан за один день (30 декабря 2025) в 8 коммитах: три PR от Claude, смёрдженные владельцем. Это типичный «одноразовый спринт с ИИ»: широкая по охвату, но непроверенная в работе кодовая база.

## Назначение и идея

Идея — «4 уровня информации» (отсюда описание репозитория «метаданные 4 уровня»):

1. **Стратегический** — имя папки;
2. **Тактический** — расширенные метаданные папки (`.folder-meta.json`, `.folder-readme.md`, `.folder-scripts/`);
3. **Оперативный** — обобщённые метаданные файла (`*.meta.json`, `*.summary.md`, `*.toc.md`);
4. **Практический** — само содержимое файла.

Цель: навигация и поиск по большим коллекциям документов без открытия самих файлов, плюс почва для автоматизации (AI-генерация описаний, интеграция с Elasticsearch/Meilisearch — описаны в доках как планы). Сценарии из README: домашняя библиотека, проектная документация, персональная база знаний.

## Как устроено (архитектура)

- **schemas/** — две JSON Schema (draft-07): `folder-meta.schema.json` (192 строки) и `file-meta.schema.json` (296 строк) формализуют структуру метаданных.
- **tools/** — три автономных CLI на чистом Python (без внешних зависимостей):
  - `metadata_manager.py` (422 строки) — init-folder / init-file / read / update; считает статистику папки, MD5/SHA256 файлов, определяет тип по расширению;
  - `crawler.py` (418 строк) — рекурсивное сканирование, поиск файлов без метаданных, JSON- и HTML-отчёты;
  - `search.py` (265 строк) — построение индекса по `*.meta.json`, текстовый/теговый/фасетный поиск. **Содержит блокирующий баг** (`os` не импортирован на уровне модуля — модуль неработоспособен при импорте, см. assessment.md).
- **scripts/auto_metadata.sh** (157 строк) — пакетная генерация базовых метаданных (вызывает metadata_manager по относительному пути — хрупко).
- **web/** — Flask-приложение `app.py` (257 строк, ~9 JSON-эндпоинтов: /api/search, /api/folders, /api/file, /download, /api/stats, /health), SPA-фронтенд `templates/index.html` (293 строки) + `static/js/main.js` (645 строк) + `static/css/main.css` (994 строки, тёмная/светлая тема). В `web/tools/` лежит **дубликат** search.py с тем же багом.
- **Деплой** — `render.yaml` (Blueprint для Render.com, gunicorn, healthcheck), `Procfile`, `runtime.txt` (python-3.11.0), `requirements.txt` (Flask 3.0, gunicorn; остальное закомментировано).
- **docs/** — 6 подробных руководств (~3800 строк md): METHODOLOGY, AI_AUTOMATION, MIGRATION_GUIDE, SEARCH_INTEGRATION, WEB_INTERFACE, RENDER_DEPLOYMENT — в основном описывают будущие/возможные расширения, а не реализованное.
- **examples/sample_library/** — демо-«научная библиотека» с одним разделом physics и одним документом со всеми видами метаданных.
