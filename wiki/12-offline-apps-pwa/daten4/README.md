# daten4 — динамический планировщик (одностраничные HTML-сборки + MVP AI-версии)

## Обзор

**daten4** — репозиторий «динамического планировщика»: конструктора планов/форм на основе шаблонов. Он состоит из двух слоёв:

1. **Четыре автономных HTML-файла** в корне (`dynamic-planner-v2.html`, `dynamic-planner (1).html`, `dynamic-planner(8).html`, `dynamic-planner-DEMO.html`) — это собранные (бандлированные) одностраничные React-приложения по ~245–460 КБ каждое. Работают полностью офлайн в браузере, данные хранятся в `localStorage`. Разные файлы — разные итерации/версии одного приложения.
2. **Папка `ai-planner/`** — MVP-прототип «AI-Powered Dynamic Planner»: клиент-серверная система управления большими шаблонами с chunking (разбиение шаблонов 5000+ строк на части по ~500 строк), RAG-поиском через ChromaDB и AI-ассистентом на Claude API. Добавлен через PR #1 (ветка `claude/review-repository-BWvEy`), автор коммита — claude.

Описание репозитория на GitHub: «dynamic planner, динамический планировщик с шаблонами и подключением ИИ». Корневой README — две строки: «dinamic planer динамический планировщик в одном файле HTML» (что уже не совсем точно: файлов четыре, плюс целый подпроект `ai-planner`).

## Назначение и идея

Идея планировщика: пользователь выбирает или создаёт **шаблон** (набор секций и полей — текст, дата, время, выпадающий список, чекбоксы, группы полей, условная логика «если поле … то …»), а затем заполняет его как план: встреча, конференция, отпуск, блог-пост, день рождения, еженедельный отчёт, список покупок и т.д. Судя по извлечённым UI-строкам, в приложении есть готовые примеры шаблонов, статусы задач («В работе», «Выполнено», «Запланировано»), приоритеты, экспорт/импорт данных («Данные успешно импортированы!»).

Слой `ai-planner` развивает идею дальше: когда шаблон становится очень большим (декларируется 5000+ строк JSON), его разбивают на чанки, индексируют в векторной БД (embeddings через OpenAI `text-embedding-3-large`, хранение в ChromaDB), а AI-ассистент (Claude 3.5 Sonnet, модель `claude-3-5-sonnet-20241022`) отвечает на вопросы по шаблону, ищет разделы семантически и автозаполняет поля на основе контекста (RAG).

## Как устроено (архитектура)

- **HTML-планировщики**: единый файл = инлайновый CSS (в v2 — свой CSS с переменными; в DEMO и (8) — Tailwind) + минифицированный бандл React 18 (`createRoot`, десятки `useState`). Персистентность — `localStorage`, есть импорт/экспорт JSON. Внешних запросов нет (упоминаний `api.anthropic` или fetch к внешним сервисам в бандлах не обнаружено) — то есть сами HTML-версии ИИ не используют.
- **ai-planner/backend** (Node.js + Express): `server.js` (helmet, CORS, rate limiting — 100 запросов/15 мин и 20 AI-запросов/мин, логирование, graceful shutdown), `routes/api.js` (7 endpoint'ов: `/api/chunk`, `/api/index`, `/api/search`, `/api/ask`, `/api/autofill`, `DELETE /api/index/:id`, `/api/health`), `services/chunking-engine.js` (274 строки — разбиение шаблона на чанки с overlap), `services/rag-engine.js` (456 строк — embeddings, поиск в ChromaDB, промпты к Claude, автозаполнение).
- **ai-planner/frontend**: только два файла — компонент `AIAssistant.jsx` (282 строки, чат с быстрыми вопросами) и API-клиент `services/api.js` (174 строки). **Каркаса приложения нет**: ни `package.json`, ни `index.html`, ни `App.jsx` — фронтенд как проект не запускается.
- **DevOps**: `docker-compose.yml` (ChromaDB + backend + Redis), но `backend/Dockerfile`, на который ссылается compose, **отсутствует**; GitHub Actions workflow `index-templates.yml` лежит в `ai-planner/.github/workflows/` (не в корне репозитория), поэтому **GitHub его никогда не запустит**.
- **Документация**: подробные `README.md`, `PROJECT_SUMMARY.md`, `DEPLOYMENT.md`, `docs/GETTING_STARTED.md` (449 строк) — но часть заявлений в них не совпадает с содержимым репозитория (см. [Характеристика и оценка](assessment.md)).
