# Характеристика и оценка daten4

## Что есть

- **Четыре работающих офлайн HTML-сборки планировщика** (~245–460 КБ каждая): полноценные бандлы React 18 с Tailwind/собственным CSS, конструктор шаблонов (типы полей, группы, условная логика «Если поле…»), готовые примеры (встреча, конференция, отпуск, блог-пост, покупки), статусы/приоритеты, localStorage-персистентность, импорт/экспорт («Данные успешно импортированы!»). Это самая ценная и, по-видимому, реально функционирующая часть репозитория (в браузере не запускалось — поведение оценено по коду; помечаю: не проверено вживую).
- **Осмысленный backend-код `ai-planner`**: `chunking-engine.js` (274 строки) и `rag-engine.js` (456 строк) — законченные классы с понятной логикой (chunking с overlap, embeddings через OpenAI API, ChromaDB, RAG-промпты к `claude-3-5-sonnet-20241022`, автозаполнение полей, оценка confidence); Express-сервер с helmet, CORS и двухуровневым rate limiting; 7 REST-endpoint'ов.
- **CLI-утилита** `scripts/chunk-template.js` (185 строк) — реально может резать JSON-шаблон на чанки без всякой инфраструктуры.
- **Обильная документация**: `ai-planner/README.md`, `PROJECT_SUMMARY.md`, `DEPLOYMENT.md`, `docs/GETTING_STARTED.md` (449 строк) — установка, API-ключи, troubleshooting.
- **Пример шаблона** `templates/examples/api-documentation.json` (412 строк, 8 секций, aiHints).
- **docker-compose.yml** с ChromaDB, Redis и healthcheck'ами (но см. ниже).

## Чего нет

- **Тестов** — ни одного тестового файла не обнаружено, хотя в `backend/package.json` заявлены jest/supertest и скрипт `"test": "jest --coverage"`.
- **Работающего CI** — workflow `index-templates.yml` лежит в `ai-planner/.github/workflows/`, а GitHub Actions читает только корневой `.github/workflows/`; workflow никогда не запускался и не запустится без переноса.
- **Лицензии** — файла LICENSE нет (GitHub: «License: Not specified»); в `backend/package.json` указан MIT, противоречие не оформлено.
- **Каркаса frontend в `ai-planner`** — нет `package.json`, `index.html`, `App.jsx`, конфига Vite; инструкция «cd frontend && npm install» из README невыполнима.
- **`backend/Dockerfile`** — отсутствует (проверено: 404), при этом `docker-compose.yml` собирает backend из него → «рекомендуемый» вариант запуска через Docker Compose из GETTING_STARTED.md падает.
- **`scripts/generate-embeddings.js`** — упомянут в структуре README и в workflow, но в репозитории отсутствует (404).
- **Исходников HTML-приложений** — только минифицированные сборки, среда сборки не закоммичена; править планировщик можно только пересобрав из внешнего (не опубликованного) проекта.
- Issues, releases, changelog, скриншотов/демо-ссылки (GitHub Pages не настроен, судя по метаданным — не проверено).

## Перепроверка самоотчётов (это аудит-перепроверка)

В репозитории есть самоотчёты `PROJECT_SUMMARY.md` и `DEPLOYMENT.md`. Сверка с фактами:

| Заявление | Реальность |
|---|---|
| DEPLOYMENT.md: «Ожидаемый результат (14 файлов)» и список из 16 позиций | В списке 16 позиций, не 14; все 16 файлов в репозитории есть (проверено пофайлово) — сам счётчик ошибочен |
| PROJECT_SUMMARY.md: «api-documentation.json — шаблон документации API (5000+ строк)» | Файл содержит **412 строк** — завышение более чем в 10 раз |
| README (`ai-planner`): в структуре указаны `scripts/generate-embeddings.js`, `frontend/package.json`, `backend/src/utils/`, `frontend/src/utils/` | `generate-embeddings.js` и `frontend/package.json` отсутствуют (404); папки utils не видны в дереве |
| PROJECT_SUMMARY.md: «GitHub Actions — автоматическое chunking при push» | Workflow есть, но неактивен (не в корне репозитория); ни одного запуска |
| PROJECT_SUMMARY.md: «Полноценный MVP прототип» | Backend-код полон, но система в целом незапускаема из коробки: нет Dockerfile, нет frontend-каркаса |
| Корневой README: «планировщик в одном файле HTML» | Файлов четыре + подпроект ai-planner |

## Плюсы

- Идея «планировщик = динамическая форма по шаблону» проработана и доведена до используемого офлайн-артефакта: файл можно просто открыть в браузере.
- Backend `ai-planner` написан аккуратно: разделение на движки/маршруты/сервер, rate limiting для AI-endpoint'ов, `.env.example`, обработка ошибок, санитарный `/api/health`.
- RAG-конструкция (chunking с overlap → embeddings → ChromaDB → Claude с источниками и confidence) — правильный современный паттерн, код читается легко.
- Хорошая по объёму русскоязычная документация с troubleshooting.
- Видна эволюция продукта (4 итерации HTML + AI-ветка) — репозиторий отражает живой поиск формы.

## Минусы

- Разрыв «документация ↔ реальность»: README/SUMMARY описывают файлы и цифры, которых нет; для стороннего пользователя это ловушка (следование GETTING_STARTED приводит к ошибкам на первом же шаге).
- `ai-planner` не запускается end-to-end: нет Dockerfile, нет frontend-приложения, workflow мёртв.
- Хранение версий приложения файлами `(1)/(8)/v2/DEMO` без исходников — невозможно ни диффать, ни сопровождать; имена с пробелами и скобками ломают URL.
- HTML-версии и AI-слой не интегрированы: заявленное в описании репозитория «подключение ИИ» в самих планировщиках отсутствует (в бандлах нет обращений к API).
- Нет тестов, лицензии, CI; счётчики в самоотчётах не сходятся.
- Зависимость сразу от двух платных API (Anthropic + OpenAI) без опции локальных embeddings.

## Качество кода и документации

Код backend — уровень добротного прототипа: JSDoc-комментарии, console-логирование с эмодзи, понятные имена, нет явных антипаттернов; но нет ни одного теста и обработка ошибок местами сводится к пробросу. Frontend-фрагменты (AIAssistant.jsx) чистые, но существуют в вакууме. Документация многословная и структурированная, однако достоверность ниже её объёма — часть содержимого написана «авансом» и не выверена по факту. HTML-бандлы оценке качества не подлежат (минифицированы).

## Зрелость: 2/5

Обоснование: есть реально открываемые в браузере артефакты (тянет выше 1), есть содержательный и неплохо написанный backend-код и объёмная документация. Но: система `ai-planner` не запускается по собственной инструкции, тестов и CI фактически нет, лицензия не оформлена, исходники основного продукта не опубликованы, а самоотчёты содержат проверяемо неверные утверждения. Это экспериментальный прототип, а не продукт; до 3/5 не хватает воспроизводимого запуска и правдивой документации.

*Ограничение покрытия аудита: HTML-бандлы (~1,6 МБ минифицированного кода) анализировались по заголовкам, строкам UI и маркерам API, без запуска в браузере; содержимое `docs/`, `templates/` и workflow прочитано полностью или большей частью, backend/frontend-исходники — полностью.*
