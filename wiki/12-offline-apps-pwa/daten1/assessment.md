# Характеристика и оценка daten1

## Что есть (реально сделано и работает)

- **Пять работоспособных офлайн-блокнотов** на sql.js (SQLite в WebAssembly). Флагман `notebook-2d-mega.html` — действительно большое приложение: ~3970 строк, ~90 именованных JS-функций, 5 таблиц БД (`users`, `notes`, `folders`, `note_history`, `templates`), Markdown-рендер (marked + GFM-таблицы), подсветка кода (highlight.js), диаграммы Mermaid, wiki-ссылки `[[...]]` с backlinks, вложенные папки с drag&drop, шаблоны заметок, корзина, история версий, bulk-операции, расширенный поиск, дашборд с графиками Chart.js, achievements, напоминания с Notification API, тёмная тема, горячие клавиши (Ctrl+N/F/D/E), мобильные свайпы.
- **PWA-обвязка**: `manifest.json` (shortcuts, SVG-иконки) и `sw.js` (cache-first, кэш CDN-библиотек) — установка и офлайн-режим для mega-версии.
- **Три играбельных варианта аркады** «Космический Защитник» (2D/2.5D/3D): счёт, уровни, жизни, экраны старта/окончания, клавиатура и touch.
- **Три учебных md-документа на русском**, из которых `browser-games-guide.md` (~1000 строк) — полноценный учебник с работающими примерами кода вплоть до полного Arkanoid.
- **Архив flower_shop_master_levels_v7.zip** — целостный снапшот 114 файлов: один и тот же магазин на 7 стеках (PHP → Flask → Django → Express → API+React → Next.js/TS → микросервисы с Docker/K8s), с README на каждый уровень и заполненными базами flowers.db.

## Чего нет

- **Тестов** — ни одного (ни unit, ни e2e); при ~13 000 строк JS-логики регрессии ловить нечем.
- **CI/CD** — нет `.github/workflows`; нет и автопубликации на GitHub Pages, хотя для такого репозитория это напрашивается.
- **Лицензии** — файла LICENSE нет; формально код нельзя легально переиспользовать.
- **Документации** — README из двух строк («Info nnnn»): ни списка приложений, ни ссылок на живые демо, ни скриншотов, ни инструкции запуска. CLAUDE.md отсутствует.
- **Упаковки/сборки** — по замыслу не нужна, но нет даже index.html-каталога, чтобы открыть репозиторий как витрину.
- **Issues/веток/релизов** — 0 issues, релизов нет; история — единственная ветка main.
- **Изоляции данных между версиями** — см. минусы.

## Плюсы

- **Zero-install архитектура**: каждый файл — законченное приложение, работающее с file:// или любого статического хостинга; отличная демонстрация паттерна «SQLite в браузере».
- Mega-блокнот по набору фич сопоставим с младшими версиями Notion/Obsidian-подобных инструментов — впечатляющий объём для одного HTML-файла.
- Последовательная линейка версий (2d → 2.5d → 3d → ultra → mega) наглядно документирует эволюцию — полезно как учебный материал.
- Мобильная поддержка сделана всерьёз: touch-управление в играх, свайпы и адаптив в блокноте.
- Русскоязычные гайды по геймдеву самодостаточны и аккуратны.

## Минусы

- **Конфликт данных**: `notebook-2d-mega.html` и `notebook-2d-ultra.html` используют один ключ `localStorage` — `notebook_ultra_db` (строки 1394/1684 mega). На одном домене они молча делят одну базу с разными схемами — риск порчи данных.
- **Неэффективная персистентность**: `JSON.stringify(Array.from(db.export()))` хранит каждый байт БД десятичным числом с запятой (~3.7× раздувание) в localStorage с лимитом ~5 МБ — реальный потолок базы всего ~1.3 МБ. IndexedDB решил бы проблему.
- **PWA сломается вне корня домена**: абсолютные пути `/notebook-2d-mega.html`, `/sw.js` в манифесте и SW не работают на GitHub Pages проектного типа (`/daten1/`).
- **Зависимость от CDN**: «офлайн»-режим наступает только после первой успешной загрузки с 8 внешних URL; без интернета первый запуск невозможен, версии библиотек не зафиксированы локально.
- **Дублирование кода** между пятью блокнотами и тремя шутерами без общего ядра — исправление бага требует правок в нескольких файлах.
- «Многопользовательность» — переключение локальных профилей без аутентификации; название `Многопользовательский Блокнот` вводит в заблуждение.
- Zip-архив в git — антипаттерн: содержимое не диффится, не индексируется поиском, дублирует тематику репозиториев daten2/meta4.

## Качество кода и документации

Код — типичный результат интенсивной генеративной сессии: читаемый, с русскими комментариями, последовательным неймингом (`renderNotes`, `saveDatabase`, `handleFolderDrop`), но монолитный (весь JS в одном `<script>` на тысячи строк), без модулей, линтера и обработки краевых случаев (ошибки кэширования в sw.js просто глотаются `catch(() => {})`). SQL-запросы параметризованы (`db.exec('... WHERE user_id = ?', [currentUserId])`) — базовая гигиена соблюдена. Документация проекта — фактически отсутствует (README-заглушка), при этом учебные md-файлы внутри — хорошего качества. Живых демо-ссылок нет, что для витрины HTML-приложений — главный недочёт.

## Зрелость: 2/5

Обоснование: работоспособные и местами богатые по функциональности демо (это больше, чем 1/5), но: нет тестов, CI, лицензии, README, живых демо; есть подтверждённые дефекты (общий ключ localStorage у двух версий, нерабочие PWA-пути вне корня домена); развитие остановилось после двухдневного спринта в декабре 2025 (последний коммит — правка README 03.01.2026). До 3/5 не хватает минимальной инженерной обвязки и сопровождения.

*Ограничение покрытия аудита: HTML-файлы проанализированы по структуре, заголовкам, списку функций, схемам БД и ключевым фрагментам кода, но не исполнялись в браузере; поведение в рантайме (например, фактическая работоспособность экспорта в PDF или 3D-сцен) не проверялось. Содержимое zip проверено по списку файлов и README уровней, код уровней детально не читался.*
