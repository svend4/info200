# Характеристика и оценка data70

## Что есть

- **Полный сырой архив**: 153 файла `chat_export/*.txt` (существование файлов 001–153 подтверждено выборочно, 154-го нет) в едином парсируемом формате + первый экспорт `chatgpt_export_full.txt` (~7,6 МБ, 7 953 307 байт). Это реальные данные, а не заглушки.
- **Многослойная аналитика**: 7 файлов `analysis_*` и 6 файлов `part10–14` — статистика (1105 разговоров, 29 802 сообщения), кластеры, каталог 88 тем, 13 изобретений, стратегия монетизации. Документы содержательные, с конкретными таблицами и цифрами, а не общими словами.
- **Работающий конвейер в граф знаний**: `prepare_for_infom.py` — аккуратный скрипт на чистом stdlib (re/json/os), результаты его работы (`infom_import.json`: 197 нод, 576 рёбер; `infom_snapshot.json`) закоммичены — то есть скрипт реально запускался и отработал.
- **Монорепозиторий-надстройка** из 14 папок: проверенные кластеры соответствуют заявленному шаблону (README + map + next_steps; в `01_social_law` — 15 тем-подпапок, в `07_inventions_patents` — 24 карточки, что совпадает с сообщением коммита «24 patent cards»).
- **Уникальный контент**: кластер соцправа Германии (SGB IX/XII, Persönliches Budget) с 50+ шаблонами на немецком — редкая предметная база, привязанная к реальной судебной практике.
- **История через PR**: работа велась через pull request'ы (мерджи PR #5, #6 в истории), осмысленные сообщения коммитов.

## Чего нет

- **Файла LICENSE** — в README заявлен «открытый доступ, используйте свободно», но юридически значимой лицензии (CC0/CC-BY/MIT) в корне нет; для «завещания идей» это критичный пробел.
- **Тестов** — для `prepare_for_infom.py` нет ни одного теста (при этом парсер завязан на хрупкое регулярное выражение с жёстко зашитым `1105`).
- **CI** — нет `.github/workflows`, ничего не проверяется автоматически (даже валидность JSON или битые внутренние ссылки монорепо).
- **Инструкции запуска** — как воспроизвести `infom_import.json` и что делать с ним дальше (какой командой загрузить в infom), описано только косвенно в docstring.
- **Приватность/анонимизация** — политика работы с персональными данными не описана: в архиве реальные медицинские и юридические детали, в `analysis_04_social_law.md` автор назван по имени.
- **Карточек в `88_topics_full/`** — `monorepo/STRUCTURE.md` обещает «Карточки на все 88 тем каталога», фактически в папке только README-индекс со ссылками (см. «перепроверка» ниже).
- **Актуальность веток**: 2 несмерженные ветки `claude/…` (июнь 2026) висят поверх `main` (апрель 2026) — их судьба не определена.

## Плюсы

- Реальные, объёмные, машиночитаемые данные с единым форматом — редкость для «info»-репозиториев профиля.
- Дисциплина слоёв: сырьё → аналитика → навигация → граф; правило неизменности первоисточников сформулировано явно.
- Аналитика конкретна: числа, таблицы, приоритеты (А/Б/В с баллами), бюджеты MVP — можно перепроверять и использовать.
- Готовый мост к другому репозиторию профиля (`infom`) — редкий случай фактической, а не декларативной связи между репо.
- Сильная человеческая мотивация и честный контекст (MANIFEST) — понятно, зачем всё это.

## Минусы

- Скрипт хрупкий: регулярка `РАЗГОВОР (\d+)/1105:` и диапазон `range(1, 154)` жёстко зашиты — на другом экспорте конвейер молча даст пустой результат.
- Классификация тем — по спискам ключевых слов, без валидации качества; «архетипы» (MSCF/ADCO…) нигде в репо не расшифрованы.
- Двойная таксономия (кластеры A–J и папки 01–10) усложняет навигацию, несмотря на таблицу соответствия.
- Расхождения в цифрах между документами (5 МБ vs 7,6 МБ; «карточки 88 тем» vs индекс) — мелкие, но для архива-«истины» нежелательные.
- Огромные txt-файлы в git без LFS: клонирование тяжёлое, диффы бессмысленные.
- Нет юридической лицензии и политики персональных данных — при заявленной цели «пусть используют все» это главный риск.

## Качество кода и документации

- **Код** (1 файл): чистый, с docstring и русскими комментариями, разумной декомпозицией на функции; типизация частичная (`tuple[str, str]`); без внешних зависимостей — запускается голым Python 3.10+. Но: нет тестов, нет CLI-аргументов (пути и константы зашиты), захардкоженная дата `"2026-03-28"` в снапшоте. Оценка кода: 3,5/5.
- **Документация**: обширная и в целом согласованная; README корня — хорошая точка входа; карточки монорепо следуют шаблону. Слабое место — точность отдельных цифр и обещаний (см. перепроверку) и отсутствие «как воспроизвести». Оценка документации: 4/5.

## Зрелость: 3/5

Обоснование: как **архив** — состоявшийся и практически завершённый (данные зафиксированы, аналитика написана, навигация построена) — на 4/5. Как **проект/продукт** — только каталог намерений: ни один из 88 пунктов не доведён здесь до кода, лицензии нет, конвейер в infom одноразовый и без тестов, две ветки повисли — на 2/5. Итоговая интегральная оценка — 3/5: ценность высокая, инженерная зрелость средняя.

*Ограничение покрытия: из ~350–400 файлов прочитано полностью ~10 и по заголовкам ещё ~12; содержимое кластеров 02–06, 08–10, веток `claude/*` и основной массы 153 txt-файлов не читалось — оценка их качества экстраполирована по проверенным образцам.*
