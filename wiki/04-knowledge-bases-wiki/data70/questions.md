# Вопросы к data70

## 1. Что находится в несмерженных ветках `claude/trusting-allen-XHaaw` (07.06.2026) и `claude/restructure-monorepo-folders-zUtMN` (05.06.2026) и планируется ли их мердж?

`main` не менялся с 25 апреля 2026, но две ветки обновлялись в июне — именно они создают впечатление «активного» репозитория.

**Варианты ответов:**
- А. Там готовая доработка монорепо, просто не смерджена.
- Б. Это брошенные эксперименты, содержимое устарело.
- В. Не помню / нужно посмотреть.

**Варианты дальнейших действий:**
- При А: открыть PR, прогнать проверку ссылок, смерджить — main станет актуальным.
- При Б: удалить ветки, чтобы дата обновления репозитория не вводила в заблуждение.
- При В: провести ревизию diff'а веток против main (это быстро — репо в основном md) и принять решение А или Б.

## 2. Какова юридическая форма «открытого доступа» — какую лицензию вы имеете в виду?

README обещает «используйте свободно», MANIFEST называет архив «завещанием идей», но файла LICENSE нет. Без него формально действует «all rights reserved», и осторожные люди не смогут легально реализовать ваши идеи — что противоречит цели.

**Варианты ответов:**
- А. Полный отказ от прав (CC0) — пусть берут всё.
- Б. Свободно, но с указанием авторства (CC-BY 4.0).
- В. Тексты открыты, но патентные идеи хочу сначала защитить.

**Варианты дальнейших действий:**
- При А: добавить LICENSE = CC0 1.0 + строку в README.
- При Б: LICENSE = CC-BY 4.0 + для скрипта MIT.
- При В: дуальная схема — CC-BY на всё, кроме `07_inventions_patents/`, а для 3–5 главных изобретений оформить defensive publication (фиксирует приоритет, блокирует чужие патенты).

## 3. Загружен ли граф (`infom_snapshot.json`) в infom на самом деле, и работает ли поиск по нему?

Скрипт и JSON-результаты закоммичены (197 нод, 576 рёбер), но подтверждения замкнутого контура (запрос → ответ по архиву) в data70 нет.

**Варианты ответов:**
- А. Да, загружен, GraphRAG-поиск по темам работает.
- Б. Загружен, но пользы мало — граф слишком «метаданный», без полного текста.
- В. Нет, остановился на генерации JSON.

**Варианты дальнейших действий:**
- При А: задокументировать в README data70 команду запроса и 2–3 примера ответов — это главный демонстрационный кейс связки репозиториев.
- При Б: перейти от графа метаданных к полнотекстовому RAG: чанкинг 153 txt-файлов + эмбеддинги, граф оставить как навигационный слой.
- При В: доделать последний шаг пайплайна (загрузку) или честно пометить интеграцию как «эксперимент, не завершён».

## 4. Точны ли ключевые цифры аналитики, и чем объясняется расхождение «5 МБ» против фактических 7,6 МБ у `chatgpt_export_full.txt`?

Аналитика оперирует точными числами (1105 разговоров, 29 802 сообщения, 455 МБ исходника), но исходный `chat.html` в репо не попал (в .gitignore) — цифры невоспроизводимы, а одна проверяемая цифра README не сошлась.

**Варианты ответов:**
- А. «5 МБ» — старая цифра до дополнений файла; остальное считал скрипт по chat.html.
- Б. Цифры оценочные, писались вручную/ИИ — возможны неточности.
- В. Есть скрипт подсчёта, он просто не закоммичен.

**Варианты дальнейших действий:**
- При А: обновить README и добавить в него дату/версию цифр.
- При Б: пометить оценочные числа как «≈» и пересчитать ключевые (число разговоров, сообщений) простым скриптом по chat_export/ — данные для этого в репо есть.
- При В: закоммитить скрипт подсчёта рядом с `prepare_for_infom.py` — воспроизводимость резко повысит доверие к аналитике.

## 5. Осознанно ли опубликованы персональные медицинские и юридические данные, и нужна ли анонимизация третьих лиц?

`analysis_04_social_law.md` называет автора по имени, указывает город, GdB и Pflegegrad; в 78 МБ разговоров почти наверняка есть имена врачей, чиновников, номера дел.

**Варианты ответов:**
- А. Да, публикация своих данных — осознанное решение (см. MANIFEST).
- Б. Свои данные — да, но третьих лиц не проверял.
- В. Не думал об этом, надо проверить.

**Варианты дальнейших действий:**
- При А: добавить в MANIFEST явный абзац-согласие, чтобы снять вопросы у переиспользующих архив.
- При Б: прогнать по chat_export/ поиск паттернов (Aktenzeichen, фамилии с титулами Dr./Frau/Herr) и замаскировать третьих лиц — это требование GDPR даже при открытой публикации своих данных.
- При В: временно перевести сырьё в приватный репозиторий/LFS, оставив открытой аналитику, до завершения проверки.

## 6. Какой из путей продолжения приоритетен для вас: продукт (SozialHelper), инструмент (поиск/RAG по архиву) или публикация (книга/вики)?

Архив разложен на 88 тем и 5 суперпроектов с бюджетами €100–220K, но без команды и финансирования реалистичен только один трек за раз.

**Варианты ответов:**
- А. Соцправо: помочь таким же людям, как я, — и это же первая «волна» монетизации.
- Б. Инструмент для себя: поиск и RAG по собственной памяти.
- В. Публикация: главное — чтобы идеи не пропали, остальное вторично.
- Г. Ничего: архив завершён, силы уходят на другие репозитории.

**Варианты дальнейших действий:**
- При А: начать с пакета шаблонов из `01_social_law` (Gumroad/бот) — нулевые вложения, готовый контент.
- При Б: связка с daten22 (SQLite FTS) — офлайн-поиск за несколько вечеров, затем эмбеддинги.
- При В: MkDocs/Quartz-сайт из monorepo на GitHub Pages + сабмит в Internet Archive.
- При Г: сделать только «быстрые улучшения» (LICENSE, цифры, ветки) и заморозить с тегом-релизом v1.0 — зафиксированное состояние и есть цель архива.
