# Рекомендации по info15

## Быстрые улучшения

1. **Написать корневой README.md** (сейчас 2 строки): что это за вики, о каком канале, как читать, ссылки на `yersham_wiki/README.md` и `yersham_wiki_v2/README.md`.
2. **Синхронизировать CLAUDE.md с реальностью**: убрать несуществующие `raw/` и `wiki/` из схемы (или создать их), заменить `15-video-full-catalog` в карте связей на 6 реальных каталогов `20–25-catalog-*`, дописать историю обновлений (каталоги, v2).
3. **Починить нумерацию**: переименовать `20-catalog-agi-future.md` (коллизия с `20-innovations-2026.md`) и закрыть дыру `15-*` — например, каталоги перевести в `30–35-*`.
4. **Убрать дубли из `yersham_wiki_v2/README.md`**: карта разделов и «дельта» повторяются дважды с разными формулировками — след неаккуратного merge.
5. **Добавить LICENSE** (например, CC BY-SA для текстов) и дисклеймер о том, что вики — конспект чужого контента с непроверенными «утечками».
6. **Добавить линк-чекер** (простой скрипт + GitHub Action): валидность `[[wiki-ссылок]]`, уникальность номеров файлов, синтаксис youtu.be-ID.

## Серьёзные доработки

1. **Восстановить слой `raw/`**: выгрузить список видео канала (yt-dlp / YouTube Data API: названия, ID, даты, просмотры) и, по возможности, транскрипты — тогда каждая статья станет проверяемой, а «компиляция» воспроизводимой. Это главный разрыв между заявленной архитектурой Карпати и фактической реализацией.
2. **Автоматизировать цикл обновления**: скрипт/агент, который по расписанию берёт новые видео канала, кладёт их в `raw/`, прогоняет «компиляцию» (Claude Code по правилам CLAUDE.md) и открывает PR. Без этого вики о канале с 2+ видео в день мертва по определению.
3. **Слить v2 в v1**: v2 — это 190 строк «практического слоя», который логичнее встроить в v1 как раздел (сами авторы v2 в `06-v2-new-video-evidence.md` пишут, куда именно встраивать). Две параллельные вики умножают навигационную путаницу.
4. **Верификация фактов**: пометить каждое утверждение типа «утечка», «слух» отдельным тегом и завести страницу проверки — вики сама оценивает верифицируемость канала на 6/10, но не применяет этот скепсис к себе.

## Варианты продолжения

**Сценарий 1: «Живой радар» — автоматически обновляемая вики канала.** Довести до конца исходную задумку: raw-слой из YouTube API, ежедневный агентный прогон (ingestion → compilation → linting по CLAUDE.md), PR с новыми статьями и обновлением каталогов. Результат — первый в профиле действительно самообновляющийся LLM Knowledge Base, а заодно живая демонстрация методики Карпати на реальном потоке 2+ видео/день. Трудоёмкость умеренная: конвейер из yt-dlp + Claude Code + GitHub Actions.

**Сценарий 2: «Шаблон-фабрика» — обобщить до инструмента `channel2wiki`.** Извлечь из info15 повторяемый паттерн: «любой YouTube-канал/подкаст/блог → структурированная вики». Оформить CLAUDE.md-правила, структуру каталогов и промпты как переиспользуемый шаблон (или Claude Code skill), где @yersham — просто первый пример. Ценность смещается с контента на метод; это хорошо продаваемая история для портфолио и напрямую реализует тезис самой вики «базовая единица масштабирования — не модель, а повторяемый workflow».

**Сценарий 3: «Исследовательский корпус» — заморозить и использовать как датасет.** Признать снапшот законченным, зафиксировать релизом v1.0 с лицензией, и использовать корпус (37 связных статей, 194 ссылки, готовый граф `[[связей]]`) как эталонные данные для экспериментов из других репозиториев профиля: сравнение RAG vs GraphRAG vs прямого чтения вики, тесты агентной навигации по знаниям, оценка качества суммаризации. Минимум усилий, максимум переиспользования.

**Сценарий 4 (дополнительный): «Аналитическое издание».** Переработать лучшие статьи (11-frontier-unrealized, 14-knowledge-systems, 18-narrative-2025) в самостоятельные лонгриды/публикации о трендах ИИ 2025–2026 — контент уже наполовину готов, но заперт в формате конспекта чужого канала.

## Сочетания с другими репозиториями профиля

1. **info15 + infom (ГрафРАГ) = живой стенд «LLM Wiki vs GraphRAG» на одном корпусе.** Статья `14-knowledge-systems.md` теоретически сравнивает RAG, Knowledge Graphs и LLM-вики — а связка с infom позволяет провести это сравнение эмпирически: распарсить `[[связи]]` info15 в граф знаний, поднять GraphRAG-поиск и замерить качество ответов против прямого чтения markdown агентом. Получится уникальный воспроизводимый бенчмарк подходов к базам знаний на русскоязычном корпусе — то, чего нет в открытом доступе.

2. **info15 + information (новости/ньюз) + daten8 (мониторинг интернет-объявлений) = автономный «AI-новостной радар».** У daten8 есть паттерн мониторинга внешних источников, у information — новостной формат, у info15 — структура знаний и рейтинги важности. Вместе: конвейер, который отслеживает новые видео канала (и другие источники), автоматически пишет вики-статьи и генерирует дайджест «что важного случилось в ИИ за неделю» с ★-приоритизацией. Инновация — новостная лента, у которой за каждой новостью стоит накопительная база знаний, а не одноразовая заметка.

3. **info15 + info30 (Claude Code Knowledge System) + info200 (хаб вики) = эталонная «фабрика знаний» профиля.** info30 даёт систему знаний вокруг Claude Code, info15 — отработанную конвенцию (CLAUDE.md-правила, связи, каталоги), info200 — центральный хаб. Объединение превращает 61 разрозненный репозиторий в единую федеративную вики, где info15 служит образцом оформления узла. Уникальный результат — самодокументирующийся GitHub-профиль: агент по правилам info15 сам ведёт вики о каждом репозитории.

4. **info15 + in4n (динамический информационный граф) = интерактивная карта знаний канала.** Экспортировать граф `[[связей]]` и 194 видео-узла в визуализацию in4n: интерактивная карта тем ИИ 2025–2026, где кликом открывается статья и видео. Из статичного markdown получается исследуемый визуальный артефакт — «Obsidian graph view», но веб-публичный и тематически размеченный.
