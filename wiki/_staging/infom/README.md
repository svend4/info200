# infom — геометрическая GraphRAG-система (граф знаний + Q6-семантика)

## Обзор

**infom** (в коде — InfoM, «Geometric GraphRAG System») — один из самых проработанных технических репозиториев профиля svend4. Это самостоятельная GraphRAG-система на чистом Python (ядро — только stdlib): текст → извлечение сущностей и связей (LLM NER) → граф знаний → сообщества → ответы на вопросы в режимах local/global/hybrid. Отличительная черта — «геометрическая семантика»: каждая сущность получает не только embedding, но и Q6 hex-адрес (6 бит, 64 ячейки гиперкуба), тангрэм-сигнатуру формы кластера, фрактальную размерность границы и гептаграммный/октаграммный профиль.

Система обёрнута сразу в три интерфейса: MCP-сервер для Claude Code (`infom_mcp.py`, 11 инструментов), REST API на FastAPI (`infom_api.py`, 13 эндпоинтов, включая вебхуки для Make.com/n8n/Zapier) и GitHub Actions-агент (`.github/workflows/infom-agent.yml` на базе claude-code-action). Есть конфиги деплоя на Fly.io, Railway и Render.

## Назначение и идея

Замысел (описан в `CLAUDE.md` и `docs/architecture/genesis.md`) — «понимающий» слой персональной AI-инфраструктуры автора: инструмент, превращающий сырые архивы знаний (в первую очередь репозиторий `data70` с 1105 экспортированными диалогами ChatGPT) в запрашиваемый граф знаний. Ключевые идеи:

- **Q6-адресация**: любой embedding (6D…1536D) через average-pool проецируется в 6-битный адрес — сжатая топологическая навигация по семантическому пространству (идея заимствована из репозитория `meta`/hexcore).
- **Геометрические сигнатуры**: форма сообщества (тангрэм), сложность границы (box-counting фрактальная размерность), профили по 7/8 лучам — как дополнительные признаки для поиска и объяснения.
- **Работа без реального LLM**: `semantic_sim.py` даёт 32-мерные «словарные» семантические векторы и синтез ответов из контекста графа — вся система тестируема офлайн и бесплатно; при этом `config.py` поддерживает 10 провайдеров (Ollama, OpenAI, Cohere, Groq, OpenRouter, Jina, Together, Gemini, mock, semantic) с fallback.
- **Агентная эксплуатация**: паттерн «мозг + данные» — репозиторий infom служит «мозгом» (инструкции в `skills/*.md`, задача в `tasks/current_task.md`), а анализируемый репозиторий — «данными»; ночной cron-агент строит граф и пишет отчёты в `results/`.

В `results/analysis_data70_2026-03-28.md` лежит реальный результат применения: граф по data70 (46 нод, 8 рёбер, 6 сообществ) с ответами на 4 аналитических вопроса.

## Как устроено (архитектура)

Четырёхуровневая иерархия (описана в `pipeline.py`):

```
L0  GraphNode      — сущность: embedding + архетип + Q6 hex-адрес
L1  HyperEdge      — кластер 3–8 нод (Tangram + Heptagram)
L2  Community      — «шестиугольное» сообщество (Q6 + Fractal + Octagram)
L3  KnowledgeMap   — сота всех сообществ с фрактальными границами
```

Основные подсистемы:

- `indexer.py` — чанкинг по предложениям с перекрытием, LLM-извлечение сущностей/связей (JSON-промпт), классификация по 16 архетипам, сборка KnowledgeMap;
- `graph/` — структуры графа, label propagation для сообществ, PCA-lite (power iteration) для 2D-раскладки — всё на stdlib;
- `signatures/` — Q6 (hexsig), тангрэм, фрактал, гептаграмма, октаграмма;
- `search/` — двухэтапный HNSW-подобный поиск (Hamming ball по Q6 → косинусный rerank), Multi-Projection LSH (3 независимые ортогональные проекции), локальный/кластерный/граничный/радиальный поиск, бенчмарк recall;
- `graphrag_query.py` — режимы local (вокруг ноды), global (MapReduce по сообществам), hybrid; расширение запроса через `archetypes/query_expander.py`;
- `visualizer/` — ASCII-рендер и экспорт в интерактивный D3.js HTML (пример — `infom_graph.html`, 1669 строк).

Интеграционный слой: `infom_mcp.py` (JSON-RPC 2.0 через stdio, персистентность в `graph_snapshots/latest.json`), `infom_api.py` (FastAPI + CORS + Swagger), `Dockerfile`/`fly.toml`/`railway.toml`/`render.yaml`, инструкции интеграции в `docs/integrations/` (Make.com, n8n, Zapier/Activepieces). Дополнительно — два «openclaw»-скилла (`openclaw-skills/`): обёртка GraphRAG-API и скилл по немецкому социальному праву (Sozialrecht, SGB IX/XII/V/II/III).

- ~33–36 коммитов; последняя активность — 28–29 марта 2026 (merge PR #4 из ветки `claude/...`). На дату аудита (июль 2026) — около трёх месяцев без коммитов.
