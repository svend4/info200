# daten40 — корпус спецификаций IFOS (Internet Function OS) + полигон Make.com-пайплайна

## Обзор

**daten40** — это append-only репозиторий-хранилище проекта **IFOS (Internet Function OS)**: концептуальной B2B-платформы для каталогизации и стандартизации «интернет-функций». Репозиторий содержит 210 так называемых OS_PACK-блоков (по данным `blocks/_block_index.json` — 4225 файлов внутри блоков: концептуальные Markdown-документы, ~1466 JSON-схем, ~139 OpenAPI-спецификаций, ~546 Python-заглушек), мастер-индексы, очереди задач и HTML-навигатор. Важно: это **не работающее программное обеспечение**, а «бумажная архитектура» (design specification) — что честно указано в самом мастер-индексе проекта (`master_index/IFOS_MASTER_INDEX_20260618.md`: «Design Specification (paper architecture) — no production code yet»).

Вторая, историческая часть репозитория — артефакты **тестирования пайплайна Make.com + Claude AI → GitHub API** (январь 2026): тестовые файлы 10+ форматов, отчёты о создании трёх Make.com-инструментов для сохранения текстовых и бинарных файлов в GitHub, документация по борьбе с проблемами Base64/ZIP.

## Назначение и идея

Идея IFOS (изложена в founding-документе `blocks/00_GENESIS/IFOS_00001_14240_concept_genesis/`): вместо изобретения новых инструментов — **рационализировать и каталогизировать уже существующие** интернет-функции (плагины, сценарии Make/n8n, API, приложения) в единый реестр с паспортами, репутацией и единым API-слоем. Каждая функция/рецепт получает паспорт: входы/выходы, зависимости, риски PII, лицензия, уровень качества L0–L5 (Quality Ladder от Draft до Enterprise/Gov).

Шестислойная архитектура IFOS:

1. **Function Registry** — единый реестр интернет-функций с паспортами
2. **Vocabulary / Schema** — унифицированные схемы данных
3. **Composer / Macros** — составные функции, «рецепты» и макросы
4. **Blueprints** — готовые one-click сценарии развёртывания
5. **Trust Layer** — репутация, SLA, evidence, аудит
6. **AI Layer** — паспортизация, дедупликация, интеллектуальная оркестрация

Репозиторий служит «складом» этой проработки: тематические диапазоны шагов (1–88800) нарезаны на блоки по ~400 шагов, каждый блок = пакет из главного MD-документа, JSON-схем, OpenAPI-спеки, примеров и Python-скелетов.

## Как устроено (архитектура)

- **`blocks/`** — ядро: 210 OS_PACK-блоков в 7 слоях (`00_GENESIS`, `01_FOUNDATION`, `02_CORE_PLATFORM`, `03_DEVELOPER`, `04_ADVANCED`, `05_ENTERPRISE`, `06_FINANCE_LEGAL`; есть и пустой каркас восьмого слоя `07_DOMAIN_PACKS` — README c «Blocks: 0» под будущие Gov/Healthcare/Education-паки), плюс машинный индекс `_block_index.json` и одностраничный HTML-навигатор `index.html` («IFOS Wiki Navigator» с поиском и фильтрами по слоям). Также — legacy-папки `NEXT-17…NEXT-20` и `NEXT-22` (январский append-only формат с manifest/checksums; `NEXT-21` отсутствует) и несколько ZIP-бандлов.
- **`master_index/`** — «позвоночник» проекта: версии Master Index (актуальный `IFOS_MASTER_INDEX_20260618.md/.json`) и дельта-файлы.
- **`tools/`** — очереди задач `NEXT_QUEUE_*.md` (последняя `NEXT_QUEUE_v1_20260618.md`: DONE=88800, следующий блок 88801–89200), правила append-only, политика публикации бинарников.
- **Январский тестовый слой**: `docs/`, `scripts/`, `config/`, `data/`, `database/`, `web/`, `archives/`, `chatgpt-tests/`, `make_test/`, `test/`, `test-notes/` — демонстрация автосоздания файлов через Make.com; отчёты `FINAL-REPORT.md`, `FINAL-THREE-TOOLS-REPORT.md`, `FILES-INDEX.md`.
- **Рабочий принцип**: append-only — файлы не перезаписываются, новые версии добавляются с датой/версией в имени; источник истины — последний Master Index по дате.

## Статус и активность

- **809 коммитов** (по данным страницы репозитория), все от svend4; один открытый issue.
- Две волны активности: **12–13 января 2026** (тесты Make.com-пайплайна, первые IFOS-блоки NEXT-17…22, стратегия append-only) и **18 июня 2026** (массовая заливка 210 распакованных OS_PACK-блоков, по коммиту на файл, свежий Master Index и навигатор).
- Очередь задач актуальна: определён следующий диапазон (88801–89200, Gov Domain Packs), перечислены критические задачи (регенерация битого ZIP и 5 потерянных блоков). При этом пересчёт индекса в рамках аудита показал, что реальных проблем целостности больше: 8 дыр нумерации (3 из них нигде не задокументированы) и 30 задублированных диапазонов — подробности в [структуре](structure.md) и [оценке](assessment.md). Проект выглядит **активным** — последняя активность за ~2 недели до даты аудита.
- Мастер-индекс ссылается на репозиторий **svend4/data70** как источник (экспорт чатов, «РАЗГОВОР 5/1105») — daten40 является частью связки репозиториев.
