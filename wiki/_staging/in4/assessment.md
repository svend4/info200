# Характеристика и оценка in4

## Что есть

- **Завершённая 15-страничная серия** (~854 КБ, ~14 900 строк HTML) о домашних AI-кластерах: все файлы из оглавления README реально существуют и непустые — перепроверено скачиванием каждого файла.
- **Глубокое и конкретное содержание**: не обзорные «статьи ни о чём», а плотные справочные таблицы с числами — например, в `networking-deep-dive-ru.html` для каждого канала (Wi-Fi 7, 1G…40GbE) указаны реальная пропускная способность, латентность в микросекундах, поддержка RoCE v2 и цены на б/у оборудование; в `model-quantization-guide-ru.html` — формулы расчёта памяти и скорости, таблица «модель × железо» в tok/s.
- **Полный жизненный цикл темы**: выбор железа → сеть → кластеризация → модели/квантизация → продакшн (systemd, Docker, Prometheus/Grafana, Ansible, безопасность) → экономика (TCO, $/tok/s, ROI, электричество по странам).
- **Инженерная ветка с амбицией на вклад в open source**: два руководства по портированию prima.cpp на Vulkan с планом из 7 фаз, словарём CUDA→Vulkan, разбором алгоритма Halda и «чеклистом для хакатона» — это уровень проектной документации, а не пересказа.
- **Аккуратная вёрстка**: единый тёмный стиль GitHub-подобной темы, адаптивность (media queries), цветовое кодирование оценок; страницы читаются локально без зависимостей.
- **Честная датировка**: README явно указывает «Данные актуальны на февраль 2026» и перечисляет источники (arXiv:2504.08791, arXiv:2511.07425, Jeff Geerling, distributed-llama и др.).

## Чего нет

- **Лицензии** — ни LICENSE, ни указания условий использования контента (проверено: 404).
- **Публикации**: GitHub Pages не включён (svend4.github.io/in4 → 404), index.html нет — читать можно только через raw/клон или довериться README.
- **Интерактивности**: ноль `<script>` во всех файлах; «калькулятор» (часть 11) и «ROI-калькулятор» — статические таблицы, пользователь не может подставить свои цены/бюджет.
- **Гиперссылок на источники внутри страниц**: внешние `href` есть лишь в 3 файлах из 15; проверяемость утверждений (бенчмарки, цены) страдает.
- **Провенанса данных**: не помечено, какие бенчмарки измерены автором, а какие скомпилированы из чужих публикаций.
- **CI, тестов, линтеров** — для чисто документационного репозитория некритично, но даже проверки битых внутренних ссылок нет.
- **Общих ассетов**: CSS продублирован в каждом файле — правка стиля требует 15 правок.
- **Обновлений**: тема (цены на железо, новые модели) устаревает за месяцы, механизма актуализации нет.

## Плюсы

- Редкая по полноте русскоязычная база знаний по локальному LLM-инференсу на «народном» железе — целостная серия, а не разрозненные заметки.
- Высокая плотность фактуры: цены, микросекунды, tok/s, формулы — материал пригоден как практический справочник и основа для расчётных инструментов.
- Сквозная драматургия серии (части 0→11 с «переоценкой фаворитов» в части 7) — видно редакторскую работу, README как оглавление удобен.
- Самодостаточные HTML-файлы: работают офлайн, без сборки и зависимостей.
- Уникальный фокус на prima.cpp и его Vulkan-портировании — тема, слабо покрытая даже в англоязычном сегменте.

## Минусы

- Два дублирующих Vulkan-гайда (`prima-cpp-vulkan-porting-guide.html` и `prima-vulkan-port.html`, суммарно ~219 КБ) без пометки, какой актуальнее.
- Контент заморожен на 09.02.2026; апрельский коммит — лишь мердж старого PR. Для «ценового» справочника это быстрый путь к устареванию.
- Формат HTML-монолитов затрудняет переиспользование: данные заперты в вёрстке, нет ни Markdown-, ни JSON/CSV-версий таблиц.
- Достоверность чисел не перепроверяема из-за отсутствия ссылок на первоисточники в тексте (аудит не может подтвердить или опровергнуть конкретные бенчмарки — помечено как «не проверено»).
- Нет входной точки (index.html) и сквозной навигации — UX чтения зависит от README на GitHub.

## Качество кода и документации

Как «код» репозиторий оценивать почти не за что (HTML-вёрстка чистая, семантика простая: h2 с id-якорями, таблицы, блоки-заметки; в Vulkan-гайдах корректные `<pre>`-блоки). Как **документация** — качество высокое: структурированные разделы с оглавлениями внутри страниц, последовательная терминология (PRP, GGUF, RoCE, speculative decoding), формулы с пояснениями. Слабые места документации: отсутствие ссылок-источников в тексте, дублирование материала в двух Vulkan-гайдах, отсутствие версии/чейнджлога у страниц.

## Перепроверка заявлений (аудит-перепроверка)

Собственных самоаудитов/отчётов в репозитории нет. Проверены заявления README:
- Все 15 заявленных HTML-файлов существуют и содержательны — **подтверждено**.
- «Данные актуальны на февраль 2026» — согласуется с историей коммитов (весь контент от 09.02.2026) — **подтверждено**.
- Заявленные темы (RDMA, квантизация, Prometheus/Grafana, systemd, Ansible) реально раскрыты в соответствующих файлах (проверено по заголовкам разделов и выборочному чтению) — **подтверждено**.
- Ветка PR #2 называлась `claude/review-repository-…`, но содержала не отчёт-ревизию, а части 8–11 и новый README; сам PR провисел с 9 февраля до мерджа 18 апреля 2026.
- Точность конкретных цифр (цены, бенчмарки tok/s) по внешним источникам — **не проверено** (ссылки в тексте отсутствуют).

Ограничение покрытия: из ~14 900 строк HTML детально прочитаны README, структура и выборочные фрагменты 6–8 страниц; остальные проверены по заголовкам разделов и метрикам (размер, блоки кода, ссылки).

## Зрелость: 3/5

Обоснование: контент завершён, объёмен и качественно структурирован (это тянет на 4 для чистой документации), но проект не оформлен как продукт — нет лицензии, публикации (Pages), входной точки, ссылок на источники, механизма актуализации, а «калькулятор» не интерактивен; развитие остановлено через день после старта. Итог — крепкая «тройка»: ценная, но законсервированная и неопубликованная база знаний.
