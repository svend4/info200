# daten6 — система динамического каталога (проектная документация + HTML/CSS/JS-прототип)

## Обзор

**daten6** — репозиторий-проект «Система Динамического Каталога»: модульная веб-платформа для создания и управления иерархическими коллекциями контента с мозаичным (плиточным) интерфейсом. Фактическое содержимое — это **обширная проектная документация** (21 markdown-файл, суммарно порядка 25 000 строк) и **работающий кликабельный прототип** на чистом HTML/CSS/JavaScript без сборки и зависимостей. Серверного и «боевого» фронтенд-кода (Express, MongoDB, React из заявленного стека) в репозитории нет — проект остановился на фазе проектирования.

Внутри фактически три слоя контента:

1. **Базовая система каталога** — архитектура, техспецификация, схема БД (MongoDB), план реализации на 8–12 недель + рабочий прототип (`prototype/`).
2. **Версионированная система контента** — концепция многомерного версионирования (версии × уровни детализации × ревизии), система «якорей/плагинов» для подключения внешних источников (PHP/Python/Node.js), автоматические трансформации «контент → заголовок».
3. **Методология APPENDIX_3 v2.0** — самостоятельная универсальная методология компиляции документов из 5 частей (основы извлечения, версионирование, якоря, чанкование, практические кейсы), которая по смыслу выходит за рамки каталога и ссылается на другие репозитории профиля (например, кейс интеграции 21 496 строк юридического контента и «репозиторий data1»).

## Назначение и идея

Ключевая идея — **разделение статики и динамики**: один раз создаётся «скелет» (HTML-структура, стили, логика, API), а контент (элементы каталога, изображения, метаданные, теги) добавляется и обновляется отдельно, без изменения кода. Поверх этого:

- **Мозаичная компоновка** — каталог как «фотообои» из карточек с превью и счётчиками вложенных элементов;
- **Иерархия неограниченной глубины** с «голографическим принципом» (каждый уровень выглядит одинаково, содержит разный контент);
- **Целевые применения**: коллекции (марки, монеты, открытки), меню ресторанов, галереи, интернет-магазины, базы знаний;
- В версионированной ветви — энциклопедии, законодательство, архивы с полной историей изменений и автокомпиляцией контента из отзывов партнёров (приложения APPENDIX_1 и APPENDIX_2 описывают «свободную энциклопедию туризма» с двунаправленным потоком контента между партнёрскими страницами и каталогом).

## Как устроено (архитектура)

- **`prototype/`** — автономный прототип: `index.html` (статический скелет: шапка, поиск, breadcrumb, сетка, модальное окно), `styles.css` (632 строки, адаптивный grid), `data.js` (мок-данные: 8 корневых категорий, 31 элемент, цепочки «марки» и «меню» глубиной до 5–6 уровней), `app.js` (389 строк: состояние `AppState`, навигация с `history.pushState`, поиск по текущему уровню, модальные карточки). Запускается открытием файла или `python3 -m http.server`.
- **`docs/` (19 файлов)** — четыре «канонических» документа базовой системы (`ARCHITECTURE.md`, `TECHNICAL_SPECIFICATION.md` с REST-API и React-компонентами, `DATABASE_SCHEMA.md` с Mongoose-схемами и индексами, `IMPLEMENTATION_PLAN.md` на 6 этапов); документы версионированной системы (`VERSIONING_SYSTEM.md`, `PLUGIN_ANCHOR_SYSTEM.md`, `COMPARISON.md`, `DEMO_Hierarchical_Versioning.md`, `INTEGRATION_MAP_v1.0.0.md`); и крупный блок методологии (`APPENDIX_3_*` — 8 файлов, включая пять частей v2.0 по 1200–2700 строк, `CHUNKING_METHODOLOGY_v1_0.md`, приложения про партнёрскую обратную связь и энциклопедию).
- **`BRANCHES.md`** — описывает «две параллельные ветки» (`claude/dynamic-catalog-system-hweJv` и `claude/versioned-content-system-71e5`); на момент аудита эти ветки **уже не существуют** — они влиты в `main` через PR #1–#3 и удалены, так что весь контент лежит в одной ветке.

Заявленный (но не реализованный) стек: React/Vue + Zustand + TailwindCSS + Vite; Node.js 20 + Express/Fastify + MongoDB 7 + Redis; деплой Vercel/Railway, хранение S3/Cloudinary.
