# Характеристика и оценка meta2

## Что есть (проверено по файлам)

- **Работоспособная по построению система** из 6 этапов: предобработка → сегментация → описание краёв (Танграм + Фрактал) → матрица совместимости → сборка (8 алгоритмов) → верификация (21 валидатор). Код реальный и содержательный: `pipeline.py` (~1086 строк), `main.py` (1553 строки), `models.py` с продуманными dataclass-моделями, `synthesis.py` с ядром алгоритма.
- **Огромный тестовый корпус**: папка `tests/` превышает лимит отображения GitHub в 1000 файлов («93 entries omitted» → ~1093 файла). Выборочная проверка (`test_annealing.py`) показывает настоящие тесты с фикстурами, а не заглушки. Есть property-based тесты (Hypothesis), интеграционные, мутационное тестирование (коммит «85.2% mutation score, 622/730 killed»).
- **Полноценный CI** (`.github/workflows/ci.yml`): матрица Python 3.11/3.12, ruff, mypy (20+ модулей поимённо), отдельные джобы для property-тестов, интеграционных, бенчмарков и сборки пакета с `twine check`.
- **Инфраструктура**: multi-stage Dockerfile с непривилегированным пользователем, docker-compose с профилями api/cli/benchmark и healthcheck, Makefile, REST API (`tools/server.py`) с OpenAPI-спецификацией.
- **Инструменты для данных**: `tools/tear_generator.py` генерирует синтетические «рваные» фрагменты; `tools/mix_documents.py`, `evaluate.py`, `profile.py`, `benchmark.py`; пакет `benchmarks/` из 8 bench-модулей с папкой `results/`.
- **Обширная русскоязычная документация**: README (222 строки), теория с математикой (`PUZZLE_RECONSTRUCTION.md`, 868 строк), два роадмапа (817 + 1191 строка), план развития (844 строки), changelog, 4 статусных отчёта.

## Чего нет

- **Файла LICENSE** — проверено напрямую: `LICENSE` и `LICENSE.md` возвращают 404, хотя `pyproject.toml` и все статусные документы заявляют MIT. Формально код не имеет действующей лицензии.
- **Реальных данных**: в репозитории нет ни одного скана настоящего разорванного документа и нет результатов на публичных датасетах (например, DARPA Shredder Challenge). Вся валидация — на синтетике из `tear_generator.py`.
- **Публикации в PyPI** (не найдено упоминаний об опубликованном пакете) и релизов/тегов, оформленных на GitHub (тег `v1.0.0` упоминается в DEV_STATUS.md — существование на GitHub не проверено).
- **Актуального README**: цифры в README (42 384 теста, 305 модулей) отстают от последних самоотчётов (57 624 теста, ~320 модулей).
- **Подтверждения зелёного CI**: статус прогонов GitHub Actions в рамках аудита проверить не удалось — заявление «100% тестов проходят» помечается как «не проверено».
- **Скриншотов/демо**: нет ни одного изображения результата сборки, GIF или примера «до/после».
- **Сообщества**: 1 звезда, 0 форков, 0 issues.

## Плюсы

- Редкая для профиля глубина инженерии: реестровая архитектура, типизация (mypy), property-based и мутационное тестирование, CI из 6 джобов, Docker, REST API — всё в одном репозитории.
- Оригинальная и внятно документированная алгоритмическая идея (Танграм + фрактальная кромка → синтез подписи края) с математикой и ссылками на литературу.
- 8 взаимозаменяемых алгоритмов глобальной сборки с режимами `auto`/`all` и консенсусом — готовая площадка для исследований комбинаторной оптимизации.
- Документация-журнал позволяет полностью восстановить историю решений; changelog ведётся аккуратно.
- Самодостаточность: генератор синтетических данных избавляет от необходимости искать датасеты для старта.

## Минусы

- **Нулевая внешняя валидация**: ни реальных сканов, ни сравнения с академическими бенчмарками — практическая точность системы на настоящих документах неизвестна; статус «Production/Stable» этим не подкреплён.
- Отсутствие LICENSE-файла при заявленной MIT — юридическая дыра.
- Рассинхронизированные самоотчёты и устаревший README подрывают доверие к цифрам; 6 перекрывающихся статусных документов — избыточно.
- Гигантская доля `utils/` (130 модулей из 305) и парные `_extra`-тесты — почерк массовой AI-генерации; часть кода могла никогда не исполняться в реальных сценариях, несмотря на юнит-тесты.
- Разработка остановилась 28.02.2026 сразу после релиза; открытый PR не влит; вероятно, дефолтная ветка — рабочая `claude/*`, а не `master` (не проверено до конца).
- Метрики «42–57 тыс. тестов» во многом достигнуты микротестами и парametrized-размножением — количество не тождественно качеству покрытия сценариев.

## Качество кода и документации

По прочитанной выборке (~15 модулей) код высокого качества: docstrings на русском с примерами использования, аннотации типов, аккуратные dataclass-модели, осмысленные имена, graceful-fallback при отсутствии опциональных зависимостей (cv2, flask, pytesseract). Документация — сильнейшая сторона: от теории с псевдокодом до инструкции для следующей сессии. Слабое место документации — дублирование и рассинхронизация статусных файлов.

## Зрелость: 4/5

Обоснование: по инженерным артефактам (архитектура, тесты, CI, Docker, документация) проект тянет на 4–5 — это лучший код-репозиторий профиля. Балл снят за отсутствие валидации на реальных данных (главный риск: система может не работать на настоящих сканах), отсутствие LICENSE, неподтверждённый статус CI и рассинхронизацию заявленных метрик. До 5/5 не хватает именно доказательств практической работоспособности, а не кода.

*Ограничение покрытия*: репозиторий очень большой (305+ модулей, 1000+ тестов); аудит опирался на репрезентативную выборку из ~15 файлов кода, полные тексты 8 документов и листинги каталогов. Запуск тестов и проверка статусов GitHub Actions не выполнялись.
