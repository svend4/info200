## Варианты продолжения

**Сценарий А — «Исследовательский инструмент» (публикация).** Довести проект до научной статьи или препринта: идея синтеза танграм-геометрии и фрактальной кромки выглядит оригинальной, реализация с 8 алгоритмами сборки и консенсусом — готовый экспериментальный стенд. Нужны: валидация на реальных/публичных данных, сравнение с baseline-методами из литературы, аккуратный раздел о результатах. Это придало бы репозиторию внешнюю ценность и цитируемость, а профилю — флагманский проект.

**Сценарий Б — «Прикладной сервис для архивов/форензики».** Развернуть REST API как готовый сервис: веб-интерфейс загрузки сканов, очередь заданий, отчёты HTML (экспортёр уже есть). Целевая аудитория — архивы, музеи, генеалогические сообщества, у которых есть повреждённые документы. Минимальный путь: docker-compose уже поднимает API; добавить фронтенд, аутентификацию и лимиты. Практическая обратная связь от реальных документов одновременно закроет пробел валидации.

**Сценарий В — «Библиотека комбинаторной оптимизации + CV-дескрипторов».** Выделить из проекта два переиспользуемых пакета: (1) `assembly/` — унифицированный набор из 8 метаэвристик (SA, GA, ACO, MCTS, beam, exhaustive) с единым интерфейсом и реестром — применим к любым задачам упорядочивания; (2) `algorithms/fractal/` — фрактальные и CSS-дескрипторы кривых. Сам meta2 станет их первым потребителем. Это повысит переиспользуемость кода в других репозиториях профиля.

**Сценарий Г — «Заморозка с витриной».** Если продолжения не планируется: выполнить только быстрые улучшения (лицензия, README, релиз, демо-картинки), зафиксировать v1.0.0 как законченный портфолио-проект. Даже в замороженном виде это сильнейшая демонстрация инженерной культуры в профиле.

## Сочетания с другими репозиториями профиля

1. **meta2 + daten22 / data20 (офлайн-поиск на SQLite FTS4) = «Архивная станция: восстановление + поиск».** Конвейер meta2 уже заканчивается OCR-верификацией (Tesseract) — распознанный текст восстановленных документов автоматически индексируется в офлайн-поисковик на FTS4 из daten22/data20. Получается уникальный полностью офлайн-инструмент для архивов: скан обрывков → сборка листа → OCR → полнотекстовый поиск по восстановленному фонду. Ни один из компонентов по отдельности такого не даёт.

2. **meta2 + data7 (задача коммивояжера, оптимизация) = «Единая лаборатория метаэвристик».** Сборка фрагментов в meta2 — та же комбинаторная оптимизация, что и TSP в data7 (SA, генетика, муравьиная колония присутствуют в обоих доменах). Объединение даёт общую библиотеку метаэвристик с единым интерфейсом и два непохожих тестовых полигона (маршруты и пазлы): новые алгоритмы проверяются сразу на двух классах задач, а сравнение «какая эвристика где сильнее» — готовый исследовательский материал.

3. **meta2 + info40 (AI Agent Orchestration Platform) = «Агентная реконструкция документов».** Оркестратор агентов из info40 управляет конвейером meta2: агент-диспетчер выбирает метод сборки по числу фрагментов, параллельно запускает конкурирующие алгоритмы, агент-верификатор читает отчёт 21 валидатора и при низком консенсусе эскалирует спорные стыки человеку. Инновация — «human-in-the-loop форензика», где агенты автоматизируют рутину, а человек решает только неоднозначные случаи.

4. **meta2 + infom (ГрафРАГ) = «База знаний из восстановленных документов».** OCR-текст собранных документов поступает в GraphRAG-конвейер infom: строится граф сущностей и связей по восстановленному архиву, поверх — вопросно-ответный интерфейс. Уникальный результат: можно «разговаривать» с уничтоженным архивом — от коробки обрывков до семантического поиска и связей между документами.
