# Характеристика и оценка data40

Аудит-перепроверка проведена 02.07.2026: прочитаны README и все 3 сопроводительных документа, backend целиком (server.js, database.js, init-database.js, все 3 route-файла, README, package.json), а также index.html, script.js (частично — файл 1982 строки), auth.js, admin.js, api-client.js, sw.js, manifest.json, blog.js (выборочно); скачаны и посчитаны все ~80 файлов репозитория; проверены страницы коммитов. Покрытие кода чтением — репрезентативная выборка (~15 файлов из 46 JS прочитаны, остальные оценены по размеру и заголовкам), это ограничение честно указано.

## Что есть

- **Работоспособное статическое демо магазина** (запускается открытием `index.html`, серверу не требуется — «не проверено» в рантайме, но код самодостаточен): каталог ~30 букетов, корзина, промокоды, оформление и трекинг заказов, конструктор букетов, сертификаты, wishlist/сравнение, лояльность, рефералка, подписки, блог, live-чат (симуляция), админ-панель, A/B-тесты, «расширенная аналитика».
- **PWA-обвязка**: `manifest.json` (119 строк), `sw.js` с precache и offline-fallback, `offline.html`, `pwa.js`.
- **SEO-обвязка**: `sitemap.xml`, `robots.txt`, Schema.org в `index.html`, `seo.js`, OG-теги.
- **Автономный учебный бэкенд** (`backend/`): Express + SQLite, корректная параметризация SQL (везде `?`-плейсхолдеры), bcrypt для паролей, JWT, схема из 7 таблиц, сид-скрипт, `.env.example`, грамотный `.gitignore` (БД и .env не коммитятся — проверено: `flower_shop.db` в репо отсутствует, 404).
- **Необычно богатая документация**: README (400 строк), FEATURES_ANALYSIS.md — честная матрица ~175 функций с пометками «NOT IMPLEMENTED» там, где функции нет; BACKEND_MIGRATION.md — внятное пошаговое руководство; backend/README.md — полная документация API с curl-примерами; MOBILE_APP_SPEC.md — 673 строки спецификации.
- **История разработки прозрачна**: 52 коммита с осмысленными русскими сообщениями «этап N — что сделано», 12 merge-PR.

## Чего нет

- **Тестов — ни одного** (ни unit, ни e2e; ни jest/supertest для бэкенда, ни чего-либо для фронтенда). В README тестирование честно указано как «направление для вклада».
- **CI/CD** — нет `.github/workflows`, нет линтера, нет форматтера.
- **Лицензии** — файла LICENSE в корне нет; README говорит «создан в образовательных целях», backend/package.json заявляет MIT — противоречие не разрешено.
- **Интеграции фронтенда с бэкендом** — `api-client.js` написан, но не подключён ни к одной странице (проверено grep по `index.html`: 23 скрипта, api-client среди них нет). Магазин по-прежнему живёт на localStorage.
- **Изображений** — в репозитории ноль картинок; товары «иллюстрированы» emoji и CSS-градиентами. Иконки из manifest.json (`icon-*.png`) в репо отсутствуют — PWA-установка с такими путями «не проверено», вероятно сломана.
- **Реальных платежей, email-отправки, SMS** — всё симуляция (в FEATURES_ANALYSIS это помечено).
- **Деплоя** — нет GitHub Pages/hosting-конфига, демо нигде не опубликовано.
- **Мобильного приложения** — есть только спецификация и js-«мост»; кода React Native нет (спека это и не скрывает).
- **Авторизации на бэкенд-API** — маршруты POST/PUT/DELETE `/api/products`, PATCH статуса заказа и GET `/api/orders/admin/all` не проверяют ни JWT, ни роль (проверено чтением routes/products.js и routes/orders.js) — любой аноним может править каталог и читать все заказы.

## Плюсы

- Редкая для профиля полнота: это не «info»-заглушка, а целостное, большое, связное демо с реальной функциональной шириной (175+ функций).
- Дисциплинированная поэтапная разработка с самодокументированием; FEATURES_ANALYSIS честно различает уровни реализации и прямо помечает нереализованное.
- Бэкенд написан аккуратно: параметризованный SQL, bcrypt, JWT, promise-обёртки, сид, разделение маршрутов — хорошая учебная заготовка.
- Нет зависимостей и сборки — демо запускается «из коробки» в браузере.
- Секреты и БД корректно исключены из git.

## Минусы

- **Бэкенд не пристёгнут** — главная заявленная ценность второй версии («миграция на API») остановилась в шаге от результата.
- **Анти-паттерны безопасности** (частично осознанные): пароли открытым текстом в localStorage (`auth.js:42`), захардкоженные креды админки `admin/admin123` в клиентском `admin.js`, JWT-fallback-секрет в коде, отсутствие авторизации на мутирующих API-маршрутах.
- **Плоская структура из ~70 файлов в корне** и связь модулей через глобальные переменные — сопровождать тяжело.
- **Данные вшиты в код** (каталог, отзывы, блог) и фиктивны: выдуманные отзывы с датами и именами, «5000+ клиентов», телефоны и email несуществующего магазина — для портфолио стоит явно маркировать как вымысел.
- Ни тестов, ни CI, ни лицензии, ни живого деплоя; README устарел относительно собственного кода.
- Дублирование тематики внутри профиля: цветочные магазины также в daten2 («7 flowersshops»), meta4 («flower shop project»), интернет-магазины в daten23, info10 — канонический вариант не определён.

## Качество кода и документации

Код — чистый «ванильный» JS с подробными русскими комментариями, единообразным стилем и говорящими именами; уровень — добротный учебный/демо (генерация Claude за одну сессию, что видно по авторству коммитов). Архитектурных абстракций нет: модули не изолированы, состояние глобально, повторяются паттерны «прочитал localStorage → отрисовал innerHTML». Документация — сильная сторона (4 документа, ~2 200 строк), но два из четырёх документов рассинхронизированы с кодом. Backend-код качественнее фронтенда: там есть слои (server/database/routes), обработка ошибок и валидация входа, хотя авторизация недоделана.

## Зрелость: 3/5

Обоснование: это законченное в рамках своей задачи, крупное и хорошо документированное **демо** (что тянет выше 2), но до продукта далеко: нет ни одного теста, ни CI, ни лицензии, ни деплоя, бэкенд не интегрирован, безопасность демонстрационная, данные фиктивны, а разработка остановилась в один день 21.01.2026 (что не позволяет дать 4). Итог: развитый прототип / учебная витрина — 3/5.
