# info5 — концепция четырёхуровневой пирамиды автоматизации (чистая документация, без кода)

## Обзор

**info5** — это документационно-концептуальный репозиторий, описывающий «INFO5» — методологию и архитектуру четырёхуровневой пирамиды автоматизации рутинной офисной работы. Идея: между мощным ИИ (уровень 1) и тысячами SaaS-приложений (уровень 4) существует разрыв, который проект предлагает закрыть двумя промежуточными уровнями — специализированными «мини-агентами» (уровень 2) и «кластерами приложений» (уровень 3).

В репозитории **нет ни строчки исполняемого кода** — только Markdown-документация (~8,5 тыс. строк в 23 md-файлах): методология, архитектура, roadmap, FAQ, глоссарий, примеры кластеров и агентов, сценарии использования, а также полная инфраструктура open-source-проекта (CONTRIBUTING.md, шаблоны Issues/PR, двойная лицензия MIT + CC BY 4.0).

Весь репозиторий создан за **один день — 28 января 2026** (6 коммитов, 5 из них сгенерированы Claude через PR #1), после чего активность полностью прекратилась.

## Назначение и идея

Проблема, которую формулирует проект: пользователь сегодня вручную выбирает из ~5000+ SaaS-приложений, сам их настраивает и интегрирует, теряя 60–70% рабочего времени на рутину.

Предлагаемое решение — пирамида из четырёх уровней:

| Уровень | Содержание | Статус проработки (по README проекта) |
|---------|-----------|--------------------------------------|
| 1 (вершина) | Большие нейросети + агенты (GPT-4, Claude 3) | «Хорошо проработан» (уже существует на рынке) |
| 2 | 200–310 специализированных мини-агентов | Методология создана, реализации нет |
| 3 | 200–300 кластеров приложений (иерархия: 15–20 супер-категорий → 80–100 мета-категорий → кластеры) | Методология создана, полной таксономии нет |
| 4 (основание) | 5000+ приложений (Make.com, Zapier, Mailchimp и т.п.) | «Хорошо проработан» (уже существует) |

Пример работы: запрос «Настрой CRM для стартапа» → ИИ уровня 1 делегирует задачу мини-агенту «CRM Setup Expert» (ур. 2) → тот выбирает приложение из кластера «SMB CRM» (ур. 3) → и настраивает, например, HubSpot (ур. 4).

Ключевая ценность проекта в текущем виде — **проработанная понятийная рамка**: методологии кластеризации (на базе NAICS, BPMN, таксономий G2/Capterra) и проектирования мини-агентов (YAML-профили с зонами ответственности, знаниями приложений, use cases и метриками).

## Как устроено (архитектура)

Репозиторий организован как «книга»:

- `docs/architecture/` — общая архитектура (`overall-architecture.md`: паттерны Single Agent / Multi-Agent Sequential / Orchestrated, потоки данных, обратная связь, отказоустойчивость) и подробное описание четырёх уровней (`four-levels.md`);
- `docs/methodology/` — две центральные методологии: кластеризация приложений (уровень 3) и проектирование мини-агентов (уровень 2);
- `docs/research/existing-solutions.md` — обзор существующих кандидатов на роли уровней 2–3 (Zapier categories, BPMN, NAICS, RPA и др.);
- `levels/` — конкретные примеры: профили мини-агентов (MA-001 «Team Communication Expert» и др.) и кластеров (L3-001 «SMB Team Chat», 18 приложений с ценами);
- `examples/use-cases.md` — сквозные сценарии «до/после» (стартап с нуля: 90+ часов → 3 часа);
- `timeline/past-present-future.md` — историческая шкала 2010→2028+;
- `docs/ROADMAP.md` — план Phase 0 (Q1 2026) → Public Launch (Q1 2027) → Mature (2028+);
- справочники: `docs/FAQ.md`, `docs/GLOSSARY.md`, `docs/COMPARISON.md` (сравнение с Zapier, RPA, AutoGPT), `docs/QUICK_START.md`;
- `.github/` — 4 шаблона Issues + шаблон PR; `CONTRIBUTING.md`; `LICENSE` (MIT для будущего кода + CC BY 4.0 для документации).

Подробное дерево — в [structure.md](structure.md).

## Статус и активность

- **6 коммитов, все от 28.01.2026** (Initial commit от svend4 + 4 коммита от Claude + merge PR #1). С тех пор — **более 5 месяцев без единого коммита** (проверено 02.07.2026).
- Roadmap обещал на февраль 2026 «полную таксономию кластеров» и «прототипы 5 мини-агентов» — в репозитории ничего из этого не появилось.
- Issues: 0, Forks: 0, Stars: 1 — заявленное «open source сообщество» не сформировалось.
- Перепроверка заявлений README (аудит): «~35 000 строк документации» — **фактически ~8 540 строк** (завышение в ~4 раза); «5000+ приложений организовано в структуру» — фактически перечислено лишь несколько десятков приложений в примерах кластеров; «Лицензия: TBD» в README — при том, что файл LICENSE (MIT + CC BY 4.0) в репозитории есть.

**Итог: концепт-документ, сгенерированный за один день и заброшенный.** Как документ — целостный и хорошо структурированный; как проект — не начат.
