# Рекомендации по info5

## Быстрые улучшения

1. **Исправить README**: заменить «Лицензия: TBD» на реальную ссылку на LICENSE (MIT + CC BY 4.0); убрать или скорректировать «~35 000 строк документации» (реально ~8,5 тыс.).
2. **Пометить честный статус**: добавить в шапку README плашку «Concept / Phase 0 — документация, реализация не начата», сдвинуть или удалить устаревший roadmap (Q2 2026 «Pilot» уже нереален — на дворе июль 2026).
3. **Снять недоказуемые цифры** («ROI 20–50x», «60–80% экономии», «уровень знания Slack 98%») или явно пометить их как гипотезы/целевые ориентиры.
4. **Починить ссылки**: заменить абсолютные пути `/docs/...` на относительные (`docs/...`), чтобы навигация работала и вне веб-интерфейса GitHub; добавить CI-проверку ссылок (markdown-link-check) — это единственный осмысленный CI для md-репозитория.
5. **Убрать дублирование** корневого README и `docs/README.md` — оставить один источник истины по статусу и оглавлению.
6. **Свести самоаудит в один файл** STATUS.md с честными числами (файлы, строки, что сделано/не сделано) — репозиторий уже пострадал от завышенных самоотчётов.

## Серьёзные доработки

1. **Машиночитаемая таксономия — главный недостающий артефакт.** Перевести кластеры из прозы в данные: `clusters.yaml`/`clusters.json` (id, супер-категория, мета-категория, приложения, цены, интеграции). Даже 30–50 кластеров с 500 приложениями превратили бы концепт в переиспользуемый датасет — и это единственный путь подтвердить заявление «5000+ приложений организовано».
2. **Один работающий мини-агент вместо 200 описанных.** Реализовать MA-001 «Team Communication Expert» как реальный агент (например, Claude + tool use + профиль из `level-2-mini-agents.md`), который по запросу рекомендует и сравнивает приложения своего кластера. Один прототип докажет жизнеспособность всей пирамиды.
3. **Спецификация интерфейсов уровней.** Псевдоклассы `TaskDelegation`/`ClusterQuery` из `overall-architecture.md` довести до формальной схемы (JSON Schema / OpenAPI): как уровень 1 делегирует уровню 2, как уровень 2 запрашивает уровень 3.
4. **Сократить и сфокусировать документацию**: FAQ на 668 строк и roadmap до 2028 года для несуществующего продукта — балласт; ценность сосредоточена в двух методологиях и примерах, их и стоит развивать.
5. **Валидация идеи против рынка 2026 года**: со времени написания появились MCP-серверы, каталоги инструментов агентов и маршрутизация моделей — раздел `existing-solutions.md` нуждается в обновлении, иначе позиционирование устарело.

## Варианты продолжения

**Сценарий 1: «Таксономия как продукт» (данные, без агентов).**
Отказаться от амбиции построить всю пирамиду и сделать только уровень 3: открытый, машиночитаемый каталог SaaS-приложений, размеченный по кластерам методологии info5 (функция × отрасль × процесс × технология). Такой датасет полезен сам по себе (выбор инструментов, RAG-справочник для любых агентов) и может стать «строительным материалом» для чужих агентных систем. Трудоёмкость умеренная, результат проверяемый, идеально совместим с генеративной рабочей моделью автора.

**Сценарий 2: «Один вертикальный срез» (proof of concept).**
Выбрать один кластер (например, Team Chat или Email Marketing) и построить полный вертикальный срез пирамиды: каталог кластера → один мини-агент с реальным tool use → интеграция с Make.com/Zapier API на уровне 4 → демо «настрой команде чат» от запроса до результата. Это превращает красивую диаграмму в проверяемое утверждение и даёт материал для честного README «что реально работает».

**Сценарий 3: «Методология как публикация» (без реализации).**
Признать info5 текстовым произведением: довести две методологии до качества статьи/white paper, убрать маркетинговые цифры, добавить обзор состояния агентной экосистемы 2026 (MCP, реестры инструментов, orchestration-фреймворки) и опубликовать как аналитический материал. Минимум усилий, честный жанр, и репозиторий перестаёт претендовать на то, чем не является.

**Сценарий 4: «Слияние с родственными репо профиля» (консолидация).**
Не развивать info5 отдельно, а влить его содержимое как концептуальную главу в более живой агентный проект профиля (см. ниже) — info5 сильнее как теоретическая рамка, чем как самостоятельный проект.

## Сочетания с другими репозиториями профиля

1. **info5 + info40 (AI Agent Orchestration Platform, Production) = пирамида с реальным исполнением.** info5 даёт то, чего обычно нет у оркестраторов, — принцип организации «армии» агентов (кластеры ответственности, профили специализации, иерархия делегирования), а info40 даёт то, чего нет у info5, — работающую платформу. Результат: оркестратор, в котором агенты создаются не ситуативно, а по таксономии info5 (1 агент = 1–3 кластера), с маршрутизацией задач по уровням пирамиды. Это уникально: большинство оркестраторов не имеют системной модели покрытия предметных областей.

2. **info5 + info4 (база данных методов/скиллов ИИ) = каталог «скилл ↔ кластер приложений».** Скиллы из info4 разметить по кластерам уровня 3 из info5: для каждого кластера приложений — какие скиллы/методы агента его обслуживают, для каждого скилла — какие приложения он покрывает. Получается двусторонняя матрица «способности × инструменты», которой нет ни в одном публичном каталоге скиллов: она позволяет автоматически определять, какого мини-агента (набора скиллов) не хватает для покрытия кластера.

3. **info5 + daten4 (динамический планировщик) = планировщик, знающий, кому делегировать.** Паттерны декомпозиции задач из `overall-architecture.md` (Single Agent / Sequential / Orchestrated) сделать стратегиями планировщика daten4, а таксономию кластеров — его адресной книгой исполнителей. Инновация: планировщик, который не просто разбивает задачу на шаги, а сопоставляет каждый шаг конкретному кластеру приложений и профилю агента.

4. **info5 + infom (ГрафРАГ) = навигация по таксономии через граф знаний.** Иерархию «супер-категория → мета-категория → кластер → приложение» (плюс связи «интегрируется с», «альтернатива») загрузить как граф знаний в infom и отвечать на вопросы типа «чем заменить Mailchimp в связке с Shopify при бюджете $50» через graph-RAG. Уникальность: рекомендательная система по SaaS-инструментам, где объяснимость обеспечивается путём по графу, а не «мнением» LLM.
