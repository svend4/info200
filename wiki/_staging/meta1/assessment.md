# Характеристика и оценка meta1

## Происхождение (важно для аудита)

meta1 — **копия чужого open-source проекта с собственным масштабным расширением**. Файл `info` содержит единственную строку — ссылку на https://github.com/Asouei/continuum-runtime. Перепроверка подтвердила: upstream существует, опубликован в npm (`continuum-runtime`, автор Aleksandr Mikhailishin, MIT), и его `package.json` **байт-в-байт совпадает** с meta1 (имя, версия 3.0.0, описание). Однако upstream содержит 18 модулей ядра и 42 строки экспортов в `src/index.ts`, а meta1 — **117 модулей и 205 строк экспортов**: волны фич v3.1–v4.4 добавлены только здесь, коммитами `claude` от 26–27.02.2026, и в npm-пакет НЕ попали.

## Что есть

- **Полный работоспособный по виду конвейер** plan → execute → verify → heal: planner c Anthropic SDK, executor с DAG и таймаутами (676 строк), replayer со сравнением sha256 (384 строки), 4-уровневый repair-cascade (283 строки), lineage поколений плана.
- **13 JSON-схем** + генерация типов из них (`scripts/generate-types.js`, ajv-валидация в рантайме) — контрактная дисциплина.
- **~150 файлов тестов** (vitest): 145 в `tests/core/` (примерно по тесту на модуль), тесты песочниц и хранилища; LLM и Docker корректно мокируются (проверено на `tests/core/repair-cascade.test.ts`).
- **CLI на ~45 команд** (commander), из которых лишь `run` требует LLM — остальное локально и детерминировано.
- **Две песочницы**: LocalSandbox и DockerSandbox за общим интерфейсом.
- **Отличный двуязычный README** (EN + RU) с демо-видео, диаграммами, таблицами «когда использовать»; LICENSE (MIT); SCOPE.md с явными рамками MVP; `.claude/` SessionStart-хук для сессий Claude Code on the web.
- **Огромный слой enterprise-функций** (v3.1–v4.4): конфиги/профили, dry-run, preflight, doctor, шаблоны, миграции планов, вебхуки, плагины, middleware, event bus, очередь запусков, rate/resource limiter, чекпоинты, снапшоты, RBAC, аудит-лог, метрики, таймлайн, профайлер, экспорт/архив, DOT-графы.

## Чего нет

- **CI** — нет `.github/workflows`; 150 тест-файлов есть, но никто автоматически их не гоняет. **Проходят ли тесты — не проверено** (в рамках аудита прогнать сюиту без выкачивания всего репозитория невозможно).
- **Публикации расширенной версии** — npm-пакет `continuum-runtime` (v3.0.0) принадлежит upstream-автору; функции v3.1–v4.4 из meta1 нигде не опубликованы и в README не описаны.
- **Согласованных версий** — `package.json` 3.0.0 против `.version('4.4.0')` в CLI: `continuum --version` и версия пакета противоречат друг другу.
- **CHANGELOG, CONTRIBUTING, документации новых команд** — ~35 из ~45 CLI-команд не упомянуты в README; SCOPE.md (v2.1) объявляет «вне рамок» параллельное исполнение, которое уже реализовано (коммит «Add parallel DAG executor»).
- **Связи с upstream** — репозиторий не является GitHub-форком (нет метки fork), изменения не предлагались в первоисточник; двухмесячный разрыв между разработкой (февраль) и merge (апрель) без последующей активности.
- **Issues, веток с задачами, дорожной карты** после v4.4.

## Плюсы

1. Сильная, редкая по нынешним временам инженерная идея: детерминированное воспроизведение ИИ-кода с криптографической верификацией и «механической починкой прежде LLM».
2. Дисциплинированная архитектура: schema-first, строгий TS, ESM, паттерн «модуль+тест», версии фич задокументированы прямо в экспортах.
3. Масштаб покрытия тестами (145+ файлов) необычно высок для репозиториев профиля svend4.
4. Честная фиксация первоисточника (файл `info`) — это не скрытое присвоение, MIT-лицензия сохранена.
5. Расширение v3.1–v4.4 демонстрирует предельный кейс «Claude Code как фабрика фич»: 14 согласованных релизных волн за ~2 дня.

## Минусы

1. **Код обогнал документацию на 14 версий**: README/SCOPE описывают v3.0/v2.1, реальность — v4.4. Новичок не узнает о 80% возможностей.
2. **Версионный хаос**: 3.0.0 в package.json против 4.4.0 в CLI — прямое противоречие, попадёт в вывод `--version`.
3. **Ни один тест не подтверждён запуском** (нет CI, нет бейджей, нет артефактов прогонов) — при генерации сотни модулей за два дня риск «зелёных по виду, красных по факту» тестов высок.
4. **Неясен правовой/этический статус развития**: расширять чужой MIT-проект можно, но авторство в package.json осталось upstream-автора, а изменения ему не предложены.
5. **Риск фич-инфляции**: RBAC, очереди, вебхуки и плагины для локального CLI-инструмента без единого реального пользователя — классический признак генеративного оверинжиниринга.
6. Двухдневный спринт без последующего сопровождения — типичный для профиля паттерн «вспышка и заморозка».

## Качество кода и документации

Код (по прочитанной выборке: `replayer.ts`, `repair-cascade.ts`, `executor.ts`, `planner.ts`, `access-control.ts`, `local.ts`, `index.ts`, тесты) — аккуратный, типизированный, с JSDoc-комментариями, осмысленными интерфейсами и без явного мусора; уровень выше среднего для сгенерированного кода. Документация базового слоя (README EN/RU) — образцовая маркетингово-техническая, но **устаревшая относительно кодовой базы**; документация расширений отсутствует. Ограничение покрытия аудита: из ~340 файлов детально прочитано ~15 ключевых, остальное оценено по деревьям каталогов, экспортам и истории коммитов.

## Зрелость: 3/5

Обоснование: унаследованная база v3.0 — зрелый, опубликованный в npm продукт (что тянуло бы на 4/5), и объём тестов впечатляет. Но собственный вклад meta1 не верифицирован (нет CI, тесты не подтверждены), не опубликован, не задокументирован и внутренне противоречив по версиям; проект заморожен после разового спринта. Это добротный **эксперимент-полигон**, а не сопровождаемый продукт — твёрдая тройка.
