# daten14 — BIOS-I: концепт «операционной системы интеграции» для интернета

## Обзор

**daten14** — это чисто документационный репозиторий, содержащий развёрнутый проект-концепт под названием **BIOS-I** (Business Internet Operating System for Integration). Девиз проекта: **«Не изобретай — интегрируй»**. Описание репозитория на GitHub — «Программы интеграция решений» — точно передаёт суть: это проект о рационализации программного обеспечения через систематизацию, интеграцию и автоматизацию уже существующих решений вместо создания новых.

В репозитории нет ни строчки исполняемого кода — только манифест и восемь подробных разделов проектной документации на русском языке общим объёмом ~10 200 строк (~385 КБ markdown). Внутри документов при этом много «кода-как-спецификации»: YAML-схемы, TypeScript-интерфейсы, Python-псевдореализации, SQL и Cypher.

## Назначение и идея

Исходный тезис (изложен в `RATIONALIZATION_MANIFESTO.md`): цифровая экосистема страдает не от дефицита решений, а от их хаоса. 60 000+ плагинов WordPress, 400+ млн репозиториев GitHub, 3+ млн мобильных приложений, 1 500+ приложений Make.com — всё это не интегрировано, плохо документировано и не имеет проверенных комбинаций. «Рационализация» позиционируется как полноценная научная дисциплина, равная изобретательству.

BIOS-I предлагает метасистему из пяти ключевых компонентов:

1. **Универсальный каталог** — агрегация компонентов всех экосистем (WordPress, npm, PyPI, GitHub, Make.com, Docker Hub) в единый формат с объективными метриками качества.
2. **Граф совместимости** — связи «зависит / интегрируется / конфликтует» между компонентами.
3. **Кластеры** — проверенные комбинации компонентов для типовых задач (e-commerce-стек, DevOps-пайплайн, marketing automation).
4. **Макросы** — версионируемые, параметризуемые и композируемые сценарии автоматизации «одной кнопкой» (например, «Запуск интернет-магазина» разворачивает WordPress + WooCommerce + Stripe + доставку + аналитику).
5. **ИИ-система** — семантический поиск, рекомендации, AI-ассистент, предсказание совместимости.

## Как устроено (архитектура)

Документация описывает семислойную архитектуру (раздел `docs/03-architecture/`):

```
Presentation  → Web App, CLI (@bios-i/cli), API Gateway, IDE-плагины
Orchestration → Macro Engine, Workflow Engine, Deployment Engine
Intelligence  → AI Assistant, Semantic Search, Recommender System
Cluster       → Cluster Registry / Builder / Tester
Connector     → Integration Manager, Bridge Factory, Adapter Pool
Catalog       → Universal Catalog, Graph DB, Metrics Store
Data          → краулеры экосистем (WordPress, Make.com, GitHub, npm …)
```

Документация организована как «книга» из 8 пронумерованных разделов: теория рационализации → диагностика экосистем → архитектура → каталогизация → кластеры → макросы → ИИ-компоненты → дорожная карта (фазы 0–5, от MVP WordPress-краулера до маркетплейса и экосистемы партнёров). Всё это — проект/спецификация; реализация ни одной фазы не начата.
