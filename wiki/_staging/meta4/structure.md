# Структура meta4

Особенность репозитория: содержимое размазано по трём веткам, причём основная ветка практически пуста. Ниже — «объединённое» дерево с указанием, в какой ветке что лежит.

```text
meta4/
├── README.md                  # (main) 2 строки: «# meta4» / «info» — единственный файл main
│
│  ── ветка copilot/flower-shop-setup (draft PR #2, не слита) ──
├── main.py                    # CLI-солвер задачи «Магазин цветов»: stdin → stdout, ~45 строк
├── .gitignore                 # правила для Python-кэша: __pycache__/, *.pyc
│
│  ── ветка copilot/fix-typo-in-documentation (draft PR #1, не слита) ──
└── README.md                  # та же шапка, но тело «info» заменено на «Hallo»
```

## Ключевые файлы и модули

| Файл (ветка) | Что делает |
|---|---|
| `README.md` (main) | Заглушка: заголовок `# meta4` и слово `info`. Ни описания задачи, ни инструкций запуска. |
| `main.py` (copilot/flower-shop-setup) | Решение задачи оптимизации букета. Функция `solve()`: читает весь stdin одним блоком (`sys.stdin.buffer.read().split()`), парсит t тестов; в каждом — n (число цветов) и m (бюджет), затем n чисел лепестков. Считает частоты через `Counter`; для каждого значения лепестков x жадно берёт максимум цветов x в бюджет, затем цветы x+1, затем «апгрейдит» часть взятых x до x+1 (каждый апгрейд стоит 1 монету: `upgrades = min(take_current, next_count - take_next, m - spent)`). Так как цена цветка равна числу лепестков, ответ = потраченные деньги + апгрейды. Вывод — по строке на тест. Сложность O(n) на тест по времени и памяти. |
| `.gitignore` (copilot/flower-shop-setup) | Две строки: исключает `__pycache__/` и `*.pyc` (в одном из 4 коммитов PR Copilot вычищал случайно закоммиченный байткод). |
| `README.md` (copilot/fix-typo-in-documentation) | Однострочная правка `info` → `Hallo` — выполнение требования из issue (сам issue на момент аудита не виден: 0 открытых issues). |

## Особенности организации

- **Весь полезный код — вне main.** Пока PR #2 не слит, клонирование репозитория даёт только двухстрочный README. Это главный структурный факт meta4.
- **PR созданы агентом GitHub Copilot** (автор «Copilot AI», назначен svend4): ветки с характерными именами `copilot/...`, коммиты вида «Initial plan» → реализация → чистка. Репозиторий выглядит как полигон для процесса «issue → Copilot coding agent → draft PR».
- Пакетной структуры (модулей, `pyproject.toml`, `requirements.txt`) нет — `main.py` задуман как одиночный скрипт для проверяющей системы (стиль соревновательного программирования: быстрый ввод через `sys.stdin.buffer`, вывод одним `sys.stdout.write`).
- Условие задачи, примеры входных данных, тесты и ссылки на источник (похоже на формат задач Codeforces — не проверено) в репозитории отсутствуют.
