# daten30 — учебно-демонстрационный «динамический хаб» на микросервисах (Termux + Flutter)

## Обзор

**daten30** («Daten30 — Dynamic Hub Portal») — полноценный учебно-демонстрационный проект по микросервисной разработке, рассчитанный на запуск прямо на Android-телефоне через Termux. Репозиторий охватывает **три сценария развертывания** нарастающей сложности:

1. **Demo-App** — простое демо: 3–5 микросервисов + Flutter-приложение со статическим UI;
2. **Hub Portal** (рекомендованный) — «скелет + плагины»: Service Registry, Message Bus, 5 микросервисов-плагинов и Flutter-приложение, которое **генерирует UI динамически из JSON-схем**;
3. **Production** — описательный сценарий с PostgreSQL/Redis/RabbitMQ/Kubernetes (в основном документация + K8s/Helm манифесты в demo-app).

Проект почти полностью документирован по-русски: свыше десятка методологических документов в корне (DEVELOPER_GUIDE.md — 1768 строк, DYNAMIC_HUB_METHODOLOGY.md — 1556 строк и др.).

## Назначение и идея

Ключевая идея — **«одно приложение + бесконечное количество микросервисов = любая функциональность без обновления приложения»**. Flutter-приложение (`hub-portal/flutter-hub/lib/main.dart`, 731 строка) при запуске опрашивает Service Registry (`GET /api/services`), получает список активных сервисов вместе с их `ui_schema` (JSON-описание интерфейса: список, карточки, фильтры, поиск) и строит экраны на лету через `DynamicWidgetBuilder`. Микросервисы — независимые Flask-приложения, которые при старте **саморегистрируются** в реестре и общаются через Message Bus (pub/sub). Всё заточено под Termux: SQLite вместо тяжёлых СУБД, bash-скрипты `start-all.sh` / `stop-all.sh` / `health-check.sh`, данные в `~/termux-backend/`.

Вторая часть проекта — `demo-app/` — это отдельная «витрина идеального стека»: 5 polyglot-микросервисов (Flask+MongoDB, Flask+PostgreSQL, **Go/Gin+Cassandra+Kafka**, **Node/Fastify+Redis**), 4 минималистичных фронтенда (Alpine.js, Svelte, Preact, SolidJS), Flutter-мобильное приложение, docker-compose, Kubernetes-манифесты (15 yaml) и Helm-чарт.

## Как устроено (архитектура)

Сценарий Hub Portal (основной):

- **Service Registry** (порт 5000, `hub-portal/infrastructure/registry-service/registry_service.py`) — Flask + SQLite: регистрация/удаление сервисов, health-check, хранение UI-схем, история событий, статистика;
- **Message Bus** (порт 5999, `message_bus.py`) — pub/sub с персистентными подписками в SQLite и историей событий;
- **5 микросервисов-плагинов** (порты 5001–5005): товары (CRUD + seed-данные, SQLite), погода, крипто-котировки, новости, задачи (три последних — на mock-данных);
- **Flutter Hub App** — автообнаружение сервисов, динамическая генерация UI из JSON-схем, автообновление каждые 30 секунд (Timer.periodic).

CI/CD: 7 GitHub Actions workflow (сборка APK, smoke-тест бэкенда на Python 3.9–3.11, деплой, релизы) + README к ним. Подробности — в [structure.md](structure.md).
