Аудит-перепроверка выполнена 03.07.2026 по данным GitHub-страниц (WebFetch) и прямому чтению ~20 ключевых файлов через raw.githubusercontent.com. Клонирование недоступно, поэтому точный подсчёт файлов/строк по всему дереву не проводился; глубокие каталоги (android/, helm/, monitoring/, nginx/, frontend-preact/, frontend-solidjs/) проверены выборочно — ограничение покрытия учтено в выводах.

## Что есть (реально сделано и проверено)

- **Рабочий по коду Hub Portal**: Service Registry (`registry_service.py`, ~10,4 КБ) с SQLite, регистрацией, health-check, статистикой и историей событий; Message Bus (`message_bus.py`, ~11,5 КБ) с персистентными подписками; 5 микросервисов-плагинов (product/weather/crypto/news/task, порты 5001–5005) с саморегистрацией и UI-схемами. Код связный, эндпоинты согласованы между сервисами, скриптами и Flutter-клиентом.
- **Flutter-приложение с динамическим UI** (`flutter-hub/lib/main.dart`, 731 строка): ServiceDiscovery, DynamicWidgetBuilder, автообновление каждые 30 с — идея «UI из JSON-схемы» реализована, а не только описана.
- **Polyglot demo-app**: проверено наличие и содержимое Flask+MongoDB+Redis (user-service), Flask+PostgreSQL (order-service, ~10 КБ), Go/Gin+Cassandra+Kafka (main.go — настоящий Go-код с горутиной-консьюмером), Node/Fastify (notification-service: index.js, package.json), 4 фронтенда (Alpine.js index.html ~16 КБ, Svelte, Preact, SolidJS), docker-compose.yml, 15 Kubernetes-манифестов, Helm-чарт.
- **CI/CD**: 7 GitHub Actions workflow + README к ним (сборка APK universal+split с checksums и релизами по тегу, smoke-проверка бэкенда на Python 3.9/3.10/3.11, деплой, ночные сборки).
- **Обширная русскоязычная документация**: 12+ документов в корне; методология, сравнение стеков, шпаргалки, руководства Termux.
- **Активность**: ~98 коммитов за 6–9 января 2026, работа велась через PR (виден merge PR #25), автор коммитов в основном claude, мерджи — svend4.

## Чего нет

- **Тестов**: ни одного юнит/интеграционного теста; CI-workflow `test-backend.yml` устанавливает pytest, но выполняет лишь `py_compile` и curl-проверки («pytest not found, skipping tests» заложено в сам скрипт).
- **Лицензии**: LICENSE отсутствует — формально код нельзя легально переиспользовать.
- **requirements.txt / упаковки**: зависимостей нет ни в корне, ни в сервисах hub-portal (устанавливаются «pip install flask flask-cors requests» из README); нет pyproject, нет версионирования зависимостей.
- **Реальных данных/интеграций**: weather, crypto, news — mock-данные с random; заявка «в production можно использовать OpenWeatherMap» не реализована.
- **Безопасности**: нет аутентификации, `app.run(host='0.0.0.0')` у всех сервисов, регистрация в Registry без какой-либо проверки — любой процесс может зарегистрировать «сервис».
- **Конфигурируемости hub-portal**: пути БД (`~/termux-backend/...`) и адреса (`127.0.0.1:5000`) захардкожены, в т.ч. в Flutter-клиенте.
- **CHANGELOG, CONTRIBUTING, CLAUDE.md**: отсутствуют; issues/PR-активность нулевая после января.
- **Скриншотов/демо**: нет ни одного изображения работающего приложения; собранный APK в релизах не проверялся (не проверено).

## Плюсы

- Идея «динамический хаб: скелет + плагины» доведена до связной работающей вертикали: реестр → шина → плагины → динамический Flutter-UI.
- Отличная, местами образцовая русскоязычная документация с проверяемо точными метриками (числа строк совпали).
- Реальный polyglot-опыт: Python, Go, Node.js, Dart, Svelte/Preact/SolidJS, K8s, Helm — редкая широта для учебного репозитория.
- Ориентация на Termux/Android — нестандартная и практичная ниша («сервер в кармане»), с продуманными скриптами запуска и health-check.
- Настоящий CI: автосборка APK с split-архитектурами, checksums и релизами — выше среднего для проектов профиля.
- Честная документация неудач: 7 «FIX»-файлов по проблемам сборки Flutter — полезная troubleshooting-база.

## Минусы

- Документация местами описывает несуществующую структуру (backend-flask, ARCHITECTURE.md, requirements.txt) — README писался «на вырост» и не синхронизирован с кодом.
- Нулевое тестовое покрытие при живом CI — конвейер создаёт видимость тестирования.
- Дублирование: три независимых product-service (hub-portal, demo-app, termux), три Flutter-приложения — без общего кода.
- Mock-данные в 3 из 5 плагинов снижают демонстрационную ценность хаба.
- Безопасность и конфигурация на нуле (hardcoded пути/порты, открытые 0.0.0.0, регистрация без auth).
- Проект заброшен после 4-дневного спринта: полгода без коммитов, ни issues, ни развития roadmap v1.1+.

## Качество кода и документации

Код — чистый учебный Flask/Dart: понятные docstring-шапки на русском, логичная структура эндпоинтов, но с типичными упрощениями (голые `except:`, отсутствие валидации схем, прямые f-строки в SQL отсутствуют — используются параметризованные запросы, что плюс). Flutter-код в одном файле, но структурирован по классам. Документация — сильнейшая сторона (объём, структура, точность цифр), однако её достоверность подпорчена ссылками на несуществующие файлы. Соотношение «описано/реализовано» примерно 1.5:1 в пользу описанного.

## Зрелость: 3/5

Обоснование: полная вертикаль работает «по коду» (не проверено запуском — не проверено), есть CI, обширная документация и продуманная архитектура (+); нет тестов, лицензии, управления зависимостями, реальных данных, безопасности, и проект не сопровождается полгода (−). Это качественно выполненный **учебно-демонстрационный** проект уровня «завершённый прототип», но не продукт: до 4/5 не хватает тестов, синхронизации доков с кодом и хотя бы одного подтверждённого развертывания (скриншот/релиз APK).
