# Характеристика и оценка info10

Аудит-перепроверка от 02.07.2026. Репозиторий маленький, прочитаны **все** файлы (покрытие 100%).

## Что есть

- **Три работающих по структуре FastAPI-приложения** (`web_mcp_gateway.py`, `web_mcp_gateway_medium.py`, `lorenzo_pro_gateway.py`) — синтаксически корректный, читаемый код с ясным замыслом: RAG-поиск по корпусу lorenzo, скачивание файлов, запись в GitHub, очистка голосового ввода.
- **Инфраструктура деплоя**: Dockerfile (python:3.12-slim + git), docker-compose.yml (gateway + Redis), `.env.example`, инструкции для Render.com.
- **Хорошая по объёму документация**: `daf-gateway/README.md`, `daf-gateway/docs/DAF_FULL_DOCUMENTATION.md` (концепция, этапы, системный промпт, деплой), `SESSION_SUMMARY.md`.
- **Осмысленная связка с экосистемой профиля**: шлюз построен вокруг `docstoolkit.rag.ask` — RAG-пакета из репозитория lorenzo (docs-toolkit); идея «репозиторий как набор живых инструментов» перекликается с nautilus и info40.

## Чего нет

- **Ключевой зависимости**: `docstoolkit` нет ни в repo, ни в `requirements.txt`, ни в Dockerfile — **ни один из трёх шлюзов не запустится** (`ModuleNotFoundError: docstoolkit`). Нет и самого корпуса (1719+ MD-файлов лежат в lorenzo).
- **Тестов** — вообще (папка `test/` содержит hello-текстовики, а не тесты).
- **CI/CD** — нет GitHub Actions и любых пайплайнов.
- **Лицензии** — файла LICENSE нет.
- **Аутентификации**: `LORENZO_API_KEY` объявлен в `.env.example`, но в коде нигде не проверяется; `Depends, Header` импортированы и не используются — авторизация была задумана и не реализована/удалена.
- **Безопасности**: `/api/download` и `/api/git/write` берут `req.path` без валидации — `Path("/app") / req.path` допускает выход за пределы каталога (`../…` и абсолютные пути), т.е. path traversal + запись произвольных файлов + push в репозиторий от имени токена; CORS `allow_origins=["*"]`; токен подставляется в URL для `git push` (риск утечки в логи).
- **Упаковки**: нет pyproject/setup, версий зависимостей (requirements без пиновки).
- **Корневого README**: 2 строки, не отражает содержимое; описание репо «info, shop» — про «shop» в репозитории нет ничего.

## Плюсы

- Ясная и интересная концепция: единый HTTP-шлюз «поиск + скачивание + запись + голос» для любых нейросетей над корпусом знаний.
- Компактный, читаемый код; логичная эволюция «лёгкий → средний → pro» задокументирована.
- Есть Docker/compose и инструкции деплоя — редкость для репозиториев профиля такого размера.
- Подробная русскоязычная документация с системным промптом для агента.

## Минусы

- Код неработоспособен из коробки (отсутствует главная зависимость), т.е. проект не проходит собственный «Quick Start».
- Заявления документации существенно опережают код (MCP-активация, rate limiting, tool calling, «production-ready»).
- Серьёзные дыры безопасности: отсутствие аутентификации при наличии эндпоинта записи в GitHub, path traversal, открытый CORS.
- Мусор в репозитории: дубликат файла с пробелом в имени, тестовые hello-файлы, README-заглушка в корне.
- `clean_voice_query` после подстановок делает `.lower()`, что стирает только что подставленные «Lorenzo/Nautilus/Svyazi» — логическая ошибка.
- Redis в docker-compose объявлен, но кодом не используется.

## Качество кода и документации

Код: 3/5 за читаемость на этом объёме, но 1/5 за инженерию — нет валидации входа (`request["messages"][-1]["content"]` упадёт KeyError на любом нестандартном запросе), нет обработки ошибок subprocess, нет тестов, неиспользуемые импорты, дубликат файла. Документация: подробная и структурированная (2/5 → 4/5 по полноте), но **недостоверная** в части статуса и функций — для аудита это ключевой минус.

## Зрелость: 1/5

Обоснование: одна чат-сессия, выгруженная в репозиторий 11.05.2026 и с тех пор не тронутая; ~190 строк Python; ни один сервис не запустится без ручной доустановки внешнего пакета; нет тестов, CI, лицензии, аутентификации; самозаявленный статус «полностью готово» опровергнут перепроверкой. Балл выше 1 не дают именно неработоспособность и расхождение документации с кодом; наличие Docker и подробных доков — единственное, что отличает от чистой заглушки.
