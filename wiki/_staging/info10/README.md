# info10 — DAF-шлюз (Dynamic Activation Fabric) к корпусу Lorenzo, выгруженный из чат-сессии

## Обзор

`info10` — маленький репозиторий (описание на GitHub: «info, shop»), который фактически содержит один подпроект: **daf-gateway** — «Dynamic Activation Fabric», FastAPI-шлюз, задуманный как «живой» веб-доступ любой нейросети (Grok, Claude, GPT и др.) к корпусу знаний из репозитория **lorenzo** (заявлено 1719+ MD-документов, 1,68 млн слов). Помимо подпроекта в репозитории есть только двухстрочный README, файл `SESSION_SUMMARY.md` (протокол чат-сессии с Grok от 11 мая 2026) и тестовая папка `test/` с тремя hello-файлами, созданными при проверке GitHub API.

Весь код — результат одной сессии: три варианта шлюза («лёгкий», «средний», «тяжёлый/pro»), Dockerfile, docker-compose с Redis, пример `.env` и подробная русскоязычная документация `DAF_FULL_DOCUMENTATION.md`.

Важный вывод аудита: **в текущем виде код неработоспособен** — все три шлюза импортируют `docstoolkit.rag` (пакет из репозитория lorenzo), которого нет ни в этом репозитории, ни в `requirements.txt`; контейнер, собранный по Dockerfile, упадёт с `ModuleNotFoundError` при старте. Подробности — в [assessment.md](assessment.md).

## Назначение и идея

Идея DAF: репозиторий знаний — не «хранилище файлов», а набор живых инструментов, которые нейросеть активирует по HTTP:

- **Поиск** по MD-корпусу lorenzo через RAG (`docstoolkit.rag.ask`) — эндпоинты `/api/ask` и OpenAI-совместимый `/v1/chat/completions`;
- **Скачивание файлов «в песочницу» модели** — `/api/download`;
- **Запись обратно в GitHub** — `/api/git/write` (git add/commit/push с токеном в репозиторий svend4/info10);
- **Очистка голосового ввода** — функция `clean_voice_query` заменяет русские надиктованные слова («лоренцо», «наутилус», «связь») на канонические имена (Lorenzo, Nautilus, Svyazi);
- заявлена (но не реализована) «автоматическая активация 13 MCP-серверов».

Таким образом info10 — это инфраструктурный «спутник» монорепозитория lorenzo: попытка превратить его корпус в онлайн-API для внешних моделей. К слову «shop» из описания репозитория содержимое отношения не имеет.

## Как устроено (архитектура)

Три варианта одного шлюза, по нарастанию сложности (все на FastAPI + uvicorn):

1. `web_mcp_gateway.py` (16 строк) — один эндпоинт `POST /api/ask`, порт 8081;
2. `web_mcp_gateway_medium.py` (23 строки) — `POST /v1/chat/completions` с ответом в формате OpenAI chat.completion, порт 8082;
3. `lorenzo_pro_gateway.py` (75 строк, «главный», DAF v3.1) — порт 8083: chat-эндпоинт с очисткой голосового ввода, `/api/git/write` (subprocess: git add/commit/push с `GITHUB_TOKEN`), `/api/download` (FileResponse), `/api/health`; логирование через structlog, CORS открыт для всех.

Деплой: `docker compose up --build` (сервисы gateway + redis; Redis в коде не используется) либо Render.com с Root Directory = `daf-gateway`. Файл `l orenzo_pro_gateway.py` (с пробелом в имени) — случайный дубликат главного файла, отличающийся одной строкой докстринга.

## Статус и активность

- Всего **14 коммитов**: initial commit 28.01.2026, тестовая папка 10.05.2026, затем 11 коммитов 11.05.2026 — выгрузка всех файлов DAF-сессии. С 11 мая 2026 активности нет (проверено 02.07.2026).
- 0 звёзд, 0 форков, релизов нет.
- В репозитории есть самоотчёты (`SESSION_SUMMARY.md`, `docs/DAF_FULL_DOCUMENTATION.md`) со статусом «Полностью готово к использованию» — аудит-перепроверка показала, что это **не соответствует действительности** (отсутствует ключевая зависимость, часть заявленных функций не реализована; см. [assessment.md](assessment.md)).
