# Рекомендации по info

## Быстрые улучшения

1. **Добавить LICENSE** (для текстов логично CC BY-SA 4.0 или CC0) — сейчас переиспользование формально запрещено, что противоречит образовательной цели.
2. **Закрыть или пометить ссылки-заглушки** `[...](#) *(будущий документ)*` в `10-технологии-и-компьютеры/02-языки-программирования.md` и др. — либо создать документы, либо вынести в раздел «Планы» README.
3. **Добавить дисклеймер об ИИ-происхождении контента** и о том, что факты не верифицированы, — особенно критично для категории `09-медицина-и-здоровье` (дозировки, «когда к врачу»).
4. **Настроить простейший CI**: markdownlint + проверка битых относительных ссылок (например, `lychee` или `markdown-link-check`) — 5 минут работы, защищает индекс от рассинхронизации.
5. **Вынести changelog из README** в отдельный `CHANGELOG.md` — сейчас история версий занимает больше половины README и заслоняет содержание.
6. **Продублировать имена папок латиницей или добавить таблицу соответствий** — кириллические пути ломают часть инструментов и требуют percent-кодирования в URL.

## Серьёзные доработки

1. **Извлечь машиночитаемый слой соответствий.** Главная ценность репозитория — «параллели» (7 = радуга = дни недели = ноты = чудеса света). Сейчас они закопаны в прозу. Стоит построить `correspondences.yaml`/`JSON`: сущность → число → система → культура. Это превратит текстовый корпус в базу знаний, пригодную для графов, поиска и того самого «псевдо ИИ» из описания.
2. **Фактчекинг с источниками.** Пройти документы (начиная с медицины) и проставить ссылки на источники (ВОЗ, энциклопедии); утверждения без источника помечать. Можно автоматизировать роем ИИ-агентов с обязательной ссылкой на первоисточник.
3. **Реализовать заявленный «псевдо ИИ»**: правило-ориентированный отвечатель «что соответствует X?» (например, CLI/веб-инструмент: ввод «7» → все системы из семи элементов; ввод «вторник» → Марс, железо, красный). База уже есть — нужен слой запросов.
4. **Единый фронтматтер** (YAML: категория, теги, связанные числа, статус проверки) в каждом документе — включит корпус в любые пайплайны (RAG, статические сайты, графы знаний).

## Варианты продолжения

**Сценарий А — «Энциклопедия соответствий» (граф знаний).** Довести идею «параллелей» до конца: извлечь из 39 документов все соответствия в типизированный граф (узлы: числа, цвета, планеты, дни, ноты, божества; рёбра: «соответствует в традиции X»). Опубликовать как интерактивный граф (D3/vis.js) со страницей на каждое число/систему. Это уникальный продукт: аналогов структурированной русскоязычной базы культурных соответствий практически нет. Репозиторий из «текста про параллели» становится «базой параллелей».

**Сценарий Б — офлайн-справочник/приложение.** Корпус самодостаточен и компактен (~758 КБ) — идеален для офлайн-приложения с полнотекстовым поиском: SQLite FTS + простая оболочка (у автора уже есть весь стек в daten22/data20). Целевая аудитория — учащиеся без стабильного интернета. Минимальный путь: mkdocs/Zola-сайт + PWA с кешированием.

**Сценарий В — RAG-корпус для русскоязычного ассистента.** Использовать документы как эталонный тестовый корпус для экспериментов с RAG/GraphRAG: однородный, тематически размеченный, с естественными перекрёстными связями. На нём удобно сравнивать чанкинг, эмбеддинги и графовые стратегии; попутно ассистент «спроси энциклопедию» станет реализацией «псевдо ИИ».

**Сценарий Г — заморозка с оформлением.** Если развития не планируется: добавить LICENSE, дисклеймер, тег `v2.2`, статус «завершено» в README — и репозиторий останется приличным законченным артефактом, на который можно ссылаться из хаба info200.

## Сочетания с другими репозиториями профиля

1. **info + infom (ГрафРАГ) = граф знаний соответствий с вопросно-ответным слоем.** infom занимается GraphRAG; info даёт готовый корпус с естественной графовой структурой (числовые параллели — это готовые рёбра). Результат: русскоязычный GraphRAG-демонстратор, где запрос «что связывает 7 нот и 7 планет?» отвечается путём по графу с цитатами из документов — реализация «псевдо ИИ» из описания и одновременно живой бенчмарк для infom. Инновация: тестовый GraphRAG-корпус, где «правильные» связи известны заранее — можно измерять точность извлечения графа.

2. **info + in4n (динамический информационный граф) = интерактивный атлас параллелей.** in4n строит динамические графы информации; наполнить его извлечёнными из info соответствиями и получить навигацию «кликнул на число 4 → развернулись стихии, времена года, стороны света, Евангелия». Уникальность: визуальная энциклопедия, где навигация идёт не по рубрикам, а по структурным изоморфизмам между культурами.

3. **info + daten22/data20 (офлайн-поиск на SQLite FTS) = офлайн-энциклопедия.** Готовый корпус + готовый офлайн-движок полнотекстового поиска = автономное образовательное приложение на русском (~1 МБ), работающее без интернета. Инновация в нише: офлайн-первый справочник символики и систем — сочетание, которого нет ни в одном из двух репозиториев поодиночке.

4. **info + lorenzo (docs-toolkit) = конвейер качества корпуса.** Python-пакет docs-toolkit из lorenzo (заточенный под тысячи md-файлов) применить к info: валидация ссылок, генерация индекса вместо ручного ИНДЕКС.md, фронтматтер. info становится эталонным «маленьким» полигоном для инструментов lorenzo перед прогонами на корпусе в ~2815 файлов.

5. **info + info3 (гуманитарные формулы) = формализация соответствий.** info3 ищет «формулы» для гуманитарных знаний; таблицы соответствий из info — идеальное сырьё для записи вида `7(радуга) ≅ 7(ноты) ≅ 7(дни)`. Получается единый формальный язык описания культурных изоморфизмов, у которого сразу есть заполненная база примеров.
