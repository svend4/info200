# Вопросы к info

## 1. Что означает «псевдо ии» в описании репозитория — планировался ли программный слой поверх корпуса?

Описание обещает «параллели, соответствие предметов и явлений, псевдо ии», но в репозитории нет ни строчки кода.

**Варианты ответов:**
- А. Да, планировался правило-ориентированный движок соответствий («спроси, что связано с числом 7»), руки не дошли.
- Б. «Псевдо ИИ» — это сам корпус: структурированное знание, имитирующее «умную» систему без кода.
- В. Идея размытая, описание писалось на вырост.

**Варианты дальнейших действий:**
- При А: начать с машиночитаемого слоя (`correspondences.yaml`) и простого CLI-запросчика; затем связать с infom (GraphRAG) — см. recommendations.md.
- При Б: переформулировать описание репозитория честнее («база знаний о системах и соответствиях») и вложиться в навигацию/индексы.
- При В: зафиксировать в README раздел «Замысел», выбрать один из сценариев А–В из рекомендаций и вести к нему.

## 2. Проверялись ли факты в документах, и как относиться к медицинскому разделу?

14 из 16 коммитов — авторство claude; источников нет ни в одном документе, при этом `09-медицина-и-здоровье` содержит дозировки, нормы и советы «когда вызывать скорую».

**Варианты ответов:**
- А. Не проверялись — корпус принят «как сгенерировано».
- Б. Выборочно вычитаны, но без фиксации источников.
- В. Точность не важна: корпус — сырьё для экспериментов, а не справочник.

**Варианты дальнейших действий:**
- При А: добавить дисклеймер в README и шапку каждого медицинского документа немедленно; затем поэтапный фактчекинг с источниками (приоритет: медицина).
- При Б: зафиксировать статус проверки в фронтматтере каждого файла (`verified: partial/none`), чтобы прогресс был видим.
- При В: явно пометить репозиторий как «синтетический корпус для NLP-экспериментов» — это снимает ответственность и даже повышает его ценность как датасета.

## 4. Почему имена папок и файлов кириллические, и не мешает ли это?

Кириллические пути требуют percent-кодирования в URL и ломают часть инструментов (некоторые CI, старые файловые системы, генераторы сайтов).

**Варианты ответов:**
- А. Осознанный выбор: корпус русскоязычный, читаемость важнее совместимости.
- Б. Так получилось, готов мигрировать на латиницу/транслит.
- В. Нужен компромисс: кириллица в заголовках, латиница в путях.

**Варианты дальнейших действий:**
- При А: оставить, но добавить в README таблицу «папка → URL-encoded путь» и проверить, что все инструменты в планируемых сценариях (mkdocs и т.п.) переваривают кириллицу.
- При Б: один коммит-переименование (например, `01-chislovye-sistemy` или `01-number-systems`) + правка всех относительных ссылок скриптом.
- При В: миграция путей на транслит с сохранением русских H1-заголовков — лучший вариант перед постройкой сайта/приложения.
