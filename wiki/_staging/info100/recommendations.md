## Серьёзные доработки

- **Реализовать стадию Distill**: сейчас методология написана вручную, и конвейер бесконечно синтезирует один скилл из одного `parallel-bidirectional.yaml`. Нужен модуль, извлекающий новые методологии из `knowledge/raw/` (хотя бы по структурным паттернам, а лучше через LLM-вызов), иначе «эволюции» нет по определению.
- **Универсальный сборщик вместо пары захардкоженных**: `agents/core/base-collector.yaml` уже описывает параметризуемого агента — реализовать один `collector.py --repo svend4/<name>`, а список целей вынести в конфиг. Это откроет все 61 репозиториев профиля как источники.
- **Настоящая генетика**: скрещивание двух методологий в один скилл, мутации параметров, инкремент generation, отбор по fitness на реальных задачах из `benchmarks/tasks/standard-tasks.yaml` (сейчас они не исполняются, а `run.py` — заглушка).
- **Тесты пайплайнов и CI-проверка**: pytest для collector/synthesizer/tester (с моками GitHub API), запуск в отдельном workflow на PR.
- **Осмысленный fitness**: текущий 1.0 означает «код компилируется» — добавить метрики полезности (решение задач бенчмарка, время, размер, покрытие интерфейса).

## Варианты продолжения

### Вариант 1. Реанимация как «фабрика скиллов» для Claude Code

Самый прагматичный путь: перенацелить синтез с шаблонных Python-классов на реальные артефакты — скиллы/плагины Claude Code (SKILL.md + скрипты). Источники знаний уже собираются из репозиториев профиля; вместо генерации класса-заглушки конвейер генерирует черновик скилла, валидатор проверяет его структуру и прогоняет на тестовой задаче, отчёт уходит в Issue. Тогда fitness становится осмысленным («скилл решил задачу N»), а лаборатория начинает производить то, что реально используется в других проектах владельца (info20, info30 прямо посвящены расширению Claude Code).

### Вариант 2. Мета-индексатор профиля svend4

Развить ingest-часть и отказаться от «эволюции»: один универсальный сборщик обходит все 61 репозиториев, строит единый граф `concepts.json` (проекты, методологии, взаимные ссылки) и публикует сводный отчёт. Это превращает info100 в автоматический «инвентаризатор» профиля — фактически движок для того самого хаба-вики, которым должен стать info200. Ежедневный cron здесь наконец обретает смысл: граф и отчёты обновляются по мере коммитов в других репо.

### Вариант 3. Честная исследовательская песочница эволюционных агентов

Если интересна именно эволюция: сузить масштаб до одной чётко измеримой задачи (например, агенты, решающие задачи из `benchmarks/tasks/`), реализовать популяцию, мутации параметров промптов/конфигов, турнирный отбор по фактическому success_rate и вести журнал поколений в `meta/evolution-log/`. Малый, но настоящий эволюционный цикл ценнее нынешнего широкого, но декоративного. Результаты (какие мутации повышают fitness) станут содержательным материалом для статей/заметок в info-репозиториях.

### Вариант 4 (минимальный). Архивирование с честным статусом

Если возвращаться к теме не планируется: зафиксировать в README статус «эксперимент завершён, Variant C пройден 17.04.2026», отключить cron, оставить репозиторий как задокументированный кейс «автономного цикла на GitHub Actions» — он и в таком виде полезен как референс для других репо профиля.

## Сочетания с другими репозиториями профиля

1. **info100 + info40 (AI Agent Orchestration Platform, Production)** = производственный конвейер эволюции агентов: info40 даёт оркестрацию и «производственный» рантайм, info100 — петлю отбора (fitness, tested/retired). Уникальность: оркестратор, который не просто запускает агентов, а автоматически заменяет слабых на «потомков» с лучшим fitness — самооптимизирующаяся платформа, ни один из репо поодиночке этого не умеет.
2. **info100 + infom (ГрафРАГ) + in4n (динамический информационный граф)** = живой граф знаний профиля: сборщики info100 наполняют граф (сейчас — 5 узлов в plain-JSON), infom добавляет RAG-поиск по нему, in4n — динамическую визуализацию/обновление. Получается самообновляющаяся GraphRAG-база по всем 61 репозиториям — инфраструктура, которой нет ни в одном репо профиля.
3. **info100 + info4 (база данных ИИ-скиллов и методов)** = замкнутый цикл «каталог → генерация → тест → каталог»: info4 хранит методы/скиллы как знания, info100 превращает их в исполняемые артефакты и возвращает результаты тестирования (fitness) обратно в каталог. Инновация: каталог скиллов с эмпирической оценкой работоспособности каждого метода, а не просто описаниями.
4. **info100 + info200 (хаб вики)** = автоматический аудитор: конвейер info100 (ingest → report) перенацеливается на генерацию и еженедельное обновление вики-страниц по каждому репозиторию профиля в info200 — то, что сейчас делает рой агентов вручную, становится cron-задачей.
