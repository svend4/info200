## Серьёзные доработки

- **Восстановить все 7 уровней в одном дереве**: извлечь из истории коммитов (24–25.12.2025) уровни 1–7 и разложить по папкам `level1-php/ … level7-microservices/` с общим корневым README-«лестницей». Это возвращает проекту его главную идею, сейчас разрушенную «flatten»-реорганизацией.
- **Тесты и CI**: pytest для двух эндпоинтов (products, orders + негативные случаи), smoke-тест сборки фронтенда; GitHub Actions, прогоняющий каждый уровень в матрице — сам CI станет частью «учебной лестницы».
- **Персистентность данных**: вынести SQLite на том/внешний путь через переменную окружения (сейчас заказы пишутся внутрь контейнера и исчезают при редеплое) или на верхних уровнях перейти на Postgres.
- **Документация курса**: для каждого уровня — «что добавилось по сравнению с предыдущим, зачем, какой ценой» (сравнение LOC, зависимостей, времени запуска). Именно это превращает набор приложений в учебный курс.
- Docker-compose для одновременного запуска всех уровней на разных портах — «музей архитектур» в одну команду.

## Варианты продолжения (минимум 3 сценария)

**Сценарий А — «Учебный курс-лестница» (максимально соответствует замыслу).** Восстановить 7 уровней в папках, написать к каждому главу-объяснение (что нового, какие проблемы предыдущего уровня решает, какие приносит), добавить CI-матрицу и единый docker-compose. Результат — открытый курс «эволюция веб-приложения от PHP-файла до микросервисов» на одном сквозном примере; такой формат хорошо цитируется и может стать самым звёздным репо профиля.

**Сценарий Б — «Один продакшен-магазин».** Отказаться от идеи семи уровней, выбрать уровень 5 (или 6 из истории — Next.js+Prisma) и довести до реального использования: слить PR #11, добавить админку товаров, персистентную БД, страницу заказа вместо `alert()`, изображения товаров (в ветке уровня 1 уже есть `images/`), деплой на Render. Результат — небольшой, но действительно рабочий интернет-магазин.

**Сценарий В — «Полигон для ИИ-агентов».** Проект и так на ~100% написан Claude через PR. Формализовать это: превратить daten2 в бенчмарк-полигон, где агенту даётся задание «переведи приложение с уровня N на уровень N+1», а CI проверяет неизменность поведения (одинаковые API-тесты для всех уровней). Результат — воспроизводимый эксперимент по агентной миграции стека, тематически связанный с info40 и info100.

**Сценарий Г — «Шаблон-генератор магазинов».** Извлечь общую модель (products/orders/order_items + корзина) в спецификацию и генерировать по ней магазины любой тематики на любом из 7 стеков — «7 уровней» становятся выбором в генераторе, а не отдельными папками.

## Сочетания с другими репозиториями профиля (минимум 2)

1. **daten2 + meta4 (flower shop project) = единый «Flower Shop Curriculum».** В meta4 лежит информационная/документальная часть того же цветочного проекта, в daten2 — код семи уровней (частично в истории). Слить их: meta4 даёт теорию, ТЗ и материалы «из чата 14.12.2025», daten2 — эталонные реализации. Получается редкий артефакт: полный след учебного проекта «от переписки-замысла до 7 работающих реализаций», где можно проследить каждое решение.

2. **daten2 + info5 (4-уровневая пирамида автоматизации) = методология «уровней зрелости» с живым кодом.** info5 описывает абстрактную пирамиду уровней автоматизации; daten2 — конкретная лестница технологических уровней одного приложения. Скрестить: на каждую ступень методологии из info5 повесить работающий уровень магазина из daten2 как иллюстрацию. Получится «исполняемая методология» — теория уровней, которую можно запустить и потрогать, уникальный формат для обучения.

3. **daten2 + info40 (AI Agent Orchestration Platform) = бенчмарк агентной миграции стеков.** Оркестратору из info40 нужны реалистичные многошаговые задачи; daten2 даёт готовую задачу «мигрируй магазин с уровня N на N+1 без изменения поведения» с проверкой одинаковыми API-тестами. Инновация: измеримый, воспроизводимый бенчмарк для агентов на реальном (а не синтетическом) приложении.

4. **daten2 + daten22/data20 (offline-приложения с SQLite FTS4) = «Уровень 0: офлайн-магазин».** Добавить к лестнице ступень ниже PHP: полностью офлайн-каталог цветов с полнотекстовым поиском по SQLite FTS (опыт daten22 и data20). Получается расширение лестницы в сторону локальных/встраиваемых приложений — «от офлайн-каталога до микросервисов», чего нет ни в одном учебном репозитории профиля.
