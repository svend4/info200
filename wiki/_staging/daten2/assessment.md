# Характеристика и оценка daten2

## Что есть (реально сделано и работает)

- **Рабочий уровень 5 на main**: полноценная связка React (Vite) + Flask API + SQLite. Локальный сценарий из README (`python api.py` + `npm run dev`) корректен: CORS включён, фронтенд ходит на `http://127.0.0.1:5001`, порты совпадают (5001/5173). Каталог, корзина, оформление заказа — весь цикл покупки реализован.
- **Корректная работа с БД в API**: параметризованные SQL-запросы (инъекций нет), цена позиции берётся из таблицы `products`, а не из данных клиента, базовая валидация (`name`/`items` обязательны, иначе 400).
- **Готовая база данных**: `flowers.db` (28 КБ) закоммичена заполненной — проект запускается «из коробки», без сидинга.
- **Docker-инфраструктура**: грамотный multi-stage Dockerfile (Node-сборка → python-slim + gunicorn), следы реального деплоя на Render (`allowedHosts: ['.onrender.com']`, порт 10000, PR #3–#7 с починкой docker-compose и Render).
- **Реальная история 7 уровней**: коммиты уровней 1–7 (PHP → Flask → Django → Express → React+Flask → Next.js+Prisma → микросервисы) подтверждаются историей 19–25.12.2025; уровень 1 целиком сохранён в ветке `claude/level1-php-GBpVR`.
- **Готовые исправления в PR**: PR #11 (раздача статики Flask-ом + `VITE_API_URL` вместо хардкода) и PR #12 (недостающий `app.js` уровня 4) — написаны, но не слиты.

## Чего нет

- **Шести из семи уровней на main** — описание репозитория («7 flowersshops — 7 level programm») текущему содержимому не соответствует; уровни 2–4, 6, 7 есть только в истории коммитов.
- **Тестов** — ни одного (ни pytest для API, ни каких-либо тестов фронтенда).
- **CI/CD** — `.github/workflows` отсутствует (проверено, 404).
- **Лицензии** — LICENSE нет (проверено, 404): формально код нельзя переиспользовать.
- **Скрипта инициализации БД на main** — схему `flowers.db` можно узнать только из бинарника (на ветке уровня 1 есть `init_db.php`, на main аналога нет).
- **Lock-файла** — `package-lock.json` отсутствует, хотя Dockerfile на него ссылается (спасает glob `package-lock.json*`); сборки невоспроизводимы.
- **Документации курса** — нет обзорного README про все 7 уровней, сравнения технологий, критериев перехода между уровнями — т.е. нет именно того, что составляло бы учебную ценность.
- **.gitignore, CLAUDE.md, CONTRIBUTING** — отсутствуют.

## Плюсы

- Ясная и по-своему сильная учебная идея: одна задача — семь технологических ступеней; такой формат редко встречается в открытом виде.
- Код чистый, короткий и читаемый; для учебного уровня — образцовый минимализм (весь main читается за 10 минут).
- Полный цикл работы через PR (12 штук), а не свалка коммитов в main.
- Docker и опыт реального деплоя (Render) — не только «hello world» на localhost.
- Запуск «из коробки» благодаря закоммиченной БД.

## Минусы

- **Задеплоенный main сломан**: Dockerfile кладёт собранный фронтенд в `./static`, но `api.py` на main статику не отдаёт, а `App.jsx` зашивает `http://127.0.0.1:5001` — контейнер отдаёт голое API без UI. Исправление существует (PR #11), но не слито с 25.12.2025.
- Потеря 6 уровней при «flatten»-реорганизации — главная ценность проекта (лестница уровней) разрушена самой историей разработки.
- PR #12 чинит уровень 4, которого на main уже нет, — признак рассинхронизации процесса.
- Слабые места API: заказ принимает несуществующий `product_id` (вставится позиция с ценой 0.0), количество не проверяется на положительность, нет ограничения на размер заказа.
- Заказы пишутся в SQLite внутри контейнера (`chmod 666 flowers.db`) — данные эфемерны, теряются при редеплое.
- Бинарник БД в git; нет lock-файла; CORS открыт для всех источников.

## Качество кода и документации

Код — аккуратный учебный минимум: осмысленные имена, параметризованный SQL, `useMemo` для итога корзины, дизейбл кнопки заказа при пустых полях. Архитектурных слоёв нет намеренно. Документация — один короткий README только про уровень 5 (структура + команды запуска), на русском; README ветки уровня 1 аналогичен. Самоописаний/самоаудитов в репозитории нет; **перепроверка внешних заявлений**: заявленные «7 уровней» в описании репо на main НЕ подтверждаются (только уровень 5), число коммитов (~29) и 12 PR подтверждены страницами GitHub; языковая статистика (JS 51%, Python 22%) соответствует содержимому.

## Зрелость: 2/5

Обоснование: рабочий локальный прототип одного уровня с Docker-инфраструктурой и историей реального деплоя (это больше, чем 1/5), но: продакшен-сборка main сломана, готовые фиксы не слиты полгода, 6 из 7 заявленных уровней утрачены на main, нет тестов, CI, лицензии и обзорной документации. Ограничение покрытия аудита: содержимое уровней 2–4, 6, 7 оценено только по заголовкам коммитов и PR (деревья перезаписаны) — «не проверено» построчно; бинарник `flowers.db` изнутри не инспектировался (схема восстановлена по коду API).
