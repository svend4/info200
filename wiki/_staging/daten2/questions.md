- В. Уровни планировалось разнести по отдельным репозиториям.

**Варианты дальнейших действий:**
- При А: зафиксировать это в README (таблица уровней со ссылками на коммиты/ветки) и поправить описание репо, чтобы оно не вводило в заблуждение.
- При Б: восстановить уровни 1–7 из истории (коммиты 24–25.12.2025) в папки `level1/…level7/` — сценарий А из рекомендаций.
- При В: создать репозитории `daten2-level1…7` или теги, а daten2 сделать индексом-оглавлением.

## 3. Куда должны сохраняться заказы в задеплоенной версии? Сейчас они пишутся в `flowers.db` внутри контейнера и исчезают при редеплое.

**Варианты ответов:**
- А. Никуда — проект чисто учебный, потеря заказов приемлема.
- Б. Нужна персистентность: том/внешний диск для SQLite.
- В. На верхних уровнях — «настоящая» БД (Postgres), это часть лестницы сложности.

**Варианты дальнейших действий:**
- При А: явно написать в README «демо, данные не сохраняются».
- При Б: путь к БД через переменную окружения + persistent disk на Render; убрать `chmod 666` в пользу корректного владельца.
- При В: сделать Postgres частью уровней 6–7 при восстановлении лестницы и показать миграцию SQLite → Postgres как учебный шаг.
