# daten2 — учебный «магазин цветов» в 7 уровнях сложности (на main остался только уровень 5)

## Обзор

**daten2** — учебный проект «7 flowersshops — 7 level programm»: одно и то же приложение (интернет-магазин цветов с каталогом, корзиной и оформлением заказа) реализуется на семи уровнях технологической сложности — от PHP-файла с SQLite до микросервисов уровня «Enterprise». Однако **текущее содержимое ветки `main` — только уровень 5** (React + Vite на фронтенде, Flask API + SQLite на бэкенде): в ходе экспериментов с деплоем на Render каждая новая ветка уровня *заменяла* содержимое main, и последним слитым оказался уровень 5. Уровень 1 (PHP + SQLite) сохранился в ветке `claude/level1-php-GBpVR`; уровни 2–4, 6, 7 доступны только в истории коммитов.

Код почти полностью сгенерирован Claude (автор коммитов уровней — `claude`, владелец сливал PR). Проект маленький: на main около 10 файлов и ~300 строк кода.

## Назначение и идея

Идея — «лестница сложности»: показать одну и ту же предметную задачу (магазин цветов) на разных технологических ступенях. По истории коммитов и README веток восстанавливается такая лестница:

1. **Уровень 1** — PHP + SQLite, весь сайт в одном `index.php` (сохранился в ветке `claude/level1-php-GBpVR`);
2. **Уровень 2** — Flask + SQLite;
3. **Уровень 3** — Django (PR #8);
4. **Уровень 4** — Node.js Express + EJS (PR #9);
5. **Уровень 5** — React (Vite) + Flask API + SQLite — **текущий main** (PR #10);
6. **Уровень 6** — Next.js + TypeScript + Prisma + Tailwind (коммит 24.12.2025, на main не сохранился);
7. **Уровень 7** — «Enterprise», микросервисы для деплоя на Render (коммит 24.12.2025, на main не сохранился).

README на main честно описывает только уровень 5 и ссылается на «структуру как в чате 14.12.2025» — проект вырос из переписки/чата.

## Как устроено (архитектура)

Текущий main (уровень 5) — классическая двухзвенная связка:

- **backend/** — Flask-приложение `api.py` (~60 строк): два эндпоинта — `GET /api/products` (активные товары из SQLite) и `POST /api/orders` (создание заказа с позициями; цена берётся из БД, не от клиента). База `flowers.db` (28 КБ) закоммичена в репозиторий уже заполненной; скрипта инициализации на main нет.
- **frontend/** — React 18 + Vite 5 + axios: весь UI в одном компоненте `App.jsx` (каталог карточками, корзина с +/−, форма имя/телефон, alert с номером заказа). Интерфейс на русском, цены в евро.
- **Dockerfile** — multi-stage: Node 20 собирает фронтенд → Python 3.12-slim + gunicorn отдаёт API на порту 10000 (конфигурация под Render; в `vite.config.js` разрешён хост `.onrender.com`).

**Важный найденный дефект:** Dockerfile копирует собранный фронтенд в `./static`, но `api.py` на main статику **не отдаёт**, а `App.jsx` жёстко зашивает `API = 'http://127.0.0.1:5001'` — то есть Docker-образ с main в продакшене отдаёт только API, без UI. Оба дефекта исправлены в **открытом, но не слитом PR #11** (ветка `claude/level5-react-flask-GBpVR`: раздача статики через Flask + `VITE_API_URL`/относительные пути). Также открыт PR #12 с починкой уровня 4, которого на main уже нет.
