# robot — прототип «магазина скилов» для промышленных роботов (ETD Robotics Skill Runtime)

## Обзор

Репозиторий `svend4/robot` — это архив-дамп исследовательского прототипа **ETD Robotics Skill Runtime**: концепции «app store для роботов» промышленного уровня. Несмотря на пустое описание («info») и README из двух строк, внутри лежит целостный proof-of-concept: фреймворк упаковки, валидации и дистрибуции «скилов» (навыков) для гуманоидных и промышленных роботов, построенный поверх ОЕМ-стека управления (в духе Boston Dynamics Atlas / Hyundai / Unitree).

Содержимое трёх видов:

1. **Документы в корне** (6 md + 3 json) — архитектура маркетплейса, модель лицензирования и экономики скилов, защита IP, governance магазина, анализ анонса skill-store от Unitree.
2. **Три zip-архива** `etd_proto_repo (1|5|6).zip` — три поколения полного прототипа: Python-валидатор пакетов, 4 референс-пакета скилов, симуляция, маркетплейс-модуль, 40 документов, CI-workflow.
3. **Экспорт диалога с ChatGPT** («Роботы Hyundai», ~420 КБ в трёх форматах) — «история происхождения» проекта: от обзора робототехники Hyundai через разбор репозитория `data2` (ЕТД по Крюкову) к идее ETD-скилов как «приложений для Android-подобной ОС роботов».

## Назначение и идея

Ключевая идея: ценность роботов смещается от «железа» к загружаемым, переиспользуемым способностям (скилам). Unitree строит потребительский магазин действий; ETD позиционируется как **индустриальный аналог с более строгим governance**, потому что скил робота двигает массу и может нанести физический вред.

Принципы прототипа:

- скил-пакет — это декларативный артефакт (`manifest.yaml`, `skill.json`, `capabilities.json`, `chs_profiles.json`, `execution_contract.json`, телеметрия, приёмочные тесты);
- пакет может эмитить **только безопасные высокоуровневые skill-intent'ы** и никогда не может переопределять E-stop, торки сервоприводов, коллизионную защиту, баланс и human-protective-stop (список forbidden capabilities);
- перед установкой пакет проходит схемную, семантическую и совместимостную валидацию (уровни A/B/C/D), проверку профиля станции (workcell) и, для коммерческих пакетов, entitlement;
- маркетплейс различает open-source, бесплатные бинарные, платные коммерческие, enterprise-private и dataset-пакеты — с раздельными осями «дистрибуция / доступность исходников / сертификация / лицензия».

Название ETD отсылает к «Единой Теории Движения» (Крюков) из репозитория `data2`: в манифестах скилов уровни движения MVS/SVS/BVS/CHS (кисть-контакт / траектория руки / поза тела / контекст задачи) используются как каркас описания навыка.

## Как устроено (архитектура)

Слои прототипа (внутри архива, самый полный — `etd_proto_repo (1).zip`, 123 файла):

- **Ядро** — `etd_reference_validator.py` (~120 строк): проверяет обязательные файлы, схемы, семантику (уникальность профилей, наличие entrypoint, lifecycle-события телеметрии, отсутствие запрещённых capabilities, полезная нагрузка в пределах ограничений) и совместимость с рантаймом (сервисы, класс робота, версия) → уровень A/B/C/D и score.
- **Примеры** — 4 пакета: `etd.pickplace.basic`, `etd.assembly.precision`, `etd.inspect.vision`, `etd.cobot.safeassist`.
- **Маркетплейс** — `marketplace/skill_store.py` + `skill_store_index.json` + политики (`marketplace_policy.json`, лицензионные политики): решение об установке с учётом валидации, риска и entitlement.
- **Симуляция** — `sim/`: demo-прогоны, сценарии отказов (missing service → уровень D), генератор отчёта `report_runner.py`.
- **Интеграция** — `adapters/` (generic OEM adapter, отклоняющий небезопасные низкоуровневые команды; загрузчик профилей станций), `station_profiles/`.
- **Релизы** — `scripts/release_package.py` и собранные `release_out/*.zip`.

Файлы в корне репозитория — это выборочные копии документов и отчётов из архивов (проверено побайтово: `documentation-blueprint.md` = копия из архива 1; `report_summary.json` = копия отчёта из архива 6).
