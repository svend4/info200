# Структура information

## Дерево репозитория

Дерево тривиально — в git-истории один коммит и один файл:

```
information/                  # ветка main, 1 коммит («Initial commit», 11.03.2026)
└── README.md                 # 2 строки: «# information» и «info» — весь контент репозитория
```

Проверено отсутствие типичных файлов (все дают 404 в raw): `LICENSE`, `CLAUDE.md`, `.gitignore`, `index.html`, `docs/`, `news.md`, `info.md`, шаблоны `.github/` — ничего этого нет.

## «Невидимая» часть: GitHub Issues как хранилище данных

## Особенности организации

1. **Паттерн «Issues как база закладок»**: репозиторий служит только контейнером для issue-трекера; git-дерево — пустышка. Заголовок issue дублирует заголовок статьи (иногда с довеском вида «/ Хабр»), тело — голый URL.
2. **Нет рубрикации**: без labels невозможно фильтровать закладки по темам (ИИ, финансы, данные), хотя темы явно разные и материал разноязычный (русский + немецкий).
3. **Нет захвата контента**: сохраняется только ссылка, а не текст статьи — при исчезновении источника закладка обесценивается (типичная проблема link rot).
4. **Один день жизни**: и коммит, и все закладки созданы 11.03.2026; после этого паттерн не развивался.
