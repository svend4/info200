# info2 — T-Hub, «Тезаурус-Хаб» программного кода: концепция + прототип реестра дедуплицированных компонентов

## Обзор

**info2** — репозиторий проекта **T-Hub (Thesaurus Hub)**: концепция «реестра уникальных программных компонентов», где каждый фрагмент кода хранится в единственном экземпляре и идентифицируется по хешу содержимого (content-addressed storage). Идея позиционируется как ответ на проблему дублирования кода: по оценке автора, современные магазины приложений и реестры пакетов содержат «миллионы приложений с 80–90% дублирующегося кода».

Репозиторий состоит из двух примерно равных частей:

1. **Концептуальная документация** — 13 markdown-файлов (~6 900 строк) на русском языке: определения, анализ «общего vs уникального» кода, 4-уровневая архитектура, схема БД, roadmap на 4 фазы, бизнес-модель.
2. **Работающий прототип** (`prototype/`, ~7 500 строк JavaScript + ~550 строк SQL) — Node.js-приложение: REST API на Express с JWT-аутентификацией и Swagger, движок дедупликации (3 уровня: exact / normalized / semantic), резолвер зависимостей на semver, CLI на 8 команд, схема PostgreSQL на 10+ таблиц, интеграции с Redis, Elasticsearch, Prometheus, WebSocket, а также зачаток фронтенда на Next.js + MUI и полный DevOps-обвес (Docker Compose на 8 сервисов, Kubernetes-манифесты, GitHub Actions CI).

## Назначение и идея

Ключевая метафора: «как Wikipedia упорядочила знания, а Amazon — торговлю, T-Hub упорядочивает программный код». Механика:

- **Единый реестр компонентов** — каждый компонент существует в одном экземпляре, идентифицируется SHA-256-хешем содержимого;
- **Автоматическая дедупликация при публикации** — 3 уровня: точное совпадение хеша, совпадение после нормализации (удаление комментариев/пробелов), «семантическая» схожесть (Jaccard-похожесть токенов, порог 0.85);
- **Умное разрешение зависимостей** — граф зависимостей, semver-ограничения, обнаружение циклов, топологическая сортировка;
- **Сборка приложений из компонентов** — манифест `thub.json` / `*.thub.yaml` описывает приложение как набор ссылок на компоненты реестра.

Проект оформлен как «стартап-питч + доказательство осуществимости»: в README и PROJECT-SUMMARY.md есть бизнес-модель (Open Core, Pro $29/мес, маркетплейс 70/30), целевые метрики ($1M ARR, 100 000 компонентов) и roadmap — всё это на данный момент чисто декларативное.

## Как устроено (архитектура)

Заявленная 4-уровневая архитектура: ОС → Docker → «Оркестрация + T-Hub Engine» (Kubernetes) → микросервисы, собираемые из компонентов. Фактическая архитектура прототипа:

- **`prototype/api/`** — Express-сервер (`server.js`, 683 строки): маршруты аутентификации (register/login, bcrypt + JWT), CRUD компонентов, поиск, статистика; `auth.js` (306 строк) — middleware и rate-limit; `advanced-routes.js` (408 строк) — маршруты поиска через Elasticsearch с graceful fallback, кэширование через Redis, метрики; `swagger.json` (505 строк) — OpenAPI-спецификация, отдаётся на `/api-docs`.
- **`prototype/core/`** — два движка: `deduplication.js` (249 строк, SHA-256 + нормализация + Jaccard) и `dependency-resolver.js` (336 строк, semver, циклы, топосортировка).
- **`prototype/db/`** — пул подключений PostgreSQL и репозитории (`index.js`, 524 строки), миграция `001_initial_schema.sql` (369 строк: users, components, dependencies, tags, download-статистика, триггеры, представления, gin/pg_trgm-индексы), сиды с примерами.
- **`prototype/cache|search|realtime|monitoring/`** — Redis-кэш (505 строк), Elasticsearch-сервис (523), WebSocket-сервер и клиент (441+241), Prometheus-метрики (349).
- **`prototype/cli/`** — CLI `thub` на commander/inquirer/chalk: init, publish, search, install, info, build, deduplicate, stats.
- **`prototype/__tests__/`** — unit-тесты движка дедупликации на mock-реестре (296 строк) и интеграционные тесты API (245 строк).
- **`frontend/`** — скелет Next.js 14 + React 18 + MUI: одна страница (`index.jsx`), 3 компонента, 1 хук.
- **Инфраструктура** — `docker-compose.yml` (8 сервисов: api, postgres, redis, elasticsearch, minio, nginx, prometheus, grafana), `k8s/base/` (deployment, ingress), `.github/workflows/ci.yml` (269 строк: lint, тесты, интеграционные тесты с сервисами, security-аудит, сборка Docker-образа, деплой-заглушки).

Подробнее — в [structure.md](structure.md).
