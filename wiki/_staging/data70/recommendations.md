## Серьёзные доработки

- **Тесты и CI**: pytest на парсер (фикстура — мини-файл экспорта), проверка валидности JSON-графов и битых внутренних ссылок монорепо в GitHub Actions. Малой кровью снимается риск «молчаливой» поломки конвейера.
- **Полнотекстовый поиск по архиву**: 78 МБ текста без поиска почти бесполезны для читателя. Индекс SQLite FTS5 + простое веб/CLI-приложение превратят архив из «свалки на память» в рабочий инструмент.
- **Улучшить классификатор**: заменить keyword-matching на эмбеддинги (локальная модель) с ручной проверкой топ-тем; расшифровать и задокументировать систему «архетипов» (MSCF/ADCO/…).
- **Git LFS или релизы** для тяжёлых txt: держать в git только аналитику и монорепо, а 78 МБ сырья — в LFS/Release-артефактах.
- **Дедупликация таксономий**: свести кластеры A–J и папки 01–10 к одной канонической системе, вторую оставить как алиас в индексе.

## Варианты продолжения

### 1. «SozialHelper» — продукт из кластера соцправа
Самый зрелый кластер (`01_social_law`, ~300 разговоров, 50+ немецких шаблонов, каталог 70 услуг, судебная практика BSG) уже сегодня — почти готовая база знаний для людей с инвалидностью в Германии. Продолжение: выделить шаблоны в структурированный вид (YAML/JSON + md), собрать Telegram-бота или статический сайт с пошаговыми маршрутами («отказ ведомства → Widerspruch → иск»), как и предлагает сам архив (карточка `01_persoenliches_budget` уже содержит план монетизации: книга, SaaS SozialPlaner, бот, пакеты шаблонов). Это путь наименьшего сопротивления к первому реальному пользователю.

### 2. Завершить контур GraphRAG: data70 → infom → ответы
Мост в граф знаний построен наполовину: JSON сгенерирован, но в data70 не видно подтверждения, что infom его реально загрузил и по нему можно спрашивать. Продолжение: довести пайплайн до конца (загрузка снапшота, семантические эмбеддинги вместо пустых `embedding: []`, RAG-поиск по полному тексту разговоров, а не только по метаданным) и закоммитить в data70 инструкцию + скрипт запроса. Тогда архив станет «живой памятью», у которой можно спросить «что я решил про TetraDrone в феврале 2025?».

### 3. Книга/публичная вики «Архив идей»
MANIFEST прямо формулирует цель — чтобы идеи пережили автора. Монорепо уже структурирован как книга: 11 глав-кластеров, карточки, суперпроекты. Продолжение: статический сайт (MkDocs/Quartz) поверх `monorepo/` с поиском, публикация на GitHub Pages, оглавление из `00_index/`. Минимум нового контента, максимум доступности — и распределённое хранение усиливается (сайт индексируется поисковиками и веб-архивом).

### 4. Патентно-публикационный трек
24 карточки `07_inventions_patents` довести до формата defensive publication: по 3–5 лучших (TetraDrone, FlamberRotor, WILOS) оформить технические раскрытия и опубликовать (например, через препринт/Defensive Publications), зафиксировав приоритет и защитив идеи от чужого патентования — это дешевле патентов и соответствует духу «открытого завещания идей».

## Сочетания с другими репозиториями профиля

1. **data70 + infom (ГрафРАГ)** = «живой персональный граф памяти». Уже начато самим автором (`prepare_for_infom.py`, `infom_snapshot.json`): data70 даёт 78 МБ реального корпуса и готовый граф 197 нод / 576 рёбер, infom — движок GraphRAG. Уникальность: персональный GraphRAG на полном многолетнем корпусе одного человека с его собственной разметкой тем (коды 111/999/…) — готовый кейс-исследование «второго мозга», какого нет в открытых примерах.

2. **data70 + daten22 (offline search, SQLite FTS4)** = «офлайн-архив выживания». daten22 умеет офлайн-поиск по SQLite FTS; проиндексировать 153 файла экспорта — и получится автономное приложение-архив, работающее без интернета с телефона/флешки. Это буквально отвечает на главную боль MANIFEST (архив терялся при госпитализации и войне): офлайн-копия с поиском — максимальная живучесть знаний.

3. **data70 (кластер 01_social_law) + soz150 (writing os) + info150 (info med)** = «конвейер социальных документов». data70 даёт юридическое сырьё (50+ шаблонов SGB IX/XII, судебные стратегии, медицинские письма), soz150 — «операционную систему письма» для сборки документов, info150 — медицинскую информационную часть. Вместе — генератор персонализированных заявлений/возражений для людей с инвалидностью в Германии: ниша с 13 млн потенциальных пользователей (цифра из аналитики data70), где сейчас нет русскоязычных инструментов.

4. **data70 + lorenzo (docs-toolkit)** = «фабрика структурирования архивов». docs-toolkit из lorenzo (Python-пакет для работы с тысячами md-файлов) применить к монорепо data70: автогенерация индексов, проверка ссылок, конвертация карточек. Обратно: конвейер data70 (экспорт → кластеры → карточки → граф) обобщить в методику, которой можно обработать и 2815 md-файлов lorenzo — получится переиспользуемый инструмент «archаeology-of-knowledge» для любых больших личных архивов.

5. **data70 + info200 (хаб вики)** = витрина всего профиля: карта 88 тем и таблица соответствия кластеров из data70 — готовый «оглавительный» слой для навигации по остальным 60 репозиториям (многие из них — daten4 «динамический планировщик», data7 «коммивояжёр», meta4 «flower shop» — прямо соответствуют темам каталога data70).
