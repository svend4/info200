# Рекомендации по data4

## Быстрые улучшения

1. **Расширить README** (30 минут): расшифровать «Soz», описать идею в 5–10 предложениях — что за приложение, для кого, в чём «социальность» бюджета (совместные/семейные бюджеты? обмен шаблонами? челленджи экономии?).
2. **Зафиксировать замысел в `docs/idea.md`**: сценарии использования (3–5 user stories), минимальный набор сущностей (доход, расход, категория, счёт, пользователь/группа).
3. **Добавить LICENSE** (MIT/Apache-2.0), чтобы будущий код был переиспользуем.
4. **Создать 5–10 issues** с планом MVP — тогда репозиторий перестанет быть «немой» заготовкой и будет виден roadmap.
5. **Выбрать и зафиксировать стек** хотя бы одной строкой в README (например, «офлайн-first HTML+SQLite, как daten22» — в духе других репо профиля).
6. Если проект не планируется — **пометить в README «заготовка, не начат»** или заархивировать репозиторий, чтобы описание не вводило в заблуждение.

## Серьёзные доработки

- **MVP персонального бюджета**: одностраничное офлайн-приложение (localStorage/SQLite) с вводом операций, категориями, месячной сводкой и экспортом CSV/JSON. Это ядро, без которого «соц»-надстройка бессмысленна.
- **Модель данных и синхронизация**: продумать формат хранения (JSON-схема операций и категорий), чтобы позже добавить обмен между пользователями (семейный бюджет = слияние двух журналов операций).
- **Социальный слой**: общие бюджеты (несколько участников пишут в один журнал), публичные шаблоны категорий/лимитов, сравнение «моя структура расходов vs средняя».
- **Тесты и CI** с первого модуля: расчёты бюджета — как раз та логика, где юнит-тесты дёшевы и полезны.

## Варианты продолжения (минимум 3 сценария)

### 1. Офлайн-first персональный бюджет (минимальный, реалистичный)

Сделать то, что написано в описании, в самой простой форме: одностраничное приложение (HTML+JS, хранение в localStorage или SQLite/FTS-подход из daten22), ввод доходов/расходов, категории, месячные итоги, экспорт. Без сервера и регистрации — в духе офлайн-линейки профиля (daten22, data20). Это даёт работающий продукт за несколько сессий и материализует репозиторий; «социальность» откладывается на потом как экспорт/импорт журналов между людьми.

### 2. Семейный/групповой бюджет — «соц» как совместность

Развить именно социальную часть: бюджет как общий журнал нескольких участников (семья, соседи по квартире, поездка компанией). Ключевые фичи — общий счёт, взаимные долги (кто кому сколько после общих трат, splitwise-механика), роли и лимиты. Технически: embedded-бэкенд (как в data20) или простая синхронизация через файлы/git. Это самый уникальный сценарий — обычных трекеров бюджета много, а «соц»-акцент даёт отличие.

### 3. ИИ-советник по бюджету

Подключить агентную инфраструктуру профиля (info40 — AI Agent Orchestration, info7 — оркестратор и бот): пользователь ведёт журнал трат, а агент категоризирует операции, находит аномалии, предлагает лимиты и план накоплений, отвечает на вопросы «могу ли я позволить X в этом месяце». data4 становится «кейсом-приложением» для агентной платформы автора — двойная польза: и продукт, и демо платформы.

### 4. Слияние с soz150 (альтернатива отдельному развитию)

Если отдельный репозиторий не оправдан, перенести идею как модуль в soz150 («соц»-направление, writing os): бюджет — один из «социальных» инструментов. data4 тогда закрыть/заархивировать со ссылкой. Это честный сценарий против расползания на 61 репозиторий.

## Сочетания с другими репозиториями профиля (минимум 2 идеи)

1. **data4 + daten4 (dynamic planner) = финансовый планировщик с обратной связью.** Динамический планировщик задач + журнал бюджета: планы получают стоимость, а бюджет — календарное измерение. Получается инструмент «планирую неделю/месяц и сразу вижу, во что это обойдётся и укладываюсь ли в лимиты», с перепланированием при выходе за бюджет — то, чего нет ни в чистых планировщиках, ни в трекерах трат.

2. **data4 + daten8 (мониторинг интернет-объявлений) = бюджет с умными покупками.** Мониторинг объявлений/цен подключается к статье планируемых расходов: пользователь заводит «хочу ноутбук, лимит 500», daten8 отслеживает объявления, а data4 показывает, когда накоплений хватает и предложение попало в лимит. Инновация — связка «накопительная цель ↔ живой рынок»: приложение само говорит «пора покупать».

3. **data4 + daten22 (offline search, SQLite FTS4) + data20 (offline app, embedded backend) = офлайн-бюджет с полнотекстовым поиском.** Хранение операций в SQLite с FTS-индексом по описаниям трат: мгновенный офлайн-поиск «все траты на лекарства за год», без сервера и облака. Уникальность — приватность по умолчанию: полнофункциональный личный финансовый аналитик, не отправляющий данные никуда.

4. **data4 + info40 (AI Agent Orchestration Platform) = агент-бухгалтер как продакшн-кейс.** Оркестратор агентов получает реальный прикладной сценарий: агент-категоризатор, агент-аналитик аномалий, агент-советник по накоплениям работают над одним журналом бюджета. Для info40 это демонстрация платформы на живой задаче, для data4 — готовый «мозг» приложения.
