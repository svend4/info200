# meta — монорепо hex-проектов на графе Q6 (64 гексаграммы = 6-мерный гиперкуб)

## Обзор

**meta** — самый крупный и технически насыщенный «hex-репозиторий» профиля svend4: монорепо из **48 проектов** (в README заявлено 24 — список устарел), объединённых одной математической идеей. 64 гексаграммы И-Цзин трактуются как вершины 6-мерного гиперкуба **Q6** (граф Кэли группы (Z₂)⁶): каждая вершина — 6-битное число 0..63, каждое ребро — переворот одной черты (расстояние Хэмминга = 1). На этой структуре построены проекты из десятков областей: теория графов, криптография, коды, машинное обучение, оптимизация, поле Галуа GF(2⁶), статистическая физика, биоинформатика (генетический код), стековый язык программирования, клеточные автоматы, игры и визуализация.

Репозиторий создан 18 февраля 2026 и за ~6 дней (до 23 февраля) получил **324 коммита**, преимущественно от агента Claude Code (в README прямо указано: «Агент: Claude Code, модель claude-sonnet-4-6»). Разработка велась через 11 pull request'ов (10 слиты, 1 открыт). Это интенсивный AI-driven эксперимент с настоящими тестами (десятки тысяч строк) и работающим CI.

## Назначение и идея

Идея — «одна структура, N углов зрения»: показать, что нетривиальный конечный объект (Q6, 64 вершины, 192 ребра) достаточно богат, чтобы служить учебно-исследовательской площадкой для практически всей дискретной математики. Общая библиотека `libs/hexcore` (333 строки, ноль внешних зависимостей) даёт базовые операции (соседи, расстояние Хэмминга, кратчайшие пути, код Грея, шары/сферы Хэмминга, триграммы, орбиты, подкубы), а каждый проект в `projects/` — самостоятельное CLI-приложение, зависящее только от hexcore.

Поверх модулей построен второй уровень — **оркестратор `libs/q6ctl`**: реестр 42 модулей, 8 тематических кластеров (K1 «криптографический» … K8 «схемный»), 11 «суперкластеров» (межкластерных пайплайнов, например SC-1 «Шифр Германа» = hexperms + hexuniqgrp + hexcrypt), исполнитель пайплайнов «модуль:команда» с JSON-передачей stdout→stdin и именованными контекстами. Отдельная сюжетная линия — коллекция PDF-статей математика Franz German (и документов М. Беляева) в корне репо: они анализируются в docs и служат источником идей для новых модулей (hexpack, hextrimat, hexperms, hexuniqgrp и др.). Проект `hexglyph` добавляет неожиданное измерение: собственный TTF-шрифт «Solan» (глифы, кодирующие вершины Q6) и ~65 аналитических модулей `solan_*.py` вокруг него.

## Как устроено (архитектура)

- `libs/hexcore/` — единственная общая зависимость всех проектов; чистый Python, стандартная библиотека.
- `libs/q6ctl/` — оркестратор: `registry.py` (42 ModuleInfo, 8 ClusterInfo, 11 SuperClusterInfo), `pipeline.py` (subprocess-цепочки, JSON-пайп), `context.py` (сохранение результатов), `q6cli.py` (команды list/run/pipe/call/ctx/info).
- `projects/` — 48 каталогов; классические проекты — один главный модуль + README + examples; новая волна («glyph»-серия: sbox_glyphs, codon_glyphs, ca_glyphs…) интегрирована с реестром; вне реестра остаются hexboya, hexglyph, hexiching, hexintegration, hexkub, hexliuxing.
- `tests/` — 48 файлов, ~50 200 строк; ~8 500 тест-функций, из них ~5 500 — сгенерированное покрытие `test_hexglyph.py` (30 491 строка).
- `docs/` — architecture.md, q6-math.md, projects-overview.md (939 строк, характеристики 24 проектов), papers-index.md, superclusters.md, synergies_and_filter.md (фильтр отбора новых модулей), analysis_herman_andreev.md.
- `scripts/` — 12 shell-скриптов суперкластерных пайплайнов; `tools/` — smoke_test.py (24 CLI) и extract_papers.py.
- `.github/workflows/ci.yml` — 3 джоба: pytest на Python 3.10/3.11/3.12, smoke-тест, синтаксический lint.

## Статус и активность

Вся история — один спринт 18–23 февраля 2026 (324 коммита, 11 PR); с тех пор (на дату аудита 02.07.2026) активности нет — проект «спит» после взрывного старта. CI настроен и, судя по слитым PR, зелёный. Аудит-перепроверка выявила отставание документации от кода: README описывает 24 проекта/27 тест-файлов/1707 тестов, реально 48 проектов/48 тест-файлов/~8,5 тыс. тест-функций; в `registry.py` пути модулей hexforth и hexpath указывают на несуществующие файлы (проверено: 404). Выборочный локальный запуск тестов ядра (hexcore + q6ctl + registry, 198 тестов) подтвердил: тесты настоящие и проходят.
