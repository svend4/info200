# Характеристика и оценка meta

## Что есть

- **Работающее ядро**: `libs/hexcore/hexcore.py` (333 строки) — аккуратная, документированная (docstrings по-русски), типизированная библиотека графа Q6 без внешних зависимостей. Проверено локальным запуском тестов: **88 тестов hexcore проходят**.
- **48 проектов** в `projects/` — от теории графов и криптографии до биоинформатики и собственного Forth-подобного языка. У «классических» 24 есть README и примеры; уровень реализации по docs/projects-overview.md — 400–1000 строк на проект (выборочно подтверждено: hexvis 821, hexgraph 705, hexbio/codon_glyphs 706 строк).
- **Оркестратор q6ctl**: реестр (42 модуля, 8 кластеров, 11 суперкластеров), пайплайны subprocess+JSON, именованные контексты, единый CLI. Проверено локально: **тесты test_q6ctl и test_registry проходят** (110 тестов; один упал только из-за отсутствия в моей частичной копии projects/hexpack — тест реально запускает пайплайн).
- **Массивный тест-сьют**: 48 файлов, ~50 200 строк, ~8 500 тест-функций (из них 5 511 — сгенерированное покрытие `test_hexglyph.py` на 30 491 строку). Тесты содержательные: проверяют конкретные математические свойства (спектры, границы кодов, свойства bent-функций), а не только «не падает».
- **CI**: `.github/workflows/ci.yml` — pytest на Python 3.10/3.11/3.12 + smoke-тест 24 CLI + синтаксический lint. Makefile дублирует те же цели локально.
- **Документация-исследование**: 7 файлов в docs/, включая незаурядные `superclusters.md` (какие комбинации кластеров дают emergent-результат) и `synergies_and_filter.md` (формальный фильтр: из 11 предложенных модулей строить только 3). Это редкий пример задокументированного процесса отбора идей.
- **Уникальный контент**: TTF-шрифт Solan (2 файла), HTML-viewer, PDF-коллекция статей Franz German с индексом и извлечением текста (tools/extract_papers.py), сравнительный анализ статей в analysis_herman_andreev.md.
- **История разработки через PR**: 11 PR, ветки claude/*, осмысленные сообщения коммитов с метриками тестов.

## Чего нет

- **Лицензии** — файла LICENSE нет (проверено: 404). Формально код нельзя переиспользовать.
- **Упаковки/установки** — нет pyproject.toml/setup.py; импорты через `sys.path.insert('../../')`; ни pip install, ни запуск вне корня репо невозможны.
- **Актуальной документации** — README/architecture/projects-overview описывают 24 проекта, реально их 48; заявленные «1707 тестов, 27 файлов» устарели минимум вчетверо; papers-index.md перечисляет 33 PDF, в корне их ~75.
- **README у новых проектов** — например, projects/hexiching/README.md отсутствует (404); hexboya, hexkub, hexliuxing, hexintegration не описаны нигде.
- **Полноты реестра** — 6 каталогов проектов не зарегистрированы в registry.py (hexboya, hexglyph, hexiching, hexintegration, hexkub, hexliuxing); smoke-тест покрывает только 24 CLI из 48.
- **Гигиены репозитория** — ~75 PDF + 5 ODT (с именами вида `!!!!SOLAN !Shrift! neu!!!! (2).odt`) и артефакт `.coverage` закоммичены в корень; нет папки papers/ или Git LFS.
- **Issues/релизов** — 0 releases, задачи не трекаются; открыт 1 незакрытый PR (#11).
- **Внешней валидации математики** — нет сравнения с эталонными библиотеками (SageMath, SymPy) хотя бы в виде отдельного проверочного скрипта.

## Плюсы

1. Редкая для профиля глубина: это не «info-заметки», а десятки тысяч строк работающего, протестированного кода с CI.
2. Дисциплинированная архитектура: радиальная зависимость только от hexcore, интеграция через subprocess/JSON — проекты действительно независимы.
3. Тесты проверяют математику (границы Синглтона/Хэмминга, спектр гиперкуба, свойства WHT), что резко повышает доверие к результатам.
4. Метадокументация процесса (фильтр модулей, суперкластеры) — видно мышление, а не только код.
5. Кросс-дисциплинарность как фича: один граф связывает крипто, ML, биологию, И-Цзин и типографику (шрифт Solan).
6. Zero-dependency: всё на стандартной библиотеке Python — воспроизводимо где угодно.

## Минусы

1. **Битые пути в реестре** (найдено аудитом): `registry.py` указывает `projects.hexforth.hexforth` и `projects.hexpath.hexpath`, но файлов hexforth.py/hexpath.py не существует (проверено: 404; реальные точки входа — interpreter.py и game.py/cli.py). Значит `q6cli call hexforth ...` и пайплайны с этими модулями сломаны, а test_registry проверяет только структуру, не существование путей.
2. Документация системно отстаёт от кода (24 vs 48 проектов, счётчики тестов, индекс PDF) — для монорепо, который сам себя позиционирует как «карту», это существенно.
3. Взрывной AI-спринт без последующего сопровождения: вся история — 6 дней февраля 2026, дальше тишина 4+ месяца; открытый PR #11 висит.
4. Засорённый корень (десятки бинарных PDF/ODT, .coverage) и инородный flower_shop.py.
5. Отсутствие лицензии и упаковки блокирует любое внешнее использование.
6. Половина проектов вне контуров качества (не в registry, не в smoke-тесте, без README) — «тёмная материя» монорепо.

## Качество кода и документации

Код (по прочитанной выборке: hexcore, q6ctl полностью; hexglyph.py, smoke_test.py, registry.py, interpreter.py, фрагменты тестов) — уверенный современный Python: type hints, dataclasses, `from __future__ import annotations`, argparse-CLI по единому шаблону, русскоязычные docstrings, ASCII-схемы в комментариях. Стиль однороден по всему репо (следствие генерации одним агентом). Тесты — unittest, местами параметризация циклами; сгенерированный test_hexglyph.py механичен, но корректен. Документация написана хорошо и подробно (README 323 строки, projects-overview 939 строк), но её фактическая точность на момент аудита — устаревшая примерно наполовину. Оценки покрытия: заявление «все тесты проходят» проверено лишь частично (198 тестов ядра локально — проходят; полный прогон ~8,5 тыс. тестов в среде аудита невозможен — не проверено).

## Зрелость: 3/5

Обоснование: (+) большой объём реально работающего кода, содержательные тесты, CI на трёх версиях Python, продуманная архитектура и метадокументация — это уверенные 3 балла и лучший результат среди «hex/info»-репозиториев профиля. (−) До 4/5 не дотягивает из-за: битых путей реестра, двукратного отставания документации, отсутствия лицензии и упаковки, бинарного мусора в корне, полного затишья после спринта и того, что половина проектов не охвачена реестром/smoke-тестами. Ограничение аудита: из ~300+ файлов кода детально прочитано ~15, остальное оценено по деревьям каталогов, реестру, тестам и документации.
