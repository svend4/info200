# Вопросы к universal-file-storage-mcp

## 1. Код ни разу не компилировался (39 ошибок tsc) — это осознанная «заготовка из чата» или вы считали проект рабочим?

Судя по истории (архив, загруженный за один день 29.01.2026) и характеру ошибок (схемы инструментов и опции транспорта под несуществующий API SDK), код был сгенерирован в диалоге и не запускался.

**Варианты ответов:**
- А. Да, это сохранённый концепт из чата с Claude, до запуска руки не дошли.
- Б. Считал рабочим — не знал, что не собирается.
- В. Собирался локально в другой версии, в репозиторий попала не та.

**Варианты дальнейших действий:**
- При А: пометить в README статус «concept / не запускалось», чтобы не вводить в заблуждение (есть звезда — люди находят репо); чинить только при реальной потребности (см. recommendations.md, «Быстрые улучшения» п.1).
- При Б: применить три механические правки из recommendations.md и добавить CI с `tsc --noEmit` — впредь некомпилирующийся код не пройдёт.
- При В: найти и запушить рабочую версию, сверить с текущей документацией.

## 2. Какой сценарий использования для вас главный: файлы телефона, NAS или «всё сразу»?

Замысел покрывает 4 типа хранилищ, но качество проработки разное: Termux/Android задокументирован блестяще, NAS-ветка небезопасна и хрупка, S3 отсутствует вовсе.

**Варианты ответов:**
- А. Телефон (скриншоты, фото, заметки) — главный кейс.
- Б. NAS/домашний сервер.
- В. Именно универсальность «всё в одном».
- Г. Конкретного кейса нет — исследовал возможности MCP.

**Варианты дальнейших действий:**
- При А: сценарий C из recommendations.md — сузить до «Termux-first», выбросить NAS/S3, довести до рабочего состояния за минимальное время.
- При Б: переписать NAS-адаптер на JS-библиотеку SMB (без sudo mount и пароля в командной строке), добавить аутентификацию HTTP.
- При В: сценарий B — плагинная архитектура адаптеров + индексация; это долгий путь, планировать этапами.
- При Г: закрыть как эксперимент (сценарий D), ценные куски (описания инструментов, Termux-гайд) перенести в живые проекты.

**Варианты ответов:**
- А. Нет, спасибо — надо чинить перед любым реальным использованием.
- Б. Знал, но сервер задуман только для localhost и доверенной машины.
- В. Безопасность отложена до «рабочей версии».

**Варианты дальнейших действий:**
- При А: пункты 1–2 «Серьёзных доработок» из recommendations.md (SMB-библиотека вместо sudo mount, `path.resolve`-проверка, токен на HTTP).

- При В: зафиксировать это в issues, чтобы ограничения не потерялись.
