# universal-file-storage-mcp — MCP-сервер «все файлы во всех хранилищах для Claude» (прототип, не компилируется)

## Обзор

`universal-file-storage-mcp` — это MCP-сервер (Model Context Protocol) на TypeScript/Node.js, задуманный как единая точка доступа Claude AI к файлам пользователя на любой платформе: локальные диски Windows/Linux/macOS, Android-телефон (через ADB или Termux), NAS (SMB/CIFS) и облачные хранилища (WebDAV; S3 заявлен, но не реализован). Сервер предоставляет Claude четыре инструмента: `list_storages`, `search_files` (полнотекстовый поиск с OCR картинок через Tesseract), `read_file` и `list_files`.

Репозиторий — типичный «архивный слепок» одного дня: все 9 коммитов сделаны 29.01.2026, код загружен архивом и распакован ботом claude через три PR. Документация обширная и качественная (7 md-файлов, ~4 200 строк, включая подробнейший гайд по запуску на Android/Termux), но сам код — единственный файл `src/index.ts` — **не компилируется**: проверка `tsc --noEmit` при аудите дала **39 ошибок типов**, а HTTP-обвязка MCP-транспорта написана под несуществующий API SDK. То есть проект в текущем виде ни разу не собирался и не запускался.

## Назначение и идея

Идея сильная и практичная: у пользователя файлы разбросаны по ноутбуку, телефону, NAS и облаку, а Claude «видит» только то, что ему вставили в чат. Универсальный MCP-сервер с адаптерами под каждый тип хранилища даёт Claude единый интерфейс: «найди все файлы со словом "бюджет" на NAS и в телефоне», «прочитай текст со скриншота». Ключевые фишки замысла:

- **адаптерная архитектура** — одно API (`listFiles`/`readFile`/`searchFiles`) поверх local/NAS/cloud/Android;
- **OCR для скриншотов** (tesseract.js, языки eng+rus) — поиск по тексту на изображениях;
- **запуск сервера прямо на телефоне** через Termux — самый проработанный документально сценарий (848-строчный гайд + 523-строчный автоустановщик);
- заявленная перспектива: индексация (SQLite FTS5), кэширование, S3/Google Drive/Dropbox, web-UI (roadmap до v3.0 в ARCHITECTURE.md).

## Как устроено (архитектура)

Всё в одном файле `src/index.ts` (821 строка):

1. **Конфигурация** — захардкоженный массив `STORAGES` из 6 хранилищ (пути вида `D:\Documents`, `/home/max/documents`, NAS `//192.168.1.5/shared`); настройка выполняется правкой исходника, пароли — из `.env`.
2. **Класс `StorageAdapter`** — один класс со `switch` по типу хранилища: local через `fs/promises`; NAS через `sudo mount -t cifs` (вызов shell); cloud через библиотеку `webdav`; Android через `adb shell ls/cat` с парсингом вывода. OCR — `Tesseract.recognize`. Поиск — наивный: прочитать каждый файл верхнего уровня целиком и сделать `includes()`.
3. **4 MCP-инструмента** зарегистрированы через `McpServer.registerTool` с zod-схемами и подробными описаниями (docstring-качество высокое).
4. **HTTP-слой** — Express + `StreamableHTTPServerTransport`, но транспорт создан с несуществующими опциями `{ server, endpoint }` и ни один маршрут Express не привязан к обработке MCP-запросов — эта часть неработоспособна даже концептуально, не только по типам.

Подробнее: [structure.md](structure.md). Расхождения между документацией и кодом (S3, кэширование, «защита от path traversal», рабочий поиск по PDF/DOCX — всё заявлено, ничего нет) разобраны в [assessment.md](assessment.md).

## Статус и активность

- **9 коммитов, все за один день — 29 января 2026** («Initial commit» → загрузка архива → распаковка в корень тремя PR с ботом claude). С тех пор (на 02.07.2026, 5 месяцев) активности нет.
- 1 звезда, 0 форков; issues/ветки сверх main — не обнаружены.
- Сборка: `npm run build` невозможна — 39 ошибок TypeScript (проверено при аудите установкой зависимостей и запуском `tsc --noEmit`).
- `npm test` тоже нерабочий: скрипт вызывает jest, которого нет в devDependencies.
- Файла LICENSE нет (MIT заявлен только в package.json и README).

Статус: **экспериментальный прототип / заготовка** — хорошо документированный замысел с некомпилирующимся кодом.
