# Характеристика и оценка nautilus

## Что есть (реально сделано и работает)

- **Рабочий движок портала**: `portal.py` с 14 зарегистрированными адаптерами, ранжированием, консенсус-моделью и Q6-навигацией; CLI (`--query`), веб-SPA (`--serve`) и REST API (`api.py`, 12 эндпоинтов) — всё на stdlib.
- **Формальная спецификация**: `PORTAL-PROTOCOL.md` (~1000 строк) — полноценный протокол в стиле RFC (BCP 14, 17 разделов: модель данных, реестр, паспорта, уровни совместимости 0–3, Q6, консенсус, REST-семантика, кэширование, безопасность, версионирование, алгебра мостов, Protocol 3). Плюс `openapi.yaml` (OpenAPI 3.1) и `INTEGRATION.md` (637 строк).
- **Тесты и CI**: 60 тест-функций в 4 файлах (перепроверено пересчётом: 27+15+13+5), CI-воркфлоу гоняет pytest, `validate_links.py --strict` и `health_check.py`. Тесты содержательные: консенсус-структура, кросс-репо-ссылки, регистрация кастомного адаптера.
- **Работавшая автоматизация**: `sync.yml` — еженедельный бот `nautilus-sync-bot`, реально коммитивший (последний коммит 2026-04-27); `auto_update.yml` — самореистрация внешних репо через `repository_dispatch`. Авто-снапшоты в репо (`snapshot.md`, `ecosystem_stats.json`, `health_report.txt`, `link_report.json`).
- **Инструментарий анализа экосистемы**: health check (score 0–100), валидация ссылок, gap-анализ Q6-покрытия, TF-IDF-поиск (207 документов), кластеризация, diff, timeline, интерактивные визуализации (`q6_map.html`, `graph.html` на D3.js).
- **Bridge-система**: 33 типизированных моста в 12 паспортах (перепроверено: ровно 33), алгебра v2.0 с инверсией, композицией, транзитивным замыканием и детекцией конфликтов.
- **Развёртывание**: Dockerfile + docker-compose (4 сервиса, healthcheck), Python SDK, `py.typed` + mypy.ini.

Реальный консенсус по запросу «knowledge» — 36 %, покрытие Q6 — 0.36. То есть «портал в экосистему» в дефолтном запуске в значительной мере показывает захардкоженный слепок экосистемы, а не живые данные. README это нигде явно не оговаривает.

Также есть внутреннее расхождение между авто-отчётами: `snapshot.md` — 152 записи / 136 ссылок, `link_report.json` — 216 записей / 317 ссылок (разные методики сбора: снапшот по одному запросу против 10 «широких» запросов валидатора).

## Чего нет

- **Лицензии** — файла LICENSE нет (проверено: 404). CC BY 4.0 заявлена только для текста протокола внутри PORTAL-PROTOCOL.md; статус кода юридически не определён.
- **Упаковки** — нет pyproject.toml/setup.py, проект не устанавливается через pip, SDK не публикуется; запуск только «клонируй и запускай скрипты».
- **Живого подключения к данным** — нет механизма клонирования/синка реальных репо-источников; репо-адаптеры ищут файлы соседних локальных каталогов (`../pro2/...`) и почти всегда падают в fallback.
- **Тестов для api.py, annotations.py, bridge_registry.py** — тестовые файлы покрывают только adapters, portal, health_check, validate_links; API-слой и две новые подсистемы v1.2 без выделенных тестов.
- **Аутентификации API** — POST /api/annotations открыт любому (для публичного деплоя это проблема; раздел Security в протоколе есть, но реализация — нет).
- **Актуальной активности** — sync-бот молчит с 2026-04-27 (~9 недель на дату аудита); вероятно, GitHub отключил cron из-за неактивности, и никто не заметил — мониторинга самого бота нет.
- **Чистоты docs/** — посторонние файлы («Вакансии в Anthropic по кластерам» ×3 формата).
- CONTRIBUTING, CHANGELOG (частично заменён STATUS-файлами), issues/PR-активности (0/0).

## Плюсы

- Лучшая в профиле инженерная культура: тесты + CI + типизация + OpenAPI + Docker + формальная спецификация + работавший бот — полный набор, крайне редкий для соседних репо профиля.
- Оригинальная и последовательная концепция: «федерация без слияния», Q6-онтология как общий адрес, паспорта с machine-readable мостами — это цельная, продуманная система, а не набор скриптов.
- Zero-dependency: запускается на любом Python 3.10+ без pip install.
- Честная внутренняя диагностика: проект сам о себе сообщает 66/100 и перечисляет проблемы — самокритика встроена в код (health_check, флаги Protocol 3).
- Документация обильная и структурированная (README, STATUS v1.1/v1.2, 6+ docs, INTEGRATION, протокол).

## Минусы

- Разрыв между витриной и реальностью: статические бейджи «links-317-valid», «tests-60-passed» и бодрый README против фактических 66/100 и 7 fallback-адаптеров.
- Ценность портала заперта в fallback-слепках: без механизма доставки реальных данных из репо-источников это скорее «музей экосистемы по состоянию на апрель 2026».
- Q6-координаты назначаются вручную и субъективно (таблица меток в pro2.py, паспорта); процедуры верификации/выведения координат нет — фундамент онтологии держится на авторской интуиции.
- Автоматизация умерла тихо: нет алерта на остановку sync-бота.
- Юридическая неопределённость (нет лицензии) блокирует любое внешнее переиспользование протокола, на которое проект явно претендует (авторегистрация чужих репо).

## Качество кода и документации

Код — аккуратный, идиоматичный Python: dataclasses, ABC, типизация (py.typed), докстринги на русском с примерами, разумная обработка ошибок (адаптеры не бросают исключения), HTML-экранирование против XSS, кэш с offline-режимом. Документация — выдающаяся по объёму и структуре для персонального проекта; протокольный документ близок к профессиональному стандарту. Слабые места: ручные статические бейджи, дублирование метрик между README/STATUS/снапшотами с расхождениями, отсутствие тестов у трети подсистем.

## Зрелость: 4/5

Обоснование: по инженерным атрибутам (тесты, CI, спецификация, Docker, автоматизация, SDK) это самый зрелый репозиторий профиля — твёрдая «4». До «5» не дотягивает из-за: отсутствия лицензии и упаковки, fallback-природы большинства данных (продукт не выполняет свою главную функцию «живого портала» без ручной подготовки окружения), остановившейся автоматизации и отсутствия внешних пользователей (1 звезда, 0 issues).

*Ограничение покрытия аудита: файлы читались выборочно через raw-доступ (~35 из ~90); тесты, mypy и CI локально не запускались; крупные docs (IMPLEMENTATION_STAGE_PART_1–4, INTEGRATION.md целиком) просмотрены частично.*
