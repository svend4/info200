# info150 — монорепо triage4: стек дистанционного триажа и 17 доменных адаптаций

## Обзор

Описание репозитория на GitHub — лаконичное «info med», но за ним скрывается один из самых крупных и инженерно зрелых проектов профиля svend4: **монорепозиторий из ~20 пакетов** вокруг флагманского исследовательского стека `triage4` — системы поддержки решений для автономного дистанционного триажа пострадавших (сценарии класса DARPA Triage Challenge Event 3).

Состав:

- **`triage4/`** — флагман: пайплайн perception → signatures → reasoning → handoff. Заявлено 130 Python-модулей и 759 тестов (в каталоге `tests/` — 99 файлов тестов; точное число тестов без запуска pytest не проверено, но порядок правдоподобен). Docker, systemd, nginx-шаблоны, Prometheus `/metrics`, SBOM-генератор, mutation-testing (mutmut), property-тесты (hypothesis), собственный CI-линтер запрещённых формулировок (claims-lint).
- **17 сиблингов `triage4-*`** — доменные copy-форки флагмана: дикая природа (wild/bird/fish), фитнес (fit/desk/stroll), телемедицина (clinic), уход за пожилыми (home), промбезопасность (site), ветеринария (pet), спасательные операции (rescue), животноводство (farm), безопасность на воде (aqua/coast), спорт (sport), мониторинг водителя (drive), безопасность толпы (crowd). Каждый — самостоятельный pip-пакет с тестами, Makefile, docs/PHILOSOPHY.md и опциональным Web UI (FastAPI + React/Vite/TS).
- **`biocore/`** — узкий «замороженный» слой общих утилит (4 модуля: `seeds`, `coords`, `text_guards`, `sms`), извлечённых только после того, как паттерн буквально повторился в ≥12 сиблингах.
- **`portal/`** — read-only слой координации между сиблингами по принципу «Не слияние — совместимость» (вдохновлён svend4/nautilus): типизированные мосты (6 видов `BridgeKind`) между отчётами сиблингов через добровольные адаптеры; пилоты — fish/bird/wild.
- **Замороженные архивы** — лог проектной ChatGPT-сессии от 2026-04-01 (477 КБ JSON, три формата) и `triage4_repo_v13.zip` (альтернативный SaaS-вариант, 84 модуля ~4500 LOC) с картой заимствований `V13_REUSE_MAP.md`.

## Назначение и идея

Идея трёхслойная и явно задокументирована в корневом README:

1. **Флагман + каталог сиблингов (углубление, независимость).** `triage4` решает задачу дистанционной оценки состояния пострадавших по видео/аудио/тепловизору: эйлерово усиление видео для пульса, FFT движения грудной клетки, акустические и позные сигнатуры, байесовский «цифровой двойник» пациента, CRDT-синхронизация в условиях отсутствия связи, правила Ларрея 1797 года как «живой» регрессионный baseline. Архитектурное правило: **сиблинги не импортируют друг друга** — каждый развивается вглубь как отдельное будущее приложение.
2. **`biocore` — механические извлечения.** Только байтово-идентичные утилиты, замороженный объём.
3. **`portal` — совместимость вместо слияния.** Портал ничего не извлекает и не меняет: читает `Report`/`Alert` сиблингов через адаптеры и находит межсиблинговые связи (co-occurrence, эскалации, географические/временные корреляты), которых не видит ни один сиблинг в одиночку.

Всюду подчёркнута рамка «research-grade decision-support, не медицинское устройство»: regulatory-документы (REGULATORY, SAFETY_CASE, RISK_REGISTER), claims-lint в CI блокирует запрещённые формулировки («diagnose», «FDA-cleared» и т.п.).

Концептуально проект — прямой наследник репозиториев профиля: **meta2** (структурные дескрипторы, фракталы, matching), **infom** (граф знаний), **in4n** (динамическая визуализация) — это зафиксировано в архивном дизайн-логе и в `triage4/LICENSES/`.

## Как устроено (архитектура)

- Единый ритуал для каждого пакета: `make install-dev → make qa → make demo` (у флагмана — `benchmark`); `qa` = ruff + mypy + pytest (+ claims-lint у флагмана).
- CI из двух workflow: `ci.yml` — глубокая проверка флагмана на Python 3.11 и 3.12 (линт, типы, тесты, полный бенчмарк, ~14 демо-скриптов как smoke-тесты); `qa.yml` — матрица из 16 пакетов (biocore + флагман + 14 сиблингов) плюс отдельный job портала с пилотными сиблингами. **Три новейших сиблинга (coast, desk, stroll) в матрицу CI не включены** — см. assessment.md.
- Web UI: у флагмана многостраничный React-интерфейс, у каждого сиблинга — опциональный (`pip install '<pkg>[ui]'`) FastAPI-дашборд + одностраничный React/Vite/TS-фронт.
- K3-матрица (сигнал/структура/динамика × тело/смысл/миссия) — концептуальная карта из 9 ячеек; по STATUS.md все 9 реализованы.

Подробное дерево — в [structure.md](structure.md).
