# info4 — коллекция Claude-скиллов и проект «базы методов» (псевдо-RAG)

## Обзор

**info4** — репозиторий-коллекция из ~101 готового скилла для Claude AI (файлы `.skill` — ZIP-архивы, каждый содержит `SKILL.md` с YAML-фронтматтером `name`/`description` и инструкциями в формате Anthropic Agent Skills), плюс обширная двуязычная (EN/RU) документация (~80 документов), 22 релизных ZIP-архива и подробно проработанный, но **не реализованный в коде** архитектурный проект превращения коллекции в «базу методов» для ИИ (авторский термин — «Pseudo-RAG»).

Описание репозитория на GitHub: «ИИ скиллы, база данных методов скилл, псевдо RAG». Языковая статистика GitHub (Python 71,7 %, Shell 28,3 %) обманчива: она учитывает только 3 служебных скрипта (~713 строк); фактически репозиторий на 99 % состоит из markdown-документов и бинарных ZIP-архивов.

## Назначение и идея

Проект решает две задачи:

1. **Каталог скиллов.** Собрать и категоризировать большую коллекцию скиллов для Claude: от базовых (организация файлов, обработка текста, конвертации) через офисную автоматизацию (PDF, Excel, email) и программирование (тест-генератор, git-ассистент, web-скрейпер) до DevOps (Docker, Kubernetes). Скиллы разложены по 4 уровням сложности + категории «special» (миграция чатов между сессиями, создание скиллов) и «other».

2. **Архитектурная идея «Skills как база методов» (Pseudo-RAG).** Ключевое концептуальное отличие от классического RAG: RAG ищет по запросу **ответы/контекст**, а «Method DB» ищет **методы/инструменты** — ИИ перед решением задачи запрашивает базу, получает список релевантных скиллов и композирует из них решение. Описаны два варианта: `VARIANT_1_EXTERNAL_SERVICE.md` (1 284 строки — скиллы как независимый микросервис с FastAPI, PostgreSQL, Redis, Kubernetes) и `VARIANT_2_METHOD_DATABASE.md` (1 107 строк — семантический поиск по методам), плюс гибрид (`COMPARISON_AND_HYBRID.md`, 814 строк). Всё это — только проектная документация, кода нет.

Отдельная сюжетная линия — **чекпойнты миграции между чатами** (skill `chat-migration-*` версий v1–v6 и скрипт `checkpoint_creator.py`): перенос контекста проекта из одной сессии Claude в следующую через структурированный пакет файлов. Версии v4.0 «Quantum», v5.0 «Cosmic» и v6.0 «Infinity» — откровенно спекулятивные/художественные (в `CHANGELOG.md` честно помечены как «NOT IMPLEMENTATION — vision/art project»).

## Как устроено (архитектура)

- **`skills/`** — 101 файл `.skill` в 6 папках: `level-1-basic` (22), `level-2-intermediate` (11), `level-3-advanced` (12), `level-4-professional` (12), `special` (15), `other` (29). Проверенный образец (`smart-file-organizer.skill`) — ZIP с единственным `SKILL.md` (~9 КБ): фронтматтер + сценарии использования; исполняемого кода внутри нет.
- **`docs/`** — ~80 документов: `en/` (40), `ru/` (14), `checkpoints/` (11, история версий v2.0–v6.0), `versions/`.
- **`scripts/`** — весь «код» проекта: `checkpoint_creator.py` (376 строк, CLI-генератор чекпойнт-пакета), `organize_skills.sh` (189 строк), `organize_docs.sh` (148 строк).
- **`releases/`** — 22 ZIP-архива (от `all-88-claude-skills.zip` 275 КБ до `MEGA_ARCHIVE_102_SKILLS_COMPLETE.zip` 688 КБ) с индексом.
- **`_archive/`** — описание старой плоской структуры.
- **Корень** — главная проблема: ~180 файлов старой плоской структуры (все `.skill`, `.zip` и ~70 md-документов) **остались в корне**, потому что реорганизация 2026-01-28 файлы *копировала, а не перемещала* (заявлено прямо в `FINAL_STATUS_COMPLETE.md`: «скопированы, не перемещены», «строк удалено: 0»). Контент задублирован.

Подробности — в [structure.md](structure.md).

## Статус и активность

Вся история — **один день: 28 января 2026** (22 коммита, PR #1–#6): загрузка файлов владельцем + автоматизированная ревизия/реорганизация Claude-агентом в ветке `claude/review-repository-7aBtE`. С тех пор (5+ месяцев на момент аудита) активности нет. Проект сам объявил себя завершённым (`PROJECT_COMPLETE_87_SKILLS_100_PERCENT.md`, `FINAL_STATUS_COMPLETE.md`), но собственные «следующие шаги» не выполнены: `README.md` так и остался заглушкой из двух строк («# info4 / info»), хотя готовый `README_NEW.md` (245 строк) лежит рядом; корень не расчищен; ни один из архитектурных вариантов не реализован. Issues: 0, звёзд: 1, форков: 0.

Репозиторий содержит собственные самоаудиты (`REPOSITORY_REVIEW.md` — оценка 6,8/10; `FINAL_STATUS_COMPLETE.md` — заявка 9,2/10 после реорганизации). Перепроверка показала: количественные заявления в основном честные (число строк архитектурных доков совпало с точностью до навигационных вставок, структура папок совпадает), но заявленный итог «полностью готово» не достигнут — см. [assessment.md](assessment.md).
