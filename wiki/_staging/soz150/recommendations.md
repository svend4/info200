## Серьёзные доработки

1. **Загрузить полную кодовую базу v50/v14**: 35 отсутствующих панелей + модули `db`, `store`, `hooks`, `components`, `security/`, `rag/` + `package.json` и конфиг сборки. Пока их нет, `wos-v14/` — мёртвый фрагмент. Заодно исправить `lazy(() => import(path))` с переменным путём на статические импорты или `import.meta.glob` — иначе Vite не соберёт ленивые чанки.
2. **Тесты для детерминированной логики**: regex-правила `ASSERTION_RULES`, `detectLegalDocType`, расчёт сроков (§64 SGG, +3 дня §37 SGB X) — это чистые функции, покрываются unit-тестами за день и защищают самое юридически чувствительное место.
3. **Рефакторинг состояния артефакта**: 14+ `useState` → `useReducer`/Zustand (план уже есть в handoff, «Приоритет 4»).
4. **Единый слой хранения** в v14: перевести localStorage-хранилища (`wos-gutachten`, `wos-fristen`, …) на IndexedDB рядом с `Cases`/`Documents`, добавить экспорт/бэкап всех данных одним файлом.
5. **Роутер на эмбеддингах** (handoff, «Приоритет 3a»): Transformers.js + multilingual-e5-small вместо LLM-вызова — ~20 мс вместо ~800 мс, детерминированно, офлайн, без расхода токенов.

## Варианты продолжения

**Сценарий А. «Личный правовой комбайн» — довести v50 до ежедневного инструмента.**
Считать главной линией модульное PWA-приложение: перенести полный исходник, собрать, закрепить сборку в CI, настроить автобэкап IndexedDB. Артефакт v1.4 при этом становится «AI-ядром» — его CAGE-пайплайн и Assertion Checker встраиваются в панель AI приложения. Результат — офлайн-первый персональный кейс-менеджер по социальному праву с ИИ-генерацией и проверкой документов; целевой пользователь — сам автор и его текущие дела (S 6 SO 58/26 ER и др.).

**Сценарий Б. «Открытый инструмент для Betroffene» — публичный продукт для получателей Persönliches Budget.**
Ниша реально пуста: люди с инвалидностью в Германии, ведущие споры по §29 SGB IX без адвоката. Вычистить персональные данные из кода, добавить лицензию и дисклеймер, немецкую локализацию UI, упаковать v14 как устанавливаемое PWA. Ценность продукта — не ИИ, а зашитая экспертиза (типовые ошибки MDK, шаблоны с §§, калькулятор сроков), работающая офлайн. ИИ-функции сделать опциональными (свой ключ API).

**Сценарий В. «CAGE как фреймворк» — извлечь домен-независимое ядро.**
В артефакте главное — переносимый паттерн: роутер → инжекция skills → генерация → исполнение → доменный assertion-checker → auto-retry. Извлечь его в маленькую библиотеку (`cage-core`), где домен задаётся пакетом skills и набором assertion-правил; немецкое право — первый reference-домен. Тогда те же механики применимы к медицине (info150), магазинам (data40/daten23) и др. Таксономия L0–L5 из handoff — готовый манифест такого фреймворка.

**Сценарий Г (минимальный). «Заморозить как архив».**
Если работа продолжается в другом месте — привести репозиторий в честное архивное состояние: README с пометкой «снапшот от 13.04.2026, актуальная разработка — там-то», удалить zip, пометить репозиторий archived. Дешёво и снимает путаницу для будущего себя.

## Сочетания с другими репозиториями профиля

1. **soz150 + data4 («Soz соц апп — программ перс бюджет»)** → единственный в своём роде «социально-правовой комбайн» для Persönliches Budget. Оба проекта — про один и тот же домен с двух сторон: data4 ведёт бюджет/финансы ПБ, soz150 — правовую борьбу за него (Widerspruch, сроки, Gutachten, письма в KSV). Объединение даёт замкнутый цикл: расчёт бюджета → заявление → отслеживание Bescheid → автоматический Widerspruch с аргументами из базы ошибок MDK → учёт часов ассистентов. Такого продукта на рынке нет.
2. **soz150 + info4 («база данных ИИ-скиллов»)** → «скилловая ОС» профиля. Skill Composer из Writing OS умеет генерировать skills диалогом, а info4 — систематизировать методы/скиллы. Скрестить: общий реестр skills (формат `id/desc/triggers/ctx` уже задан в soz150), который семантический роутер CAGE подключает в любом приложении профиля. Инновация — переносимые «навыки» как данные, а не код: один реестр обслуживает и право, и медицину (info150), и магазины.
3. **soz150 + infom (ГрафРАГ) / in4n (динамический граф)** → юридический GraphRAG. В roadmap soz150 прямо описан «Case Knowledge Graph» (дела ↔ нормы §§ ↔ прецеденты BSG с рёбрами governed_by/cites). infom даёт технологию графового RAG: роутер вместо плоского поиска обходит граф и собирает контекст «норма + прецедент + похожее дело». Получается нишевый GraphRAG по немецкому социальному праву — исследовательски свежая комбинация.
4. **soz150 + daten22 (offline search, SQLite FTS4)** → офлайн-справочник SGB/BSG внутри PWA: полнотекстовый поиск по текстам законов и решениям BSG без сети — усиливает офлайн-первую философию v14 и снимает зависимость Legal Research-скилла от LLM.
5. **soz150 + info40 (AI Agent Orchestration Platform)** → CAGE-пайплайн как один из управляемых агентов оркестратора: длинные юридические процессы (сбор фактов → анализ Bescheid → генерация → проверка → отправка) становятся многошаговыми оркестрируемыми workflow, а не одним чатом.
