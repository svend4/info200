# soz150 — Writing OS: ИИ-среда для немецкой социально-правовой документации

## Обзор

**soz150** — репозиторий-«перевалочный пункт» проекта **Writing OS** — ИИ-системы для работы с немецкой социально-правовой документацией (SGB IX/XII, SGG: Widerspruch, Klage, Eilantrag, Persönliches Budget). Описание репозитория: «info соц, writing os, социально-юридическое приложение».

В репозитории лежат **две разные кодовые базы под одним именем «Writing OS»**:

1. **`WritingOS (5).jsx`** (2043 строки, ~110 КБ) — самодостаточный React-артефакт для claude.ai: «Writing OS Unified v1.4». Это AI-песочница по паттерну **CAGE** (Context-Augmented Generative Execution): семантический LLM-роутер выбирает 1–3 «скилла» из базы, контекст скилла инжектируется в system prompt, Claude генерирует код, код исполняется в браузере (JS через `new Function`, Python через Pyodide WASM), при ошибке — auto-retry (до 2 попыток), а юридические документы автоматически проверяются двухуровневым **Legal Assertion Checker** (L1 — regex-структурный, L2 — семантический через стриминг Claude).

2. **`wos-v14/`** — **фрагмент** гораздо более крупного приложения «Writing OS v50 — App.jsx v14 (38 панелей)»: локальный PWA-комбайн для ведения социально-правовых дел (Akten, сроки/Fristen, Widerspruch-ассистент, OCR, RAG-поиск, переводчик, бюджет Persönliches Budget, учёт часов ассистентов и т.д.). В репозитории есть только `App.jsx` (176 строк) и **3 из 38 панелей**; остальные 35 панелей и все базовые модули (`db`, `store`, `hooks`, `security/`, `rag/`) в репозитории **отсутствуют** — проект в таком виде не собирается.

Плюс подробный handoff-документ `WRITING_OS_HANDOFF (1).md` (514 строк) — качественная передаточная документация по артефакту №1.

## Назначение и идея

Практическая цель — помощь в реальных делах по немецкому социальному праву: Persönliches Budget (§29 SGB IX), Eingliederungshilfe, споры с KSV Sachsen и Sozialgericht (в коде фигурируют реальные номера дел вида «S 6 SO 58/26 ER»). Идея Writing OS: пользователь пишет намерение на русском/немецком/английском → система сама подбирает юридическую «экспертизу» (skills с §§ и прецедентами BSG), генерирует документ или расчёт срока, исполняет код и **проверяет юридическую корректность** результата (наличие Az., Frist, Begründung, ссылок на §§ SGG и т.п.). Это редкое сочетание: генеративная песочница кода + доменная юридическая валидация.

Репозиторий при этом выполняет роль хранилища снапшотов для передачи между чат-сессиями Claude (имена файлов « (1)», « (5)» — типичные суффиксы браузерных загрузок), а не полноценного дома проекта.

## Как устроено (архитектура)

Пайплайн артефакта «Writing OS Unified» (из handoff, подтверждено кодом):

```
Ввод пользователя
  → [1] Semantic Router      (LLM-вызов, ~800 мс) — выбор 1–3 skills из 10 встроенных + пользовательских
  → [2] Context Injection    (buildSysPrompt)     — skill.ctx в system prompt
  → [3] Main LLM call        (SSE-стриминг)       — генерация кода/документа
  → [4] Code Execution       (JS / Pyodide WASM)  — исполнение в браузере
  → [5] Auto-retry loop      (макс. 2 попытки)    — автоисправление ошибок
  → [6] Legal Assertion Check (L1 regex + L2 LLM) — итог: 0.4*L1 + 0.6*L2
```

Встроенные skills: Deadline Calc (§84/§87 SGG), Court Analyzer, Template Generator, Persönliches Budget (§29 SGB IX), SGB XII Expert, Eilantrag §86b, Code Sandbox, Data Analysis, Legal Research (BSG), Document Writer. Есть Skill Composer — создание новых skills диалогом с Claude, хранение в localStorage; сессии Python-неймспейса сохраняются в файлы `.wos`.

Приложение `wos-v14` устроено иначе: offline-first PWA с PIN-блокировкой (LockScreen + auto-lock), 3 темами, hot-keys (Alt+клавиша на каждую из 38 вкладок), IndexedDB (`Cases`, `Documents`), локальным RAG (эмбеддер + векторное хранилище в браузере), service worker. Присутствующие панели: генератор официальных писем в органы (Sachstandsanfrage, Akteneinsicht §25 SGB X, Mahnung/§88 SGG…), трекер медицинских заключений (MDK/GdB/EGH с базой типовых ошибок MDK для Widerspruch) и аналитика на Recharts.
