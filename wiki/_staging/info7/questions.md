# Вопросы к info7

## 1. Почему проект помечен «Production Ready / 99.5% / tested», если в нём нет ни одного теста, а сборка сломана?

Аудит установил: 0 файлов `*.test.ts`, нет CI, `packages/info7` без package.json, битый экспорт в `leonardo-ai/src/index.ts`, `npm install` из README не работает из-за `workspace:*`. При этом README, FINAL_STATUS.md и SYSTEM_AUDIT.md дают три разных статуса (99.5% / 100% / 92%).

**Варианты ответов:**
- А. Статусы писал ИИ в ходе сессии, автор их не проверял — это артефакт генерации.
- Б. «Production ready» задумывалось как цель/маркетинг витрины, а не констатация.
- В. Автор считал, что успешная генерация кода = готовность, и о поломках не знал.

**Варианты дальнейших действий:**
- При А: ввести правило для всех репо профиля — статусные бейджи ставятся только после зелёного CI; в info7 заменить бейджи на «experimental».
- При Б: разделить в README «Vision» и «Current state»; текущее состояние описать по данным этого аудита.
- При В: настроить smoke-CI (pnpm install + build) — он немедленно покажет реальную готовность; починить два найденных дефекта сборки.

## 2. Какова судьба проекта: он завершён, заморожен или ждёт продолжения?

Вся история — 101 коммит за 3 дня (5–7 февраля 2026), затем 5 месяцев тишины. Последний коммит совпадает с объявлением «100% Complete».

**Варианты ответов:**
- А. Проект — разовый эксперимент по генерации большой системы с Claude; продолжения не планируется.
- Б. Это пауза; платформу планируется развивать.
- В. Идеи перенесены/переносятся в другие репо (info40, info100 и др.).

**Варианты дальнейших действий:**
- При А: пометить репо как архив (GitHub archive), в README — честный итог эксперимента; ценность останется как референс архитектуры.
- При Б: начать со сценария «Честный минимум» из рекомендаций (починка сборки, тесты, один пакет на npm).
- При В: добавить в README указатель «продолжение в …», а enterprise-слой и граф знаний перенести в целевой репозиторий, чтобы код не пропал.

## 3. Где обещанный «бот» и связь с OpenClaw? Является ли OpenClaw реальным внешним проектом?

Описание репозитория обещает «оркестратор и бот», но бота в коде нет. Документы (ARCHITECTURE.md, openclaw-security) описывают «OpenClaw/Moltbot» с «500+ community skills» и «230+ вредоносными скиллами» с ущербом $2.3M — без проверяемых источников.

**Варианты ответов:**
- А. OpenClaw — реальный внешний проект (или его форк/аналог), цифры взяты из его экосистемы.
- Б. OpenClaw в этом репо — вымышленная/модельная система для сравнительного анализа, цифры сценарные.
- В. Бот существует в другом репозитории профиля (например, infon/robot).

**Варианты дальнейших действий:**
- При А: добавить в SECURITY_AUDIT.md ссылки на источники; тогда sandbox-пакет стоит развивать как реальный инструмент (заменив vm2).
- При Б: явно пометить документы как thought experiment, чтобы аудиторы и читатели не принимали цифры за факты.
- При В: связать репозитории ссылками и вынести бот-адаптер к meta-agent-coordinator в общий пакет.

## 4. Планировалась ли реальная LLM-интеграция агентов, и как быть с медицинским/психологическим доменами?

Все 10 «профессиональных агентов» — правила и захардкоженные таблицы; ни одного вызова LLM. При этом medical-diagnosis-assistant и mental-health-counselor выдают «оценки срочности» и «рекомендации», что при заявке «production» несёт этические и юридические риски.

**Варианты ответов:**
- А. Да, LLM-слой планировался следующим этапом; правила — каркас.
- Б. Нет, задумка именно rule-based (детерминированность, отсутствие затрат на API).
- В. Медицинские/психологические агенты — демо предметной модели, не для использования.

**Варианты дальнейших действий:**
- При А: добавить LLM-слой сначала в 1–2 «безопасных» агента (career, home-manager); для health-агентов — дисклеймеры и отказ от диагнозов.
- При Б: убрать слова «AI» из описаний агентов и позиционировать их как экспертные системы; усилить таблицы знаний.
- При В: пометить папки healthcare/care дисклеймером «not for real use» прямо в README пакетов.

## 5. Почему в монорепо одновременно npm workspaces и pnpm, и каким инструментом он собирался хоть раз?

Корневые скрипты — `npm run … --workspaces`, но зависимости объявлены через `workspace:*` (протокол pnpm/yarn), а `packages/info7` вовсе не пакет. Похоже, полная сборка ни разу не запускалась.

**Варианты ответов:**
- А. Сборка ни разу не запускалась целиком — код проверялся только на уровне генерации.
- Б. Использовался pnpm локально, README с npm — ошибка.
- В. Пакеты собирались по одному, поэтому конфликт не всплывал.

**Варианты дальнейших действий:**
- При А: минимальный CI-workflow немедленно; исправление найденных дефектов; фиксация lock-файла.
- При Б: заменить инструкции на pnpm, добавить `packageManager: "pnpm@x"` в корневой package.json.
- При В: тем более нужен корневой интеграционный build в CI, т.к. пакеты зависят друг от друга через @info7/common.

## 6. Осознан ли выбор vm2 для «security»-пакета?

@openclaw/sandbox зависит от `vm2 ^3.9.19` — библиотека официально прекращена в 2023 из-за неустранимых sandbox-escape уязвимостей (в т.ч. CVE-2023-37466). Для пакета, чья единственная миссия — безопасность, это дисквалифицирующая зависимость.

**Варианты ответов:**
- А. Не знал о статусе vm2 — выбор сделала модель по старым данным.
- Б. Знал, но это концепт: важно было показать архитектуру sandbox, а не защиту.
- В. Планировалась замена (isolated-vm / worker_threads), руки не дошли.

**Варианты дальнейших действий:**
- При А или В: заменить на isolated-vm или Node permission model + worker_threads; добавить эксплойт-тесты.
- При Б: добавить в README пакета жирное предупреждение «insecure by design, do not use», иначе название «security» вводит в заблуждение.

## 7. Что из четырёх подсистем автор считает ядром, ради которого репозиторий стоит поддерживать?

Оркестратор (openclaw-meta-agents), граф знаний (info7), Leonardo AI и enterprise-kit — четыре разнонаправленные системы; поддерживать все одному человеку нереалистично.

**Варианты ответов:**
- А. Оркестратор — он же перекликается с info40 и описанием репозитория.
- Б. Граф знаний — общая «память» для всех агентных проектов профиля.
- В. Leonardo AI — исследовательский интерес (RL + RAG + «сознание»).
- Г. Ценность именно в интеграции всех четырёх.

**Варианты дальнейших действий:**
- При А: сценарий «Честный минимум» (см. рекомендации), остальное — frozen.
- При Б: скрестить с infom (ГрафРАГ) и вынести в отдельный переиспользуемый пакет.
- При В: оформить Leonardo как research-репо с ноутбуками/экспериментами и метриками обучения.
- При Г: тогда обязателен один сквозной работающий demo-сценарий (сценарий 2 рекомендаций), иначе интеграция остаётся декларацией.
