## Варианты продолжения (сценарии)

### Сценарий 1. «Честный минимум»: рабочий оркестратор-библиотека
Сузить проект до одного npm-пакета `@info7/openclaw-meta-agents` (иерархия, декомпозиция задач, выбор агентов — самая законченная часть кода). Починить сборку, написать тесты, опубликовать на npm с честным README «hierarchical task orchestration toolkit, experimental». Остальные пакеты пометить как frozen. Это превращает репозиторий из «витрины» в маленький, но настоящий продукт за 1–2 недели работы.

### Сценарий 2. «Платформа с одним живым сценарием»
Не сокращать состав, но довести один сквозной сценарий до реального исполнения: Telegram-бот принимает задачу → meta-agent-coordinator декомпозирует → career-counselor (с LLM-вызовом) отвечает → результат и опыт пишутся в граф знаний → RAG обогащает следующий запрос. Один work-flow, который реально запускается командой `pnpm demo`, докажет жизнеспособность всей архитектуры и даст материал для честного «status: alpha».

### Сценарий 3. «Исследовательский артефакт + слияние с info40»
Признать info7 исследовательским прототипом (какими являются его 38 документов) и перенести лучшие части в info40 («AI Agent Orchestration Platform, Production» — судя по описанию, та же предметная область): из info7 взять enterprise-слой (multi-tenancy, RBAC, audit) и граф знаний, из info40 — производственную основу. info7 остаётся архивом с указателем «продолжение в info40», дублирование в профиле исчезает.

### Сценарий 4. «Security-спинофф»
Выделить openclaw-security в отдельный репозиторий и сделать его настоящим: заменить vm2 на isolated-vm, написать эксплойт-тесты (timeout, память, сеть, escape-попытки), оформить как универсальный «skill sandbox» для любых агентных платформ. Тема изоляции исполнения скиллов агентов сейчас востребована, и это самый рыночный кусок репозитория — при условии избавления от уязвимого фундамента.

## Сочетания с другими репозиториями профиля

1. **info7 + infom (ГрафРАГ) = граф знаний с настоящей семантикой.** У info7 есть добротный каркас графа (9 типов узлов, 12 типов связей, обход, центральность), но эмбеддинги — заглушка из char-кодов. У infom — тематика GraphRAG. Скрестив их (движок графа из info7 + реальный retrieval/эмбеддинги по методике infom), получится уникальный для профиля компонент: «активная база знаний» с гибридным поиском (графовые пути + векторная близость), которую можно подключать ко всем агентным репо профиля как общую память.

2. **info7 + info40 (AI Agent Orchestration Platform, Production) = единая зрелая платформа оркестрации.** Два репозитория решают одну задачу с разных концов: info40 позиционируется как production-платформа, info7 несёт уникальные слои, которых обычно нет в прототипах — multi-tenancy, RBAC, audit-log и 5-уровневую иерархию агентов. Перенос enterprise-слоя info7 в info40 даёт редкую комбинацию: открытая оркестрация агентов с мультиарендностью «из коробки» — то, чем не могут похвастаться большинство OSS-оркестраторов.

3. **info7 + info100 (лаборатория агентов) = полигон для доменных агентов.** 10 профессиональных агентов info7 (юрист, медик, финансист и т.д.) сейчас никогда не исполнялись. Если info100 — «лаборатория агентов», то из связки получается инновационный evaluation-стенд: лаборатория прогоняет агентов info7 по сценарным наборам (кейсы из example-файлов уже готовы — 5,7 тыс. строк сценариев), меряет качество через метрики @info7/common и пишет результаты в граф знаний. Итог — бенчмарк доменных агентов, воспроизводимый и расширяемый.

4. **info7 + meta1 (Continuum, детерминированный рантайм) = воспроизводимая оркестрация.** Главная беда мультиагентных систем — недетерминизм. Если исполнять иерархию meta-agents info7 внутри детерминированного рантайма meta1 (фиксированные seed, журналирование шагов), получится редкая вещь: multi-agent workflow с полным replay — любой прогон можно воспроизвести бит-в-бит для отладки и аудита решений «сознательного слоя» Leonardo.

5. **info7 + daten4 (динамический планировщик) = планировщик, который учится.** Task-decomposer в info7 статичен (шаблоны декомпозиции), daten4 занимается динамическим планированием. Объединение — декомпозиция задач, перестраиваемая на лету по опыту из RL-контура Leonardo (experience buffer уже накапливает исходы) — даёт самонастраивающийся планировщик задач, уникальный среди репо профиля.
