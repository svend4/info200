# Вопросы к in4n

## 1. Какой из трёх вариантов (1-browser / 2-react / 3-obsidian) считается главным направлением?

Функциональность разошлась: игра и редактор — только в прототипе, эпохи и семантический зум — только в React, реальные данные — только в Obsidian. Развивать три ветки параллельно дорого.

**Варианты ответов:**
- А. Плагин Obsidian — путь к реальным пользователям.
- Б. React-версия — основа будущего веб-продукта.
- В. Браузерный прототип — площадка экспериментов, остальное вторично.
- Г. Все три равноценны, это осознанный «веер» вариантов.

**Варианты дальнейших действий:**
- При А: перенести лучшие режимы прототипа в плагин, оптимизировать под большие хранилища, готовить публикацию в каталог Obsidian (см. сценарий А в [рекомендациях](recommendations.md)).
- При Б: выделить общее ядро, доделать геймификацию React-версии (счёт, playScore), деплой на Pages/Vercel.
- При В: консервировать React и Obsidian как замороженные, все новые режимы делать в index.html.
- При Г: тогда обязательно выделить общий `core/`-модуль, иначе тройное дублирование продолжит расползаться.

**Варианты дальнейших действий:**

## 3. Планируется ли публикация плагина в каталоге сообщества Obsidian?

Плагин рабочий по коду и близок к публикуемому состоянию, но нет LICENSE, versions.json, автор в manifest — заглушка «InfoAquarium», и есть мёртвый Voronoi-код.

**Варианты ответов:**
- А. Да, публикация — цель.
- Б. Нет, плагин только для личного хранилища.
- В. Не решено.

**Варианты дальнейших действий:**
- При А: чек-лист публикации: LICENSE, versions.json, manifest (author/authorUrl), README плагина со скриншотами, производительность на 1000+ заметок, релиз с main.js — затем PR в obsidian-releases.
- При Б: минимум — инструкция ручной установки и фикс Voronoi; производительность оптимизировать по мере роста собственного хранилища.
- При В: дешёвый тест спроса — выложить demo-GIF в сообществах Obsidian и посмотреть реакцию, прежде чем вкладываться.

## 4. Voronoi-режим в Obsidian-плагине сейчас мёртв (d3-delaunay не бандлится) — чинить или убрать?

Клавиша V в плагине проверяет `globalThis.d3?.Delaunay`, которого в Obsidian никогда нет — ветка не выполняется. Это единственный найденный «тихий» дефект.

**Варианты ответов:**
- А. Чинить: добавить d3-delaunay в dependencies — esbuild сбандлит.
- Б. Убрать ветку и упоминание режима — меньше кода, меньше сюрпризов.
- В. Оставить как есть (не мешает).

**Варианты дальнейших действий:**
- При А: `npm i d3-delaunay` + `import {Delaunay} from 'd3-delaunay'` вместо globalThis — 15 минут; заодно перевести браузерный прототип с CDN на локальные копии.
- При Б: удалить ~15 строк в `main.ts` и хоткей V из плагина.
- При В: как минимум задокументировать в коде, что режим требует внешнего d3 и в Obsidian не работает, чтобы следующий аудит не считал это багом.

## 5. Каков целевой источник данных за пределами демо-графа из 12–15 понятий?

Браузерная и React-версии работают только на захардкоженных «философских» понятиях. Ценность системы проявится на реальных данных.

**Варианты ответов:**
- А. Заметки Obsidian (уже работает) — этого достаточно.
- Б. Базы знаний профиля: lorenzo (~2815 md), info30, info15 и др.
- В. Произвольный JSON/API — нужен формат импорта.
- Г. Демо-данных достаточно, проект про визуальную механику, а не про данные.

**Варианты дальнейших действий:**
- При А: сфокусироваться на сценарии А (плагин), производительность в приоритет.
- При Б: написать Node-скрипт «markdown-папка → graph JSON» и загрузчик в React-версии — сразу появится флагманское демо на 2815 узлов (идея сочетания №1 в [рекомендациях](recommendations.md)).
- При В: спецификация формата (nodes/links/groups/eras) + drag-n-drop загрузка JSON в React-версии.
- При Г: усилить арт-направление (сценарий Б): пресеты графов, сохранение из редактора, скринсейвер-режим.
