# Характеристика и оценка data50

## Что есть

- **Один качественный аналитический обзор** — `review-habr-article.md`: структурированный разбор реального кейса (ИИ-клон CTO Extreme Networks) с источником, датами, таблицей метрик (80% ревью на ИИ, рост совпадения стиля с 50% до 85–90% за 7–8 месяцев), балансом «плюсы/риски» и выводами. Для одиночного документа — добротная работа: есть ссылка на первоисточник (habr.com/ru/news/992546/), факты отделены от анализа.
- **Минимальный README** — формально присутствует, но содержит лишь заголовок и слово «info».
- **Рабочий процесс через PR**: обзор добавлен ИИ-агентом (автор коммита `claude`, ветка `claude/review-habr-article-Mc4AC`) и влит владельцем через PR #1 — репозиторий использовался как полигон связки «Claude → PR → merge».
- Заявленная тема («аи аватары») в единственном файле действительно раскрывается — расхождения описания с содержимым нет, но и глубины нет: тема представлена одним документом.

## Чего нет

- **Кода** — вообще (репозиторий чисто документный).
- **Тестов и CI** — нечего тестировать, workflows отсутствуют.
- **Лицензии** — нет `LICENSE`; формально контент «all rights reserved».
- **Документации проекта** — README не объясняет ни цель, ни планы, ни как пополнять репозиторий.
- **Структуры для роста** — нет папок (`reviews/`), индекса обзоров, шаблона обзора, фронтматтера/тегов.
- **Второго и последующих материалов** — база знаний по ИИ-аватарам закончилась на первой записи.
- **Самоаудитов/отчётов** — в отличие от ряда других репозиториев профиля, здесь нет файлов статуса; перепроверять внутренние заявления не пришлось. Внешние заявления (описание «info, аи аватары») соответствуют содержимому, но масштаб — один файл.

## Плюсы

- Единственный содержательный файл сделан аккуратно: структура, метрики, источник, дата, сбалансированный анализ рисков (прозрачность, предвзятость, масштабируемость).
- Тема актуальная и узкая — «цифровые двойники руководителей» — потенциально хорошая ниша для тематической базы знаний.
- Чистая история без мусора; понятный PR-процесс добавления контента.
- Хорошо стыкуется с другими «info»-репозиториями профиля (см. рекомендации): может стать тематическим разделом общего хаба.

## Минусы

- Репозиторий **почти пуст**: 2 файла, 3 коммита, одна тема — «база знаний» из одной записи.
- README-заглушка не даёт ни контекста, ни навигации; название data50 неинформативно.
- Смешение языков: описание по-русски, контент по-английски — не определена целевая аудитория.
- Нет лицензии — переиспользование обзора формально ограничено.
- Активность угасла: контент — февраль 2026, затем только мердж в апреле 2026; признаков продолжения нет.
- Дублирование функции с другими репозиториями профиля (information — «новости», data70 — «много тем»): непонятно, зачем отдельный репозиторий под одну статью.

## Качество кода и документации

Кода нет — оценивается только документация. Единственный обзор — **хорошего качества** (чёткая структура, таблица, ссылки, датировка, критический анализ), но это разовый артефакт генерации, а не система. Проектная документация — **отсутствует** (README-заглушка). Соглашений об оформлении, шаблонов и метаданных нет.

## Зрелость: 1/5

Обоснование: репозиторий находится на стадии «первая проба» — есть один аккуратный документ и ничего вокруг него: ни цели в README, ни структуры, ни лицензии, ни продолжения за ~5 месяцев (февраль–июль 2026). Единица, а не ноль — потому что единственный артефакт содержателен, тема заявлена и подтверждена, а история чистая. Для повышения до 2/5 достаточно внятного README, папочной структуры и 3–5 новых обзоров; до 3/5 — регулярного пополнения и индекса.

*Ограничения покрытия аудита: репозиторий прочитан полностью (оба файла), история коммитов и ветки проверены по страницам GitHub; список issues отдельно не просматривался (при 3 коммитах и 1 PR существенных скрытых артефактов не ожидается — не проверено).*
