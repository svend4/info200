# Характеристика и оценка daten

Аудит-перепроверка: репозиторий исследован через листинги GitHub и чтение ~25 ключевых файлов (обе точки входа, конфиги деплоя, CI, сервисы, тесты, все самоаудиты). Полный клон недоступен (прокси), поэтому точные подсчёты строк/файлов не выполнялись — количественные заявления репозитория проверены выборочно и помечены ниже.

## Что есть (реально сделано)

- **Запускаемый bootstrap-бэкенд** (`ios_bootstrap/main.py`): FastAPI с /health, /api/status, Swagger/ReDoc, глобальным обработчиком ошибок, CORS и раздачей React SPA. Код чистый и самодостаточный; 7 интеграционных тестов (`test_basic.py`) выглядят проходимыми.
- **«Полный» бэкенд-каркас** (`main_production.py`, ~450+ строк): продуманный жизненный цикл приложения (EventBus → БД → Redis → IOSRoot → сервисы → мониторинг → событийные подписки), 7 API-роутеров, middleware (error handler, rate limiter, request logger, security headers), health-checker на 11 КБ.
- **Фронтенд**: полноценный React 18 + TypeScript + Vite + Tailwind проект с современным стеком (react-query, zustand, zod, recharts) и 30+ страницами в 9 разделах (documents, search, semantic search, graph, analytics, security, api, admin, collaboration, ai) — добавлены итерациями «Etap 1–7» 16.12.2025.
- **Инфраструктура деплоя**: два двухстадийных Dockerfile, 4 railway-конфига, Procfile, `start_fullstack.py`, docker-compose.production.yml, healthcheck'и — деплой на Railway явно был доведён как минимум до стадии отладки (метки времени сборки в Dockerfile.fullstack).
- **Честные самоаудиты**: `AUDIT_ANALYSIS.md` прямо фиксирует «gap 65–75% между документацией и кодом» — перепроверка это ПОДТВЕРЖДАЕТ (см. ниже).
- **Архив-источник**: ~1118 файлов, извлечённых из конверсации в 182 сообщения, с индексом INDEX.md и прослеживаемостью до исходного сообщения (выборочно проверено: высокономерные файлы вроде `services/msg173_343.md` существуют).

## Чего нет

- **Работающего поиска** — главной заявленной функции: `SearchService.search()` возвращает `[]`; Whoosh/Elasticsearch из requirements.txt нигде не подключены к приложению.
- **Работающей БД в приложении**: в bootstrap подключение БД — TODO в коде; заявленный STATUS.md Level 1 (Database) — 0%; Alembic-миграций нет.
- **Рабочего CI**: `ci.yml` существует, но все джобы ссылаются на переименованный каталог `информационная-ОС` → CI гарантированно падает (проверено: старого пути нет, 404).
- **Лицензии** — файла LICENSE нет.
- **Актуального README**: корневой README описывает удалённые файлы (conversations.json, projects.json, users.json, memories.json, zip, папка туристическое-агентство — все 404).
- **Реальной аутентификации/безопасности**: пароли открытым текстом в коде (`admin123`/`demo123`), сессии в словаре в памяти, secret key по умолчанию «change-this-in-production».
- **Пригодных «комплексных» тестов**: `tests/test_backend_comprehensive.py` импортирует `ios_system.main` — модуль с таким путём в репозитории отсутствует (каталог называется `IOS-System`, файл — `main_production.py`), то есть тесты, скорее всего, не запускаются (запуск не проводился — помечено как сильное подозрение, не факт).
- **Интеграции архива с каркасом**: декларированный принцип «использовать существующий код из IOS-System» не реализован — каркас msg-файлы не импортирует.
- **Данных**: исходные JSON-экспорты удалены из репозитория, реальным корпусом документов система не наполнялась (в API — 3 демо-документа).

## Плюсы

1. Редкая для профиля **самокритичность**: собственный аудит выявил и задокументировал разрыв «документация vs код» ещё до внешней проверки.
2. **Грамотная инкрементальная стратегия** (Level 0–5, bootstrap-обёртка, фичефлаги) — методологически это один из самых зрелых подходов в профиле.
3. **Современный, связный стек**: FastAPI + pydantic-settings + SQLAlchemy async + Redis / React + Vite + Tailwind + react-query — выбор без экзотики.
4. **Деплой продуман до деталей**: два режима (bootstrap/fullstack), healthcheck'и, обработка $PORT Railway, SPA-fallback.
5. **Прослеживаемость архива**: схема msgNNN_NNN + INDEX.md позволяют найти происхождение любого фрагмента.
6. **Обширная документация** (9+ md-руководств: QUICKSTART, BOOTSTRAP_GUIDE, DEPLOYMENT, RAILWAY_*, STATUS, планы).

## Минусы

1. **Функциональное ядро — заглушки**: поиск, граф знаний, классификация возвращают пустоту; «полный режим» — это красивый корпус без двигателя.
2. **Рассинхронизация документации с реальностью в обе стороны**: корневой README отстал (описывает удалённое), STATUS.md отстал (не знает о 30+ страницах фронтенда, «11 TS-файлов» давно неверно), QUICKSTART и CI ссылаются на несуществующий путь.
3. **Мёртвый груз ~1118 msg-файлов** (включая .txt-обрывки, Kotlin-фрагменты, фиктивные «недельные отчёты») раздувает репозиторий и вводит в заблуждение статистику языков.
4. **Захардкоженные учётные данные и демо-сессии** в `api/routes.py` — приемлемо для демо, опасно при реальном деплое.
5. **Проект в спячке**: последняя разработка 16.12.2025, после — лишь тестовая заметка 12.01.2026; план MVP «4–8 недель» не стартовал (Level 1 = 0% спустя полгода).
6. **Дублирование конфигураций деплоя** (4 railway-файла + Procfile + 2 Dockerfile) без указания, какой актуален.

## Качество кода и документации

- **Код каркаса** — аккуратный: типизация, docstring'и (рус./англ.), логирование, разумная структура модулей. Но глубина минимальна — большинство «сервисов» по 50–80 строк заглушечного кода.
- **Код архива** — не оценивался целиком (фрагменты из чата, смесь форматов); по выборке это черновики разной степени готовности.
- **Тесты**: bootstrap-тесты (7 шт.) осмысленные; «комплексные» тесты каркаса написаны под несуществующую структуру пакета.
- **Документация** — объёмная и хорошо структурированная, но частично фиктивная (недельные отчёты из конверсации) и частично устаревшая (README, QUICKSTART, CI-пути). Самоаудиты — лучшая её часть.

## Зрелость: 2/5

**Обоснование**: репозиторий заметно выше «свалки заметок» — есть запускаемое приложение, деплой-инфраструктура, тесты Level 0, фронтенд и образцовые самоаудиты (за методологию — плюс балл). Но до 3/5 не дотягивает: ключевая функциональность — заглушки и демо-данные, CI сломан, README лжёт о содержимом, тесты каркаса неисполнимы, а разработка остановилась на первом же уровне плана полгода назад.
