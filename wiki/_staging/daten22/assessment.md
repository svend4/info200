# Характеристика и оценка daten22

## Что есть

- **Полная база знаний MBTI на русском**: 47 документов в `docs/` (42 тематических + 5 по теории архетипов) и 16 портретов типов в `types/`. Крупные документы действительно объёмны и структурированы: `21-workplace-conflicts.md` — 1044 строки, `22-learning-styles.md` — 912 строк, `types/INTJ.md` — 372 строки. Единый стиль: оглавление, разбор по всем 16 типам, таблицы, примеры.
- **Работоспособная по коду RAG-система** (`rag/`): корректный пайплайн LangChain (загрузка → чанкинг 1000/200 → мультиязычные эмбеддинги `paraphrase-multilingual-mpnet-base-v2` → ChromaDB), деградация без OpenAI-ключа до чистого поиска (`use_llm=False`), три интерфейса (CLI, Streamlit, Python API), зафиксированные версии зависимостей, `.env.example`, подробный README с примерами.
- **Оригинальная концепция PseudoRAG** (`pseudorag/` + `docs/50–54`): онтология «16 информационных архетипов» по 4 бинарным осям (материальность/динамика/масштаб/структура), шаблонное расширение запроса в структурированный вопросник с экспортом JSON/Markdown. Есть рабочее демо (`main.py`), демонстрационный тест (`test_cities.py`) и готовый пример результата (`examples/города_европы.json/.md`) — то есть код хотя бы раз реально запускался.
- **Полный Android-проект** (`android-document-search/`): Gradle-конфигурация (compileSdk 34, Room 2.6.1 + KSP, PDFBox-Android, Apache POI), Room-DAO поверх виртуальной FTS4-таблицы с MATCH-запросами и `snippet()`-подсветкой, инкрементальный индексатор (проверка mtime, лимит 50 МБ), MVVM, Material 3. Код идиоматичный (Coroutines, Flow).
- **Самоотчёт** `COMPLETION_REPORT.md` со статистикой создания документации.

## Чего нет

- **Тестов**: нет ни одного настоящего теста. `pseudorag/test_cities.py` — демо-скрипт с print'ами, не pytest; в `rag/` тестов нет; в Android-проекте настроен testInstrumentationRunner, но наличие содержательных тестов не обнаружено (не проверено до конца).
- **CI/CD**: `.github/workflows/` отсутствует (проверено — 404). Сборка Android-приложения и установка Python-зависимостей нигде автоматически не проверяются.
- **Лицензии**: файла LICENSE нет (404); в README лишь фраза «образовательный материал для свободного использования» — юридически это не лицензия.
- **`pseudorag/requirements.txt`**: README предлагает `pip install -r requirements.txt`, но файла нет (404). К счастью, код pseudorag работает на stdlib.
- **Упаковки**: нет pyproject.toml/setup.py, ни rag, ни pseudorag не устанавливаются как пакеты; импорты держатся на `sys.path.append`-хаках в каждом файле.
- **Корневого .gitignore**: как следствие — закоммичен `pseudorag/__pycache__/`.
- **Актуального корневого README**: он описывает только docs/ и types/, три кодовых подпроекта (≈100% кода репозитория) в нём не упомянуты.
- **Скриншотов и релизов Android-приложения**: в README заглушка «добавьте скриншоты», APK/релизов нет.
- **Данных для FTS-поиска**: приложение ищет по папке Documents устройства; тестового корпуса в репо нет (для RAG корпусом служат сами docs/).

## Плюсы

- Большой связный корпус контента: ~1 МБ структурированного русскоязычного Markdown единого стиля — готовый датасет для любых поисковых экспериментов.
- Три разных подхода к поиску знаний в одном репо: векторный RAG, шаблонная онтология (PseudoRAG), классический FTS4 — удачная «лаборатория поиска».
- PseudoRAG — действительно оригинальная идея (онтология из 16 архетипов, зеркалящая 16 типов MBTI), подкреплённая пятью теоретическими документами (docs/50–54).
- Код всех трёх подсистем аккуратный, читабельный, с русскоязычными докстрингами и осмысленной структурой.
- Хорошие README у подпроектов rag/ и android/ (установка, примеры, архитектура, SQL-примеры FTS4).
- Продуманные мелочи: деградация RAG без API-ключа, инкрементальная индексация в Android, нормализация эмбеддингов, лимит размера файлов.

## Минусы

- Ни одна из трёх кодовых подсистем не проверяется автоматически — работоспособность RAG и сборка Android-приложения не подтверждены (и в рамках аудита не проверялись — только чтение кода).
- Версии `rag/requirements.txt` устарели уже на момент создания (langchain 0.1.0 с deprecated-импортами `langchain_community.*`, chromadb 0.4.22); при установке «сегодня» вероятны конфликты.
- Рассинхронизация документации: корневой README не знает о коде; pseudorag/README ссылается на несуществующие templates/, tests/, requirements.txt; android/README содержит placeholder-URL `yourusername` и инструкцию checkout уже слитой ветки.
- Закоммиченный `__pycache__`, отсутствие корневого .gitignore.
- Монорепозиторий без явной сборки целого: части не интегрированы (Android-приложение не ищет по базе MBTI, PseudoRAG не связан с RAG) — «пирамида» из docs/54 остаётся на бумаге.
- Контент MBTI — компиляция по мотивам популярных источников (16personalities и др.); научная ценность типологии спорна, что сам README честно оговаривает.
- Нумерация docs/ с дырой 43–49 без объяснения.

## Качество кода и документации

- **Python (rag/)**: стандартный, чистый LangChain-boilerplate; конфигурация вынесена в config.py с переопределением через env; обработка ошибок минимальна (широкий `except Exception` в CLI). Оценка: добротный прототип.
- **Python (pseudorag/)**: хорошо типизированные dataclass'ы, продуманная модель (оси/архетипы/приоритеты/шаблоны), но релевантность определяется примитивным keyword-matching; тестов нет. Оценка: интересный прототип-концепт.
- **Kotlin (android/)**: современный стек (Room+KSP, Coroutines/Flow, ViewBinding), корректное использование FTS4 (MATCH, rank, snippet). Не проверена сборка. Оценка: выглядит завершённым MVP.
- **Документация-контент**: объёмная, единообразная, с таблицами и перекрёстными ссылками; блок 29–42 заметно тоньше (30–75 строк) — скорее конспекты, чем главы.
- **Документация-инженерная**: README подпроектов хороши, но корневой README и перекрёстная согласованность — слабое место.

## Зрелость: 3/5

Обоснование: репозиторий существенно больше «инфо-заготовки» — завершённый контентный корпус плюс три осмысленно написанных кодовых прототипа с документацией (заслуженные 3 балла). До 4/5 не дотягивает из-за полного отсутствия тестов, CI, лицензии, упаковки, неподтверждённой работоспособности (ни одного релиза/скриншота/бейджа), рассинхронизированных README и остановки разработки после однонедельного спринта (2–9 января 2026, 14 коммитов, далее тишина ~6 месяцев).

**Ограничение покрытия аудита**: из 64 md-документов контента прочитаны выборочно ~6 (заголовки и объёмы проверены по списку); из Android-проекта прочитаны README, Gradle-конфиги, DocumentDao.kt и FileIndexer.kt, остальные ~10 Kotlin-файлов проверены только на существование; res/-ресурсы не просматривались. Запуск кода не производился.
