## Серьёзные доработки

1. **CI (GitHub Actions)**: workflow с (а) `pip install -r rag/requirements.txt` + smoke-тест импорта, (б) `pytest` для pseudorag, (в) `./gradlew assembleDebug` для Android — это сразу ответит на главный открытый вопрос «а собирается ли оно вообще».
2. **Обновить RAG-стек**: langchain 0.1.0 и chromadb 0.4.22 устарели; мигрировать на актуальные langchain-core/langchain-chroma или вовсе избавиться от LangChain (пайплайн простой: chromadb + sentence-transformers достаточно), убрать `sys.path.append`-хаки через нормальную упаковку (pyproject.toml).
3. **Интегрировать подсистемы**: главный архитектурный долг — части не связаны. Например, встроить базу MBTI (docs/ + types/) в Android-приложение как предустановленный корпус для FTS4-поиска — тогда описание репозитория «Offline search app» станет полностью правдой, а приложение получит готовый контент.
4. **Реализовать уровни 3–4 пирамиды PseudoRAG**: сейчас есть только расширение запроса (уровень 1→2); заполнение вопросника ответами (через RAG или LLM) и фильтрация — описаны в docs/52–54, но не реализованы.
5. **Заменить keyword-matching в PseudoRAG на эмбеддинги**: релевантность архетипа темe сейчас определяется по спискам ключевых слов; эмбеддинг-модель из rag/ уже под рукой и дала бы качественный скачок.
6. **Выпустить APK-релиз** Android-приложения (GitHub Releases) со скриншотами — без этого приложение существует только как исходники.

## Варианты продолжения

### Вариант 1. «Карманная энциклопедия MBTI» — продуктовое направление

Довести Android-приложение до публикуемого продукта: вшить в него корпус docs/+types/ как офлайн-базу, добавить FTS4-поиск по ней, навигацию по 16 типам, матрицу совместимости как интерактивный экран. Получится законченное офлайн-приложение «справочник типов личности с поиском» — нишевый, но целостный продукт, где сойдутся все три ветки репозитория (контент + поиск + мобильный клиент). Публикация в F-Droid/RuStore даст проекту реальных пользователей и обратную связь.

### Вариант 2. «PseudoRAG как самостоятельная библиотека» — исследовательское направление

Выделить pseudorag/ в отдельный устанавливаемый Python-пакет: онтология 16 информационных архетипов — самая оригинальная идея репозитория, не зависящая от MBTI-контента. Дописать уровни 3–4 (автозаполнение вопросников через LLM), заменить keyword-matching на эмбеддинги, добавить тесты и опубликовать на PyPI. Это превращает разовый прототип в переиспользуемый инструмент «структурированной декомпозиции любой темы» — полезный для агентных пайплайнов, автогенерации баз знаний и research-ассистентов.

### Вариант 3. «Эталонная RAG-песочница на русском» — образовательное направление

Корпус из 63 согласованных русскоязычных документов единого стиля — редкость; оформить репозиторий как учебный полигон для сравнения поисковых подходов: FTS4 vs BM25 vs векторный поиск vs PseudoRAG-декомпозиция на одном и том же корпусе, с бенчмарком из 50–100 эталонных вопросов-ответов по MBTI. Такой «RAG-benchmark по-русски» имеет самостоятельную ценность для сообщества и придаст смысл сосуществованию трёх поисковых движков в одном репо.

### Вариант 4 (минимальный). Честная консервация

Если развитие не планируется: выполнить быстрые улучшения (LICENSE, README, чистка), пометить в README статус «прототип, заморожен», выпустить tag v1.0. Репозиторий и в текущем виде — приличное портфолио-свидетельство, но сейчас его главная страница вводит в заблуждение относительно содержимого.

## Сочетания с другими репозиториями профиля

1. **daten22 + data20 (offline app, embedded back end) = «Офлайн-платформа знаний»**. У data20 заявлен встраиваемый бэкенд для офлайн-приложений, у daten22 — готовый Android-клиент с FTS4 и корпус знаний. Объединение даёт переиспользуемый шаблон «офлайн-приложение с любой предзагруженной базой знаний»: движок индексации и поиска из daten22 + встраиваемая серверная часть из data20 = конструктор офлайн-справочников (медицина из info150, магазины из data40 — любой корпус подключается как модуль). Инновация — единый офлайн-стек «контент → индекс → мобильный клиент» без сети.

2. **daten22 (PseudoRAG) + infom (ГрафРАГ) = «Гибридный Graph-PseudoRAG»**. PseudoRAG раскладывает тему на 16 онтологических архетипов, но полученные вопросники — плоские списки; GraphRAG из infom строит графы знаний, но без универсальной онтологии узлов. Скрещивание: архетипы daten22 становятся типами узлов графа, матрица взаимодействий (docs/51) — типами рёбер, а расширение запросов наполняет граф. Получается инновационная система, где граф знаний строится не хаотично, а по фиксированной 16-типной онтологии — типизированный GraphRAG, которого нет в открытых инструментах.

3. **daten22 (RAG по MBTI) + info100 (лаборатория агентов) / info40 (AI Agent Orchestration Platform) = «Психотипированные агенты»**. База из 16 детальных портретов типов + когнитивные функции + матрица совместимости 16×16 — готовые «персональности» для мультиагентных систем. Оркестратор из info40/info100 назначает агентам MBTI-профили из daten22 (стиль рассуждения, роль в команде по docs/18-teams-roles.md), а матрица совместимости управляет тем, какие агенты работают в паре. Инновация — эмпирически наполненный слой «характеров» для агентных команд вместо ad-hoc системных промптов.

4. **daten22 (PseudoRAG) + daten4 (динамический планировщик) = «Онтологический планировщик»**. Расширитель запросов daten22 умеет превращать цель («открыть кофейню») в структурированный вопросник по 16 аспектам реальности (материалы, здания, процессы, общество...); планировщик daten4 умеет строить динамические планы. Вместе: декомпозиция цели по архетипам → автоматическое покрытие «слепых зон» плана (аспекты, о которых планирующий не подумал) → план с онтологической полнотой. Такой «чек-лист полноты планирования» — необычный и практичный гибрид.
