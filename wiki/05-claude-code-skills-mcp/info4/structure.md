## Ключевые файлы и модули

| Файл/модуль | Что делает |
|---|---|
| `skills/**/*.skill` | Единица контента: ZIP с одним `SKILL.md` — YAML-фронтматтер (`name`, `description` с триггерами) + markdown-инструкции для Claude. Проверено на `smart-file-organizer.skill` (SKILL.md 9 218 байт); исполняемых файлов внутри нет |
| `scripts/checkpoint_creator.py` | Единственный Python-модуль: argparse-CLI, генерирует пакет миграции чата (MASTER_INDEX.md, METHODOLOGY.md, README, «первое сообщение» для нового чата) по 6 шаблонам типов проектов; есть режим валидации |
| `scripts/organize_skills.sh`, `organize_docs.sh` | Bash-скрипты, которыми выполнялась реорганизация (копирование файлов в новую иерархию) |
| `00_MASTER_INDEX_Skills_Catalog.md` | Мастер-каталог 87 скиллов с таблицами по категориям, приоритетами и прогрессом описания; **устарел** (показывает 21 %, тогда как поздние отчёты заявляют 100 %) |
| `VARIANT_1_EXTERNAL_SERVICE.md` | Проект: скиллы как независимый микросервис — REST/GraphQL API, YAML-формат скилла вместо ZIP, Skills Registry/Executor c sandbox, Docker/K8s, биллинг. Только документация |
| `VARIANT_2_METHOD_DATABASE.md` | Проект «Pseudo-RAG»: семантический поиск не ответов, а методов; ИИ запрашивает базу методов перед решением задачи и композирует решение из найденных скиллов. Только документация |
| `CHANGELOG.md` + `docs/checkpoints/` | Эволюция чекпойнт-системы v1→v6; v4 «Quantum», v5 «Cosmic» (AGI, 2027–2028), v6 «Infinity» (пост-сингулярность) — помечены как vision/арт, не реализация |
| `REPOSITORY_REVIEW.md` | Самоаудит от Claude: 88 `.skill`, 22 ZIP, ~70 md, 1 py; 3 критические проблемы (нет .gitignore, README-заглушка, бинарный формат .skill); оценка 6,8/10 |
| `FINAL_STATUS_COMPLETE.md` | Финальный отчёт: 210 изменённых файлов, 39 567 строк добавлено, 0 удалено; «качество 6,8 → 9,2» |
| `releases/*.zip` | Готовые сборки коллекции разных составов (88, 102 скилла, чекпойнт-пакеты) |

## Особенности организации

1. **Двойная структура.** Репозиторий существует в двух экземплярах: старая плоская свалка в корне (~180 файлов) и новая аккуратная иерархия (`skills/`, `docs/`, `releases/`). Это сделано сознательно («полная обратная совместимость»), но фактически удваивает бинарный контент и сводит на нет главную цель реорганизации — навигацию.
2. **Бинарный контент в git.** ~230 бинарных ZIP-архивов (~88 `.skill` в корне + 101 `.skill` в `skills/` + 22 `.zip` в корне + 22 `.zip` в `releases/`) — недоступные для diff/поиска; сами тексты скиллов в репозитории в развёрнутом виде отсутствуют.
3. **Документация »» код.** Соотношение примерно 99:1 — это база знаний с тремя служебными скриптами, а не программный продукт.
4. **Слои истории видны в именах файлов**: BATCH_/CHAT_-отчёты — хроника генерации каталога по сессиям; CHECKPOINT_/v1–v6 — линия про миграцию чатов; VARIANT_/ARCHITECTURE_ — поздний слой архитектурного проектирования. Всё лежит вперемешку в корне.
