# claudeai-test-project-k — тестовый «hello world»-проект для проверки связки Claude AI + Desktop Commander

## Обзор

`claudeai-test-project-k` — это минимальный тестовый репозиторий, созданный 1 февраля 2026 года как «первый проект, созданный с помощью Claude Code и Desktop Commander» (цитата из README самого репозитория). Содержимое — ровно три файла: приветственный скрипт `hello.py` на Python 3, русскоязычный `README.md` и стандартный `.gitignore` для Python-проектов. История состоит из одного-единственного коммита.

Репозиторий интересен не кодом (это классический hello-world с вводом имени), а своей ролью: это полигон для проверки того, как инструментальная цепочка Claude AI ↔ Desktop Commander ↔ git ↔ GitHub обращается с кириллицей и эмодзи. Описание репозитория на GitHub прямо говорит: «тесты, Claude AI тест, Desktop Commander тест, тест???? проблемы с кодировкой текста юникода». И проблема действительно зафиксирована «в дикой природе»: сообщение единственного коммита отображается как моджибейк — `Initial commit: ð┤ð¥ð▒ð░ð▓ð╗ðÁð¢ hello.py ð© README`, то есть UTF-8-байты слова «добавлен» были интерпретированы в однобайтовой кодировке консоли (похоже на CP437/CP866 в Windows-терминале). Сами файлы при этом сохранены в корректном UTF-8 — кириллица и эмодзи в `README.md` и `hello.py` читаются без искажений.

## Назначение и идея

Назначение — проверочная песочница («smoke test») для рабочего процесса «ИИ-агент управляет локальной машиной»:

- убедиться, что Desktop Commander может создать файлы, каталог, git-репозиторий и запушить его на GitHub;
- проверить, как по пути «агент → терминал → git» проходят не-ASCII символы (кириллица, эмодзи) — и здесь тест честно выявил дефект: коммит-сообщение испортилось, а содержимое файлов — нет;
- послужить учебным «первым проектом»: в README есть план развития (тесты, requirements.txt и т.п.), который так и не был реализован.

Суффикс «-k» в имени намекает, что это один из серии одноразовых тестовых проектов (проверить у владельца — см. [Вопросы](questions.md)).

## Как устроено (архитектура)

Архитектуры как таковой нет — один скрипт:

- `hello.py` (31 строка): функция `greet(name)` возвращает f-строку «Привет, {name}! 👋»; функция `main()` печатает баннер, запрашивает имя через `input()` и выводит приветствие; стандартный запуск через `if __name__ == "__main__"`. Есть докстринги, шебанг `#!/usr/bin/env python3` и явное объявление кодировки `# -*- coding: utf-8 -*-`.
- `README.md` (54 строки): описание, инструкция запуска, структура проекта и чек-лист «Что дальше» из 5 невыполненных пунктов.
- `.gitignore` (24 строки): типовые исключения для Python (`__pycache__`, `env/`, `venv/`, `build/`), IDE (`.vscode/`, `.idea/`) и ОС (`.DS_Store`, `Thumbs.db`, `desktop.ini` — набор указывает на работу под Windows).

Зависимостей нет, достаточно Python 3.6+ (из-за f-строк). Подробнее — в [Структуре](structure.md).
