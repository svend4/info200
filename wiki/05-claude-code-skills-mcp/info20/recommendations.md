# Рекомендации по info20

## Быстрые улучшения

1. **Добавить файл LICENSE** (MIT, как заявлено в README) — сейчас лицензия юридически не оформлена.
2. **Провести факт-чекинг по официальной документации** и исправить как минимум:
   - имя пакета SDK: `@anthropics/claude-agent-sdk` → `@anthropic-ai/claude-agent-sdk`, а примеры API переписать под реальный `query()`;
   - пути MCP-конфигурации: `.claude-mcp.json` / `~/.claude/mcp.json` → `.mcp.json` в корне проекта и `claude mcp add`;
   - формат Skills: описать реальный `.claude/skills/<имя>/SKILL.md` и отделить его от slash-команд `.claude/commands/*.md`.
3. **Починить внешние ссылки**: `anthropics/claude-code-skills` и `anthropics/claude-agent-sdk` не существуют; `docs.anthropic.com/claude/docs/claude-code` — устаревший URL. Добавить в CI markdown-link-check.
4. **Добавить CLAUDE.md в сам репозиторий** — пусть проект демонстрирует то, чему учит («eat your own dog food»).
5. **Добавить дисклеймер с датой актуальности** («проверено против Claude Code версии X от даты Y») в каждый раздел — для быстро меняющегося продукта это критично.
6. **Убрать дублирование** диаграммы и таблиц между корневым README и docs/README.md (оставить в одном месте, в другом — ссылку).

## Серьёзные доработки

1. **Превратить текстовые примеры в работающие артефакты**: реальная папка `.claude/skills/` с 2–3 рабочими скиллами, реальный `.mcp.json`, минимальный MCP-сервер в `examples/mcp-server/` с package.json, который можно запустить. Тогда репозиторий станет не только пособием, но и стартовым шаблоном (template repository).
2. **Настроить CI-валидацию документации**: проверка ссылок, линтер markdown, а в идеале — smoke-тест примеров (npm install пакетов, запуск MCP-сервера) — это ловило бы вымышленные имена пакетов автоматически.
3. **Ввести процесс актуализации**: changelog, версия документации, привязка к версии Claude Code, регулярный (например, ежеквартальный) прогон агента-факт-чекера по официальным докам с автоматическим PR.
4. **Разделить «концепции» и «справочник»**: концептуальная часть (уровни расширения, RAG-подход) устаревает медленно, справочная (пути, форматы, пакеты) — быстро; их стоит развести по разным файлам с разным режимом сопровождения.
5. **Добавить раздел про новые механизмы** Claude Code, отсутствующие в тексте: hooks, subagents (`.claude/agents/`), plugins/marketplace, output styles — пособие останавливается на состоянии начала 2026 года.

## Варианты продолжения

**Сценарий 1: «Живой справочник + шаблон» (рекомендуемый).** Довести info20 до состояния верифицированного русскоязычного справочника по расширению Claude Code: исправить факты, добавить работающие примеры-артефакты, включить CI-проверку ссылок и «свежести», пометить репозиторий как template. Ценность: таких системных русских материалов мало, ниша свободна; репозиторий сможет реально использоваться как стартовая точка новых проектов профиля. Трудозатраты умеренные: 1–2 дня на факт-чекинг и артефакты, полдня на CI.

**Сценарий 2: «Слить в базу знаний info30».** В профиле уже есть info30 («Claude Code Knowledge System») — тематический близнец. Поддерживать два пересекающихся пособия расточительно: перенести уникальные разделы info20 (MCP-гайд, examples-сценарии) в info30, оставив в info20 README-указатель с редиректом, либо наоборот — выбрать info20 каноническим. Это уменьшит дублирование в профиле из 61 репозитория и сконцентрирует усилия на одном качественном ресурсе.

**Сценарий 3: «Самоприменение: пособие как конфигурация роя».** Использовать info20 не как текст «о» Claude Code, а как действующий слой знаний для остальных репозиториев профиля: выделить из него набор готовых CLAUDE.md-шаблонов, скиллов аудита и инструкций для агентов и подключать их в info200 (хаб вики) и другие проекты. Пособие превращается из статьи в переиспользуемый «extension pack», а его тезис «знания живут в репозитории» проверяется на практике.

**Сценарий 4 (минимальный): «Честная архивация».** Если развивать некогда — исправить только лицензию и добавить в README плашку «снапшот на февраль 2026, детали могли устареть, сверяйтесь с официальной документацией», затем заархивировать репозиторий. Это дешёвый способ сохранить концептуальную ценность, не вводя читателей в заблуждение устаревшим справочником.

## Сочетания с другими репозиториями профиля

1. **info20 + info30 (Claude Code Knowledge System) + info200 (хаб вики) = «Русский Claude Code Hub».** Объединить методическое пособие (info20), базу знаний (info30) и вики-хаб (info200) в единый структурированный портал: info200 даёт оболочку и навигацию, info30 — операционные знания, info20 — учебный трек «от новичка к оркестрации агентов». Уникальность: целостный русскоязычный портал по Claude Code с проверяемыми примерами — ниша, где почти нет конкуренции.

2. **info20 + info40 (AI Agent Orchestration Platform) = «пособие с живой лабораторией».** Раздел `docs/agents/` в info20 сейчас описывает вымышленный API. Вместо этого привязать его к реальной оркестрационной платформе info40: каждый паттерн оркестрации из пособия получает работающий пример в info40, а info40 получает методическую документацию. Получится редкий формат «учебник + исполняемая платформа», где документацию можно интеграционно тестировать.

3. **info20 + universal-file-storage-mcp = верифицированный MCP-гайд на собственном сервере.** В профиле есть настоящий MCP-сервер (universal-file-storage-mcp). Использовать его как сквозной живой пример в `docs/mcp/README.md`: реальная конфигурация, реальные tools/resources, реальный запуск. Пособие перестаёт опираться на абстрактные примеры, а MCP-сервер получает качественную русскую документацию — взаимное усиление двух репозиториев.

4. **info20 + info100 («лаборатория агентов») + daten4 (динамический планировщик) = курс «агентная инженерия по-русски».** Теория уровней расширения из info20 + эксперименты info100 + планировщик daten4 как учебный проект, на котором читатель по главам пособия строит скиллы, MCP-интеграцию и оркестрацию. Инновация: практикум, где каждая глава заканчивается работающим артефактом в реальном соседнем репозитории.
