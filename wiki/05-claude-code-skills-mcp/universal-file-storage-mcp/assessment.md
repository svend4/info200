# Характеристика и оценка universal-file-storage-mcp

Аудит-перепроверка выполнена 02.07.2026. Прочитаны все 13 файлов репозитория; дополнительно зависимости были реально установлены (`npm install`, SDK разрешился в @modelcontextprotocol/sdk 1.29.0) и код прогнан через `tsc --noEmit`.

## Что есть

- **Полный текст сервера в `src/index.ts` (821 строка)**: конфигурация 6 хранилищ, класс `StorageAdapter` с ветками local/NAS/cloud(WebDAV)/Android(ADB), OCR через tesseract.js (eng+rus), наивный полнотекстовый поиск, 4 MCP-инструмента (`list_storages`, `search_files`, `read_file`, `list_files`) с образцовыми описаниями и zod-схемами, аннотации `readOnlyHint`/`idempotentHint`.
- **Очень объёмная русскоязычная документация** (~4 200 строк): README (678 строк) с настройкой под Windows/Linux/macOS/Android и troubleshooting; ARCHITECTURE.md с ASCII-диаграммами, потоком данных, слоями безопасности и roadmap; QUICK_START.md с примерами диалогов с Claude; PLATFORM_SETUP.md (CIFS, systemd, ADB); TERMUX_GUIDE.md + TERMUX_SCRIPTS.md — детальный сценарий запуска сервера на Android-телефоне; GITHUB_GUIDE.md — инструкция по публикации проекта.
- **install-termux.sh (523 строки)** — аккуратный автоустановщик: проверки окружения, генерация `.env`, boot-скрипт автозапуска, start/stop/restart/status-скрипты.
- Инфраструктурная гигиена частично есть: `.env.example` (все секреты вынесены в переменные), осмысленный `.gitignore`, строгий `tsconfig.json` (strict: true).

## Чего нет

- **Работоспособной сборки**: `tsc --noEmit` даёт **39 ошибок** (проверено). Три класса ошибок: (1) `inputSchema` передан как `z.object({...})`, тогда как SDK ждёт «сырую» форму (ZodRawShape) — из-за этого все параметры инструментов нетипизируемы (TS2589/TS2339, ~30 ошибок); (2) `error.message` на `unknown` в catch при strict-режиме (TS18046, 5 ошибок); (3) `StreamableHTTPServerTransport` создан с опциями `{ server, endpoint }`, которых нет в API SDK (TS2353).
- **Работоспособного HTTP-слоя даже в замысле кода**: Express-приложение создаётся, но ни один роут не привязан к `transport.handleRequest` — MCP-запросы на `/mcp` некому обрабатывать.
- **Тестов** — ни одного; `npm test` вызывает jest, который отсутствует в devDependencies (проверено: после установки бинарника jest нет).
- **CI** — нет `.github/workflows`; даже сборка не проверяется автоматически (и она бы упала).
- **Файла LICENSE** — 404 (MIT заявлен только в package.json/README).
- **package-lock.json** — воспроизводимость установки не зафиксирована.
- **S3-адаптера** — зависимость `@aws-sdk/client-s3` объявлена, README и .env.example описывают AWS-переменные, но в коде S3 не упоминается ни разу.
- **Заявленных в доках механизмов**: кэширование результатов, индексация метаданных, rate limiting, «path traversal protection» (ARCHITECTURE.md, раздел «Безопасность») — в коде отсутствуют полностью; напротив, `path.join(config.path, subPath)` без валидации допускает выход из корня хранилища через `../`.
- Внешней конфигурации: хранилища настраиваются правкой исходника `src/index.ts`.

## Плюсы

- Ясная и востребованная идея: единый файловый доступ Claude ко всем устройствам пользователя, включая телефон.
- Правильный архитектурный паттерн (адаптеры хранилищ + MCP-инструменты) и очень качественные описания инструментов для LLM.
- Выдающийся объём и структура документации; сценарий Termux/Android проработан до автозапуска при загрузке телефона.
- Секреты вынесены в `.env`, есть `.env.example` и адекватный `.gitignore`.
- OCR-поиск по скриншотам (eng+rus) — редкая и полезная фича в MCP-серверах.

## Минусы

- Код никогда не собирался: 39 ошибок компиляции, нерабочий транспорт, нерабочий `npm test`.
- Безопасность: `mountNas` подставляет логин/пароль в shell-команду `sudo mount` (инъекция команд + пароль виден в списке процессов); точка монтирования `/mnt/nas-<id>` нигде не создаётся; отсутствует защита от `../`; сервер слушает HTTP без всякой аутентификации.
- OCR и чтение для NAS/cloud/Android сломаны по построению: `extractTextFromImage` запускает Tesseract над локальным путём, которого нет на машине сервера (файл лежит на телефоне/в облаке).
- Поиск нерекурсивный и O(полный объём всех файлов) на каждый запрос; на реальном NAS это неработоспособно.
- Доступ к приватным полям через `adapter['config']` — обход собственной инкапсуляции.
- Конфигурация хранилищ захардкожена в исходнике; документация местами противоречит коду (см. таблицу выше).
- Один коммит-день, история разработки отсутствует (загрузка архива).

## Качество кода и документации

- **Код: 2/5.** Читаемый, хорошо прокомментированный, с правильными намерениями (типы, zod, аннотации инструментов), но фактически не проходил ни компиляцию, ни запуск; несколько подсистем (HTTP-транспорт, NAS, OCR для удалённых хранилищ) неработоспособны по построению.
- **Документация: 4/5 по форме, 2,5/5 по достоверности.** Прекрасно структурирована, покрывает установку на четырёх платформах, но систематически описывает несуществующие возможности (S3, кэш, индексация, защита путей) и содержит нерабочие примеры (localhost в API-примере, YOUR_USERNAME в установщике).

## Зрелость: 2/5

Обоснование: это не пустышка — есть цельный 800-строчный сервер с продуманным API и лучшая в профиле документация на единицу кода; но проект ни разу не собирался (39 ошибок tsc — проверено), не имеет тестов, CI, лицензии и истории разработки, а часть заявленных возможностей отсутствует. От «3/5» его отделяет ровно один честный цикл: починить компиляцию, поднять транспорт, запустить и сверить доки с реальностью.

Ограничения покрытия аудита: прочитаны все файлы репозитория целиком, компиляция проверена локально; запуск сервера с реальными NAS/ADB/WebDAV-хранилищами и поведение в Claude Desktop не проверялись (нет окружения). Наличие issues проверялось только по видимым страницам GitHub.
