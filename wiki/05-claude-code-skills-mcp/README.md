# Расширения Claude Code, скиллы и MCP-инструменты

## О теме

Шесть репозиториев этой темы объединяет одна сквозная идея — **расширить возможности ИИ-ассистента Claude Code за пределы «голого» диалога**: через файловые базы знаний рядом с кодом, коллекции переиспользуемых скиллов, серверы Model Context Protocol (MCP) для доступа к файлам и технические рецензии инструментов, которыми пользуется агент. Здесь есть все три слоя экосистемы: **методология и документация** (info30, info20 — как правильно организовать знания и подключить их к Claude), **готовый контент** (info4 — библиотека из ~101 скилла; meta10 — глубокий разбор инструмента AST-поиска) и **исполняемая интеграция** (universal-file-storage-mcp — MCP-сервер; claudeai-test-project-k — тестовая песочница агентского тулчейна).

Тема хорошо вписывается в профиль как «мастерская вокруг самого инструмента»: если соседние темы про ИИ-агентов, RAG и базы знаний решают прикладные задачи, то здесь автор работает с инфраструктурой ассистента — форматами скиллов, протоколом MCP, стандартами описания знаний. Общая слабость всей группы тоже характерна: почти все проекты сильны на уровне идеи и документации, но обрываются на границе рабочего кода — каркасы без наполнения, гайды с фактическими ошибками, MCP-сервер, который ни разу не компилировался. Это скорее коллекция концептов и прототипов, чем набор готовых к установке инструментов.

## Лидеры и аутсайдеры

**Самые проработанные.** Условные лидеры темы — **info4** и **meta10**, причём по разным причинам.

- **info4** выделяется реальным объёмом: 101 скилл с продуманными описаниями и триггерами (формат проверен на образце), ~3200 строк архитектурной проработки идеи Pseudo-RAG, двуязычная документация и — редкость для темы — присутствующий файл LICENSE (MIT), CONTRIBUTING и честные самоаудиты, где заявленные размеры совпали с фактическими. Это самый «наполненный» репозиторий группы, хотя главная идея (Method DB) осталась только на бумаге, контент задублирован, а README так и остался двухстрочной заглушкой при готовой замене рядом.
- **meta10** силён качеством мысли: автор самостоятельно прочитал исходники grep-ast и нашёл реальное расхождение со статьёй-предметом (аудит подтвердил это построчно), сформулировал 8 аргументированных претензий и приложил готовое ТЗ двухстадийного пайплайна с схемой tool calls для агента. Это лучший образец «технической рецензии как жанра» в профиле, ограниченный тем, что пайплайн не доведён до кода, а сам репозиторий скрыт за неинформативным именем и README-заглушкой.

Отдельно стоит **universal-file-storage-mcp** — единственный проект темы с настоящей кодовой базой и **выдающейся документацией** (установка под 4 платформы, OCR-поиск, полный Termux-сценарий). Его не выношу в лидеры лишь потому, что код не компилируется, а документация систематически описывает несуществующие фичи.

**Заготовки и тупики.** Явный аутсайдер — **claudeai-test-project-k** (1/5): трёхфайловый hello-world, у которого нулевая самостоятельная ценность кода, а результат самого эксперимента (баг кодировки) нигде не задокументирован. **info30** и **info20** формально проработаны, но это, по сути, каркас без наполнения и учебник без работающих артефактов: у info30 «база знаний» из одного образца на категорию и несуществующие в git каталоги, у info20 — вымышленные пути MCP-конфигов, неверное имя SDK-пакета и несуществующий API `new Agent()`.

## Общие сильные стороны темы

- **Цельные, переиспользуемые концепции.** Почти в каждом репозитории есть внятная идея с потенциалом: «знания как код» рядом с проектом (info30), трёхуровневая рамка расширения Claude Code (info20), «поиск методов вместо ответов» (info4), единая точка доступа к файлам на всех устройствах (universal-file-storage-mcp), детерминированная AST-навигация по коду (meta10).
- **Сильная документация и оформление.** Развёрнутые гайды, сравнительные таблицы, ASCII-архитектуры, аккуратная перелинковка, единый стиль; у ряда проектов — двуязычность (RU/EN у info4, качественная русская подача у info20, info30, meta10).
- **Есть реальный контент, а не только обещания** — там, где он есть: 101 скилл (info4), верифицированный по исходникам разбор (meta10), образцовые описания MCP-инструментов с zod-схемами и аннотациями (universal-file-storage-mcp).
- **Внимание к нише и языку.** Систематический русскоязычный материал по Claude Code (info20), OCR-поиск как редкая фича среди filesystem-MCP (universal-file-storage-mcp), гигиена секретов (`.env.example`, `.gitignore`, strict-tsconfig).
- **Честные самоаудиты в лучших репозиториях** (info4, meta10): количественные данные перепроверяемы, спекулятивные версии явно помечены как vision, а не реализация.

## Общие слабые места и чего не хватает

- **Витринность и инфляция статусов.** «Production Ready» у каркаса с одним образцом (info30), «100 % COMPLETE» против «21 %» в том же индексе (info4), документация с галочками «готово» на несуществующих фичах (universal-file-storage-mcp). Самоописания систематически завышены относительно реальности.
- **Идеи не доходят до кода.** У info30 нет исполняемого кода вовсе; главная идея info4 (Method DB) — только документация; MCP-сервер universal-file-storage-mcp не компилируется; пайплайн meta10 спроектирован, но не реализован; примеры info20 существуют лишь код-блоками в тексте.
- **Фактические и технические ошибки vs реальный Claude Code.** Вымышленные пути MCP-конфигов и неверное имя SDK-пакета (info20), собственные форматы агентов/скиллов, несовместимые с нативными `.claude/agents`/skills (info30), опции транспорта и схемы инструментов под несуществующий API SDK (universal-file-storage-mcp).
- **Отсутствие LICENSE при заявленной MIT.** Проблема у info30, info20, universal-file-storage-mcp и claudeai-test-project-k — код формально нельзя переиспользовать (исключение — info4, где LICENSE есть).
- **Нет тестов и CI** практически во всей теме; нет валидаторов/линтеров форматов (.skill, markdown-ссылки, YAML).
- **Однодневный жизненный цикл.** Большинство репозиториев создано за один день пачкой коммитов и заморожено; собственные планы развития (NEXT_STEPS, roadmap) не исполнены.
- **Слабая связность.** Битые ссылки и заглушки-README (info30, info4, meta10), отсутствие перелинковки между репозиториями профиля, неинформативные имена (meta10, суффикс «-k»).

## Дубли и пересечения

- **info30 ↔ info20 — самое сильное пересечение темы.** Оба посвящены методологии расширения Claude Code (Skills, MCP, агенты, RAG-инструкции), оба — только markdown без работающих артефактов, оба заявляют MIT без файла LICENSE. Сам info20 в слабых сторонах прямо отмечает «пересечение по теме с info30». Разница в акценте: info30 — стандарт организации файловой базы знаний, info20 — линейный учебник. Их логично слить в один продукт с чётким разделением ролей (см. идею ниже).
- **MCP-примеры в трёх местах.** info30 и info20 оба описывают, как поднять MCP-сервер (`@modelcontextprotocol/server-filesystem` / `sdk`), а universal-file-storage-mcp такой сервер реально реализует (пусть и некомпилируемо). Живой сервер стоило бы сделать сквозным рабочим примером в обоих гайдах вместо параллельных выдуманных конфигов.
- **Скиллы info4 vs формат скиллов в info30/info20.** info4 описывает стандарт скилла и хранит 101 архив; info30/info20 излагают собственные форматы скиллов, несовместимые с реальными. Единый источник правды по формату скилла напрашивается сам собой.

## Идеи сочетаний внутри темы

- **info30 + info20 = единый портал «Claude Code Hub».** info30 становится операционным ядром (стандарт файловой базы знаний, MCP-руководство), info20 — учебным треком поверх него (от новичка к оркестрации агентов). Один продукт вместо двух пересекающихся: устраняется дублирование диаграмм и таблиц, а фактические ошибки info20 правятся один раз по общему источнику правды. Первым делом — факт-чекинг против реального Claude Code (нативные `.claude/`, актуальное имя SDK-пакета) и добавление отсутствующих LICENSE.
- **info4 + info30/info20 = устанавливаемый skill-пак.** 101 скилл из info4 конвертируется в актуальный формат плагинов/скиллов Anthropic с манифестом маркетплейса, а методология и стандарт описания из info30/info20 служат инструкцией по установке и валидации. Итог — один из крупнейших неофициальных наборов скиллов Claude, который можно поставить одной командой, вместо бинарных ZIP, недоступных для поиска и ревью.
- **universal-file-storage-mcp + claudeai-test-project-k = юникод-сертификация MCP-сервера.** Моджибейк-баг из тестовой песочницы превращается в прогоняемый набор проверок (кириллица/эмодзи в именах, содержимом, метаданных) для файлового MCP-сервера на Windows/Linux/macOS. Публичное доказательство юникод-корректности, попутно закрывающее пробел universal-file-storage-mcp с отсутствием тестов.
- **meta10 + universal-file-storage-mcp = детерминированная навигация по коду через MCP.** Спроектированный в meta10 пайплайн grep-ast → ast-grep реализуется как MCP-инструменты (`grep_ast` / `ast_grep` / `read_file`) поверх файлового доступа universal-file-storage-mcp. Claude получает структурный, полностью трассируемый поиск по кодовой базе на всех устройствах — третий путь между эмбеддинг-RAG и full-context, спецификация которого в meta10 уже написана и перепроверена.
- **info4 + meta10 = скилл «техническая рецензия».** Методика разбора из meta10 (шаблон + чек-лист верификации по исходникам) оформляется как отдельный скилл в библиотеке info4 — превращая единичный удачный документ в воспроизводимый жанр, который агент может применять к любой статье или инструменту.
