# Вопросы к data15

## 1. Какова судьба PR #5 «Orchestrator v6 improvements» (открыт 16.06.2026)?

PR обещает переход на SQLite WAL (~3200 оп/с против 48), мульти-LLM (Anthropic/OpenAI/Ollama/MiniMax), JWT+RBAC, ChromaDB и Streamlit UI — фактически новое поколение системы. Но он висит без мёржа.

**Варианты ответов:**
- А. Планирую доработать и смёржить — v6 станет основной версией.
- Б. PR экспериментальный, мёржить целиком не буду — заберу отдельные части (например, SQLite).
- В. Про PR забыл / он создан агентом и не проверялся.

**Варианты дальнейших действий:**
- При А: ревью PR (особенно миграция данных JSON→SQLite и совместимость CLI), затем мёрж и обновление DOCUMENTATION.md под v6.
- При Б: разбить PR на атомарные (storage, auth, UI), смёржить приоритетный SQLite-слой первым.
- При В: провести ревью содержимого PR как внешнего кода; если качество низкое — закрыть с комментарием и зафиксировать v5 как стабильную.

## 2. Кто целевые агенты сегодня: Hermes CLI и OpenClaw реально существуют в вашей среде?

Коннекторы ищут `hermes` в PATH и вызывают `openclaw_runner.sh` (NVM+Node.js), Multica ожидается на localhost:3000 — всё это атрибуты исходной песочницы MiniMax (видно по путям `/workspace` и файлам сессий в `user_input_files/`). Вне её всё деградирует в fallback-заглушки.

**Варианты ответов:**
- А. Да, у меня локально стоят Hermes/OpenClaw — система рабочая end-to-end.
- Б. Нет, реально работает только MiniMax-fallback (`hermes_llm.py`).
- В. Хочу переориентировать на другие исполнители (Claude Code, Ollama и т.п.).

**Варианты дальнейших действий:**
- При А: задокументировать в README точные версии/установку агентов и добавить smoke-тест доступности.
- При Б: честно пометить Hermes/OpenClaw-режимы как «требуют внешних CLI», сделать MiniMax/LLM-API основным путём, убрать мёртвый код.
- При В: реализовать реестр провайдеров из PR v6 и первым добавить коннектор Claude Code (у профиля есть info20/info30 с экспертизой по нему).

## 3. Знаете ли вы, что в репозитории закоммичены users.json с хэшами паролей (пароль админа — «admin») и, вероятно, MiniMax-ключ в git-истории?

Коммит «SECURITY: remove hardcoded MiniMax API key» убрал ключ из текущего кода, но история git обычно его сохраняет; `orchestrator/state/users.json` содержит усечённые SHA-256 без соли.

**Варианты ответов:**
- А. Ключ давно отозван, users.json — тестовые данные, риска нет.
- Б. Не проверял; ключ может быть живым.

**Варианты дальнейших действий:**
- При А: всё равно убрать state-файлы из git (гигиена), добавить .gitignore-правила и `users.json.example`.
- При Б: срочно отозвать/перевыпустить ключ MiniMax, затем git filter-repo для очистки истории; заменить схему хэширования на соль+PBKDF2.

## 4. Почему вся система — один файл на 6 579 строк? Это принцип или обстоятельства?

Монолит удобен для копирования в агентную песочницу, но 57 классов в одном файле с monkey-patch-расширениями — барьер для тестов и внешних контрибьюторов.

**Варианты ответов:**
- А. Сознательно: single-file — требование среды выполнения (агентские песочницы).
- Б. Так получилось в спринте; рефакторинг в пакет приветствуется.
- В. Файл писал агент, структура не принципиальна.

**Варианты дальнейших действий:**
- При А: зафиксировать принцип в README и добавить сборщик, который склеивает пакет в single-file артефакт (лучшее из двух миров).
- При Б/В: разбить на пакет `orchestrator/` (core, modules, api, agents) с pyproject.toml, сохранив CLI-совместимость; покрыть pytest-ами по модулям.
