# Характеристика и оценка info40

## Что есть

- **4 запускаемых FastAPI-сервиса** (~2 560 строк суммарно): Gateway с реальным httpx-проксированием и rate limiter'ом; Registry/Marketplace/Orchestrator с полноценными Pydantic-моделями, валидацией, пагинацией, OpenAPI-доками. Как standalone-демо на in-memory данных они, по-видимому, реально запускаются (не проверено запуском).
- **Оркестрационное ядро в миниатюре**: эвристическая декомпозиция задач, построение DAG зависимостей с уровнями исполнения, назначение агентов по рейтингу (`api/orchestrator_service/main.py`).
- **Каркас агента**: абстрактный `AgentWorker` с Prometheus-метриками, семафором конкурентности, отчётами о прогрессе; 2 примера агентов (имитация работы).
- **Python SDK** (~450 строк, aiohttp, async context manager) и **CLI** (556 строк, Typer + Rich) — согласованы с API сервисов.
- **Реальная схема PostgreSQL**: 9 таблиц подтверждены подсчётом `CREATE TABLE` в `database/schema.sql` (576 строк), GIN-индексы, триграммный поиск, триггеры + 667 строк seed-данных.
- **Полный инфраструктурный комплект**: 13 k8s-манифестов (проверено листингом), Helm-чарт с 13 шаблонами, 6 Dockerfile, docker-compose полного стека, docker-compose для мониторинга.
- **Мониторинг**: prometheus.yml (246 строк), alerts.yml (340 строк), recording rules, Alertmanager (106 строк), 3 Grafana-дашборда.
- **Развитая документация**: README, ARCHITECTURE.md (632 строки, Mermaid), AI_AGENT_ORCHESTRATION.md (1 040 строк концепции), CONTRIBUTING (659), SECURITY (258), CHANGELOG (230), README в 8 подкаталогах.
- **Governance-обвязка**: MIT LICENSE, шаблоны PR и issues, CI-workflow (290 строк), Makefile на 74 цели (заявка «70+» — подтверждена).
- **5 use-cases** — детально расписанные, но целиком вымышленные сценарии.

## Чего нет

- **Реальной персистентности**: сервисы НЕ подключены к PostgreSQL/Redis/RabbitMQ — данные в словарях процесса (`agents_db: Dict…`, «In-Memory Storage (Replace with Database)»). Схема БД существует отдельно от кода.
- **Аутентификации**: `get_current_user()` возвращает захардкоженный `"user-123"`; JWT — «в production».
- **Реального исполнения задач**: воркеры имитируют работу `asyncio.sleep`; поллинг задач — placeholder; связь оркестратор→воркер не реализована.
- **Работающего CI**: `ci.yml` гоняет `mypy src/` и `pytest --cov=src`, но каталога `src/` в репозитории нет; ставит зависимости из `docker/requirements/base.txt`. PR #1 слит при «5 of 9 checks passed» — пайплайн фактически красный.
- **Работающих тестов**: `tests/unit/test_registry_service.py` ожидает `status_code == 200` при создании агента, тогда как сервис возвращает 201, и шлёт плоскую схему (`pricing_mode`, `hourly_rate`), тогда как реальная модель требует вложенный объект `pricing` — тесты писались не по фактическому API и упадут. Импорт через `sys.path.insert("../../api/...")`.
- **Файла `helm/agent-platform/values-production.yaml`** — заявлен в PROJECT_SUMMARY, по факту 404.
- **Упаковки проекта целиком**: устанавливается только SDK; сервисы не оформлены как пакеты; в setup.py — вымышленные URL и e-mail (`agent-platform.example.com`).
- **Issues/веток/внешних участников**: 0 issues, 0 открытых PR, 1 звезда.

## Плюсы

- Редкая для профиля полнота инженерного контура: код + БД + Docker + k8s + Helm + мониторинг + CI + тесты + доки в одном репозитории — хороший учебный образец «как выглядит платформа целиком».
- Осмысленная предметная модель marketplace (ценообразование commercial/volunteer/hybrid, контракты, отзывы, транзакции, аудит) — согласована между API, SQL-схемой и SDK на уровне идей.
- Качественный код в отдельности: типизация, Pydantic-валидация, docstrings, Prometheus-метрики, аккуратные enum'ы.
- Схема PostgreSQL — самая «настоящая» часть: продуманные индексы (GIN, триграммы), триггеры, представления.
- Честные маркеры «In production, this would…» внутри кода.
- Есть LICENSE (MIT), SECURITY.md, CONTRIBUTING.md — формальная гигиена соблюдена.

## Минусы

- **Системное завышение заявлений**: маркетинговый README обещает production-платформу; фактически — витринный прототип. Цифры (строки, размеры документов) завышены в разы.
- **Компоненты не соединены**: схема БД, очереди, кэш существуют только в инфраструктурных файлах; сервисы работают на словарях; воркеры не получают задачи от оркестратора.
- **Тесты и CI декоративны**: не соответствуют коду и структуре, что подтверждается провалом чек-ранов в PR #1 (5/9) и 20+ замечаниями Trivy.
- **Дублирование моделей** между 4 сервисами, SDK и тестами без единого источника истины — схемы уже разъехались.
- **Одномоментность**: весь контент сгенерирован за один день (31.01.2026); после этого — только merge собственного PR в апреле; развития, issues, пользователей нет.
- Use-cases с вымышленными «результатами» могут вводить читателя в заблуждение.

## Качество кода и документации

Код — аккуратный, идиоматичный FastAPI/Pydantic, читается легко; но это «горизонтальный» код одной итерации: без слоёв, без реальных интеграций, с повторами между сервисами. Документация обильна и хорошо структурирована (особенно ARCHITECTURE.md и README подкаталогов), однако страдает главным грехом: описывает желаемое, а не действительное — PROJECT_SUMMARY перечисляет файлы и объёмы, которых нет. Для использования репозитория как референса документацию нужно читать вместе с этим аудитом.

## Зрелость: 2/5

Обоснование: превосходный по охвату скелет (что тянуло бы на 3), но ни один сквозной сценарий не работает по-настоящему: нет БД-персистентности, auth — заглушка, агенты — имитация, тесты падают, CI не подогнан под репозиторий, один из заявленных файлов отсутствует, а ключевые метрики проекта завышены. Как концепт-документ + учебный каркас — ценно; как «production-ready платформа» — не соответствует заявленному уровню.
