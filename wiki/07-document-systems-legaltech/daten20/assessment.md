## Что есть (реально сделано)

- **Работоспособное предметное ядро**: мега-шаблон `mSchablone` (проверен), парсер (`src/core/parser.py` — читаемый типизированный код), финансовые модели с реальными ставками немецкого соцстрахования и Decimal-арифметикой (`src/models/financial.py`), предметные тестовые фикстуры (`tests/conftest.py`).
- **16 CLI-приложений** в корне — существование проверено выборочно (`doc-processor.py`, `doc-ocr.py`, `doc-translator.py`, `doc-dashboard.py`, `enterprise-admin.py`, `locustfile.py` — все 200 OK); у главного CLI осмысленная структура импортов и подкоманд.
- **Живой CI**: 13 workflow, 2500+ прогонов Actions; workflow «Tests» реально проходит на Python 3.9–3.11 с установкой tesseract/poppler.
- **Инфраструктурная обвязка**: Dockerfile, docker-compose, k8s-манифесты, nginx, alembic, Makefile с lint/format/test, pre-commit — по составу файлов (содержимое k8s/nginx не читалось).
- **Большой объём тестов**: ~80 файлов `test_*.py` на верхнем уровне `tests/` — почти по одному на каждый модуль `src/`, включая AI-надстройку — плюс ~18 поддиректорий, зеркалящих `src/` (unit, integration, e2e, performance, fixtures, core, ai, security, microservices…). Оговорка: CI прогоняет лишь 7 из этих файлов (`test_doc_*.py`).
- **729 коммитов, 116+ PR** — история разработки реальная, не однокоммитный дамп.
- **Точные попадания самоотчётов**: заявление README «BCI — 2 254 строки» совпало с `wc -l src/bci/bci_services.py` = 2254 (проверено).

## Чего нет

- **Файла LICENSE** — 404 по всем стандартным путям (LICENSE, LICENSE.md, LICENSE.txt, COPYING), при этом в README висит MIT-бейдж. Юридически проект не имеет лицензии.
- **Подтверждения «284/284» и «2 030+ тестов»**: CI по `tests.yml` запускает только `pytest tests/test_doc_*.py` — 7 файлов из ~80 (перепроверено: `test_doc_*` = 7 штук). Полный прогон всех тестов в CI не настроен (есть отдельные workflow advanced-ai-tests/e2e — их статус не проверялся); workflow «Coverage Report» стабильно падает.
- **Согласованных метрик**: три самоотчёта дают три набора цифр — AUDIT_REPORT.md (11.01: 183 py-файла / 89 176 строк Python, 127 710 строк всего в 234+ файлах), STATUS_OVERVIEW.md (19.01: 241 файл, ~140k строк, «172/172 тестов»), README (399 файлов, 214 654 строк, «284/284»). Рост за 10 дней в 1,7 раза возможен при ИИ-генерации, но ни одна цифра независимо не подтверждена.
- **Реальности заявленных внешних движков**: README обещает OCR (Tesseract/EasyOCR/PaddleOCR), перевод (Google/DeepL), spaCy NER — зависимости в CI ставятся с `|| true`, т.е. допускается их отсутствие; фактическая работоспособность не проверена.
- **Развития после января 2026**: roadmap «v5.0+ PLANNED 0%», dependabot-PR с апреля не влиты, human-коммитов нет 5+ месяцев.
- **Пользователей**: 0 звёзд, 0 форков; продукт никем, кроме автора, не проверялся.
- **Упаковки как пакета**: `setup.py` — интерактивный инсталлятор окружения, а не setuptools-пакет; на PyPI проект не публиковался (не проверено, но признаков нет).

## Плюсы

1. Настоящая, редкая предметная область: калькуляция услуг персонального бюджета по немецким правилам соцстрахования — такое не генерируется «из воздуха» и имеет практическую ценность.
2. Инженерная культура выше среднего для профиля: CI-матрица по трём версиям Python, pre-commit, Makefile, dependabot, auto-merge, Docker/k8s-обвязка.
3. Dual-version дизайн (Pure Python ↔ NumPy) — осознанное архитектурное решение с честными дисклеймерами в docstring («mock/simplified DSP», «НЕ создаёт феноменального сознания»).
4. Внутренний `AUDIT_REPORT.md` сам честно классифицирует v21–30 как «концептуальные» — самокритика в проекте присутствует.
5. История разработки прозрачна: PR-ы, осмысленные сообщения коммитов, журнал версий.

## Минусы

1. **Систематическое завышение в README**: «Production-Ready», «zero dependencies» (при Flask/PyYAML в requirements.txt), «реальные DSP алгоритмы» (docstring говорит «mock/simplified»), «2 030+ тестов» (CI гоняет подмножество). Витрина расходится с содержимым.
2. **Версионная инфляция**: v8.0.0–v23.0.0 датированы одним днём (2026-01-19); «версии» — это сессии генерации, а не релизы.
3. **Хайп-модули разъедают доверие**: `asi_beyond_human`, `cosmic_universal`, `absolute_singularity`, `the_void` в одном src/ с рабочим финансовым калькулятором делают продукт непригодным для показа заказчику без чистки.
4. **Дублирование и энтропия**: подтверждённые пары директорий, существующие одновременно (`network6g`/`network_6g`, `explainable`/`explainable_ai`, `quantum`/`quantum_ml`/`qml`, `emotions`/`emotions_ai`, `federated`/`federated_learning` — все дают 200); ~80 тест-файлов свалены плоско в один `tests/`, а CI гоняет из них лишь 7.
5. **Мёртвый груз поддержки**: 13 workflow и dependabot продолжают жечь Actions-минуты на проекте, который не развивается; Coverage перманентно красный.
6. Отсутствие LICENSE при MIT-бейдже — прямое несоответствие заявленного и фактического.

## Качество кода и документации

Прочитанные модули ядра (`parser.py`, `financial.py`, `conftest.py`, `doc-processor.py`) — добротный Python: типизация, docstring, Decimal для денег, дата-классы, разумная декомпозиция. AI-модули выборки (bci, consciousness) — большие, структурированные, но по собственным дисклеймерам упрощённо-имитационные; их ценность — учебная/демонстрационная, не прикладная. Документация огромна (150+ файлов), но на ~80 % это самоотчёты о процессе генерации (PLAN/SESSION_REPORT/STATUS), а не документация для пользователя; при этом README как пользовательский вход написан хорошо, только не правдиво в деталях.

## Зрелость: 3/5

Обоснование: есть реальное работающее ядро с предметной ценностью, живой CI, тесты, Docker и история из 729 коммитов — это выше типичного «info»-репозитория профиля (2/5 не дать). Но: ключевые метрики недостоверны и противоречат друг другу, полный тестовый прогон в CI не подтверждён, лицензии нет, половина кодовой базы — концептуальные имитации, развитие остановлено на самоироничной «Пустоте v30». До 4/5 не дотягивает из-за разрыва «заявлено/проверено» и отсутствия внешних подтверждений работоспособности (0 пользователей, падающий coverage).
