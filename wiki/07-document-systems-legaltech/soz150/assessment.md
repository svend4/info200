# Характеристика и оценка soz150

## Что есть

- **Полный исходник работающего артефакта** `WritingOS (5).jsx` (2043 строки): семантический роутер skills, песочница JS + Python (Pyodide WASM) с персистентным REPL, SSE-стриминг, auto-retry при ошибках кода, сохранение сессий в `.wos`, Skill Composer и двухуровневый Legal Assertion Checker с доменными правилами по SGG (Widerspruch/Klage/Eilantrag). Судя по коду, это законченная, продуманная вещь уровня «продвинутый прототип».
- **Отличный handoff-документ** `WRITING_OS_HANDOFF (1).md`: архитектура (CAGE), таблицы всех функций, форматы данных, константы, честный раздел «Известные ограничения» с severity, дорожная карта на 5 приоритетов, паттерны расширения, глоссарий. Редкий по качеству образец передаточной документации в профиле.
- **Фрагмент большого приложения** `wos-v14/`: оболочка на 38 панелей и 3 содержательные панели (генератор писем в органы с правовыми основаниями, трекер медзаключений с базой типовых ошибок MDK, аналитика Recharts). Виден масштаб основного проекта: PIN-шифрование, PWA, локальный RAG, IndexedDB.
- **Уникальная доменная экспертиза**, зашитая в код: §§ SGB IX/X/XII и SGG, прецеденты BSG (B 8 SO 9/19 R и др.), правила исчисления сроков (§64 SGG, +3 дня почтовое правило §37 SGB X), типовые ошибки MDK-заключений. Это контент, который сложно воспроизвести.

## Чего нет

- **35 из 38 панелей и все базовые модули** приложения v14: `db`, `store`, `hooks`, `components`, `security/LockScreen`, `security/crypto`, `rag/embedder`, `rag/vectorStore` и др. — `App.jsx` их импортирует, но в репозитории они отсутствуют (проверено: 404 по каждому пути). Приложение **не собирается**.
- **`package.json`, сборка, манифест зависимостей** — нет даже для присутствующего фрагмента (react, recharts не зафиксированы).
- **Тесты** — ни одного (при том, что regex-правила Assertion Checker и расчёт сроков — идеальные кандидаты на unit-тесты).
- **CI/CD** — отсутствует.
- **Лицензия** — отсутствует; для кода с юридическим контентом и потенциальными пользователями это существенно.
- **Осмысленный README** — 2 строки «# soz150 / info»; вся реальная информация спрятана в handoff-файле с непрезентабельным именем.
- **Дисклеймер** «не является юридической консультацией» — для инструмента, генерирующего Widerspruch/Klage, желателен.
- Issues/задачи — не используются; дорожная карта живёт только внутри markdown.

## Плюсы

1. Реальная, редкая ниша: self-help legal tech для немецкого социального права (SGB IX/XII), причём с механизмом **проверки** сгенерированных документов, а не только генерации.
2. Архитектурно интересный паттерн CAGE и таксономия расширяемости L0–L5 — это переносимо на другие домены.
3. Handoff-документ честен: сам перечисляет XSS-риски, отсутствие таймаутов, недетерминированность роутера — с оценками severity и готовыми фрагментами исправлений.
4. Grep-подтверждаемая аккуратность: заявленные в документации цифры совпадают с кодом (см. «Перепроверка» ниже).
5. Доменные данные (ошибки MDK, §§, BSG-прецеденты) встроены прямо в код панелей — работают офлайн.

## Минусы

1. Репозиторий — свалка снапшотов, а не проект: имена « (1)», « (5)», zip-дубликат, пустой README, отсутствие большей части кодовой базы v14.
2. Подтверждённые кодом риски безопасности: `new Function()` без песочницы (строка 397), `dangerouslySetInnerHTML` без санитизации (строка 594), нет таймаута исполнения — всё это признано в handoff как HIGH/MEDIUM, но не исправлено.
3. Два несвязанных «Writing OS» под одной крышей без объяснения их взаимоотношений — аудитору пришлось устанавливать это раскопками.
4. `const P = path => lazy(() => import(path))` в `App.jsx` — динамический import с переменным путём; Vite/Rollup такое статически не разрезает, при реальной сборке лениво-загружаемые панели, скорее всего, сломаются (не проверено сборкой — файлов не хватает).
5. Хранение части данных в localStorage (gutachten, fristen…) при наличии IndexedDB — двойная система хранения, риск рассинхронизации; localStorage не переживает очистку сайта.
6. Ключ API в артефакте не передаётся (расчёт на прокси claude.ai) — вне claude.ai артефакт работать не будет; это нигде не оговорено.

## Качество кода и документации

Код артефакта — плотный, идиоматичный React без TypeScript; секции хорошо разграничены, имена говорящие, но 2043 строки в одном файле и 14+ useState в главном компоненте затрудняют сопровождение (сам handoff предлагает useReducer/Zustand). Панели v14 — аккуратные, с комментариями на русском/немецком, но с локальными анти-паттернами (глобальный счётчик `let _ID = Date.now()` для id, прямые обращения к localStorage без абстракции). Документация — двухполюсная: README нулевой, зато handoff — 5/5.

## Перепроверка самоотчётов (аудит-перепроверка)

В репозитории есть самоотчёт — `WRITING_OS_HANDOFF (1).md` (статус на 13.04.2026). Проверка его заявлений по факту:

| Заявление handoff | Факт | Вердикт |
|---|---|---|
| «Всё в одном файле: WritingOS.jsx, ~2043 строк» | `wc -l` = ровно 2043 строки | совпадает |
| «40 функций» | grep по объявлениям даёт ~37 верхнеуровневых (+ вложенные хелперы) | примерно совпадает |
| 5 типов вызовов Anthropic API (router, main, composer, semantic, retry) | найдено ровно 5 `fetch("https://api.anthropic.com/v1/messages")` — строки 71, 320, 806, 1528, 1645 | совпадает |
| Ограничения: `new Function()` без sandbox; `dangerouslySetInnerHTML` без DOMPurify | подтверждено в коде: строки 397 и 594 | совпадает (и не исправлено) |
| Константы `MAX_RETRIES=2`, ключ `wos_custom_skills_v1`, формула 0.4·L1+0.6·L2, порог 60 | все найдены в коде | совпадает |
| Pyodide 0.25.1 с CDN jsdelivr | подтверждено (строки 371, 375) | совпадает |
| `App.jsx v14 (38 панелей)` (шапка файла) | в NAV ровно 38 вкладок, в карте Panels — 38 записей | совпадает по коду, **но** в репозитории лежат лишь 3 файла панелей из 38 |

Итог перепроверки: **handoff достоверен** по отношению к артефакту; вводит в заблуждение только состояние `wos-v14` — по наличию папки можно подумать, что там всё приложение, тогда как это ~8% его файлов.

## Зрелость: 2/5

Обоснование: содержимое интеллектуально зрелое (работающий прототип + образцовая документация одного из компонентов), но как **репозиторий** проект незрел: не собирается, большая часть заявленной кодовой базы отсутствует, нет README, лицензии, тестов, CI, зависимостей; 5 коммитов за 2 дня и тишина 2,5 месяца. Оценка 2/5 отражает «ценный, но сырой склад снапшотов»; при переносе полной кодовой базы v50 и минимальной инфраструктуре легко поднимется до 3–4.

*Ограничение покрытия аудита: проверка выполнялась без клонирования (raw-доступ + WebFetch); прочитаны все 8 файлов репозитория (100% содержимого), zip распакован и сверен. Работоспособность артефакта в среде claude.ai и поведение сборки v14 вживую не проверялись.*
