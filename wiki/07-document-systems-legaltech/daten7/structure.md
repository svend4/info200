## Ключевые файлы и их роли

| Файл | Роль | Что внутри реально ценного |
|---|---|---|
| README.md | навигация | аннотация каждого документа, схема выбора конфигурации, «следующие шаги» для пользователей и разработчиков |
| MODULAR_DATA_PIPELINE_ARCHITECTURE.md | концепция | самый компактный документ; фиксирует главную идею — аккордеон из модулей-«ступенек» с триадой ввод/обработка/вывод |
| CONFIG_MINIMAL.md | спецификация MVP | 7 модулей, честно перечислены ограничения (нет PDF, ML, визуализации) и зависимости |
| CONFIG_STANDARD.md | спецификация ETL-уровня | модули 8–20 с деталями (типы join, правила валидации, типы графиков) |
| CONFIG_MAXIMUM.md | спецификация enterprise | модули 21–52, включая ML/NLP/безопасность/автоматизацию |
| MODULES_SUMMARY.md | реестр | единственное место, где все 52 модуля видны разом; таблица категорий (с мелкими накладками, см. assessment) |
| MODULE_EXAMPLES.md | UX-прототип на бумаге | ASCII-макеты развёрнутого/свёрнутого состояний модулей — фактически текстовые wireframe'ы |
| PIPELINE_PATTERNS.md | проектирование потоков | JSON-описания конвейеров, которые могли бы стать схемой конфигурационного формата |
| APPENDIX_A | plug-in подсистема | манифест module.json, версионирование `email_extractor@1.0.0`, CLI-команды |
| APPENDIX_B | контракт кода | `BaseModule.process(ModuleInput) -> ModuleOutput` — центральный интерфейс всей системы |
| APPENDIX_C | примеры реализации | 6 модулей с module.json + processor.py + requirements.txt (только как текст в md) |
| APPENDIX_D | onboarding | пошаговый гайд + чеклист публикации модуля |

## Особенности организации

1. **Плоская структура без папок** — для 12 файлов приемлемо; навигация обеспечивается README-оглавлением с относительными ссылками (все ссылки указывают на существующие файлы — проверено по списку корня).
2. **Единый шаблон описания модуля** (Категория/Приоритет → Ввод → Обработка → Вывод) выдержан во всех трёх CONFIG-файлах — документация однородная.
3. **Двухслойность**: слой «что строим» (архитектура + конфигурации) и слой «как расширяем» (приложения A–D о plug-in системе). Второй слой заметно опережает первый: подробно описана экосистема установки модулей для системы, у которой нет ни одной строки реализованного ядра.
4. **Код существует только внутри Markdown** — нет ни одного .py-файла; примеры из APPENDIX_C ссылаются на несуществующий пакет `core.module_api`.
5. Все документы датированы одним днём (2025-12-28) и создан коммитами бота claude — это единовременно сгенерированный пакет документации, влитый через PR #1.
