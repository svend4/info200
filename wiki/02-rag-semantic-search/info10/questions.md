# Вопросы к info10

## 1. Где должен жить пакет `docstoolkit`, без которого шлюз не запускается?

Все три шлюза импортируют `docstoolkit.rag`, но пакета нет ни в репозитории, ни в `requirements.txt` — контейнер падает при старте.

**Варианты ответов:**
- А. Ставится из lorenzo (docs-toolkit) — просто забыли прописать зависимость.
- Б. Планировалось вендорить копию пакета прямо в info10.
- В. Шлюз запускался только локально, где docstoolkit уже был установлен; про Docker-путь не думали.

**Варианты дальнейших действий:**
- При А: добавить в requirements.txt установку из git (`git+…lorenzo#subdirectory=docs-toolkit`) и шаг клонирования корпуса в Dockerfile; проверить `docker compose up`.
- При Б: скопировать пакет в `daf-gateway/docstoolkit/`, зафиксировать версию, синхронизацию с lorenzo описать в README.
- При В: задокументировать локальный сценарий запуска и всё равно починить Docker-путь либо удалить Dockerfile, чтобы не обещать несуществующее.

## 2. Каков реальный статус проекта: «полностью готово», как написано в документации, или прототип?

`DAF_FULL_DOCUMENTATION.md` заявляет «Статус: Полностью готово к использованию», но аудит показал неработоспособность из коробки и нереализованные функции (MCP-активация, rate limiting, tool calling).

**Варианты ответов:**
- А. Это оптимистичная запись из чат-сессии; реальный статус — прототип.
- Б. Где-то (Render.com?) есть работающий деплой с доустановленными зависимостями.
- В. Проект заброшен, развитие ушло в другие репозитории (nautilus, info40).

**Варианты дальнейших действий:**
- При А: заменить статус в доках на «прототип», перечислить нереализованное отдельным списком TODO.
- При Б: добавить в README ссылку на живой эндпоинт и конфигурацию деплоя; тогда перепроверить заявления повторно.
- При В: заархивировать репозиторий с честным README-указателем на преемника.

## 3. Куда info10 относится в экосистеме: самостоятельный сервис или модуль lorenzo?

daf-gateway полностью построен вокруг корпуса и пакета lorenzo, но лежит отдельным репозиторием.

**Варианты ответов:**
- А. Должен слиться с lorenzo (папкой рядом с docs-toolkit).
- Б. Останется отдельным сервисом-«спутником», который клонирует lorenzo при старте.
- В. Должен стать универсальным шлюзом для любого md-репозитория (lorenzo — лишь первый корпус).

**Варианты дальнейших действий:**
- При А: перенести папку в lorenzo, info10 заархивировать — минус один репозиторий из 61.
- При Б: добавить механизм получения корпуса (clone/volume/submodule) и указать его в docker-compose.
- При В: параметризовать REPO_URL, вынести lorenzo-специфику (словарь `clean_voice_query`) в конфиг; см. сценарий 3 в [рекомендациях](recommendations.md).

## 4. Осознан ли риск эндпоинта `/api/git/write` без аутентификации?

Сейчас любой, кто дотянется до порта 8083, может записать произвольный файл (включая пути вне `/app` через `..`) и запушить коммит в svend4/info10 от имени вашего токена. `LORENZO_API_KEY` объявлен в `.env.example`, но кодом не проверяется.

**Варианты ответов:**
- А. Сервис задумывался только для локального запуска / доверенной сети.
- Б. Проверку ключа планировали, но не дописали (об этом говорят неиспользуемые импорты `Depends, Header`).
- В. Риск не рассматривался.

**Варианты дальнейших действий:**
- При А: явно написать в README «не выставлять в интернет», привязать uvicorn к 127.0.0.1.
- При Б/В: дописать зависимость с проверкой заголовка ключа, валидацию `req.path` (`resolve()` + `is_relative_to`), заменить прямой push в main на ветку+PR; ограничить права токена одним репозиторием.

## 5. Что означает «shop» в описании репозитория «info, shop»?

В содержимом ничего про магазин нет; при этом в профиле есть отдельные «магазинные» репо (daten2, meta4, data40, daten23).

**Варианты ответов:**
- А. Наследие старого замысла (репо создавалось 28.01.2026 под другую задачу) — описание устарело.
- Б. Планировалась витрина/магазин на базе DAF, но не началась.

**Варианты дальнейших действий:**
- При А: сменить описание на «DAF gateway for Lorenzo corpus» — навигация по 61 репозиторию станет честнее.
- При Б: зафиксировать замысел issue-заметкой или перенести «магазинную» часть в профильные репо (data40/daten23).

## 6. Нужны ли три параллельных варианта шлюза (light/medium/pro) в main?

Три файла дублируют друг друга, плюс лежит случайный дубликат `l orenzo_pro_gateway.py` с пробелом в имени.

**Варианты ответов:**
- А. Это учебная история эволюции — оставить как есть.
- Б. Нужен только pro-вариант, остальное можно удалить.

**Варианты дальнейших действий:**
- При А: перенести light/medium в `examples/` или `docs/history/`, дубликат с пробелом удалить в любом случае.
- При Б: оставить один `lorenzo_pro_gateway.py`, вынести общий код (модель ответа, ask-обёртку) в модуль, обновить документацию.
