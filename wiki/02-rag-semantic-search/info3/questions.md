# Вопросы к info3

## 1. Что является главной ценностью проекта — контент (афоризмы/формулы) или код (псевдо-RAG)?

Репозиторий тянет в обе стороны: ~450 файлов гуманитарного контента и ~24 700 строк Python. Развивать одновременно оба направления дорого.

**Варианты ответов:**
- А. Контент — код лишь инструмент доступа к нему.
- Б. Код — афоризмы были тестовым датасетом.
- В. Именно связка «гуманитарное знание + машинная обработка» и есть идея.

**Варианты дальнейших действий:**
- При А: чистка и атрибуция цитат, публикация как сайт/датасет (сценарии B и C из рекомендаций), код заморозить.
- При Б: выделить ядро в pip-пакет `mini-rag` (сценарий A), контент сократить до демо-папки.
- При В: приоритет — конвейер разметки всех тем в JSON по 4 уровням, чтобы связка заработала на всём корпусе, а не на одной теме.

## 2. Проверялся ли «реальный» стек (semantic search, production API) с настоящими зависимостями?

Аудит подтвердил только запуск `micro_agent_simple.py` без зависимостей; работа FAISS, sentence-transformers, JWT-API, WebSocket и frontend вживую не проверена.

**Варианты ответов:**
- А. Да, всё запускалось локально и работало.
- Б. Запускалось частично (например, только rag_api_server).
- В. Нет, код писался «на веру» без прогона тяжёлого стека.

**Варианты дальнейших действий:**
- При А: зафиксировать это — добавить скринкаст/скриншоты дашборда в README и смок-тесты в CI, чтобы работоспособность была доказуемой.
- При Б: составить список непроверенных модулей и прогнать их; сломанное чинить или помечать experimental.
- При В: до любого развития — один вечер на `pip install -r requirements.txt` и прогон демо; результаты занести в IMPLEMENTATION-STATUS (и заодно исправить завышенные метрики).

## 3. Зачем в репозитории ~14 000 строк заведомо фантастических модулей (уровни 4–6) и какова их судьба?

`akashic_records.py`, `knowledge_telepathy.py`, `quantum_knowledge.py` и др. честно помечены «Reality: 1–30%», но составляют около половины кодовой базы и создают ложное впечатление о размере системы.

**Варианты ответов:**
- А. Это художественно-концептуальная часть проекта, она важна.
- Б. Это упражнение «дописать все 26 направлений до 100%», практической роли нет.
- В. Часть из них — заготовки на будущее (например, multi_agent_system, active_learning).

**Варианты дальнейших действий:**
- При А: вынести в `speculative/` с собственным README-манифестом — сохранить, но не смешивать с рабочим ядром.
- При Б: перенести в архивную ветку/репозиторий, ядро станет обозримым и поддерживаемым.
- При В: провести триаж: реалистичные модули (уровни 3–4) довести до тестов, фантастику (5–6) архивировать.

## 4. Откуда взяты афоризмы и как обстоит дело с правами и достоверностью атрибуции?

В корпусе смешаны классические цитаты (Сократ, Раневская, Твен) и явно сгенерированный наполнитель; заявлено «~90 000+ афоризмов», источники описаны обобщённо («классические произведения, народное творчество, стиль АиФ»).

**Варианты ответов:**
- А. Большая часть сгенерирована LLM «в стиле», реальных цитат меньшинство.
- Б. Собрано из открытых источников без проверки атрибуции.
- В. Атрибуция проверялась для классических разделов.

**Варианты дальнейших действий:**
- При А: пометить сгенерированное поле «generated: true» — тогда корпус честно пригоден как синтетический датасет.
- При Б: перед любой публикацией — выборочная проверка атрибуции хотя бы для именованных авторов (риск ложных приписываний цитат).
- При В: задокументировать методику проверки в README афоризмов и распространить её на остальные разделы.

## 5. Планируется ли разметка остальных тем в машиночитаемый формат (сейчас JSON/YAML есть только для «искусственного интеллекта»)?

Вся идея «4 уровня внутри псевдо-RAG» опирается на структурированные данные, но размечена одна тема из сотен.

**Варианты ответов:**
- А. Да, вручную по мере сил.
- Б. Да, автоматически через LLM-конвейер (заготовка — automated_extraction.py).
- В. Нет, одна эталонная тема — достаточная демонстрация.

**Варианты дальнейших действий:**
- При А: начать с 21 корневой «пары качеств» — они короткие и однородные; схему JSON зафиксировать как JSON Schema.
- При Б: собрать конвейер с валидацией по схеме и выборочной ручной проверкой 5–10%; это главный кандидат на следующую итерацию проекта.
- При В: явно написать это в README и перевести проект в статус «завершённый эксперимент» с тегом v1.0.
