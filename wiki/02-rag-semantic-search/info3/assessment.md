# Характеристика и оценка info3

## Что есть (реально сделано и проверено)

- **Большая контентная база**: папка `афоризмы/` с сотнями тематических подпапок; выборочные проверки подтвердили существование заявленных файлов (`философия/античная.txt`, `добро-и-зло/…`, `квантовые-компьютеры/…`, `нанотехнологии/…`, `смех-и-слезы/…`). В `античная.txt` — узнаваемые классические цитаты. Плюс 21 корневая папка «пар качеств» с афоризмами.
- **35 Python-модулей (~24 700 строк)**: все синтаксически корректны (`py_compile` пройден), каждый с демо-блоком. Модуль `micro_agent_simple.py` реально запущен при аудите и отработал без зависимостей (агент анализирует запрос, выбирает уровни, принимает стратегию).
- **Продуманный «реальный» слой**: семантический поиск (FAISS + sentence-transformers с fallback), персистентное хранилище (SQLite/Redis/JSON, TTL, история), production API (JWT, rate limiting, Prometheus, health checks), WebSocket, графовая БЗ (Neo4j/networkx).
- **Валидные машиночитаемые данные**: `искусственный-интеллект.json` (проверен парсером — валиден, структура level_1_formula … level_4_theorem) и его YAML-двойник.
- **Обширная документация**: ~10 600 строк markdown (7 доков в `machine-readable/` + `ФОРМАТЫ-README.md` 601 строка + README афоризмов 1 897 строк). Дорожная карта из 6 уровней с честными оценками реалистичности.
- **React-дашборд** (`frontend/`, 1 447 строк кода): JWT-логин, поиск, WebSocket-стрим, графики; работает без сборки (CDN).
- **Интеллектуальная честность в коде**: фантастические модули (`akashic_records.py` и др.) прямо помечены «Reality: 1%», «Cannot be Verified» — авторы не выдают симуляции за работающие системы.

## Чего нет

- **Тестов**: ни одного файла `test_*.py`, ни pytest-инфраструктуры (пара функций `test_*` только внутри `websocket_server.py` как ручные сценарии). При ~24 700 строках кода — ноль автоматической проверки.
- **CI/CD**: `.github/workflows/` отсутствует (проверено — 404).
- **Лицензии**: файла LICENSE нет — формально код нельзя легально переиспользовать.
- **Упаковки**: нет `pyproject.toml`/`setup.py`, `__init__.py`; requirements.txt есть, но установка «pip install -e .» невозможна.
- **Корневого README**: 2 строки («# info3 / info») — навигации по репозиторию из ~24 корневых папок нет вообще.
- **Данных для большинства тем**: машиночитаемая разметка по 4 уровням существует только для одной темы («искусственный интеллект»); сотни гуманитарных тем в JSON/YAML не переведены.
- **Заявленного файла**: `training_data_ai.json` фигурирует в структуре `machine-readable/README.md`, но в репозитории отсутствует (404).
- **Проверки работы тяжёлого стека**: работоспособность semantic search / API с реальными зависимостями (faiss, transformers, neo4j) при аудите не проверялась — «не проверено».

## Плюсы

- Оригинальная концепция: 4-уровневая система (формула → архетип → алгоритм → теорема) как способ формализации гуманитарного знания — узнаваемая авторская идея профиля svend4.
- Честная стратификация по реалистичности (уровни 1–6) — редкий случай, когда спекулятивный код явно отделён от рабочего.
- Грамотный паттерн graceful degradation: всё запускается без тяжёлых зависимостей.
- Полный вертикальный срез: данные → поиск → API → real-time → UI.
- Большой связный корпус русскоязычного контента, пригодный как датасет для RAG-экспериментов.

## Минусы

- **Инфляция самоотчёта**: `IMPLEMENTATION-STATUS.md` заявляет «~30 500+ строк кода», фактически Python + frontend ≈ 26 500; «100% реализовано» для уровней 5–6 означает лишь «написана симуляция».
- **Качество контента неровное**: рядом с подлинными цитатами Сократа — сгенерированный наполнитель («Сила: поднять тяжёлое», «Слабость онлайн: сдаться трудностям»); заявленные «~90 000+ афоризмов» не пересчитывались и выглядят завышенными.
- ~14 000+ строк (уровни 4–6) — по сути мёртвый груз: симуляции «телепатии» и «хроник Акаши» не имеют практического применения.
- Монолитная свалка в корне: сотни кириллических папок + код + доки без индекса.
- Дублирование серверов (`rag_api_server.py` vs `production_api.py`) без указания, какой актуален.
- Коммиты-«фейерверки» с эмодзи-вехами затрудняют понимание реальных изменений.

## Качество кода и документации

Код — аккуратный «AI-generated production style»: типизация, датаклассы, докстринги, единый стиль, разумные fallback-и; но без тестов и отзывов реальной эксплуатации это качество не подтверждено под нагрузкой. Документация обильная и структурированная, местами избыточная (README афоризмов содержит абзац-«простыню» на тысячи слов, перечисляющий все темы через запятую). Самоаудит `IMPLEMENTATION-STATUS.md` детален, но его метрики следует делить на поправочный коэффициент (см. выше).

## Зрелость: 3/5

**Обоснование**: проект существенно больше и связнее среднего репозитория профиля (118 коммитов, рабочий вертикальный срез, демо запускается, данные валидны) — это выше «2». Но отсутствие тестов, CI, лицензии, упаковки, наличие фактических расхождений в самоотчёте (несуществующий `training_data_ai.json`, завышенные строки), однотемность машиночитаемых данных и ~половина кодовой базы в виде спекулятивных симуляций не позволяют дать «4». Итог: добротный завершённый эксперимент, не продукт.

**Ограничение покрытия аудита**: из 35 модулей детально прочитаны ~8, остальные оценены по заголовкам, размерам и компиляции; контентные папки проверены выборочно (6–8 файлов); полный подсчёт афоризмов и запуск тяжёлого стека не выполнялись.
