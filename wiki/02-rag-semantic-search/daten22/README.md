# daten22 — база знаний MBTI + два поисковых прототипа (RAG и PseudoRAG) + Android-приложение офлайн-поиска

## Обзор

daten22 — гибридный репозиторий, в котором под одной крышей живут четыре взаимосвязанных подпроекта:

1. **Документация MBTI** — большая русскоязычная база знаний о 16 психологических типах личности Майерс-Бриггс: 47 markdown-документов в `docs/` и 16 подробных описаний типов в `types/` (общий объём порядка 1 МБ текста).
2. **RAG-система** (`rag/`, Python) — семантический поиск по этой документации: LangChain + ChromaDB + мультиязычные sentence-transformers, с CLI и веб-интерфейсом на Streamlit, опциональной генерацией ответов через GPT-3.5.
3. **PseudoRAG** (`pseudorag/`, Python) — оригинальный концептуальный прототип: онтология из «16 информационных архетипов» (аналог 16 типов MBTI, но для классификации любых сущностей реальности) и расширитель запросов, превращающий один вопрос («Города Европы») в структурированный вопросник из десятков вопросов по архетипам.
4. **Android Document Search** (`android-document-search/`, Kotlin) — полноценный Android-проект офлайн полнотекстового поиска по документам (PDF, DOCX, TXT, MD, LOG) на SQLite FTS4, Room, MVVM, Material Design 3. Именно эта часть соответствует описанию репозитория «Offline search app with SQLite FTS4».

Описание репозитория на GitHub: «Info / поисковой оффлайн апп c SQLite FTS4 / 16 архетипов Псевдо RAG». Языки по статистике GitHub: Python 71.1%, Kotlin 24.8%, Shell 4.1%.

## Назначение и идея

Сквозная идея репозитория — число 16 как организующий принцип знаний:

- Сначала была создана **энциклопедия 16 типов личности MBTI** (теория, дихотомии, когнитивные функции, соционика, совместимость 16×16, применение в карьере, отношениях, обучении и т.д. — 42 тематических документа плюс 16 описаний типов).
- Затем над ней надстроили **семантический поиск (RAG)**, чтобы задавать вопросы к базе знаний на русском языке.
- Дальше идея 16 типов была обобщена до философской онтологии: **16 информационных архетипов** (документы `docs/50-54` и код `pseudorag/`) — 4 бинарные оси (материальность, динамика, масштаб, структура) дают 16 «типов сущностей» (Кристалл, Песок, Здание, Город, Алгоритм, Общество…), по которым любой запрос раскладывается в структурированный вопросник — «псевдо-RAG» без векторной базы.
- Параллельно добавлено **офлайн Android-приложение** для полнотекстового поиска по локальным документам — практическое воплощение темы «поиск по знаниям» на мобильном устройстве.

## Как устроено (архитектура)

- `docs/` — 47 md-документов: 01–42 (теория и практика MBTI) + 50–54 (теория информационных архетипов, матрица взаимодействий, алгоритмы расширения и структурирования, пирамидная архитектура) + генерирующий shell-скрипт.
- `types/` — 16 файлов-описаний типов (INTJ.md … ESFP.md, ~440–460 строк каждый; исключение — INTJ.md на 372 строки, он создавался отдельным путём, остальные 15 сгенерированы `create_types.sh`).
- `rag/` — config.py (пути, модель эмбеддингов `paraphrase-multilingual-mpnet-base-v2`, чанкинг 1000/200), scripts/indexer.py (загрузка md → чанки → ChromaDB), scripts/query_engine.py (поиск + RetrievalQA c GPT-3.5 при наличии ключа), cli.py (интерактивный и разовый режимы), app/streamlit_app.py (веб-интерфейс, 227 строк), requirements.txt, .env.example, setup.sh.
- `pseudorag/` — core/archetypes.py (292 строки: dataclass Archetype, 4 оси, 16 определений с ключевыми словами и приоритетами), core/query_expander.py (374 строки: шаблоны вопросов по архетипам, QuestionTree c экспортом в JSON/Markdown), main.py (демо), test_cities.py (демонстрационный тест), examples/ (готовый пример «города_европы» в JSON и MD).
- `android-document-search/` — Gradle-проект (Kotlin, compileSdk 34, minSdk 24): Room-entity на виртуальной FTS4-таблице, DAO с MATCH-запросами и snippet()-подсветкой, FileIndexer (рекурсивный обход Documents, инкрементальная индексация по mtime, лимит 50 МБ), TextExtractor (PDFBox для PDF, Apache POI для DOCX), MVVM (SearchFragment + SearchViewModel), Material 3.
- `COMPLETION_REPORT.md` — самоотчёт о создании 42 документов (перепроверен аудитом — в целом достоверен, см. [assessment.md](assessment.md)).

Подробное дерево — в [structure.md](structure.md).
