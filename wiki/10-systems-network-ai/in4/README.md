# in4 — серия технических исследований о домашних AI-кластерах для локального LLM-инференса

## Обзор

**in4** — это документационный репозиторий: серия из 15 самодостаточных HTML-страниц на русском языке, посвящённых построению домашних кластеров для локального запуска больших языковых моделей (LLM). Описание репозитория: «info, домашние AI-кластеры для локального LLM-инференса, prima.cpp». Кода как такового в репозитории нет — это законченный исследовательско-справочный цикл (датирован февралём 2026), оформленный как набор богато свёрстанных страниц с таблицами, диаграммами и расчётами.

Серия состоит из трёх блоков:
- **Основная серия (части 0–7)**: от сравнения Apple Silicon и x86 ПК до практической кластеризации и финальной «переоценки фаворитов» через призму prima.cpp;
- **Технические руководства**: два подробных гайда по портированию prima.cpp на Vulkan (основной и альтернативный) и руководство по б/у Tesla GPU + ZLUDA + VPS;
- **Расширенная серия (части 8–11)**: сетевая инфраструктура (RDMA, 10GbE), квантизация моделей, продакшн-развёртывание, калькулятор стоимости и производительности.

## Назначение и идея

Идея репозитория — дать полный, практико-ориентированный справочник для энтузиаста, который хочет запускать большие LLM (в т.ч. 70B+ моделей) дома, не покупая дорогие серверные GPU. Центральная технология серии — **prima.cpp** (arXiv:2504.08791) — фреймворк распределённого инференса, позволяющий объединять разнородные домашние машины (мини-ПК, Mac Mini, одноплатники, старые Tesla-карты, арендованные VPS) в кластер через Piped-Ring Parallelism (PRP).

Серия последовательно отвечает на вопросы: какое железо купить (comparison, high-bandwidth-minipc, sbc-clusters), как объединить машины (clustering 1–3, networking-deep-dive), какие модели и квантизации выбрать (model-quantization-guide), как всё это довести до режима 24/7 (production-deployment: systemd, Docker, Prometheus/Grafana, Ansible) и сколько это стоит на самом деле (cost-performance-calculator: TCO, электричество по странам, сравнение с облачными API, ROI). Отдельная ветка — инженерный план портирования prima.cpp с CUDA на Vulkan (вплоть до «чеклиста для хакатона час за часом»), что намекает на намерение реального вклада в upstream-проект.

## Как устроено (архитектура)

- **Плоская структура**: все 16 файлов лежат в корне — README.md (оглавление серии с таблицами) и 15 HTML-страниц.
- **Самодостаточные HTML-страницы**: каждая страница содержит собственный инлайновый CSS (тёмная тема в стиле GitHub: `#0d1117`, `#58a6ff` и т.д.), медиазапросы для мобильных. **JavaScript отсутствует полностью** — даже «калькулятор» (часть 11) реализован как статические таблицы с текстовым объяснением формул.
- **Навигация**: README служит хабом-оглавлением; часть страниц (calculator, favorites, clustering-part2/3) содержит перекрёстные ссылки на предыдущие части; сквозного меню на всех страницах нет, index.html отсутствует, GitHub Pages не включён (проверено: 404).
- **Формат контента**: плотные сравнительные таблицы (цены, пропускная способность, латентность, tok/s), цветовое кодирование оценок (best/mid/weak), блоки-заметки; в Vulkan-гайдах — блоки `<pre>` с кодом (18 и 37 блоков), в остальных страницах код оформлен строками `class="cmd"`.
- **Источники**: перечислены в README (arXiv:2504.08791, arXiv:2511.07425, Jeff Geerling, distributed-llama, ServeTheHome и др.), но внутри страниц внешние гиперссылки почти отсутствуют (href на http найдены только в 3 файлах из 15) — источники упоминаются текстом.
