# Вопросы к infon

## 1. Что здесь главное: продукт TVCP, исследование «семантического видео» или ИИ-протокол?

Репозиторий содержит три полноценных проекта; бизнес-план говорит «продукт», объём коммитов последних месяцев — «исследование ray/Q6/alife».

**Варианты ответов:**
- А. Главное — TVCP как продукт, остальное выросло по пути.
- Б. Главное — исследовательский тезис «смысл, а не пиксели»; TVCP лишь первый носитель.
- В. Главное — протокол tvcp-ai/1 и экосистема «мозгов».
- Г. Это сознательная лаборатория без единого «главного».

**Варианты дальнейших действий:**
- При А: следовать собственному бизнес-плану — релиз v0.1, фокусный README, вынести ray-платформу в отдельный трек; демо-ролики для DevOps-аудитории.
- При Б: оформить воспроизводимые бенчмарки rate-distortion и препринт; TVCP заморозить на уровне демонстратора.
- При В: выделить спецификацию в отдельный репозиторий со стабильной версией, SDK и реестром реализаций.
- При Г: зафиксировать это в README (сейчас README продаёт продукт) и снять маркетинговые обещания.

## 2. Чем подтверждаются цифры «382 kbps», «9× меньше Zoom», «170 МБ/час»?

В репозитории не найдено воспроизводимой методики измерения (не проверено до конца — возможно, есть в ветке assets или черновиках).

**Варианты ответов:**
- А. Есть реальные измерения, просто не выложены.
- Б. Это расчётные оценки из бизнес-плана (кадры × размер блока × FPS).
- В. Цифры устарели/оптимистичны и требуют перепроверки.

**Варианты дальнейших действий:**
- При А: выложить методику и сырые данные, добавить bench-скрипт в scripts/.
- При Б: пометить в README как «расчётные», добавить скрипт-калькулятор и реальное измерение на loopback-звонке.
- При В: перемерить на текущем кодеке и обновить README; убрать сравнение с Zoom, если оно не выдерживается.

**Варианты ответов:**

- Б. Нет, монорепо принципиально (переиспользование примитивов дороже находимости).
- В. Компромисс: оставить код здесь, но сделать витрину (описание, топики, демо-GIF, зеркала).

**Варианты дальнейших действий:**
- При А: спланировать перенос с сохранением истории; в infon оставить ray/Q6-лабораторию.
- При Б: хотя бы переписать description и добавить топики (terminal, video-call, p2p, raytracing) — это бесплатно.
- При В: оформить GitHub Pages из ai/showcase.html + asciinema-демо; настроить go.dev-ссылки.

## 4. Насколько проверен «железный» путь звонка (камера→кодек→сеть→звук) вне Windows-демо?

Ray-платформа покрыта тестами образцово, но захват V4L2/ALSA/CoreAudio в CI не проверяется; в ai/IMPLEMENTED.md живые прогоны — на Windows.

**Варианты ответов:**
- А. Регулярно используется на Linux/macOS с реальными камерами — просто не задокументировано.
- Б. Проверялся эпизодически; основной путь — тест-паттерны и loopback.
- В. На реальном железе толком не проверялся.

**Варианты дальнейших действий:**
- При А: добавить в docs матрицу «проверено на устройствах» и записи сессий.
- При Б: добавить loopback-интеграционный тест звонка в CI и план ручных проверок перед релизом.
- При В: объявить это главным риском альфы; собрать 2–3 тестеров с разным железом до любого анонса.
