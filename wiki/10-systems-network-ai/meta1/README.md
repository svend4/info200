# meta1 — Continuum: детерминированный рантайм для ИИ-кода (зеркало + масштабное расширение)

## Обзор

**meta1** — это не оригинальная разработка «с нуля», а рабочая копия проекта **Continuum** (`continuum-runtime`), детерминированного рантайма для кода, сгенерированного ИИ. Файл `info` в корне прямо указывает на первоисточник: https://github.com/Asouei/continuum-runtime (автор — Aleksandr Mikhailishin, пакет опубликован в npm). При этом meta1 — не пассивное зеркало: поверх скопированной базы v3.0 сессии Claude за два дня (26–27 февраля 2026) добавили **14 волн новых функций (v3.1 → v4.4)**, раздув ядро с 18 до 117 модулей. Итоговая ветка была влита в main через PR #1 18 апреля 2026 года.

Слоган проекта: «ИИ-агенты пишут код, который работает сегодня и ломается завтра. Continuum чинит его навсегда».

## Назначение и идея

Continuum решает проблему невоспроизводимости ИИ-сгенерированного кода. Идея в трёх шагах:

1. **Run once** — LLM (Anthropic Claude) один раз превращает текстовую задачу в детерминированный JSON-план (`ExecutionPlan`), план кэшируется по хэшу промпта.
2. **Replay forever** — план исполняется в песочнице (Docker или локальной), каждый артефакт получает sha256-хэш; повторный запуск (`continuum replay`) сравнивает хэши и assertions и выносит вердикт: `identical`, `benign_drift`, `drifted`, `regression`.
3. **Heal when needed** — при дрейфе срабатывает **Repair Cascade** из 4 уровней: L1 повтор flaky-проверок ($0) → L2 механическая починка типа `npm ci` ($0) → L3 точечный LLM-ремонт (~$0.03) → L4 диагностика для человека. LLM вызывается «примерно в 1 из 10 отказов».

Ключевая концепция — **lineage (родословная плана)**: каждая починка создаёт новое «поколение» плана с полной историей происхождения (`gen 0 → gen 1 → gen 2`), а «доброкачественный дрейф» (хэши изменились, но тесты проходят) принимается как новая верифицированная реальность без участия LLM.

Расширения v3.1–v4.4, добавленные в meta1 (и отсутствующие в upstream и в npm-пакете!), превращают инструмент из MVP в целую платформу: конфиг-профили, dry-run, preflight, шаблоны планов, миграции, вебхуки, кэш шагов, плагины, линтер планов, rate limiter, чекпоинты, метрики, таймлайн, нотификации, экспорт/архив, профайлер, DOT-графы, аудит-лог, политики исполнения, снапшоты воркспейса, оптимизатор планов, middleware, очередь запусков, лимитер ресурсов, менеджер окружений, event bus, retry-политики, изоляция запусков, слияние планов, таймаут-менеджер и ролевой контроль доступа (RBAC).

## Как устроено (архитектура)

- **`src/core/`** — 117 модулей: конвейер `planner → executor → replayer`, хэширование (`hasher`, `canonical-json`), валидация по JSON Schema (ajv), дрейф-детектор, repair-cascade, lineage, forensics и десятки сервисных подсистем. Типичный модуль — 250–700 строк.
- **`src/cli/`** — 44 файла команд на commander; `cli/index.ts` регистрирует ~45 команд и объявляет версию **4.4.0** (при том что `package.json` — **3.0.0**).
- **`src/sandbox/`** — абстракция `Sandbox` с двумя реализациями: `LocalSandbox` (прямое исполнение) и `DockerSandbox` (изоляция через dockerode).
- **`src/storage/`** — append-only JSONL-журнал событий (`events.ts`), сводки запусков (`runs.ts`), слой запросов (`query.ts`).
- **`src/types/`** + **`schemas/`** — 13 JSON-схем (execution-plan, assertion, drift-vector, plan-lineage, repair-request/response и др.), из которых скрипт `scripts/generate-types.js` генерирует TypeScript-типы.
- **`tests/`** — около 150 тест-файлов на vitest (145 только в `tests/core/`), с моками Anthropic SDK и Docker.
- **`.claude/`** — SessionStart-хук (`npm install` в удалённых сессиях Claude Code) — след того, что расширение делалось через Claude Code on the web.

Подробности — в [structure.md](structure.md).

- **~24 коммита**. Хронология: 26.02.2026 — «Initial commit» и файл `info` от svend4; 26–27.02.2026 — ~20 коммитов от `claude` (базовая настройка проекта + волны фич v3.1…v4.4); 18.04.2026 — merge PR #1 (`claude/continuum-runtime-setup-axNhd`) от svend4. С тех пор активности нет.
