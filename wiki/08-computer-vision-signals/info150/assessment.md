# Характеристика и оценка info150

Метод аудита: клонирование и API заблокированы, поэтому проверка велась по raw-файлам (curl) и HTML-страницам GitHub (выборочно). Прочитаны: корневые документы (README, INSTALL, DEMOS, DOMAIN_ADAPTATIONS, ARCHIVES, V13_REUSE_MAP), оба CI-workflow, README/STATUS флагмана и 4 сиблингов (desk, coast, stroll, fish частично), pyproject 4 пакетов, исходники biocore/portal/score_fusion/portal_adapter и один файл тестов. **Ограничение покрытия: из ~20 пакетов детально просмотрены 6–7; выводы о качестве остальных сиблингов — экстраполяция по единообразной форме.** Счётчики тестов (759) и модулей (130) без запуска pytest не перепроверяемы — помечены как «заявлено».

## Что есть

- **Флагман triage4 с реальной инженерной культурой:** ~67 файлов тестов по вербатим-листингу `triage4/tests/` (не 99, как утверждалось в первичном аудите; веб-счётчики нестабильны, точное число без клонирования не подтверждается), CI на Python 3.11 и 3.12 с ruff + mypy + claims-lint + pytest + полный бенчмарк + ~14 демо-скриптов как smoke-тесты (`.github/workflows/ci.yml` — проверено), Dockerfile/compose/systemd/nginx, конфиг mutmut в `pyproject.toml` (проверено), hypothesis property-тесты, Prometheus-метрики, SBOM.
- **17 доменных сиблингов** единообразной формы (pyproject + Makefile + tests + web_ui + PHILOSOPHY), каждый — независимо устанавливаемый пакет с демо; 14 из них покрыты матричным CI (`qa.yml` — проверено).
- **biocore** — образцово-узкий слой утилит (проверен `seeds.py`: документированный, типизированный, с обоснованием существования).
- **portal** — работающая идея «совместимость вместо слияния»: протокол (`protocol.py` проверен), 6 типов мостов, адаптеры у трёх пилотов, отдельный CI-job с реальной установкой пилотов и demo.
- **Выдающаяся документация:** 21 документ у флагмана, включая REGULATORY / SAFETY_CASE / RISK_REGISTER; корневые INSTALL и DEMOS покрывают даже Windows-путь без make.
- **Самоаудиты** (`triage4/docs/STATUS.md`, per-sibling `STATUS.md`) в подчёркнуто честном тоне: прямо перечислены пробелы (нет реальных данных, YOLO — loopback, mutmut не прогнан, Web UI недоделан).
- **Прослеживаемость происхождения:** дизайн-лог ChatGPT и v13-архив сохранены как read-only с описями (ARCHIVES.md) и картой заимствований (V13_REUSE_MAP.md); атрибуция кода meta2 в `triage4/LICENSES/meta2.LICENSE`.
- 181 коммит, работа через PR (последний — #41), две ветки.

## Чего нет

- **Файла LICENSE в корне репозитория** — проверено (404). MIT заявлен только в `pyproject.toml` пакетов и фразой в README; в `triage4/LICENSES/` лежит лишь атрибуция upstream (meta2.LICENSE), полного текста MIT для самого проекта нет. GitHub, судя по всему, лицензию не детектирует.
- **CI-покрытия трёх новейших сиблингов:** `triage4-coast`, `triage4-desk`, `triage4-stroll` есть в дереве (добавлены 1–4 мая 2026), но отсутствуют в матрице `qa.yml` (проверено: матрица заканчивается на triage4-fish, комментарий workflow говорит «sixteen packages»).
- **Реальных данных и железа:** калибровка на 70 синтетических кейсах; PhysioNet-адаптер есть, но архив не загружен; мосты ROS2/MAVLink/Tello тестируются на моках (это честно признано в STATUS.md — подтверждаю, что заявления и код согласуются по прочитанным файлам).
- **Публикации пакетов** (PyPI) и релизов/тегов (releases не проверял — не критично для research-стадии).
- **Актуальных README у новых сиблингов** — см. «Минусы».
- Open issues/дискуссий нет — вся история решений живёт в документах и архиве, вне трекера.

## Плюсы

- Редкая для профиля глубина инженерии: детерминированный пайплайн, тесты-инварианты (critical-miss rate = 0 на изолированных смертельных признаках), CRDT с property-тестами коммутативности/идемпотентности, override Ларрея как регрессионный тест.
- Дисциплина формулировок: claims-lint в CI не даёт документации «дорасти» до медицинских обещаний — уникальный приём.
- Осознанная архитектура масштабирования на домены: три слоя с явными правилами; философия «Не слияние — совместимость» переиспользована из nautilus — межрепозиторный перенос идей внутри профиля работает.
- Документация уровня «можно отдать стороннему разработчику»: INSTALL/DEMOS покрывают все пакеты, все ОС, uninstall и troubleshooting.
- Самокритичные STATUS-документы: заявленное в них в основном совпадает с наблюдаемым (проверено выборочно).

## Минусы

- **Дрейф copy-форков в новых сиблингах (проверено):** `triage4-coast/README.md` начинается текстом про crowd-safety для стадионов («Seventh sibling») — это текст `triage4-crowd`, тогда как pyproject описывает «Coast-strip safety — beach + promenade + pier»; `triage4-stroll/README.md` — копия фитнес-README (squat/pushup/deadlift) при pyproject «Day-walk wellness — pace/fatigue/hydration/sun»; у `triage4-desk` дрейфуют оба документа — `README.md` тоже дословная копия fit-README (тот же «Stand-off fitness / wellness… squat/pushup/deadlift»), хотя пакет описан как офисный wellness-ассистент, а `STATUS.md` утверждает «No UI / API», хотя `triage4-desk/web_ui/package.json` существует (React+Vite). Таким образом дрейф README затрагивает все три новых сиблинга (coast/desk/stroll), а не два, как отмечалось изначально.
- **Документация отстаёт от факта:** корневой README и qa.yml говорят «17 пакетов», реально пакетов ~20 (17 сиблингов + флагман + biocore + portal); `docs/adaptations/` — только 01–14, для coast/desk/stroll доменных исследований нет.
- Внутренняя нестыковка в `triage4/docs/STATUS.md`: в одном месте «759 тестов», в другом «609 tests lock invariants» (вероятно, устаревшая цифра).
- INSTALL.md называет «активной веткой разработки» `claude/analyze-documents-structure-Ik1KX` — ветка существует, но упоминание в инструкции по установке быстро устаревает.
- Огромный объём при одном контрибьюторе-человеке (коммиты — от агента claude, merge — svend4): bus-factor 1, и 17 Web UI на React — большая поверхность сопровождения.
- Название репозитория (info150) и описание («info med») никак не отражают содержимое — проект трудно найти и оценить снаружи.

## Качество кода и документации

По прочитанным файлам качество кода **высокое**: модули с содержательными docstring, `from __future__ import annotations`, полная типизация, dataclasses, клампинг входов, объяснимые выходы (reasons + contributions), тесты проверяют поведение, а не покрытие. Документация — лучшая из просмотренных в профиле: многослойная, перекрёстно связанная, с честными самоограничениями. Слабое звено — синхронизация документов с быстро растущим кодом (см. Минусы) и невоспроизведённые внешние проверки (тесты не запускались в рамках аудита; статус CI-прогонов на GitHub не просматривался).

## Зрелость: 4/5

Обоснование: по инженерной дисциплине (CI, тесты, документация, воспроизводимость, регуляторная рамка) — уверенные 4–5; до 5/5 не дотягивает из-за отсутствия валидации на реальных данных/железе (по собственному признанию — главный разрыв «Alpha → credible Beta»), непокрытых CI новых пакетов, дрейфа документации и отсутствия LICENSE-файла. Это зрелый исследовательский стек, а не продукт.
