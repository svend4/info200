# Характеристика и оценка in4n

Аудит-перепроверка от 2026-07-02. Покрытие: прочитаны **все 18 файлов** репозитория (~2 400 строк) — оценка основана на полном чтении кода, но **без запуска** (npm install / сборка / открытие в браузере и Obsidian не выполнялись — работоспособность подтверждена только чтением кода, помечено как «не проверено запуском»).

## Что есть

- **Работающий по коду автономный прототип** (`1-browser/index.html`, 813 строк): физическая симуляция графа, BFS-маршруты, 5 агентов (игрок + 4 бота), ACO-феромоны с испарением, шесть переключаемых режимов (обычный, гиперболический диск Пуанкаре, игра, Вороной, кроссворд, редактор узлов/рёбер), звук на Web Audio. Версия в UI — «InfoAquarium v0.3».
- **React/Three.js-версия** (`2-react/`, ~740 строк): 3D-граф на `react-force-graph`, кастомные узлы (прозрачная сфера + wireframe + цилиндр-рельеф), террейн-оверлей Делоне/Вороного, ползунок «эпох», семантический зум с карточками узлов, полёт камеры к цели.
- **Плагин Obsidian** (`3-obsidian/`, 634 строки TypeScript): строит граф из реальных заметок через `MetadataCache`, собственная физика и рендер, гиперболический режим, феромоны, демо-граф при пустом хранилище; корректный esbuild-конвейер сборки.
- **Внятный README** с концепцией, инструкциями запуска всех трёх вариантов и таблицей «метафора → техника».
- **Осмысленная история коммитов**: 7 коммитов, 2 слитых PR с описательными сообщениями («Implement roadmap: hyperbolic projection, pheromones, 3D relief, semantic zoom» и др.).

## Чего нет

- **Тестов** — ни одного (ни unit для физики/BFS/Мёбиуса, ни e2e).
- **CI/CD** — нет GitHub Actions, ничего не собирается и не проверяется автоматически.
- **Лицензии** — файла LICENSE нет; для Obsidian-плагина это блокер публикации в каталог сообщества.
- **Lock-файлов** (`package-lock.json`) и `.gitignore` — версии зависимостей не зафиксированы, воспроизводимость сборки не гарантирована.
- **Скриншотов/демо** — для сугубо визуального проекта в README нет ни одного изображения или GIF; GitHub Pages не настроен, хотя `1-browser` идеально для этого подходит.
- **Общей кодовой базы** — алгоритмы продублированы трижды.
- **Офлайн-автономности прототипа** — заявление README «работает без сборки» верно лишь при интернете: `delaunator` и `d3-delaunay` грузятся с CDN; без сети `drawTerrain` бросит `ReferenceError: Delaunator is not defined` и приложение не запустится.
- **Данных, кроме демо** — браузерная и React-версии работают только на захардкоженном графе из 12–15 понятий.

## Плюсы

- Оригинальная, цельная концепция: не «ещё один force-graph», а связная система метафор (ландшафт, дороги, запахи, время), последовательно воплощённая в коде.
- Три уровня воплощения — от прототипа до интеграции с реальными данными (Obsidian) — грамотная лестница проверки идеи.
- Код чистый и читаемый: секционные комментарии-разделители, осмысленные имена, аккуратные константы физики, обработка вырожденной геометрии (`try/catch` вокруг Делоне), фолбэк на демо-граф.
- Реализованы нетривиальные алгоритмы: преобразование Мёбиуса/диск Пуанкаре, муравьиный выбор пути по феромонам, проекция 3D→2D для оверлеев.
- Плагин Obsidian корректно использует API (`registerView`, `MetadataCache`, `ResizeObserver`, отвязка view при выгрузке).

## Минусы

- **Мёртвый код в Obsidian-плагине**: режим Вороного (кл. V) проверяет `globalThis.d3?.Delaunay`, но `d3-delaunay` не входит в зависимости плагина и не бандлится esbuild — внутри Obsidian `d3` не существует, режим молча никогда не срабатывает (`main.ts`, строки 424–436).
- **Незавершённая геймификация React-версии**: `agentScores` инициализируется нулями и никогда не обновляется (`setAgentScores` не вызывается), `playScore` импортирован, но не используется, `AgentHUD` получает `gameMode={false}` жёстко — панель счёта всегда показывает нули (`App.jsx`).
- **Вероятная ошибка типов**: `new AquariumView(leaf, this.app)` — конструктор `ItemView` принимает один аргумент `leaf`; esbuild не проверяет типы (tsconfig `noEmit`), поэтому сборка проходит, но `tsc` выдал бы ошибку (не проверено запуском компилятора).
- Троекратное дублирование алгоритмов с расползающимися константами — правки надо вносить в три места.
- CDN-зависимости в рантайме (unpkg/jsdelivr) — хрупкость и несоответствие духу «автономного» прототипа.
- O(E) поиск ребра `findIndex` внутри каждого шага агента — на демо-графах незаметно, на большом хранилище Obsidian (тысячи заметок) станет узким местом вместе с O(N²) физикой без пространственного индекса.
- Мелочи: опечатка «ВРЕМЕННАя ОСЬ» в `InfoPanel.jsx`; `author: "InfoAquarium"` и пустой `authorUrl` в `manifest.json`.

## Качество кода и документации

Код — **выше среднего для прототипа**: единый стиль во всех трёх вариантах, компактные чистые функции, защитные проверки (`if(!a||!b) return`), TypeScript со `strictNullChecks` в плагине. Архитектурной зрелости нет (дублирование, магические константы, отсутствие модульности), но для исследовательского спайка это приемлемо. Документация — один хороший README на русском: концепция и запуск описаны отлично, но он устарел относительно кода, не имеет скриншотов, и внутренней документации (docstrings, ARCHITECTURE.md, CLAUDE.md) нет. Самоаудитов/отчётов о статусе в репозитории нет — единственный проверяемый «статус» это дорожная карта README, расхождения которой описаны выше.

## Зрелость: 2/5

Обоснование: работоспособный (по коду) многовариантный прототип с нетривиальными алгоритмами и хорошим README — это больше, чем «1» (голая идея). Но: один день разработки (7 коммитов 28.03.2026, далее тишина), ноль тестов и CI, нет лицензии и lock-файлов, README устарел, есть мёртвый и недоделанный код, никакой упаковки (плагин не опубликован, демо не задеплоено). До «3» не дотягивает из-за отсутствия какой-либо инфраструктуры качества и подтверждённой эксплуатации.
