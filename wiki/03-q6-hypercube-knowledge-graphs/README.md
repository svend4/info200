# Гиперкуб Q6, И-Цзин и графы знаний

## О теме

Это инженерное и математическое ядро экосистемы svend4. Пять репозиториев объединяет одна сквозная идея: знание представляется не сплошным вектором, а точкой дискретной геометрии — вершиной 6-мерного гиперкуба Q6 = {-1,+1}⁶, где 64 вершины отождествлены с 64 гексаграммами И-Цзин. Флип одного бита = переход в соседнюю вершину (расстояние Хэмминга 1) = минимальная «смысловая мутация». На этом общем фундаменте построены очень разные вещи: `meta` — монорепо из 48 математических проектов вокруг Q6; `pro2` — ML-фреймворк, встраивающий Q6 как геометрическое индуктивное смещение в трансформеры; `infom` — GraphRAG, использующий Q6 как объяснимый LSH-индекс; `nautilus` — мета-протокол федерации, размечающий репозитории профиля по той же Q6-онтологии; `in4n` — визуализатор графов знаний как «живого аквариума».

В профиле эта тема играет роль несущей конструкции: почти все остальные темы (RAG, базы знаний, ИИ-агенты) так или иначе опираются на идеи, кристаллизовавшиеся здесь. Характерные черты — чистый stdlib-Python без внешних зависимостей, высокая тестовая культура (у лидеров), сильная концептуальная документация и одновременно типовые болезни экспериментального кода: отсутствие лицензий, рассинхронизация README с кодом, метрики на заглушках вместо реальных прогонов.

## Лидеры и аутсайдеры

**Лидеры.**

- **`nautilus` (4/5)** — самый зрелый репозиторий темы и, по оценке, носитель лучшей инженерной культуры всего профиля: 60 тестов, CI, типизация (`py.typed`, mypy), OpenAPI, Docker, SDK и разработка через PR с ревью (16 смёржено). Есть формальная RFC-подобная спецификация протокола (`PORTAL-PROTOCOL.md`, 1002 строки) и встроенная честная самодиагностика (`health_check` открыто показывает 66/100 и перечисляет проблемы). Это единственный «активный» репозиторий темы.
- **`pro2` (3/5)** и **`meta` (3/5)** — самые проработанные из экспериментальных. `pro2` выделяется масштабом (~90K строк), редкой для исследовательского кода тестовой культурой (1971 тест-функция, посчитано напрямую) и честными самоаудитами, числа которых подтвердились перепроверкой. `meta` — дисциплинированной радиальной архитектурой (48 проектов зависят только от zero-dependency ядра `hexcore`), подтверждённым CI на трёх версиях Python и незаурядной метадокументацией (формальный фильтр отбора модулей, карта кластеров).

**Аутсайдер / заготовка.**

- **`in4n` (2/5)** — самый ранний по зрелости: цельная и оригинальная концепция «графа-аквариума» с честно реализованными нетривиальными алгоритмами (диск Пуанкаре, ACO, физика Кулон+Гук), но это скорее тройной прототип, чем продукт. Три версии дублируют алгоритмы без общего ядра, есть мёртвый код (Voronoi-режим), незавершённая геймификация, CDN-зависимости в рантайме и полное отсутствие тестов, CI и лицензии.
- **`infom` (3/5)** формально не аутсайдер по зрелости, но ближе всего к «недоведённой заготовке» по содержанию: архитектура целостная, а вот тесты без единого `assert`, реальный LLM так и не подключён (все метрики на mock/semantic-заглушках), README — две строки. Потенциал высокий, довод до продукта — нет.

## Общие сильные стороны темы

- **Единый оригинальный фундамент.** Q6-геометрия и И-Цзин — не украшение, а рабочая, проверяемая математическая идея (Q6-изоморфизм, факторизация softmax 64=8×8, граф Бян-Гуа как типизация рёбер), сквозная через все пять репозиториев.
- **Автономность и zero-dependency.** Ядра `meta`, `nautilus`, `infom` написаны только на стандартной библиотеке Python, включая собственные HTTP-сервер, SQLite-хранилище и TF-IDF — всё работает офлайн, без внешних сервисов.
- **Высокая тестовая и архитектурная дисциплина у лидеров.** Реальные тесты, проверяющие математику (а не только запуск), радиальные и слоистые архитектуры, CI с матрицей версий, PR-ревью.
- **Сильная концептуальная документация.** Формальные спецификации протоколов, инварианты разработки (`CLAUDE.md`), карты экосистемы (`genesis.md`/`codex.md`), честные самоаудиты с подтверждаемыми числами.
- **Множественные интерфейсы к одной логике.** У `infom` — Python API + MCP (11 инструментов) + REST (13 эндпоинтов); у `nautilus` — REST + SDK + OpenAPI; у `pro2` — 4 CLI-команды и портал в `nautilus`.

## Общие слабые места и чего не хватает

- **Нет лицензий.** LICENSE отсутствует буквально во всех пяти репозиториях (у `pro2` MIT заявлена, но файла нет) — общий блокер публикации и легального переиспользования.
- **Метрики на заглушках, а не на реальных прогонах.** У `pro2` все бенчмарки toy-scale (d=128, <100K токенов), громкие цифры («PPL 1.24», «LCI → π») не воспроизводились; у `infom` реальный LLM не подключён, метрики на mock; у `nautilus` 7 из 14 адаптеров отдают статические fallback-слепки апреля 2026.
- **Документация отстаёт от кода.** У `meta` README заявляет 24 проекта против реальных 48 и счётчики тестов устарели вчетверо; у `in4n` пустые чекбоксы дорожной карты при реально сделанных пунктах; у `infom` README — две строки.
- **Отсутствие или неполнота CI и упаковки.** У `pro2` при ~2000 тестах нет CI; ни у одного нет `pyproject.toml`/публикации в PyPI; установка часто через `sys.path`-хаки.
- **Bus-фактор 1 и «взрывная» разработка.** Всё сделано короткими интенсивными спринтами AI-агентом с последующими месяцами тишины; нет внешней валидации, а автоматизация (sync-бот `nautilus`) молчит с апреля 2026.
- **Слабые места безопасности и гигиены.** REST API без аутентификации при CORS `*` (`infom`, `nautilus`); засорённые корни репозиториев (у `meta` — ~75–80 PDF/ODT и `.coverage`; у `pro2` — склеенный README и десятки JSON-логов; у `nautilus` — посторонние файлы в `docs/`).
- **Подтверждённые дефекты.** У `meta` битые пути модулей в `registry.py` (`hexforth`, `hexpath` → 404); у `in4n` мёртвый Voronoi-код и незавершённая геймификация.

## Дубли и пересечения

- **Q6-адресация и граф Бян-Гуа реализованы независимо в четырёх местах.** `meta` (`hexcore`, `hexsym`, `hexiching`), `pro2` (Q6-изоморфизм, `KasatkinQ6Router`), `infom` (Q6 как LSH-индекс), `nautilus` (Q6-онтология паспортов) — каждый содержит свою версию перехода между гексаграммами и соседства по Хэммингу. Напрашивается извлечение единой канонической Q6-библиотеки (естественный кандидат — `hexcore` из `meta`) и переиспользование её остальными вместо параллельных реализаций.
- **Визуализация графов через D3.js дублируется.** D3-визуализации есть и в `nautilus`, и в `infom`; `in4n` строит свой стек визуализации графов (Canvas/Three.js) с нуля. Общий слой рендеринга графа знаний закрыл бы всех троих.
- **GraphRAG-логика частично пересекается.** `infom` — полноценный GraphRAG, а `nautilus` со своим TF-IDF-поиском и графом мостов решает смежную задачу поиска по федерации; их разумно объединить (мосты `nautilus` как граф для пайплайна `infom`).
- **Внутри `in4n` — тройное дублирование алгоритмов** (браузер / React / Obsidian) без общего ядра, константы уже разошлись. Это внутренний дубль, который просится в единый модуль физики и ACO.

## Идеи сочетаний внутри темы

- **`meta` + `pro2` = «Вычислимый И-Цзин».** Генеративная модель `pro2`, у которой пространство состояний — не токены, а вершины Q6 со строгой алгеброй из `meta` (`hexcore`, `hexsym`, `hexiching`, марковские цепи `hexstat`). Получается единственный «цифровой И-Цзин» с математической подложкой и тысячами тестов, а не с эвристиками.
- **`infom` + `nautilus` = объяснимый Q&A-портал по всей экосистеме.** 33 типизированных моста и `PortalEntry` из `nautilus` скармливаются GraphRAG-пайплайну `infom` как готовый граф с рёбрами-мостами и confidence. Ответы цитируют источники и показывают маршрут вывода («pro2 → isomorphism → meta») — прозрачность, которой нет в обычных RAG.
- **`infom` + `in4n` = визуальный отладчик GraphRAG.** Запрос к `infom` = путешественник на графе `in4n`, обход при извлечении контекста = его маршрут, частота попадания узла в ответы = яркость феромонов. Видно, какие области знаний «протоптаны» запросами, а какие мертвы — слоя наблюдаемости такого рода нет ни в одном популярном GraphRAG-стеке.
- **`pro2` + `infom` = GraphRAG с дискретным геометрическим индексом.** Модель `pro2` присваивает каждому узлу графа `infom` Q6-адрес (одну из 64 гексаграмм), рёбра типизируются по графу Бян-Гуа, а retrieval становится обходом гиперкуба вместо ANN-поиска. Объяснимый офлайн-CPU-гибрид символьного и векторного поиска — и первый реальный (не синтетический) бенчмарк для Q6-эмбеддингов.
