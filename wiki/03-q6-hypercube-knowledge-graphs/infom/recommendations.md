## Серьёзные доработки

1. **Подключить и валидировать реальный LLM** — сам CLAUDE.md называет это «следующим шагом». Прогнать индексацию data70 через Ollama (qwen2.5 + bge-m3) или Groq/Cohere, сравнить Q, число рёбер и качество ответов с SemanticAdapter, зафиксировать результаты в results/.
2. **Починить извлечение связей**: 8 рёбер на 46 нод в реальном отчёте — признак того, что EXTRACT_PROMPT/парсинг JSON теряет relations. Добавить подсчёт отброшенных связей, повторный проход по парам сущностей в одном чанке, метрику edges/nodes.
3. **Инкрементальная индексация и дедупликация сущностей**: сейчас повторная индексация плодит дубли (сущности с разными id, но одинаковыми label); нужен merge по нормализованному label + косинусной близости.
4. **Упаковка**: pyproject.toml, `pip install infom`, консольные точки входа (`infom index`, `infom query`, `infom serve`) — это превратит прототип в переиспользуемую библиотеку.
5. **Бенчмарк на публичном датасете** (например, русскоязычный фрагмент Wikipedia или HotpotQA-подобные вопросы) — единственный способ доказать, что Q6-геометрия даёт что-то сверх обычного GraphRAG.
6. **Безопасность API**: `infom_api.py` открыт всем (CORS `*`, без аутентификации) — перед реальным деплоем нужен хотя бы API-ключ в заголовке.

## Варианты продолжения

**Сценарий A — «Персональный движок памяти» (эксплуатация по назначению).** Довести до конца исходный замысел: ночной агент индексирует data70 и другие info-репозитории, накапливает единый граф знаний профиля, отвечает на вопросы через MCP прямо в Claude Code. Для этого нужны: реальный LLM (Ollama локально или Groq бесплатно), дедупликация сущностей, инкрементальные снапшоты по датам. Результат — работающая «пятая ступень» (Day 5 «Понимание» из genesis.md) личной AI-инфраструктуры, которой автор реально пользуется каждый день.

**Сценарий B — «Исследовательская публикация Q6-геометрии».** Выделить научное ядро (Q6-LSH, тангрэм-сигнатуры, фрактальные границы) в отдельный пакет с воспроизводимыми бенчмарками против baseline (FAISS flat, обычный LSH, community detection Louvain). Если Multi-Projection Q6 действительно даёт заявленный recall при O(1)-поиске на stdlib — это материал для статьи на Habr (обе идеи уже ссылаются на habr-статью) или arXiv-препринта. Ценность: единственный репозиторий профиля с потенциалом внешнего признания именно как research.

**Сценарий C — «GraphRAG-as-a-Service для no-code».** Достроить уже готовые 80%: REST API + вебхуки + деплой-конфиги + гайды Make.com/n8n/Zapier. Добавить аутентификацию, мультитенантность (граф на пользователя), тарифный лимит — и опубликовать как микросервис «граф знаний по вебхуку» для автоматизаторов. Ниша реальна: n8n-сообществу нужен дешёвый RAG без векторных БД, а stdlib-ядро означает копеечный хостинг (256 MB на Fly.io уже сконфигурировано).

**Сценарий D — «Мозг для агентной фермы».** Обобщить паттерн brain/data из `.github/workflows/infom-agent.yml`: infom становится стандартным «модулем памяти», который любой репозиторий профиля подключает одной строчкой workflow. Результаты анализа складываются в сам анализируемый репозиторий (как уже сделано для data70). Это шаг к «Day 6 — Мультиагентность» по собственной карте автора.

## Сочетания с другими репозиториями профиля

1. **infom + data70 = «Живой архив 1105 диалогов»** (уже начато — `results/analysis_data70_2026-03-28.md`). Проиндексировать весь data70 (78 МБ диалогов ChatGPT: TetraDrone, WILOS, Legal AI, 300+ диалогов по немецкому соцправу) в персистентный граф с реальными эмбеддингами. Уникальность: личный архив 15 лет мышления становится запрашиваемой базой — «что я думал про роевые дроны в 2023?» отвечается через hybrid-RAG, а сообщества графа автоматически восстанавливают тематический каталог, который в data70 ведётся вручную (88 тем).

2. **infom + lorenzo = «Семантическая карта Svyazi 2.0»**. В lorenzo ~2815 md-файлов документации плюс docs-toolkit (Python-пакет для работы с ними). Прогнать корпус через DocumentIndexer, а Q6-адреса и тангрэм-формы использовать как навигационный слой: docs-toolkit получает команду «покажи сообщества документов и фрактальные границы между темами». Инновация: автоматическая карта связности гигантского документального монорепо, где размытые границы (fd_box → 2) указывают на темы, требующие реструктуризации.

3. **infom + in4n = «Двухслойный динамический граф»**. in4n — «динамический граф информационный»; infom — статический снапшот-граф со снапшотами в JSON. Объединение: in4n даёт событийный слой (граф меняется во времени), infom — геометрический слой (Q6/формы/границы для каждого среза). Получается инструмент наблюдения эволюции знаний: как сообщество «дроны» мигрирует по Q6-кубу от месяца к месяцу, когда фрактальная граница между темами растворяется. Такого нет ни в одном открытом GraphRAG.

4. **infom + info40 = «Оркестрация с общей памятью»**. info40 (AI Agent Orchestration Platform, Production) оркестрирует агентов, но им нужна общая память. infom_mcp уже говорит по MCP — подключить его как shared-memory-сервис для всех агентов info40: каждый агент пишет извлечённые сущности в общий граф и читает контекст соседей. Инновация: «когнитивная доска» мультиагентной системы, где пересечения работ агентов видны как гиперрёбра.

5. **infom + soz150 / openclaw-skills/social-law-de = «Юридический GraphRAG по Sozialrecht»**. Скилл social-law-de уже лежит внутри infom, а база — 300+ диалогов по SGB в data70. Построить специализированный граф: нормы (SGB IX/XII/…) ↔ жизненные ситуации ↔ шаблоны документов (Widerspruch, Klage). Запрос «отказали в Eingliederungshilfe» через local-RAG возвращает и норму, и прецедент из диалогов, и готовый шаблон. Социально значимый продукт с реальной пользовательской базой (люди с инвалидностью в Германии).
