# Характеристика и оценка infom

## Что есть

- **Полный работающий GraphRAG-конвейер**: чанкинг (`indexer.py:chunk_text`, по границам предложений с overlap), LLM-извлечение сущностей/связей через JSON-промпт, построение графа с сообществами (label propagation в `graph/knowledge_map.py`), три режима ответов (`graphrag_query.py`: local/global/hybrid).
- **Оригинальный геометрический слой**: Q6-адресация (6 бит, 64 ячейки — `signatures/hexsig.py`), тангрэм-формы кластеров, фрактальная размерность границ (box-counting, `signatures/fractal.py`), гепта-/октаграммные профили. Это не декорация — Q6 реально используется как LSH-индекс первой ступени поиска (`search/hnsw.py`, `search/multi_lsh.py`).
- **Десять LLM-провайдеров** в `config.py`/`llm_adapter.py` (Ollama, OpenAI, Cohere, Groq, OpenRouter, Jina, Together, Gemini + mock + semantic), все через stdlib urllib, с graceful fallback на офлайновый `SemanticAdapter`.
- **Офлайн-режим без единой зависимости**: `semantic_sim.py` — ручной словарь понятий с 32-мерными векторами по осмысленным осям; позволяет разрабатывать и демонстрировать систему бесплатно.
- **Три интерфейса**: MCP-сервер (11 инструментов, персистентность через `graph_snapshots/latest.json`), REST API (13 эндпоинтов, включая `/webhook` и `/batch/index`), Python-API. Плюс 4 конфига деплоя (Docker, Fly.io, Railway, Render) и гайды интеграции с Make.com/n8n/Zapier в `docs/integrations/`.
- **Агентный контур**: GitHub Actions workflow на `claude-code-action@beta` (ночной cron + ручной запуск), паттерн «brain repo + data repo», инструкции-навыки в `skills/`, задача в `tasks/current_task.md`.
- **Реальный артефакт применения**: `results/analysis_data70_2026-03-28.md` — анализ репозитория data70 (46 нод, 6 сообществ, ответы на 4 вопроса) + снапшот графа + D3-визуализация `infom_graph.html`.
- **Концептуальная документация**: `docs/architecture/genesis.md` (527 строк, 13 слоёв AI-инфраструктуры) и `codex.md` — редкий для профиля случай, когда явно описано место репозитория в общей экосистеме svend4.

## Чего нет

- **Настоящих тестов**: `test_semantic.py` — демонстрационный скрипт с print'ами, **ноль assert'ов**; функции принимают аргументы (`test_rag(km)`), т.е. под pytest он даже не запустится корректно, хотя pytest — единственная активная строка в `requirements.txt`.
- **CI для качества**: единственный workflow — агент анализа, а не запуск тестов/линтера при push.
- **Лицензии** — файла LICENSE нет вообще.
- **Нормального README**: 2 строки («# infom / info»); вся реальная документация — в CLAUDE.md, который на GitHub-странице не рендерится как визитка.
- **Упаковки**: нет pyproject.toml/setup.py, установить как пакет нельзя; `.mcp.json` содержит жёсткий путь `/home/user/infom`.
- **Валидации на реальном LLM**: CLAUDE.md сам признаёт «подключение реального LLM — следующий шаг»; все опубликованные метрики получены на mock/semantic-адаптерах.
- **Данных о качестве экстракции**: в отчёте по data70 — 46 нод и всего 8 рёбер, т.е. извлечение связей почти не сработало (граф вырожденно разреженный), это нигде не отрефлексировано.

## Плюсы

- Целостная, продуманная архитектура L0–L3 с чистым разделением graph/signatures/search/adapters — код легко читать и расширять.
- Оригинальная исследовательская идея (Q6 + геометрические сигнатуры как LSH и объяснимые признаки), последовательно доведённая от теории до работающего поиска.
- Отличная инженерная дисциплина интеграций: MCP + REST + вебхуки + 4 варианта деплоя — редкая полнота для личного прототипа.
- Автономность: работает без интернета, без ключей, без pip install.
- Хороший внутрикодовый нарратив: docstrings объясняют «почему», а не только «что»; CLAUDE.md фиксирует инварианты («не снижай LP threshold»).

## Минусы

- Отсутствие тестов с проверками — при ~8 000 строк самописной линейной алгебры и геометрии регрессии никак не ловятся.
- Метрики качества (recall, modularity) взаимно противоречивы и не воспроизводимы одной командой.
- README-заглушка и отсутствие лицензии обнуляют внешнюю пригодность репозитория.
- SemanticAdapter — ручной словарь: любое понятие вне словаря получает деградированный вектор; масштабирование на реальные корпуса упирается в реальный LLM, который так и не подключён.
- Разреженность реального графа (8 рёбер на 46 нод) ставит под вопрос практическую ценность текущего NER-промпта.
- Жёсткие пути (`.mcp.json`), «магические» константы (LP threshold 1.5×, формула HyperEdge score) без экспериментального обоснования в репо.

## Качество кода и документации

Код — уверенные 4/5: единый стиль, аккуратные dataclass'ы, осмысленные имена, русские docstrings с диаграммами конвейеров, отсутствие мёртвого кода в просмотренных модулях. Документация — 3/5: CLAUDE.md и docs/architecture отличные, но README пуст, метрики противоречивы, а пользовательской инструкции «с нуля до первого графа» нет (частично закрывается docstring'ами `infom_api.py` и гайдами интеграций).

## Зрелость: 3/5

Обоснование: полноценный работающий прототип с реальным применением (анализ data70), тремя интерфейсами и деплой-конфигами — это заметно выше «эксперимента на выходных» (2/5). До 4/5 не дотягивает из-за: отсутствия тестов и CI-проверок, непроверенных/противоречивых метрик, невалидированности на реальном LLM, пустого README, отсутствия лицензии и упаковки. Ограничение покрытия аудита: из ~34 Python-модулей подробно прочитаны ~15 ключевых (точки входа, граф, поиск, сигнатуры, MCP/API, конфиги, доки); остальные оценены по заголовкам и размерам; метрики производительности не перепроверялись запуском.
