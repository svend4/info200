# Интернет-магазины и e-commerce

## О теме

Тема объединяет четыре репозитория, которые крутятся вокруг одной и той же учебной задачи — сделать интернет-магазин, почти всегда «цветочный». Это не продуктовое направление профиля, а полигон: на витрине, корзине, каталоге и SEO автор отрабатывает разные веб-стеки и разные способы разработки (от ручного кода до генерации кода агентами — Claude через pull request'ы в daten2 и GitHub Copilot в meta4). Диапазон зрелости внутри темы огромен: от целостного демо на ~34 тыс. строк (data40) и семиуровневой «лестницы стеков» (daten2) до двух почти пустых заготовок из одного README (daten23, meta4).

Сквозная идея темы — «магазин как учебный стенд»: не важно, что продаётся (везде цветы и букеты), важно, какой стек и какой процесс демонстрируется. Отсюда сильное пересечение с соседними направлениями: PWA и офлайн (data40 — полноценное PWA), full-stack платформы (бэкенды на Flask/Node.js/SQLite) и агентная разработка. При этом тема заметно «дублирующаяся»: как минимум четыре репозитория профиля посвящены цветочному магазину, и два из них — просто зарезервированные слоты без содержимого.

## Лидеры и аутсайдеры

**Лидеры.**

- **data40** — самый проработанный репозиторий темы (зрелость 3/5). Это целостное работающее демо со 175+ функциями (каталог, корзина, трекинг, конструктор букетов, лояльность, блог, админка, A/B-тесты), запускающееся без сборки и зависимостей — достаточно открыть `index.html`. Сильна и самодокументация: `FEATURES_ANALYSIS.md` с матрицей функций, `BACKEND_MIGRATION.md`, `MOBILE_APP_SPEC.md`, полный API-мануал бэкенда с curl-примерами. Есть PWA/SEO-обвязка (Service Worker, manifest, sitemap, robots, Schema.org) и прозрачная история из 52 коммитов и 12 merge-PR.
- **daten2** — ценен редкой учебной идеей: одна задача проходит семь технологических ступеней (PHP → Flask → Django → Express → React+Flask → Next.js+Prisma → микросервисы), и все семь уровней реально существуют (каждый в своей ветке плюс ветка-сборка). Код на main минималистичный и аккуратный (параметризованный SQL, цена берётся из БД, не от клиента), процесс дисциплинированный — вся разработка через 12 pull request'ов. Зрелость ниже, чем у data40 (2/5), потому что замысел «лестницы» не собран на main и продакшен-сборка сломана.

**Аутсайдеры/заготовки.**

- **meta4** и **daten23** — обе почти пустые (зрелость 1/5). daten23 — чистый зарезервированный слот: один README из двух строк («info / new»), кода нет, полгода без коммитов, и даже заявленная в описании GitHub тема магазина в README не раскрыта. meta4 чуть содержательнее (в draft-PR лежит компактный идиоматичный солвер оптимизации букета на 43 строки), но весь код вне main и висит в незакрытых draft-PR с февраля 2026; условия задачи, примеров и тестов нет, а имя «meta4» с цветочным магазином никак не связано.

## Общие сильные стороны темы

- Единый понятный домен (цветочный магазин) позволяет напрямую сравнивать разные стеки и подходы на одной и той же предметной задаче.
- Есть по-настоящему богатое демо (data40) с широкой функциональностью и сильной самодокументацией — редкая для профиля полнота.
- Аккуратные учебные бэкенды: параметризованный SQL, bcrypt + JWT, сид-скрипты, корректное исключение секретов и БД из git (data40); чистый минималистичный код на main (daten2).
- Дисциплинированный и прозрачный процесс разработки: работа через pull request'ы, осмысленная история коммитов, следы реального деплоя (Render в daten2).
- Наглядные живые примеры агентной разработки: daten2 целиком написан Claude через PR, meta4 — образец цепочки «задача → Copilot-агент → PR».
- PWA/SEO-грамотность (Service Worker, manifest, sitemap, robots, Schema.org в data40) — задел на стык с офлайн-темой.

## Общие слабые места и чего не хватает

- **Полное отсутствие тестов** во всех четырёх репозиториях — ни unit, ни e2e; корректность нигде не подтверждена автоматически.
- **Нет CI/CD и линтеров** ни в одном репозитории (`.github/workflows` отсутствует).
- **Нет лицензий**, а где упоминания есть — они противоречивы (data40: README говорит «образовательные цели», а `backend/package.json` — MIT).
- **Заявленное расходится с фактическим.** daten2: описание обещает 7 уровней, на main собран только уровень 5, продакшен-сборка Docker отдаёт API без UI, готовые исправления висят несмёрженными PR'ами. data40: устаревшие и внутренне противоречивые самоотчёты, README ссылается на 6 несуществующих HTML-страниц, объём кода занижен вдвое.
- **Незавершённость и брошенность.** Бэкенд data40 не подключён к фронтенду (магазин живёт на localStorage), код meta4 не слит в main, daten23 пуст; у трёх из четырёх репозиториев разработка фактически остановилась (data40 — все коммиты за один день, daten2/meta4/daten23 — месяцы без активности).
- **Проблемы безопасности и данных** (в основном data40): пароли открытым текстом в localStorage, захардкоженные креды `admin/admin123`, мутирующие API-маршруты без проверки JWT/ролей; фиктивные отзывы/контакты и полное отсутствие изображений (emoji и CSS-градиенты вместо картинок).
- **Нет реального деплоя/персистентности:** живого хостинга по теме нет, а в daten2 заказы пишутся в эфемерную SQLite внутри контейнера.
- **Сильное дублирование** темы без разграничения ролей репозиториев (см. ниже).

## Дубли и пересечения

Тема заметно перегружена дублями цветочного магазина. По данным источников как минимум четыре репозитория профиля посвящены одному и тому же (data40, daten2, meta4, daten23), причём для заготовок нигде не объяснено, чем они должны отличаться от уже существующего data40.

- **daten23** прямо дублирует тематику data40 «без указания, чем должен отличаться» — это чистый пустой слот. Разумно либо превратить его в конкретную нишевую вариацию, либо архивировать как отброшенную идею.
- **meta4** дублирует цветочную тематику daten2 без перекрёстных ссылок; его единственная ценность — алгоритмический солвер букета, который логичнее пристроить как «уровень 0» к лестнице daten2, чем держать отдельным магазином-заготовкой.
- **data40 и daten2** пересекаются как две реализации одного магазина, но не конкурируют, а выстраиваются в градацию сложности: daten2 — лестница стеков, data40 — «верхний уровень» (богатое PWA + бэкенд + админка).

Практический вывод из источников: стоит выбрать **data40** каноническим «магазином» профиля, подтянуть к нему daten2 как учебную лестницу, а пустые заготовки (daten23, meta4) либо наполнить конкретным замыслом, либо закрыть.

## Идеи сочетаний внутри темы

- **data40 + daten2 + meta4 = единый «учебник e-commerce».** Три цветочных проекта сливаются в одну лестницу сложности: meta4 даёт «уровень 0» (олимпиадный солвер «собери букет под бюджет»), daten2 — семь ступеней стека от PHP до микросервисов, data40 — верхний уровень (PWA + бэкенд + админка). Учебным материалом становится diff между соседними уровнями одного и того же магазина, а `FEATURES_ANALYSIS.md` из data40 — картой «что появляется на каком уровне».
- **daten2 + meta4 = агентный бенчмарк миграции стеков.** Оба репозитория — живые примеры кода, написанного агентами (Claude и Copilot). На их основе можно собрать воспроизводимый тест «переведи магазин с уровня N на N+1 без изменения поведения, проверка одинаковыми API-тестами» и «Copilot vs собственные агенты» на реальном приложении, а не на синтетическом ТЗ.
- **data40 → daten23 = сборка витрин из блоков.** Пустой слот daten23 можно оживить, вынеся из монолитного `script.js` data40 переиспользуемые блоки (баннер, сетка товаров, корзина) и собрав магазин как конфигурацию блоков под любую нишу — daten23 становится референсной сборкой конструктора.
- **daten23 как офлайн-магазин.** Заготовку daten23 разумно направить в сторону полностью офлайнового каталога с локальным полнотекстовым поиском (каталог в SQLite + FTS), опираясь на PWA-обвязку data40, — редкий класс продукта для выездной торговли и слабого интернета. Это же естественный мостик к теме офлайн-приложений.
