# data40 — «Цветочный Рай»: демо интернет-магазина цветов (frontend + учебный backend)

## Обзор

**data40** — это полнофункциональный демонстрационный интернет-магазин цветов «Цветочный Рай» (Flower Paradise). Проект написан на чистых HTML/CSS/JavaScript без фреймворков и сборки; данные хранятся в `localStorage`. В отдельной папке `backend/` лежит учебный Node.js/Express/SQLite-бэкенд с REST API, который **пока не подключён к фронтенду** (файл `api-client.js` существует, но не включён в `index.html` — миграция описана в `BACKEND_MIGRATION.md` как ручные шаги).

Это один из самых крупных и проработанных «магазинных» репозиториев профиля svend4: ~80 файлов, ~34 000 строк, 18 HTML-страниц, 46 JS-модулей, PWA (Service Worker + manifest), SEO-обвязка (sitemap, robots, Schema.org), самоописание в четырёх документах (`README.md`, `FEATURES_ANALYSIS.md`, `BACKEND_MIGRATION.md`, `MOBILE_APP_SPEC.md`).

## Назначение и идея

Заявленное назначение (из README проекта) — образовательное: демонстрация разработки полноценного e-commerce-сайта, «портфолио frontend-разработчика, база для реального проекта». Разработка велась по нумерованным «этапам» (заявлен план из 40 этапов): каталог и корзина → тёмная тема, сертификаты, личный кабинет, конструктор букетов → отзывы, лояльность, подписки, live-чат → SEO, PWA, поиск, блог, акции → email-маркетинг, админ-панель, доставка с картой, расширенная аналитика, «поддержка мобильного приложения» → Node.js-бэкенд.

Функциональный охват (реализовано как демо на localStorage): каталог ~30 букетов с отзывами и галереями, корзина с промокодами, оформление и трекинг заказов (5 статусов), конструктор букетов, подарочные сертификаты, wishlist и сравнение, программа лояльности (5 уровней), реферальная программа, подписки на букеты, календарь напоминаний, блог (~12 статей), live-чат (симуляция), корпоративный раздел, админ-панель, A/B-тестирование, email-шаблоны, QR-сканер и «мост» для мобильного приложения.

## Как устроено (архитектура)

- **Frontend без сборки**: каждая функция — отдельный JS-файл, подключаемый `<script src=...>` в конце страницы (`index.html` подключает 23 скрипта). Ядро — `script.js` (1982 строки: каталог товаров зашит в код + корзина + заказы). Стили — 9 CSS-файлов (~8 400 строк), основной `styles.css` (2823 строки).
- **Хранение данных** — целиком `localStorage` (пользователи, заказы, корзина, подписчики); отзывы и товары захардкожены в JS. Пароли пользователей хранятся открытым текстом (в `auth.js` это честно помечено комментарием).
- **PWA**: `manifest.json`, `sw.js` (precache ~11 файлов, офлайн-страница `offline.html`), `pwa.js` (установка).
- **SEO/аналитика**: `seo.js`, `sitemap.xml`, `robots.txt`, Schema.org-разметка в `index.html`, `analytics.js` (заглушки GA4 + Яндекс.Метрика).
- **Backend (`backend/`)**: Express + sqlite3, схема из 7 таблиц (users, products, orders, carts, reviews, promo_codes, sessions), маршруты `auth`/`products`/`orders`, bcrypt + JWT, сид-скрипт с тестовыми аккаунтами. БД в git не коммитится (`.gitignore`). Авторизационного middleware на CRUD-маршрутах нет — API открыт.
- **Интеграция фронтенда с бэкендом отсутствует**: `api-client.js` (403 строки, готовые обёртки над API) не подключён ни к одной странице.

## Статус и активность

- **52 коммита, все датированы 21 января 2026** — весь проект (этапы 1–30 и бэкенд) создан за один день; автор функциональных коммитов — «claude», svend4 выполнял merge 12 pull request'ов. С 21.01.2026 активности нет (на дату аудита 02.07.2026 — более 5 месяцев).
- 0 звёзд, 1 форк. README заявляет «Статус: В активной разработке» — по факту разработка остановлена.
- Самоотчёты проекта частично устарели: бейдж «25/40 этапов, 65%» не учитывает реализованные этапы 26–30 и бэкенд; раздел «Структура проекта» в README перечисляет 6 несуществующих страниц (wishlist.html, comparison.html, subscriptions.html, calendar.html, loyalty.html, referral.html — эти функции живут как JS-модули) и не упоминает ~30 реально существующих файлов. Подробнее — в [assessment.md](assessment.md).
