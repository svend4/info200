# Вопросы к meta4

## 1. Почему оба draft-PR от Copilot (26.02.2026) до сих пор не слиты и не закрыты?

Весь код репозитория живёт в PR #2; `main` пуст уже более 4 месяцев.

**Варианты ответов:**
- А. Забыл / руки не дошли — PR нужно принять.
- Б. Результат агента не устроил, но закрывать не стал.
- В. Это и был весь эксперимент: интересовал процесс, а не результат.

**Варианты дальнейших действий:**
- При А: слить PR #2, решить судьбу PR #1 (см. вопрос 3), обновить README — репозиторий мгновенно перестанет быть пустым.
- При Б: оставить в PR комментарий с претензиями к решению и либо попросить агента доработать (добавить тесты), либо закрыть PR с формулировкой — так эксперимент получит зафиксированный итог.
- При В: дописать в README 3–4 строки «что это был за эксперимент и что показал», слить PR #2 ради сохранности кода и заархивировать репозиторий.

## 2. Что означает «flower shop project» в описании: олимпиадная задача или зачаток реального магазина?

Содержимое PR #2 — солвер соревновательной задачи (формат «t тестов, n цветов, бюджет m»), но в профиле есть daten2 («7 flowersshops — 7 level programm»), data40 и daten23 (интернет-магазины).

**Варианты ответов:**
- А. Только алгоритмическая задача, взятая с соревнования (например, Codeforces).
- Б. Первый шаг к настоящему приложению цветочного магазина.
- В. Часть замысла daten2: одна из «ступеней» 7-уровневой программы.

**Варианты дальнейших действий:**
- При А: добавить в README ссылку на условие/источник задачи и sample-тесты; развивать по сценарию «задачник по оптимизации» вместе с data7.
- При Б: спроектировать минимальный API «букет под бюджет» поверх алгоритма и связать с витриной data40/daten23.
- При В: перенести код в daten2 (или сослаться из него), а meta4 закрыть/переназначить — чтобы тема «цветы» не была размазана по двум репозиториям без ссылок друг на друга.

## 3. Каков целевой текст README — `info` или `Hallo`, и откуда взялось требование «Hallo»?

PR #1 ссылается на issue с требованием текста «Hallo», но открытых issues в репозитории нет.

**Варианты ответов:**
- А. «Hallo» — тестовое требование для проверки, выполнит ли Copilot тривиальный issue; сам issue удалён/закрыт.
- Б. Требование устарело, актуален осмысленный README.
- В. Не помню / не важно.

**Варианты дальнейших действий:**
- При А: закрыть PR #1 как выполнивший экспериментальную роль и зафиксировать вывод эксперимента в README или в вики info200.
- При Б и В: закрыть PR #1, написать нормальный README (описание задачи, запуск, статус) — двусмысленность исчезнет.

## 4. Какова логика серии meta / meta1 / meta2 / meta10 и место meta4 в ней?

Соседи по серии: meta (монорепо hex-проектов), meta1 (Continuum — детерминированный рантайм), meta2 (восстановление документов), meta10 (grep-ast → ast-grep). meta4 с цветочным магазином выбивается тематически.

**Варианты ответов:**
- А. «meta*» — просто нумерованные песочницы без общей темы.
- Б. Серия задумывалась как «мета-инструменты», meta4 попал в неё случайно.
- В. Есть план объединения серии, пока не оформленный.

**Варианты дальнейших действий:**
- При А: в вики-хабе info200 пометить серию как песочницы и не искать в ней систему.
- При Б: переименовать meta4 (например, в flower-solver) или перенести содержимое в daten2/data7, чтобы серия meta* осталась однородной.
- При В: описать план серии в info200 и указать роль каждого meta*-репозитория.

## 5. Планируется ли доказательная проверка алгоритма (тесты, брутфорс-сверка)?

Жадная схема с «апгрейдами» x → x+1 в `main.py` выглядит корректной, но в репозитории нет ни одного теста и ни одного примера ввода.

**Варианты ответов:**
- А. Да, тесты нужны — задача останется живой.
- Б. Нет, решение уже принято проверяющей системой соревнования (вердикт вне репозитория).
- В. Нет, код останется как есть.

**Варианты дальнейших действий:**
- При А: добавить pytest с примерами из условия + брутфорс O(2^n) для n ≤ 15 на случайных входах; подключить GitHub Actions.
- При Б: указать в README ссылку на посылку/задачу и вердикт «Accepted» — это заменит тесты как свидетельство корректности.
- При В: хотя бы вписать в README формат ввода/вывода, чтобы код можно было использовать без реконструкции условия.
