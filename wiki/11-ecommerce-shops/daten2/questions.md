# Вопросы к daten2

## 1. Описание репозитория обещает 7 уровней, а на main лежит только уровень 5. Это осознанное решение или так вышло по процессу?

> Факт (проверено): уровни **не потеряны** — все 7 лежат в отдельных ветках (`claude/level1-php-GBpVR … claude/level7-enterprise-GBpVR`), а в ветке `claude/flower-shop-seven-levels-GBpVR` они уже собраны в одном дереве (`flower_shop_levels/levels/`). Вопрос сводится к тому, собирать ли их обратно на `main`.

**Варианты ответов:**
- А. Осознанно: main показывает «текущий/лучший» уровень, остальные — в ветках.
- Б. Так вышло по процессу: уровни вливались в `main` по одному, каждый заменял предыдущий, а собрать их обратно на `main` не дошли руки (при том что ветки со всеми уровнями сохранились).
- В. Уровни планировалось разнести по отдельным репозиториям.

**Варианты дальнейших действий:**
- При А: зафиксировать это в README (таблица уровней со ссылками на ветки) и поправить описание репо, чтобы оно не вводило в заблуждение.
- При Б: собрать уровни на `main` из готовой ветки-сборки `claude/flower-shop-seven-levels-GBpVR` (или из веток уровней) в папки `level1/…level7/` — сценарий А из рекомендаций (это слияние, а не переразработка).
- При В: создать репозитории `daten2-level1…7` или теги, а daten2 сделать индексом-оглавлением со ссылками на существующие ветки.

## 2. Почему не слиты PR #11 (починка статики уровня 5) и #12 (починка уровня 4), открытые ещё 25.12.2025?

**Варианты ответов:**
- А. Забыты — проект был отложен сразу после спринта.
- Б. Ожидали проверки на реальном деплое Render, которая не состоялась.
- В. Сознательно отложены, так как менялась стратегия (см. вопрос 1).

**Варианты дальнейших действий:**
- При А: слить PR #11 немедленно (он чинит сломанную продакшен-сборку main); PR #12 закрыть или переадресовать в папку уровня 4 после её сборки из ветки `claude/level4-express-GBpVR`.
- При Б: развернуть образ из ветки `claude/level5-react-flask-GBpVR` на Render, проверить «/» и `/api/products`, после чего слить.
- При В: закрыть оба PR с комментарием и зафиксировать новую стратегию в README.

## 3. Куда должны сохраняться заказы в задеплоенной версии? Сейчас они пишутся в `flowers.db` внутри контейнера и исчезают при редеплое.

**Варианты ответов:**
- А. Никуда — проект чисто учебный, потеря заказов приемлема.
- Б. Нужна персистентность: том/внешний диск для SQLite.
- В. На верхних уровнях — «настоящая» БД (Postgres), это часть лестницы сложности.

**Варианты дальнейших действий:**
- При А: явно написать в README «демо, данные не сохраняются».
- При Б: путь к БД через переменную окружения + persistent disk на Render; убрать `chmod 666` в пользу корректного владельца.
- При В: сделать Postgres частью уровней 6–7 при восстановлении лестницы и показать миграцию SQLite → Postgres как учебный шаг.
