# ingit — концепт offline-first платформы «Git + управление проектами + документы + финансы» (скелет кода + большая проектная документация)

## Обзор

**InGit (Integrated Git Platform)** — проект-концепция интегрированной offline-first платформы, объединяющей систему контроля версий (Git), управление проектами (Kanban/Gantt, задачи), управление документацией/знаниями и финансовый учёт — всё локально, без облака, с прицелом на домашний NAS и малые команды. Позиционируется как локальная альтернатива связке «GitHub/GitLab + Jira + Confluence + бухгалтерия».

Фактическое состояние: это **проектная документация высокого качества (~4 300 строк в 7 файлах docs/) плюс скелет реализации** — FastAPI-бэкенд со стабами API, SQLAlchemy-модели, CLI на click, git-хуки, заглушка фронтенда (React/Vite «Coming Soon»), Docker/CI/monitoring-конфиги и демо-проект. Реальной работающей функциональности через API нет: все CRUD-эндпоинты возвращают `TODO`/501/404, а модуль моделей БД содержит блокирующую ошибку и не импортируется (см. [assessment.md](assessment.md)) — из-за этого не создаётся БД, падают тесты и CI. Сам FastAPI-сервер при этом стартует, но обслуживает только корневой `/`, `/api/health` и `/api/ping`.

## Назначение и идея

Ключевые идеи проекта (изложены в `docs/METHODOLOGY.md` и `docs/IDEAS_AND_PROPOSALS.md`):

- **Offline-first**: весь функционал без интернета; данные локально (Git + SQLite), синхронизация опциональна. Вдохновлено статьёй на Хабре «Архивирование жизни через Git».
- **Metadata as Code**: задачи, документы, финансы хранятся как YAML-файлы в Git-репозитории и версионируются вместе с кодом.
- **Стандартизированная структура проекта**: нумерованные папки `00_inbox … 90_exports` (профиль, таймлайн, документы, финансы, код, задачи, вики, выгрузки).
- **Гибридное хранение**: Git для версионирования + SQL (SQLite/PostgreSQL) для быстрого поиска и связей.
- **Умные git-хуки**: валидация YAML при коммите, блокировка больших файлов и папки `00_inbox/`, автозакрытие задач по сообщениям коммитов.
- **Шифрование** критичных папок (финансы) — age/SQLCipher (заявлено, не реализовано).
- Целевая аудитория: фрилансеры, малые команды 2–20 человек, домашний архив/финансы, среды с ограниченным интернетом.

## Как устроено (архитектура)

Монорепозиторий из четырёх слоёв:

1. **`docs/`** — самая ценная часть: методология с сравнительным анализом (Git/GitLab CE/Gitea/Fossil), спецификация БД на 933 строки, план реализации с roadmap на 10–16 месяцев, спецификация API, wireframes UI, руководство по деплою, инновационные идеи.
2. **`backend/`** — Python 3.11+, FastAPI + SQLAlchemy 2 + Alembic. Точка входа `ingit/main.py` (CORS, роутеры projects/tasks/documents/health), конфиг на pydantic-settings, 7 ORM-моделей (User, Project, Repository, Task, Document, FinancialRecord, Commit) по DATABASE_SPEC. Эндпоинты — стабы с Pydantic-схемами. CLI `ingit` (click): `init` (создаёт структуру папок 00–90 + YAML-профиль + git init), `task create/list`, `report summary/weekly`, `doctor` (диагностика окружения), `version`. Тесты pytest (5 файлов), но они не проходят.
3. **`frontend/`** — Vite + React + TypeScript: статическая страница «Coming Soon» (40 строк). В package.json заявлен Electron-билд, но `src/electron/main.js` отсутствует. Богатые зависимости (antd, redux-toolkit, monaco, recharts) не используются.
4. **Инфраструктура** — `docker-compose.yml` (postgres + backend + frontend), `docker-compose.monitoring.yml`, `monitoring/` (prometheus.yml + alerts), GitHub Actions (`ci.yml`, `cd.yml`), Makefile (~35 целей), pre-commit, `scripts/` (git-хуки pre/post-commit на Python, генератор отчётов по YAML, init-db.sql), `examples/demo-project/` — демо интернет-магазина в структуре InGit с YAML-задачами/финансами/договорами.

Подробное дерево — в [structure.md](structure.md).
