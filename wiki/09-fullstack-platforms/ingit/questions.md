# Вопросы к ingit

## 1. Планируется ли вообще продолжение разработки, или это законченный концепт?

Все содержательные коммиты сделаны за один день (01.02.2026), затем только merge PR в апреле. README честно называет этап «Проектирование», но структура репо (CI, Docker, monitoring) намекает на амбиции полноценного продукта.

**Варианты ответов:**
- А. Да, планирую вернуться и делать MVP по IMPLEMENTATION_PLAN.md.
- Б. Проект заморожен, но идея важна — вернусь при появлении времени/соавторов.
- В. Это законченный design doc / эксперимент с Claude Code, кодовая часть не главное.

**Варианты дальнейших действий:**
- При А: начать с блокирующего бага `metadata` в models.py и зелёного CI (см. recommendations.md, «Быстрые улучшения» 1–3), затем один сквозной сценарий Tasks API.
- При Б: зафиксировать честный статус в README и CHANGELOG («концепт, код не запускался»), создать 3–5 issues с планом входа, чтобы не терять контекст.
- При В: оформить по сценарию 3 из recommendations.md — «спецификация как продукт», убрать из CHANGELOG галочки о нереализованном.

## 2. Известно ли вам, что бэкенд в текущем виде не запускается (колонка `metadata` в SQLAlchemy-моделях)?

Проверено на закреплённой версии sqlalchemy==2.0.25: объявление `metadata = Column(Text)` во всех 7 моделях вызывает `InvalidRequestError` при импорте `ingit.db.models` — падают тесты, QUICKSTART и CI (сам сервер стартует, но БД-сценарии нерабочие).

**Варианты ответов:**
- А. Нет, код генерировался и не запускался — спасибо, починю.
- Б. Знал(а), но не дошли руки.
- В. Не важно: код был иллюстрацией к документации.

**Варианты дальнейших действий:**
- При А/Б: минимальный PR — переименовать колонку (`extra_metadata = Column("metadata", Text)`), синхронизировать health-тесты с health.py, прогнать pytest; это час работы, переводящий репо из «не работает» в «каркас работает».
- При В: явно пометить backend/ как «reference implementation, не запускалась», чтобы CHANGELOG и QUICKSTART не вводили в заблуждение.

## 3. Какой контур для вас первичен — файловый (YAML + CLI + git-хуки) или серверный (FastAPI + БД + веб)?

Сейчас это два несвязанных слоя: CLI работает с YAML напрямую и почти жизнеспособен, а API-слой — стабы поверх сломанных моделей. Заявленный «Hybrid Storage» (Git + SQL) не реализован.

**Варианты ответов:**
- А. Файловый: суть InGit — «жизнь в Git», сервер вторичен.
- Б. Серверный: цель — локальная альтернатива GitLab+Jira, файлы лишь транспорт.
- В. Именно гибрид: YAML — источник истины, SQLite — индекс.

**Варианты дальнейших действий:**
- При А: сценарий 1 из recommendations.md — CLI-продукт через pipx, отсечь Docker/monitoring/frontend; быстрый выход к пользователям.
- При Б: сценарий 2 — чинить модели, реализовать CRUD поверх SQLite, Kanban-MVP на antd.
- При В: первым делом написать индексатор `ingit sync` (YAML→SQLite) и поиск — это самая инновационная и пока не существующая часть.

## 5. Как InGit соотносится с другими «инфо-ОС» репозиториями профиля (daten, data30, meta1, daten20)?

В профиле десятки репозиториев про «информационные операционные системы», управление документами и офлайн-приложения. InGit концептуально пересекается с ними (структура папок, метаданные, офлайн), но связей не декларирует.

**Варианты ответов:**
- А. InGit — независимый эксперимент, пересечения случайны.
- Б. InGit задумывался как «хранилищный слой» для остальных проектов.
- В. Планирую консолидацию: несколько репо должны слиться в одну платформу.

**Варианты дальнейших действий:**
- При А: добавить в README один абзац позиционирования относительно соседних репо, чтобы аудиторы и соавторы не путались.
- При Б: описать интерфейс (структура 00–90 + YAML-схемы) как стандарт и сослаться на него из daten20/data20 — см. идею «ingit + daten20» в recommendations.md.
- При В: выбрать «ядро» (вероятно, файловый контур ingit) и составить план миграции; хаб info200 — подходящее место для сводной карты.

**Варианты ответов:**
- А. Desktop — ключевая фишка (offline-first), оставить как цель.
- Б. Начну с web-SPA, Electron потом.
- В. GUI вообще не приоритет — сначала CLI.

**Варианты дальнейших действий:**
- При А: добавить минимальный `src/electron/main.js` (окно с загрузкой Vite-билда), иначе убрать build-конфиг; зафиксировать в roadmap фазу «Desktop».
- При Б: вычистить electron-* из package.json, оставить Vite-SPA и сделать один живой экран (Kanban по Tasks API).
- При В: пометить frontend/ как отложенный, перенести усилия в CLI (сценарий 1).
