# data30 — «метаслой решений»: каталог бизнес-функций, сценариев и макросов с системой доверия и рекомендаций

## Обзор

**data30** — документо-центричный проект «метаслоя решений» (описание репозитория: «info ос рационал программ»). Это полный пакет продуктовой и технической документации для платформы-каталога, в котором бизнес-автоматизация разбирается на атомарные **функции** (Function Dictionary с паспортами), **модули**, **сценарии использования** по шести бизнес-вертикалям и готовые **макросы автоматизации**, а поверх работает система **отзывов, рейтингов и рекомендаций** с ранжированием по сценариям.

Помимо ~70 markdown-документов в репозитории есть реальные исполняемые артефакты (все перепроверены в ходе аудита 03.07.2026):

- алгоритм ранжирования `src/ranking.py` (Python, чистая stdlib, 195 строк) с 4 юнит-тестами — **тесты проходят** (запущены локально: `Ran 4 tests… OK`);
- OpenAPI 3.0.3-контракт REST API с 18 путями (`docs/api/openapi.yaml`, валидный YAML);
- JSON Schema макроса и 14 готовых шаблонов макросов (`schemas/macro.schema.json`, `templates/macros.yaml` — валидны);
- 2 SQL-миграции PostgreSQL: журнал аудита с rollback и система отзывов/рейтингов (`migrations/`);
- статический HTML/CSS-прототип экрана «Поиск сценариев» (`prototype/`, 405 строк HTML).

Репозиторий собирался конвейером параллельных веток Codex-агента (ветки вида `053jns-codex/…`), что оставило характерные «шрамы слияний»: неразрешённые конфликт-маркеры прямо в README на main, битый YAML-каталог приложений, задвоенные секции в прототипе — и целую подсистему борьбы с конфликтами (архив 12 версий README в `readmes/`, скрипты `scripts/merge-branch.sh` и `resolve-readme-conflicts.sh`, инструкции `docs/merge/`).

## Назначение и идея

Идея (из `system_framework.md`, `docs/prd_brd.md`, `recommendation-system-spec.md`) — превратить разрозненные решения по автоматизации в управляемый каталог с единым языком описания:

1. **Function Dictionary / паспорта функций** — каждая функция описывается по фиксированной схеме: ID, категория, входы/выходы, ошибки, ограничения, версия (`FUNCTION_PASSPORT.md`, целевой MVP-словарь ~100 функций).
2. **Каталог приложений** — 20–50 приложений с матрицами «приложение ↔ функции» (`catalog/apps.yaml` — 31 карточка, `catalog/function-matrix.md`).
3. **Шесть бизнес-вертикалей** — Маркетинг (выбрана приоритетной в `docs/vertical-selection.md` по критериям «рынок / данные / скорость внедрения / ROI»: 18 баллов из 20), Продажи, HR, Документооборот, Поддержка клиентов, Финансы — со сценариями и pipeline для каждой.
4. **Макросы автоматизации** — единый формат «триггер → шаги → условия → ошибки → результат», хранение в JSON/YAML, валидация JSON Schema, параметризация без кода для no-code пользователей (`docs/macros/spec.md`).
5. **Система доверия** — раздельные оценки «качество» и «полезность», отзывы только при подтверждённом использовании (verified usage, 90 дней), уровни зрелости prototype → stable → recommended, анти-спам-модерация и объяснимые рекомендации «почему это рекомендовано».
6. **REST API** — CRUD по сущностям Function/Module/UseCase/Macro/Review/Rating, история изменений и откат (rollback), версионирование SemVer + revision (`docs/versioning.md`).

Целевая аудитория (по `system_framework.md`): B2B-команды, разработчики, интеграторы и no-code пользователи.

## Как устроено (архитектура)

- **Слой спецификаций** (основной объём): 8 корневых документов (`system_framework.md`, `data_model.md`, `functional_spec.md` — перечни выросли от 50 до 61 функции, 20–23 сценария, 10 макросов, 20 приложений; `FUNCTION_PASSPORT.md` на 766 строк; `recommendation-system-spec.md`; `risk-register.md` — 10 рисков R1–R10 с владельцами и буферами; `integration_inventory.md` — 20 внешних систем, все контакты TBD) плюс ~40 документов в `docs/`: roadmap с mermaid-Gantt (MVP H2-2025 → Beta H1-2026 → Scale H2-2026), KPI (TTFV ≤ 30 мин, Precision@5 ≥ 55 %), маркетинговый пакет (6 файлов), ADR-0001 о выборе PostgreSQL vs графовой БД, целевая архитектура (Web UI → API Gateway → Auth → Core Service → DB/Cache/Broker).
- **Слой данных**: `data/mvp.json` (эталонный датасет сущностей с version/revision/status — валиден), `data/recommendations.json` (факторы объяснимости — валиден), `catalog/apps.yaml` (~1165 строк — **битый YAML**, ошибка на строке 133).
- **Слой кода**: `src/ranking.py` — ранжирование `ranking_v1`: 4 сценарные конфигурации весов, порог 3 подтверждённых отзыва, log1p-нормализация, множитель свежести 0.7 при отзывах старше 12 мес., штраф за спам-риск; `tests/test_ranking.py`.
- **Слой хранения**: SQL-миграции `change_set` + `audit_log` (before/after JSONB) и `reviews` с раздельными рейтингами.
- **Слой UI**: `prototype/index.html` + `styles.css` — русскоязычный макет поиска сценариев без JavaScript.
- **Слой процессов**: `plans/` (RACI, DoD, таймлайн), `qa/` (тест-план и честный отчёт «тест-раны не выполнены», sign-off отклонён), `readmes/` + `scripts/` + `docs/merge/`.
