# daten5 — «Rationalization Platform»: прототип B2B-платформы каталогизации и интеграции существующих цифровых решений

## Обзор

**daten5** — репозиторий с описанием «info рационал инфо программ». Содержит два разнородных, но связанных артефакта:

1. **`rationalization-proposal.md`** (455 строк, по-русски) — концептуальный манифест «Рационализация вместо инновации»: идея мета-слоя («B2B операционной системы интернета») поверх существующей интернет-инфраструктуры, который не изобретает новые приложения, а каталогизирует, связывает и комбинирует существующие.
2. **`rationalization-platform/`** — сгенерированный за один спринт (1 января 2026, коммиты от бота claude) прототип этой платформы: микросервисный монорепозиторий из 7 backend-сервисов (Node.js + Python), Next.js-фронтенда, схем PostgreSQL/Neo4j и docker-compose на ~16 сервисов.

Корневой README.md репозитория — две строки («# daten5 / info»); вся содержательная документация лежит внутри `rationalization-platform/` (README, GETTING_STARTED, docs/architecture — суммарно >1000 строк документации).

## Назначение и идея

Исходный тезис манифеста: интернет достиг «информационного плато» — новых данных и принципиально новых запросов почти нет, при этом миллионы существующих приложений, плагинов и библиотек фрагментированы и не интегрированы. Предлагаемое решение — **рационализация** как научная дисциплина: интеграция, рекомбинация и каталогизация существующего вместо создания нового. Нужна «Периодическая таблица элементов» для цифровых решений.

Архитектурные компоненты идеи (и их воплощение в коде):

- **Универсальный каталог** приложений/сервисов/библиотек с capabilities, зависимостями, альтернативами → `catalog-api` (REST + GraphQL, PostgreSQL с pgvector);
- **Граф знаний приложений** → схема Neo4j (`neo4j-schema.cypher`, 448 строк);
- **Интернет-макросы (blueprints)** — готовые связки сервисов «в один клик» → `blueprint-engine` (исполнитель workflow);
- **AI-навигатор решений** → `ai-classifier` (эмбеддинги + классификация), `nl-interface` (чат), `solution-composer` (автокомпозиция решений из требований);
- **Краулеры экосистем** → `github-crawler` (реальный обход GitHub через PyGithub).

## Как устроено (архитектура)

Микросервисная схема: фронтенд (Next.js 14) → API Gateway (Node.js, прокси + auth + rate limiting + circuit breaker + метрики Prometheus) → сервисы каталога, ИИ и blueprint'ов → слой данных (PostgreSQL+pgvector, Neo4j, Redis, Elasticsearch) + RabbitMQ; всё поднимается одним `docker-compose.yml` (488 строк, ~16 сервисов, включая Prometheus и Grafana).

Реальная степень готовности неравномерна: `catalog-api` (схема БД на 604 строки SQL, GraphQL-схема 585 строк, резолверы 537 строк, REST-роуты) и `github-crawler` (433 строки работающей логики) проработаны серьёзно; `blueprint-engine` — наполовину (исполнитель на 440 строк при роутах-заглушках по 10–20 строк); фронтенд — каркас из трёх страниц, две из которых пустые заглушки. Тестов, CI, LICENSE и части заявленных в README директорий (infrastructure/, scripts/, frontend/cli, compatibility-engine) **нет** — подробности в [оценке](assessment.md).
