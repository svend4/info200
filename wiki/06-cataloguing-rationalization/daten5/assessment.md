# Характеристика и оценка daten5

Аудит-перепроверка от 03.07.2026. Прочитано: оба корневых документа, README/GETTING_STARTED/docs платформы, docker-compose, .env.example, схемы БД и 20+ файлов кода всех семи backend-сервисов и фронтенда; существование заявленных, но отсутствующих файлов проверено поштучно (HTTP 404). Покрытие близко к полному — репозиторий компактный (~73 файла).

## Что есть

- **Качественный концептуальный документ** `rationalization-proposal.md` (455 строк): проблема «информационного плато», парадигма рационализации, 5 архитектурных компонентов, 4 фазы, метрики успеха, экономическая модель, риски, roadmap Q1–Q4 2026. Это самый ценный и завершённый артефакт репозитория.
- **Проработанные схемы данных**: `schema.sql` (604 строки — pgvector-эмбеддинги, pg_trgm, ivfflat-индексы, таблицы applications/capabilities/blueprints/crawler_runs с CHECK-ограничениями) и `neo4j-schema.cypher` (448 строк — онтология узлов и связей DEPENDS_ON/SIMILAR_TO и др.).
- **Catalog API** — реальный, а не декоративный: Express + Apollo Server 4, GraphQL-схема 585 строк + резолверы 537 строк, REST-роуты с express-validator (applications.js — 464 строки), инициализация 4 хранилищ с проверкой соединений (db/init.js, 227 строк).
- **GitHub-краулер** (433 строки Python): учёт rate limit API, извлечение зависимостей из package.json/requirements.txt/go.mod, идемпотентный upsert (`ON CONFLICT ... DO UPDATE`), запись графа в Neo4j, журнал прогонов в crawler_runs.
- **AI-классификатор** с продуманным fallback: OpenAI ada-002/GPT-3.5 при наличии ключа, иначе локальный sentence-transformers и rule-based классификация — сервис не падает без ключа.
- **API Gateway** с нетривиальным middleware: собственный circuit breaker (190 строк), Redis-кэш, JWT-auth, Prometheus-метрики, агрегирующие маршруты (280 строк).
- **Blueprint-engine**: ядро WorkflowExecutor (440 строк) — шаги api_call/configure/validate/wait/conditional, отслеживание прогресса, отмена исполнения.
- **Инфраструктура одним файлом**: docker-compose на ~16 контейнеров (PG+pgvector, Neo4j 5 c APOC/GDS, Redis, Elasticsearch, RabbitMQ, все сервисы, Prometheus, Grafana) + полный `.env.example` + `GETTING_STARTED.md` с таблицей портов и примерами запросов.

## Чего нет

- **Тестов — ни одного файла**, при том что jest с coverage настроен в трёх package.json, а pytest внесён в requirements.txt. Раздел «Testing» в README описывает несуществующие команды.
- **CI/CD**: `.github/workflows/` отсутствует (404), хотя README обещает GitHub Actions.
- **LICENSE и CONTRIBUTING.md**: README ссылается на оба файла — их нет (404); MIT заявлена только в package.json.
- **Заявленных в README директорий**: `frontend/cli`, `infrastructure/` (docker/kubernetes/terraform), `docs/api`, `docs/guides`, `scripts/`, `backend/compatibility-engine` — не существуют.
- **Скриптов миграции и сидинга**: `npm run migrate`/`npm run seed` из package.json и GETTING_STARTED указывают на `scripts/migrate.js`/`seed.js` — файлов нет (404). Инициализация БД фактически работает только через init-монтирование schema.sql в контейнер PostgreSQL.
- **Рабочего фронтенда**: страницы `/applications` и `/chat` — заглушки по 7 строк (заголовок + неиспользуемый useState), страницы `/blueprints`, на которую ссылается главная, вообще нет.
- **Данных**: каталог пуст, ни одного blueprint'а, сидов нет — «10 готовых blueprints» из roadmap Q1 2026 не существуют.
- **Использования части провизионированной инфраструктуры**: RabbitMQ поднят, но код использует Bull поверх Redis; Elasticsearch поднят и подключается в db/init.js, однако REST-поиск (`search.js`) работает на PostgreSQL ILIKE, а наполнение ES-индекса нигде не реализовано (индексация не найдена — «не проверено» только для резолверов GraphQL целиком).

## Плюсы

- Сильная, внятно изложенная концепция с редкой для профиля глубиной (экономика, метрики, риски, сравнение подходов).
- Архитектурно грамотный каркас: правильное разделение сервисов, продуманные схемы данных, fallback-стратегии в ИИ-сервисах.
- Локально воспроизводимая инфраструктура (docker-compose + .env.example) — низкий порог входа для продолжения работы.
- Код читаемый: секционные комментарии, winston/structlog-логирование, обработка ошибок, graceful shutdown.
- Идемпотентный краулер с журналированием прогонов — редкая аккуратность для прототипа.

## Минусы

- **Запуск «из коробки» почти наверняка сломан**: дублирующийся ключ `api-gateway` в docker-compose.yml (строки ~252 и ~335 — YAML-парсер compose откажет или молча возьмёт второй блок) и монтирование несуществующих `./infrastructure/prometheus/prometheus.yml` и `./infrastructure/grafana/...` (Docker создаст пустые каталоги, Prometheus не стартует с директорией вместо конфига). Не проверено запуском, но дефекты видны статически.
- Документация систематически описывает несуществующее — доверять README нельзя без сверки с деревом.
- Нулевая верификация: ни тестов, ни CI, ни свидетельств хотя бы одного успешного `docker-compose up`.
- Резкий перепад глубины: ядро проработано, периферия (frontend, очереди, blueprint-роуты) — заглушки в 7–20 строк.
- Проект заморожен через 2 дня после генерации; issues/веток/следов использования нет.
- Пароли-заглушки `changeme123` зашиты как значения по умолчанию во множестве мест (для прототипа приемлемо, для «Production» — нет).

## Качество кода и документации

Код — уровня «добротный AI-сгенерированный каркас»: единообразный стиль, современные библиотеки (Apollo 4, FastAPI, Next.js 14 App Router), корректные паттерны (пулы соединений, ретраи, circuit breaker), но без единого теста и без следов отладки на живой системе. Документация объёмна (README + GETTING_STARTED + 631 строка docs/architecture) и хорошо структурирована, однако частично фиктивна: описывает целевое состояние как существующее. Манифест — лучшая часть: самостоятельный, законченный текст.

## Зрелость: 2/5

Обоснование: концепция и схемы данных — на 4/5, но проект в целом не поднимался и не проверялся (сломанный docker-compose, отсутствующие migrate/seed), тестов и CI нет, фронтенд — заглушка, данных ноль, активность прекратилась 03.01.2026. Это вертикальный «скелет» платформы после одного AI-спринта: выше «почти пустого» (1), но до «работающего прототипа» (3) не хватает хотя бы одного подтверждённого end-to-end запуска.
