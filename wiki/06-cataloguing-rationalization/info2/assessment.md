# Характеристика и оценка info2

## Что есть

- **Полный концептуальный пакет** (13 md-файлов, ~6 900 строк): от определений (01-DEFINITIONS.md) до схемы БД (05-DATA-STRUCTURE.md, 827 строк) и roadmap с бюджетом и рисками (06-ROADMAP.md, 642 строки). Документация связная, со сквозной терминологией; README реально соответствует содержимому prototype/ по составу команд CLI и модулей.
- **Работающий по коду прототип** (~7 500 строк JS): Express API с JWT-аутентификацией, bcrypt, helmet, rate-limit и Swagger (`prototype/api/`); движок дедупликации с тремя уровнями (`core/deduplication.js`); резолвер semver-зависимостей с обнаружением циклов и топосортировкой (`core/dependency-resolver.js`); CLI на 8 команд.
- **Реальная схема PostgreSQL** (369 строк SQL): UUID, `content_hash UNIQUE` как механизм дедупликации на уровне БД, trigram-индексы, триггеры, представления; плюс сиды (179 строк) и инструкция DATABASE-SETUP.md.
- **Инфраструктурные интеграции**: Redis-кэш (505 строк), Elasticsearch-поиск (523), WebSocket real-time (682 суммарно), Prometheus-метрики (349) — все с graceful fallback при недоступности сервисов (проверено в `api/advanced-routes.js`: try/catch с переходом на fallback-поиск).
- **Тесты**: `__tests__/deduplication.test.js` (296 строк, unit на mock-реестре) и `api.integration.test.js` (245 строк, supertest). Наличие подтверждено, **запуск не проверялся**.
- **DevOps-обвес**: Dockerfile, два docker-compose (8 сервисов), k8s/base (deployment+ingress), prometheus.yml, CI-пайплайн на 7 стадий.
- **Примеры**: 4 эталонных компонента (jwt-generator, rate-limiter, query-builder, validator, суммарно ~1 100 строк) и манифест `sample-app.thub.yaml` (339 строк).
- **Зачаток фронтенда**: Next.js 14 + MUI, одна страница поиска/трендов, 3 компонента, 1 хук.

## Чего нет

- **Файла LICENSE** — README заканчивается «MIT License — см. файл [LICENSE](LICENSE)», но `LICENSE`, `LICENSE.md`, `LICENSE.txt` возвращают 404. MIT указан только в package.json.
- **Lock-файлов** (`prototype/package-lock.json`, `frontend/package-lock.json` — 404). Из-за этого **CI неработоспособен по построению**: `ci.yml` использует `npm ci` и `cache-dependency-path: prototype/package-lock.json` — `npm ci` без lock-файла падает. Фактические запуски Actions не проверены (нет доступа), но структурно пайплайн пройти не может.
- **Точки входа `prototype/index.js`** — в package.json `"main": "index.js"`, файла нет (404); `require('@thub/core')` сломан.
- **Реального деплоя** — стадии deploy-staging/deploy-production в ci.yml — заглушки `echo "Deploying..."` с закомментированными kubectl/helm-командами; URL thub.io/staging.thub.io — вымышленные.
- **Подтверждения работоспособности** — нет ни одного badge, скриншота, лога запуска; репо никогда не собиралось (нет следов).
- **Семантической дедупликации в заявленном виде** — в доках упоминается «AST analysis», в коде — только Jaccard-схожесть множеств токенов (`calculateSimilarity` в deduplication.js). O(n) сравнение со всеми компонентами категории не масштабируется.
- **Issues, веток с историей, внешних пользователей** — 0 звёзд/форков/issues.
- **Полного фронтенда** — одна страница; нет `_app.jsx`, конфига Next, страниц компонента/логина, хотя package.json заявляет полный стек (react-query + swr + zustand одновременно — избыточно).

## Плюсы

- Редкая для профиля **полнота вертикального среза**: концепция → схема БД → API → CLI → тесты → Docker/K8s/CI — все слои представлены и согласованы между собой по именам и контрактам.
- **Ядро идеи реализовано честно**: дедупликация по content-hash и через UNIQUE-ограничение в БД — это работоспособная механика, а не только слова.
- **Качественный резолвер зависимостей**: конфликты версий, циклы с диагностической цепочкой, топосортировка — аккуратный алгоритмический код.
- **Грамотные паттерны**: graceful degradation внешних сервисов, пул соединений с таймаутами, параметризованные SQL-запросы, AAA-тесты на mock-реестре.
- Хорошая **русскоязычная документация концепции** — 04-THUB-CONCEPT.md (1044 строки) можно читать как самостоятельное эссе о content-addressed подходе к коду.

## Минусы

- **Проект — однодневная AI-генерация** (6 коммитов «claude» за 25.01.2026), ни разу не запускавшаяся: битый `main` в package.json, отсутствующие lock-файлы при `npm ci` в CI, отсутствующий LICENSE — три дефекта, которые обнаруживаются на первой минуте реальной работы.
- **Питч сильно опережает реальность**: бизнес-модель, $1M ARR, «99.9% uptime», контакты team@thub.io и репозиторий github.com/thub-io/thub — вымышленные; даты противоречат реальной истории — секция Timeline в README датирует фазы «Q1 2024 → 2026+», а PROJECT-SUMMARY.md заявляет «Создано: 2024-01-25», тогда как все коммиты сделаны 25 января 2026 (сам 06-ROADMAP.md использует относительные сроки — «1-2 месяца» — без календарных лет).
- **«Семантическая» дедупликация — примитив**: Jaccard по токенам даст ложные срабатывания на шаблонном коде и пропустит переименованные переменные; заявка на AST-анализ не реализована.
- Название репозитория (**info2**) никак не связано с содержимым (T-Hub) — типовая для профиля проблема обнаруживаемости.
- Дублирование документации: README.md vs README-COMPLETE.md (637 строк) пересекаются; PROJECT-SUMMARY.md устарел относительно фактической структуры.

## Качество кода и документации

Код — уровня «очень хороший учебный прототип»: подробные JSDoc-комментарии, единый стиль, разумные абстракции (Repository-паттерн, отделение core от api), обработка ошибок в ключевых местах. Но это качество «написанного», а не «выверенного запуском»: интеграционные швы (main-поле, lock-файлы, CI) битые. Документация обширна и внутренне согласована, однако смешивает жанры — техническую спецификацию и инвесторский питч с вымышленными метриками, что мешает воспринимать её всерьёз без чистки.

## Зрелость: 2/5

Обоснование: значительный объём согласованного кода и документации по всем слоям (это больше, чем 1/5 у «почти пустых» репо профиля), присутствуют тесты и CI-скелет. Но проект ни разу не запускался (битые package.json/CI/LICENSE), развитие остановилось в день создания, нет пользователей, деплой и бизнес-часть — фикция. До 3/5 не хватает: подтверждённого запуска полного стека, зелёного CI и хотя бы минимальной пост-генерационной доводки.

**Ограничение покрытия аудита**: прочитаны целиком или частично ~20 ключевых файлов (core, api/server.js head, auth/advanced-routes заголовки, схема SQL, тесты, CI, конфиги, 3 из 13 документов подробно); большие md-документы (03, 04, 05) и модули redis.js / elasticsearch.js / websocket.js оценены по размеру, заголовкам и перекрёстным ссылкам, но не построчно. `npm install` / прогон тестов не выполнялись.
